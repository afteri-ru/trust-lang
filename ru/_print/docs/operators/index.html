В TrustLang любая конструкция является выражением и возвращает значение, поэтому её можно вкладывать в другие выражения. Инструкции разделяются точкой с запятой ;; группа инструкций заключается в блок кода { ... }. Базовые правила блоков и выражений описаны в Синтаксисе.

Обработка аварийных ситуаций и гарантии освобождения ресурсов связаны с моделью Памяти, а операторы типизации — с Системой типов.

1 - Создание объектов и присваивание

Операторы создания и присваивания объектов, деструктуризация

Создание объектов

Для создания объектов в TrustLang используется несколько операторов:

  • “:=” — создаёт или присваивает значение переменной/функции (объекту по значению). Если объекта с таким именем ещё нет, он создаётся; иначе значение переприсваивается. Пример: x := 5;, hello(str) := { ... };.

  • “::=” — объявление типа (алиаса или типизированного типа), например MyInt ::= :Int32;, Status ::= (OK=0, ERROR=1, BUSY=2,):Enum;. Применять “::=” для создания значений/функций нельзя — компилятор сообщает: “cannot assign a type … to a value variable; use ‘::=’ to declare a type alias”.

    Также через ::= объявляется предварительное (forward) объявление нативного класса: String ::= %std::string { %size(): UInt64 := ...; }; — RHS — имя класса (native — с ведущим %), тело { ... } — члены-интерфейс (методы/поля/конструкторы), каждый := ... (без тела). Конструирование объекта — вызов имени класса: s: String := String('hello'); → std::string("hello"). Подробнее — Нативные типы.

Операторы “::-” и “:-” в текущей версии не реализованы; ранее они предназначались для чистых функций и значений, вычисляемых на этапе компиляции.

Присвоение нового значения

Оператор “=” применяется для присвоения нового значения уже существующим объектам. Если объект с указанным именем отсутствует, то возникает ошибка компиляции.

Оператор обмена значениями

Оператор “:=:” (swap) не создает новых переменных, а только обменивает их значения между собой. Переменные должны иметь одинаковые/совместимые типы данных, либо иметь тип :None, т. е. "_".
Используется для реализации идиомы копирования и замены (copy-and-swap idiom), так как при выполнении оператора не может быть ошибок.

В текущей реализации :=: — интринсик обмена/перемещения (используется как инструкция; результат void): a :=: b раскрывается в std::swap(a, b) (типы должны быть совместимы, не обязательно ссылки; обмен несовместимых типов — ошибка с диагностикой); форма var :=: _ — перемещение значения в discard: перемещение выполняется РЕАЛЬНО (материализуется временное, которое сразу разрушается), поэтому var остаётся в moved-from состоянии, а для владеющих ссылок (unique/shared) ресурс освобождается. См. также «Ссылочные типы».

Оператор добавления элемента

Оператор “[]=” — аналог push_back: добавляет новый элемент к контейнеру слева, увеличивая его размер на единицу. Общее правило: X []= v равносильно X.push_back(v).

  • Для словаря (Dict, в т.ч. позиционные «массивы») безымянный append добавляет позиционный элемент: d []= 999.
  • Для строк добавляет символ/строку: s []= 'd' → s.append("d").
  • Правый объект оператора должен быть совместим с типом единичного элемента левого объекта (ширина строки: узкая '...' / широкая "..." должны совпадать с типом строкового контейнера).
  • Вложенный LHS (d['x'] []= v, d[0] []= v, d.field []= v) — пока не реализован (ошибка компиляции).
  • Слияние словаря через оператор распаковки ...: d []= ... dict2 или d []= ... (a=1, b=2,) добавляет в цель все элементы словаря-операнда (аналог extend/update); размер цели растёт на число элементов (для литерала и словаря с известным размером — статически контролируется).
    d := (1, two=2,);
    d []= 999;        # добавить позиционный элемент → size 3
    d []= 'x';        # добавить ещё один элемент
    d []= ... (a=100, b=200,);  # слияние литерала → size 5 (добавлены a и b)
    d2 := (three=3, 4,);
    d []= ... d2;     # слияние переменной-словаря → size 7

    s := 'abc';
    s []= 'd';        # строка стала "abcd"
    @print('{}', s);   # > abcd

Добавление именованного элемента словаря выполняется оператором присваивания d[name] = value (установка/добавление по ключу).

Например, при определении класса :NewClass2:

    :NewClass ::= :Class{       # Базовый класс
        field1:Int32 := 1;      # поле класса
        field2:Int32 := 2;      # поле класса
        method1():Void := {};   # метод
    };

    :NewClass2 ::= :NewClass{   # наследование
        field2:Int32 := 2;      # поле field2 базового класса
        method1():Void := {};   # переопределение метода (override)
    };

    $var := 99; # Создать временную переменную $var
    {
        $var := 100; # Новая переменная перекрывает $var более высокого уровня
        @print('{}', $var)    # > 100
    }
    @print('{}', $var)    # > 99

Присваивание значения сразу нескольким переменным и оператор распаковки словаря

TrustLang поддерживает операцию присваивания значения сразу нескольким переменным, которые должны быть перечислены через запятую слева от оператора присвоения.

С правой стороны от оператора присвоения может находиться только одно значение, а для обмена значениями двух переменных, вместо записи a,b = b,a; нужно использовать оператор обмена:

    a :=: b;

В качестве правого операнда в операторе присвоения допускается использовать оператор распаковки словаря … (многоточие), который можно использовать и при передаче аргументов в функцию.

2 - Операторы

Арифметические операторы

Арифметические операторы TrustLang применимы к числовым типам и формам с присваиванием. Каждый бинарный оператор имеет парный аналог op=, который выполняет операцию и присваивает результат левому операнду (a += 1;):

Оператор Действие
+ / += сложение
- / -= вычитание
* / *= умножение (применимо и для повторения строк)
/ / /= деление (результат — число с плавающей точкой)
// / //= целочисленное деление с округлением к меньшему (как в Python)
% / %= остаток от целочисленного деления

Отдельного оператора возведения в степень нет (степень вычисляется функцией/повторным умножением). Арифметика рациональных чисел и :BigInteger — отдельная строгая ветка: смешивание с числами с плавающей точкой требует явного преобразования (см. Числа и тензоры).

Битовые (поразрядные) операторы

Записи .<. (сдвиг влево), .>./.>>. (сдвиг вправо), .&., .|., .^., .~. (И/ИЛИ/ИСКЛ-ИЛИ/НЕ) распознаются лексером и поддерживаются при SMT-верификации контрактов (транслируются в BV-операторы bvshl/bvashr/bvand/bvor/bvxor/bvnot). Генерация исполняемого C++-кода для них ещё не реализована (запланировано) — в .cppt оператор выводится как есть. Статус — в разделе Статус реализации.

Арифметическое сравнение

Операторы арифметического сравнения — классические <, >, <=, >=, ==, !=. Они применяются для сравнения скаляров и рациональных чисел; операторы равенства == и != позволяют сравнивать и составные значения.

Сравнение значений

  • == и != — сравнение с автоматическим приведением совместимых типов для любых объектов.
  • === и !== — точное сравнение для любых объектов (автоматического приведения не выполняется); для объектов сравниваются адреса размещения.

Сравнение типов

Операторы сравнения типов возвращают Bool и различаются строгостью проверки:

Оператор Смысл
<~ номинальная проверка: тип левого операнда совпадает с правым типом либо присутствует в его иерархии наследования
~~ утиная (структурная, нестрогая): у левого операнда присутствуют все поля образца правой части
~~~ строгая: номинальное тождество типа либо точное совпадение набора полей образца

Правый операнд — имя типа (:Class), строковый литерал с именем типа или словарь-образец ((field1=_, field2=0,); пустой словарь — (,)). Левый операнд — значение (проверяется его тип) или имя типа (:Base <~ :Derived).

dog <~ :Animal;             # тип dog — Animal или его наследник
dog ~~~ :Dog;               # точное тождество типа
:Dog <~ :Animal;            # Dog — подтип Animal (проверка на этапе компиляции)
:Animal <~ :Dog;            # ложь (обратное отношение — перестановкой операндов)
d ~~ (field1=_,);           # у d есть поле field1
d ~~~ (field1=_, field2=0,);# точный набор полей

Отрицаний у этих операторов нет — результат Bool проверяется как обычно: ветка else в if/match либо сравнение с false.

Статическая и динамическая проверка

  • Статика (основной путь): если тип левого операнда выведен на этапе компиляции, результат свёртывается в константу true/false (наследование — по реестру типов). Нулевая стоимость в генерируемом коде.
  • Динамика: проверки, требующие рантайм-типа значения (стёртые значения Any/элементы словаря с неизвестным типом), а также имя типа из строковой переменной, пока не реализованы — выдаётся явная диагностика компиляции.

3 - Условия и циклы

В TrustLang нет ключевого слова if: условие проверяется конструкцией, которая по смыслу соответствует математическому «следует» — два тире и угловая скобка -->. Запись легко объединяется в цепочки для проверки нескольких условий вида «else if». Ниже конструкция показана обеими формами — DSL-макросом и базовым синтаксисом (о двух формах записи см. Макросы и DSL):

Макросы DSLБазовый синтаксис
@if( условие1 ) {
    действие1
} @elif( условие2 ) действие2
@else {
    действие_иначе
};
[ условие1 ] --> { действие1 },
[ условие2 ] --> действие2,
[ ... ] --> { действие_иначе };

Для записи циклов используется оператор <-> (в базовой записи) или макросы @while/@dowhile (в DSL). Условие записывается в квадратных скобках; в зависимости от взаимного расположения условия и тела цикл бывает с предусловием (while) или с постусловием (do while). Эквивалентные формы:

Макросы DSLБазовый синтаксис
@while( cond ) {
    тело цикла
};
[ cond ] <-> {
    тело цикла
};
{
    тело цикла
} @dowhile( cond );   # постусловие
{
    тело цикла
} <-> [ cond ];   # постусловие
@while( cond ) {
    ...
} @else {
    ...    # если cond == false при входе
};
[ cond ] <-> {
    ...
}, [ ... ] --> {
    ...    # ветка else
};

Цикл с предусловием (while) поддерживает ветку else, которая выполняется, если условие входа в цикл не было выполнено ни разу.

Внимание: это отличается от аналогичной конструкции в Python, где секция else выполняется всегда, кроме прерывания цикла по break.

Перебор коллекций (foreach)

У цикла foreach нет отдельного ключа DSL — он реализуется циклом с деструктуризацией элемента и мутацией источника (оператор раскрытия списка). Пример суммирования элементов словаря:

summa := 0;
dict := (1,2,3,4,5,);
[ dict ] <-> {          # условие цикла — пока в dict есть данные
    # распаковка: первый элемент переходит в item, суффикс dict... — оставшиеся
    item, dict... := ... dict;
    summa += item;      # накопление суммы
};

Сопоставление с образцом (match)

Оператор оценки выражения (match) — приблизительный аналог операторов switch/match в других языках. Он задаётся конструкцией [ выражение ] ==> { ... } (базовый синтаксис) или макросом @match (DSL), в теле которых перечисляются ветки-условия. Эквивалентные формы:

Макросы DSLБазовый синтаксис
@match( $var ) ==> {
    @case( 1 ) { code };
    @case( 1, 2 ) { code };
    @default { code default };
};
[ $var ] ==> {
    [1] --> { code };             # $var == 1
    [1, 2] --> { code };          # ($var == 1 || $var == 2)
    [...] --> { code default };   # иначе
};

Хотя оператор внешне похож на сопоставление с образцом (pattern matching), по сути это краткая запись множественного оператора сравнения: в качестве оператора оценки можно использовать любой оператор сравнения:

  • ==> — равенство с приведением типов;
  • ===> — точное равенство;
  • ~> — проверка типа (имени класса);
  • ~~> — утиная типизация;
  • ~~~> — строгая утиная типизация.

Если в качестве оператора сравнения используется утиная типизация, оценка превращается в классическое сопоставление с образцом по полям (пример приведён на форме @match):

$value := (f1=1, f2='2',);
@match( $value ) ~~> {
    @case((f1=_,), (f1=_, f2=0,)) { ... }; # поле f2 отсутствует или является числом
    @case((f1=_, f2="",), (f1=_, f2='',)) { ... }; # поле f2 — строка
    @default { ... };
};

Переопределение функции сравнения (атрибут @[matcher("fn")])

Если сравнение по значению не сводится к == (например, сопоставление строки с регулярным выражением), функцию сравнения match можно переопределить атрибутом @[matcher("fn")], где fn — объявленная ранее функция-предикат с сигнатурой bool fn(T_value, T_pattern). В каждой ветке вместо сравнения (value == pattern) вызывается предикат fn(value, pattern); проверяемое выражение (scrutinee) вычисляется один раз во временную переменную. При заданном матчере ветки всегда порождаются как if/else-цепочка (оператор switch неприменим — шаблон не обязан быть константой).

Атрибут ставится между значением и оператором (на «сырой» форме, так как макрос @match требует оператор сразу после себя):

@func matches_regex(value:StrChar, pattern:StrChar):Bool { ... };
$s := 'foobar';
[ $s ] @[matcher("matches_regex")@] ==> {
    @case('^foo') { ... };
    @case('bar$', 'baz') { ... };
    @default { ... };
};

Семантика проверяет, что fn — объявленная функция-предикат ровно с двумя параметрами и логическим (булевским) возвратом. Атрибут @[matcher] несовместим с сопоставлением по типу (~>/~~>/~~~>).

4 - Менеджер контекста (with)

Групповой захват ссылок и автоматическое освобождение ресурсов (RAII)

Одиночный оператор захвата ссылки и синхронизации доступа к объекту (*ref, *ref(...)) выполняется для одного действия. Захват ссылки/объекта синхронизации — относительно медленная операция, поэтому выполнять её для каждого действия нерационально. Менеджер контекста (with) однократно захватывает сразу несколько ссылок/объектов и выполняет группу действий под общим локом, а также служит для автоматического освобождения ресурсов (RAII) при выходе из блока.

В базовом синтаксисе — оператор **( ... ), в DSL ему соответствует макрос @with (см. Keyword syntax (DSL)). Сравнение форм записи на примере захвата-блокировки ссылки:

Макросы DSLБазовый синтаксис
@with(lock = *ref) {
    ...   # критическая секция
};
**( lock = *ref ) {
    ...   # критическая секция
};

Захват и блокировка ссылок

Ссылочные переменные объявляются атрибутами @[reftype("shared")@]/@[reftype("weak")@] и транслируются в trust::Shared/trust::Weak; оператор take *ref/*^ref захватывает ссылку (lock/lock_const) и возвращает охраняемый доступ trust::Locker<T>. Подробнее о ссылочных типах и модели ссылок — в Управлении памятью.

with хранит список пар (замок, привязка) и связывает захваченные ссылки с именами внутри тела:

@with(lock = *ref) {     # захват-блокировка ссылки ref
    ...                  # критическая секция
} @else { ... };         # ошибка захвата (ref == nullptr) → else
  • with(lock = *ref) — создаёт временный замок auto __cap = ref.lock();, привязка lock автоматически разыменовывается в значение; вызов lock() бросает IntMinus при сбое → ветка else.
  • with(_ = *ref) — захват ссылки на всё тело без привязки значения.
  • with(*ref) — временный лок: снимается сразу, тело выполняется без лока.
  • Привязка ссылочной переменной без */*^ (with(v = ref)) — предупреждение компилятора.

Автоматическое освобождение ресурсов (RAII)

Кроме захвата ссылок, менеджер контекста позволяет выделять и освобождать ресурсы: при выходе из блока вызывается деструктор объекта (для объектов по значению). Освобождение происходит до попадания в ветку else, если она есть:

@with(name = expr, ...) {  # RAII-захват значений
    ...
} @else { ... };           # при исключении в инициализаторе expr

Это гарантирует закрытие файлов, освобождение захваченных ресурсов и т. п. независимо от того, как завершился вложенный код (штатно, по прерыванию или по ошибке).

Статус реализации

Формы &/&?/&&, параметр __timeout__, межпотоковая синхронизация и типы :Class/:Thread в текущей версии не реализованы (см. Статус). Работают: ссылочные переменные @[reftype(...)], захват ссылок with(...) с веткой else и RAII-захват значений with(name=expr).

5 - Возврат, прерывания и обработка ошибок

Последовательность команд (блок кода) можно прервать в любом месте специальными операторами прерывания. В TrustLang используются два вида прерываний, которые по смыслу соответствуют своей записи:

  • «положительное» прерывание ++ — возврат значения/сквозная передача потока (аналог return);
  • «отрицательное» прерывание -- — ошибка (аналог throw).

Прерывание может возвращать значение: ++ 'Строка' ++ — вернуть строку, -- err -- — «бросить» ошибку (примерный аналог throw err). Если значение не указано, прерывание не возвращает ничего (пустое значение).

Именованные прерывания: локальный переход и возврат

Именованные блоки кода могут выступать локальными метками передачи потока управления. Если перед оператором прерывания указать пространство имён/метку блока, то такое именованное прерывание действует только для указанного блока:

  • block ++ — break по метке block (выход из блока);
  • block -+ — continue по метке (переход на первую инструкцию блока).

Один и тот же фрагмент — именованный цикл с выходом по метке и переходом к началу блока — двумя формами:

Макросы DSLБазовый синтаксис
outer {
    @loop {
        @break outer;     # break по метке outer (как outer ++)
        @continue outer;  # continue по метке outer (как outer -+)
    };
};
outer {
    [1] <-> {
        outer ++;   # break по метке outer
        outer -+;   # continue по метке outer
    };
};

Тело функции — это блок кода, чьё имя совпадает с полным именем функции. Поэтому «положительное» прерывание по метке функции возвращает результат из неё (func_name ++ value ++); в DSL этому соответствует @return.

Перехват прерываний (try/catch)

Неименованные прерывания можно «ловить». Для перехвата используются блоки кода со специальной семантикой, которые оборачивают тело в try/catch по классу прерывания:

  • {+ ... +} — перехватывает положительные прерывания (IntPlus);
  • {- ... -} — перехватывает отрицательные прерывания (IntMinus);
  • {* ... *} — перехватывает оба типа (IntAny).

Статус реализации (важные уточнения):

  • неименованное ++ value ++ всегда бросает IntPlus (положительное/сквозное), а -- err -- — IntMinus (ошибка), независимо от наличия и глубины обработчиков;
  • именованное func ++ value ++ — обычный return из функции (метка обязана быть текущей функцией или глобальной ::);
  • неперехваченный класс пробрасывается насквозь; сквозной ++ проходит через вызовы функций до ближайшего {+}/{*};
  • перехват значения (например, через match) пока не реализован — перехваченное прерывание поглощается.

Обработка ошибок

«Отрицательное» прерывание используется для возврата ошибки лишь условно — оба вида прерываний равнозначны. Совместная обработка перехваченного значения в классическом стиле try/catch — через блоки перехвата ({*}, {-}, {+}) и оператор оценки выражения — пока не реализована: перехваченное прерывание поглощается (см. Статус).
