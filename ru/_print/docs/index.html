TrustLang — язык программирования, который транслируется в C++ и собирается внешним компилятором. Ключевые свойства модели:

  • Грамматика на правилах, а не на ключевых словах — простой однопроходный парсер и расширяемость; привычная запись с ключевыми словами реализуется макросами (Синтаксис, Макросы).
  • Безопасная модель памяти без сборщика мусора — RAII, сильные/слабые ссылки, запрет сильных циклических ссылок, защита стека (Безопасность и качество).
  • C/C++ — интеграция «первого класса» — нативные типы/функции/классы и шаблоны, embed-вставки, линковка; учитывается в каждом контексте (Типы).
  • Гибкая типизация и вывод типов — статическая и динамическая, автоматический вывод (Типы).
  • Контракты и верификация — пред-/пост-условия и утверждения проверяются SMT-решателем (Z3) (Верификация).
  • Запуск как у скриптов — файл с шебангом #!.../trust --run запускается напрямую, как Python-скрипт, но с полной компиляцией: транспиляция в C++, сборка и запуск бинарника происходят автоматически, интерпретатор не нужен.

1 - Синтаксис

Концепция и правила синтаксиса языка программирования TrustLang

1.1 - Концепция

Концепция и правила синтаксиса языка программирования TrustLang

Фундаментальные понятия

Синтаксис TrustLang имеет несколько общих для всего языка правил:

  • Язык построен на грамматических правилах, а не на ключевых словах. Лексер и парсер получаются однопроходными, простыми и быстрыми, а привычная запись с ключевыми словами (@if, @while, @func, …) реализуется поверх базового синтаксиса через макросы.
  • Термины исходного текста сначала распознаются лексером и обрабатываются макропроцессором, и только затем попадают в парсер. Это позволяет с помощью макросов модифицировать даже базовые синтаксические конструкции.
  • Инструкции (операторы) разделяются точкой с запятой ;.
  • Блоки кода записываются в фигурных скобках { ... }.
  • Любая конструкция (в том числе блок кода) является выражением и возвращает значение, поэтому её можно вкладывать в другие выражения.

Синтаксис TrustLang можно условно разделить на несколько слоёв, каждый из которых отвечает за свою область:

  1. Алгоритмический слой — минимально необходимая основа, описывающая сам алгоритм: литералы, именованные объекты, операторы и управляющие конструкции (Операторы). Этот слой оптимизирован для машинного разбора и не содержит «синтаксического сахара».
  2. Оформительский слой — не влияющие на алгоритм средства оформления и упрощения записи: макросы, вспомогательные проверки.
  3. Атрибуты — отдельный слой записи свойств элементов, которые не меняют алгоритм, но влияют на детали его реализации (оптимизации, интеграция с C/C++).
  4. Верификация — слой контрактов, который не пересекается с остальными и не влияет ни на алгоритм, ни на его реализацию, а служит для доказательства корректности алгоритма.

Блоки кода

Последовательность идущих подряд инструкций группируется в блок кода { ... }, который выполняется как единое целое и завершается точкой с запятой ;. Блок кода возвращает значение своей последней инструкции; тип этого значения можно ограничить явно: { ... }:Type.

Блоки кода используются для ограничения области видимости переменных (см. Иерархия кода) и могут быть именованными — тогда они выступают локальными метками передачи потока управления (см. Возврат, прерывания и ошибки). Тело функции тоже является блоком кода в пространстве имён её определения. Перехват и прерывание потока внутри блока описаны в разделе Обработка ошибок.

Блок кода с нативным синтаксисом {% ... %} содержит исходный текст на языке реализации (C++), который подставляется в выходной текст напрямую (см. Нативные типы).

1.2 - Именование объектов

Правила именования переменных, функций и типов данных

В качестве имен объектов и названий типов данных можно использовать буквы, цифры и знаки подчеркивания в любых комбинациях, при условии, что первый символ имени не является цифрой.

Имя не может состоять из единственного знака подчеркивания, так как это специальный термин, который используется в служебных целях.

Для избежания коллизий имен можно использовать пространство имен и модульную структуру кода, которые TrustLang поддерживает одновременно. Допускается переопределение и перегрузка функций.

При создании объектов имя идентификатора может содержать один или несколько специальных символов — квалификаторов (или сигилов), за которыми закреплено определённое значение.

Квалификаторы имён

  • ‘@’ — префикс собачка используется для указания имени макроса, который обрабатывается препроцессором до начала синтаксического анализа исходного текста программы.
  • ‘$’ — знак доллара в начале имени объекта обозначает временное имя, время жизни которого ограничено семантикой языка.
  • ‘::’ — двойное двоеточие разделяет пространства имён и является признаком постоянного объекта, значение которого сохраняется после выхода из текущей области видимости. Если имя начинается с ‘::’, то область его видимости будет глобальной и он будет доступен из других модулей программы.
  • ‘.’ — префикс точка используется при обращении к полю модуля или класса (ограничивает область видимости только текущим объектом). Префикс точка также может быть использован при определении или вызове функции для указания имени аргумента, который нельзя перекрыть макросом препроцессора.
  • ‘\’ — обратный слеш в начале имени обозначает имя программного модуля, а также разделяет имена каталогов в иерархии размещения программных модулей в файловой системе.
  • ‘:’ — двоеточие в начале термина обозначает имя типа данных или конструктор класса, который всегда является постоянным
  • ‘%’ — префикс знак процента указывается для нативных имён переменных и функций

Разрешение имен (name lookup)

Если имя объекта не содержит квалификатора, оно является простым.

Когда TrustLang встречает простое имя объекта без квалификатора, в дело вступает алгоритм разрешения имён (name lookup), который связывает простое имя, встретившееся в исходном тексте программы, с его декларацией или созданным объектом.

Разрешение простых имен без квалификатора (name lookup, или поиск имени функции/переменной) происходит всегда в строго определённом порядке:

  • в первую очередь происходит поиск имени среди макросов
  • в случае вызова функции выполняется статическое разрешение имен при перегрузке функций
  • далее выполняется поиск имени среди локальных объектов до объектов текущего модуля
  • в последнюю очередь выполняется поиск среди статических объектов с постепенным расширением пространства имен области поиска от текущей до глобальной

Такая последовательность разрешения имён всегда предоставляет возможность переопределить глобальные/локальные объекты или имена аргументов у функций для уже существующего кода без его серьёзных изменений.

Например, для имени name в области имён ns поиск происходит в следующей последовательности: @name → %name → $name → ns::name → ::ns::name → ::name, а для имени аргумента arg проверяется только @arg:

    ns:: {
        name(arg='value');
    };

И в то же время всегда остаётся возможность указать конкретный объект независимо от работы алгоритма разрешения простых имён. Достаточно указать квалификатор в имени объекта в явном виде.

Например, обратиться к глобальному объекту name из пространства имён ns из примера выше нужно по полному имени объекта ::ns::name, а именованный аргумент ’. arg’ не будет заменён макросом @arg, если такой будет определён:

    ::ns::name(.arg='value');

Расширение поиска пространства имён

Для указания нескольких областей имен для расширенного поиска при разрешении простых имён без квалификатора, используется синтаксическая конструкция ... = ns::name, ns::name2; или @using(ns::name, ns::name2); при использовании DSL.

Поиск в перечисленных областях имён производится в порядке их указания до конца текущего блока кода, до следующего оператора расширенного поиска или до оператора ... = _;, который отменяет расширенный поиск в пространствах имен до конца текущего блока кода (до конца модуля).

Предварительное объявление

В тексте программы можно ссылаться только на реально существующие (созданные) объекты. Но для тех случаев, когда требуется сослаться на объект, который создан в другом модуле или будет создан позже, можно сделать предварительное объявление, при котором компилятор регистрирует имя и тип объекта без его реального создания.

За счет предварительного объявления можно ссылаться только на статические объекты (типы данных), или локальные поля класса, о которых компилятор ещё не знает, но которые будут определены в процессе компиляции позже.

Для предварительного объявления используется полное квалифицированное имя, которое должно в точности совпадать с именем объекта при его последующем создании.

Для предварительного объявления используется такой же синтаксис, как и при реальном создании объекта, только справа от оператора создания должно быть указано многоточие.

Область видимости предварительного объявления соответствует области видимости его размещения, а не реальной области видимости объекта, который будет впоследствии создан.


    # Предварительное определение переменной модуля
    # Действует для всего модуля
    var_module:Int32 := ...;

    func() := {
        @return func2(var_module);
    };

    func2(arg:Int32):Int32 := {
        @return $arg*$arg;
    }

    var_module:Int32 := 1;

Имена аргументов, специальные и системные имена

Обозначение имен аргументов у функций очень похоже на обращение к аргументам в bash-скриптах, где “$1” или “$name” — порядковый номер или имя соответствующего аргумента.

Зарезервированное имя “$0” обозначает текущий объект, а именем “$$” обозначается родительский объект.

Все аргументы функции собраны в одном словаре со специальным именем $*

Неизменяемая виртуальная переменная компилятора “$^” содержит результат выполнения последнего оператора или блока кода.

Неизменяемые объекты

TrustLang реализует динамическую иммутабельность. Это свойство лексического объекта, а не свойство типа данных и означает, что объект может стать неизменяемым не только в момент создания, но и в будущем при одной из операций присвоения/изменения значения.

Для придания объекту свойства иммутабельности (невозможности изменять свое значение далее по тексту программы), используются символ ‘^’ карет (крышечка/домик) после имени объекта.

    val := 0; # Create mutable variable
    val = 1; # Set new value 
    val^ = 2; # Set unchangeable value 
    val = 3; # Error  !!!

Свойство иммутабельности у аргументов функций зависит от типа функции. У чистых функций аргументы, передаваемые по ссылке (владеющие переменные), всегда иммутабельные. Свойство мутабельности у остальных аргументов указывается при определении функции на общих основаниях:

    func( arg1^:Int32, arg2:Int32) := {
        arg1 = 1;    # Error (arg1 - immutable)

        arg2 = 1;    # OK
        arg2^ = 2;    # OK - set immutable value
        arg2 = 3;    # Already error
    }

Иммутабельность вызовов и атрибуты

Признак неизменяемости может относиться и к вызовам функций. Чистые функции и принудительное вычисление на этапе компиляции (::-, cube^(...)) в текущей версии не реализованы — см. Функции и Статус. Атрибуты объектов (в т.ч. реальная форма @[имя(...)] перед объявлением) описаны в разделе Макросы и Взаимодействие с C/C++.

1.3 - Макросы и DSL

Макросы в TrustLang являются элементами метапрограммирования.

Макрос — это один или несколько последовательных терминов, которые заменяются на другой термин или на целую синтаксическую конструкцию (последовательность лексем) и выступают в роли специализированных регулярных выражений для поиска и замены последовательностей терминов.

Макросы обрабатываются лексером перед отправкой токенов в парсер для синтаксического анализа, что позволяет изменять даже синтаксис языка, например, превратить синтаксис TrustLang на основе грамматических правил в более привычный синтаксис на основе ключевых слов, так как такой текст легче воспринимается при последующем чтении исходного кода программы.

Определение макросов

Определение макросов аналогично определению других объектов и состоит из трёх частей <имя макроса> <оператор создания/присвоения> <тело макроса> и завершается точкой с запятой “;”, т. е. применяются обычные операторы := или = для создания нового или переопределения уже существующего объекта, а имя макроса указывается между двумя символами "@@" и может содержать одну или несколько лексем (терминов).

Все макросы относятся к глобальному пространству имен, поэтому первый термин в имени макроса должен быть уникальным, иначе он будет перекрывать локальные и глобальные переменные при разрешении имен, если они записаны в тексте программы без квалификаторов (сигилов).

Телом макроса может быть корректное выражение языка, последовательность лексем (которая заключается в двойные собачки "@@", т. е. @@ лексема1 лексема2 @@) или обычная текстовая строка (которую нужно указать между тройными собачками "@@@", т. е. @@@ текстовая строка @@@@).

В имени макроса после первого термина могут присутствовать один или несколько образцов. Образец — это термин, который при сопоставлении последовательности лексем с идентификатором макроса может заменяться любым другим одиночным термином (т. е. фактически это сопоставление по заданному шаблонному образцу).

Для создания термина-образца в начале его идентификатора нужно поставить знак доллара (что соответствует квалификатору локальной переменной), т. е. имя макроса @@ FUNC $name @@ будет соответствовать последовательности лексем как FUNC my_func_name, так и FUNC other_name_func.

Для удаления макроса используется специальный синтаксис: @@ name @@@@; или @@ два термина @@@@;, т. е. имя макроса указывается после открывающего @@, а завершает удаление универсальный терминатор @@@@.

    # Тело макроса из текстовой строки (как в препроцессоре С/С++)
    @@ macro_str @@@ строка - тело макроса @@@@; # Строка для лексера

    # Удаления макроса @macro_str
    @@ macro_str @@@@;

Аргументы макросов и их раскрытие

Макросы можно определять как с аргументами (параметрами в скобках), так и без них. Если макрос был определён с аргументами, то их проверка будет выполняться макропроцессором при определении и раскрытии макроса. Если макрос был определён без аргументов, то их наличие макропроцессором игнорируется.

Первый терм имени макроса является ключом группы макросов: в одной группе может быть много макросов с одинаковым первым именем, но разной арностью (разным числом/составом дополнительных термов), например break, break $label, break $a $b. Такие макросы сосуществуют и не конфликтуют.

При раскрытии из макросов группы выбирается самый длинный (наиболее специфичный) — тот, который потребляет больше всего термов входного буфера. Диагностика «duplication» выдается только при полном совпадении сигнатуры (всех термов), а не при совпадении одного лишь первого имени. Разные арности одной группы дубликатами не являются.

Макросы с аргументами в скобках и без них — тоже разные сигнатуры: форма-вызов и бесскобочная форма с одним первым именем могут сосуществовать (бесскобочная форма сопоставляется и вызову, потребляя только первый терм; форма-вызов — всему вызову целиком).

    @@ macro @@ := term; # Макрос без аргументов
    @@ macro $value @@ := term(@$value); # Макрос с дополнительным термом-шаблоном (другая арность)

    macro;        # ОК -> term;          (форма арности 1)
    macro 42;     # ОК -> term(42);      (форма арности 2, longest-match)

    # Но 
    @@ call() @@ := term(); 

    call(); # ОК -> term();
    call;   # ОК -> term;  (бесскобочная форма `call`, если она определёна)

Если при определении макроса указаны аргументы, то место для их вставки в теле макроса записывается как имя локальной переменной, перед которой добавлен символ "@", т. е. @$arg.

Место для вставки числа реально переданных аргументов отмечается лексемой "@$#". Если требуется вставить переданные аргументы в виде словаря, то место для вставки отмечается лексемой "@$*".

Если макрос принимает произвольное количество аргументов (аргументы макроса завершает многоточие), то место их вставки в тело макроса отмечается лексемой "@$…".

По аналогии с препроцессором C/C++ для соединения двух лексем в одну в теле макроса используется оператор "@##", а для преобразования лексемы в текстовую строку применяются операторы @#, @#" или @#’, например, @@macro($arg)@@ := @@ func_ @## @$arg( @#" arg ) @;, тогда вызов macro(name); будет преобразован в func_name ("name");

Примеры использования макросов:

    # Обычные макросы (тело макроса корректное выражение)
    @@ macro @@        := replace();
    @@ macro2(arg) @@  := { call(@$arg); call()};

    # Тело макросов из последовательности лексем
    @@ if(...) @@    := @@ [ @$... ]--> @@; # Выражение может быть не полным
    @@ elif(...) @@  := @@ ,[ @$... ]--> @@;
    @@ else @@       := @@ ,[...]--> @@;
 
    # Запись условного оператора с использованием 
    # определённых выше макросов
    @if( condition ){
        ...
    } @elif( condition2 ) {
        ...
    } @else {
        ...
    };

Например, одна и та же логика «цикл до 5» — двумя формами:

Макросы DSLБазовый синтаксис
count := 1;
@while( true ) {
    @if( count > 5 ) {
        @return 42;
    };
    count += 1;
};
count := 1;
[ 1 ] <-> {
    [ count > 5 ] --> {
        -- 42 --;
    };
    count += 1;
};

Отладочный вывод компилятора (@__DEBUG__, @__DEBUG_SCOPE__)

Встроенные системные макросы для отладки самого компилятора (работают только в debug-сборке компилятора; в релизной сборке вызов не даёт вывода и сопровождается предупреждением). Оба макроса не генерируют код — анализатор применяет эффект и удаляет маркер.

  • @__DEBUG__(<masks>) — управляет фильтром сообщений, которые создаёт компилятор через TRUST_DEBUG; @__DEBUG__() — выключить. Применение фильтра дублируется в самом выводе эхом (@__DEBUG__: debug messages ENABLED, filter='…' / DISABLED (empty filter)) — видно, что параметры фильтрации применились/изменились/выключены. На дамп состояния эхо и фильтр не влияют.
  • @__DEBUG_SCOPE__([<маски имён>...] [, key=value...]) — печатает текущее состояние анализатора в этой точке (независимо от фильтра @__DEBUG__). Позиционные аргументы — только фильтр имён (маски через запятую); пустой вызов @__DEBUG_SCOPE__() печатает полный дамп. Именованные опции (значения без кавычек): level=current|all, types=on|off, max=<N>, count=only.

Префиксы строк вывода (каждая строка): для сообщений TRUST_DEBUG — .../файл:строка места вызова в компиляторе; для вывода @__DEBUG__/@__DEBUG_SCOPE__ — .../файл:строка самого макроса в .src. Каталоги в пути заменяются многоточием (.../file.src:12: ).

Именованные опции проверяются при разборе макроса: при неизвестном имени/значении выдаётся диагностика с полным списком поддерживаемых опций и допустимых значений.

Фильтрация сообщений обязательна: без заданного @__DEBUG__-фильтра сообщения TRUST_DEBUG не печатаются. Фильтровать можно по ключевому слову, по компоненту, по файлу и по пути компилятора.

@__DEBUG__("scope,resolve");        # включить сообщения TRUST_DEBUG по этим ключевым словам
x := 1;
@__DEBUG_SCOPE__();                                        # полный дамп состояния анализатора
@__DEBUG_SCOPE__("x*", level=all, types=on, max=10);       # с фильтром имён и опциями
@__DEBUG__();                       # выключить сообщения (на дамп не влияет)

Вывод (фрагмент): prog.src:1: @__DEBUG__: debug messages ENABLED, filter='scope,resolve', src/semantic/name_resolution.cpp:129: enter FuncDecl depth=3, prog.src:3: scope: depth=2 names=1, prog.src:3: [1] ModuleDecl \prog.src`: x`.

Keyword syntax (DSL): привычный синтаксис на ключевых словах

Особенности ассоциативной памяти

Синтаксис языка TrustLang основан на строгих правилах без использования ключевых слов, и как бы он ни выглядел логичным, ассоциация по ключевым словам вспоминается гораздо легче, например if, чем комбинация минус минус правая угловая скобка –>. Из-за этого имеет смысл использовать не “чистый” базовый синтаксис, а более привычный диалект с использованием ключевых слов.

TrustLang уже содержит набор макросов, которые расширяют базовый синтаксис TrustLang, основанный на правилах, набором предопределённых ключевых слов как в классических языках программирования, которые можно адаптировать или дополнить под собственную предметную область.

Мнемонические команды (@func)

Чтобы не запоминать правила грамматики и специальные символы, часть DSL-макросов оформлена как мнемонические команды — команды-макросы с удобным именем вместо комбинаций специальных символов.

Команда @func — определение функции без необходимости помнить оператор :=:

@func myfn ( a:Int32 ) { @print('{}', a); };
@func add ( a:Int32, b:Int32 ): Int32 { @return a + b; };
# → void myfn(int32_t a);  int32_t add(int32_t a, int32_t b);
  • @func <имя> ( <аргументы> ) { <тело> } — определение функции (Void). Раскрывается в <имя>( <аргументы> ) := { <тело> }.
  • @func <имя> ( <аргументы> ): <тип> { <тело> } — определение функции с типом возврата. Раскрывается в <имя>( <аргументы> ): <тип> := { <тело> }. <тип> может быть составным (например Tuple(Int32, Int32)).

Внимание: имя func зарезервировано DSL (как main, module, return, if и др.), поэтому не используйте его как имя функции/переменной.

Константы

  • @true — 1:Bool
  • @yes — 1:Bool
  • @false — 0:Bool
  • @no — 0:Bool

Операторы

  • @if(…) — Первый условный оператор

  • @elif(…) — Второй и все последующие условные операторы

  • @else — Оператор иначе

  • @while(…) — Оператор цикла с предусловием

  • @dowhile(…) — Оператор цикла с постусловием

  • @loop — Оператор бесконечного цикла

  • @break [метка] — Выход из ближайшего цикла или из именованного блока метка (один идентификатор, без ::). Без метки: @break;

  • @continue [метка] — Переход на начало ближайшего цикла или именованного блока метка (один идентификатор, без ::). Без метки: @continue;

  • @return [значение] — Выход из текущей функции (аналог break по имени функции @__FUNCTION__). Void-форма: @return;. Со значением: @return <значение>; (один rvalue: имя, литерал, строка, вызов или словарь (a, b,) в скобках)

  • @match( … ) — Оператор оценки выражения

  • @case( … ) — Оператор сравнения с образцом

  • @default — Оператор выбора по умолчанию

Встроенные функции и проверки

  • @assert( cond ) — Вычислить выражение и проверить его на истинность во время выполнения
  • @assert( cond, ‘fmt’, args… ) — Проверка с сообщением: при провале вместо текста условия выводится std::format(fmt, args...) (форматная строка — узкий литерал '...')
  • @verify( cond ) — Вычислить выражение и проверить его на истинность во время выполнения; в отличие от @assert, условие вычисляется даже при отключённых проверках
  • @verify( cond, ‘fmt’, args… ) — То же, но с форматным сообщением при провале

Если запустить компилятор с флагом -Wno-assert, тогда рантайм проверки @assert удаляются из текста программы, а вычисления внутри @verify выполняются, но их результат игнорируется.

Предопределённые макросы

При работе парсера TrustLang автоматически формируются несколько зарезервированных макросов, часть из которых соответствует макросам препроцессора у C/C++. Данные предопределённые макросы можно использовать как обычные константы.

1.4 - Иерархия кода

Области имён, модули и пакеты

Пространства имён

TrustLang поддерживает пространства имён; разделитель, как и в C++, — двойное двоеточие ::. Область имён может быть указана как для отдельного идентификатора, так и для целого блока кода.

В отличие от namespace в C++, области имён в TrustLang служат не только для организации кода логическими группами и избежания конфликтов имён: имя, в котором явно указана область имён, относится к статическим объектам (память под которые выделяется на этапе компиляции).

Глобальное имя не может быть перекрыто макросом или локальной переменной при разрешении имён (name lookup). Чтобы создать глобальную (статическую) переменную, достаточно записать её имя с глобальным квалификатором ::var. Пространство имён для блока кода указывают перед открывающей фигурной скобкой (ns:: { ... };).

::var := 0;    # глобальная переменная (не перекрывается макросом/локальной)

ns:: {          # область имён ns
    a:Int32 := 2;   # ns::a
    sub:: {         # вложенная область имён
        c:Int32 := 3;   # ns::sub::c
    };
};

Модули

TrustLang реализует программные модули и пакеты: идея иерархического расположения файлов в каталогах файловой системы (как в Python), но разделитель имён — не точка, а обратная косая черта \.

Имя модуля может содержать только строчные английские буквы, цифры и символ подчёркивания (кроме первой и последней позиций). Ограничение связано с прямым отображением имён модулей на объекты файловой системы: у разных файловых систем могут различаться кодировки и требования к регистру.

Под модулем понимается файл с исходным кодом (расширение *.src). Модули хранят часто используемые функции, классы, константы и т. п. Их условно делят на модули и программы: программы предназначены для непосредственного запуска, модули — для импорта в другие программы (функционально они не отличаются).

Объекты модуля

Все объекты, определённые внутри одного модуля без указания глобального пространства имён, видны только в рамках текущего файла и в модулях, подключённых после его определения.

Время жизни статических и локальных переменных верхнего уровня модуля одинаково и ограничено временем жизни самого модуля, но для многопоточности они различаются: статическая переменная модуля всегда существует в единственном экземпляре для всех потоков, а локальная переменная модуля — своя для каждого потока (аналог thread_local в C++11).

Импорт модулей

Относительное имя модуля начинается с одного символа \ и указывает на файл относительно текущего модуля. Абсолютное имя начинается с \\ и указывает на файл относительно каталога текущего исполняемого файла (или каталогов поиска модулей, которые можно переопределить, например, аргументами командной строки).

Проще всего импортировать модуль, записав его имя со скобками как вызов функции; в скобках можно передать аргументы инициализации модуля, список импортируемых функций и т. д. Если перед именем модуля стоит символ препроцессора (@\dir\module()), модуль импортирует не только код, но и свои макросы (только при статической загрузке).

Загрузка модулей возможна статически или динамически (по аналогии со статической и динамической линковкой библиотек):

  • \dir\module() — статическая загрузка по относительному пути;
  • @\dir\module() — статическая загрузка с импортом макросов;
  • \\root\dir\module() — статическая загрузка по абсолютному пути;
  • \( "каталог\файл" ) — динамическая загрузка во время выполнения (при динамической линковке макросы импортировать нельзя).

При динамической загрузке компиляция модуля и все проверки выполняются во время выполнения приложения; статическая загрузка позволяет выявить возможные ошибки на этапе компиляции.

Помимо импорта по исходному тексту, TrustLang описывает семантический ABI — способ представления скомпилированного модуля, при котором бинарные символы связаны с типизированным семантическим определением, а сопоставление объектов выполняет компилятор языка. Принцип описан в Семантическом ABI модулей.

Пакеты

Пакет — это каталог, который включает другие каталоги и модули и содержит дополнительный файл __init__.src. Пакеты используются как дополнение к пространствам имён и позволяют работать с модулями через указание уровня вложенности. В отличие от Python и Java, где модули/пакеты заменяют пространства имён, в TrustLang модульная структура и области имён используются одновременно и при указании полного имени объединяются: \root\dir\module::ns::name::var, где root и dir — каталоги относительно текущего модуля, module — имя файла (root/dir/module.src).

Файл __init__.src, в отличие от Python, не может быть пустым — он должен в явном виде загружать входящие в пакет модули:

\simper();
\compper();
\annuity();

Импорт пакетов использует тот же синтаксис, что и импорт модулей. Пример пакета fincalc (__init__.src + модули simper.src, compper.src, annuity.src):

\fincalc();                 # импорт всего пакета
\fincalc\simper();          # импорт одного модуля
sp := \fincalc\simper();    # импорт модуля с псевдонимом
\fincalc\simper(__import__="fv");  # импорт конкретной функции

Пространства имён и классы

В TrustLang не применяется декорирование (манглинг) имён по типам аргументов. Методы классов (когда ООП будет реализовано) получают уникальные идентификаторы по аналогии с Python: глобальная функция с именем класса и метода, объединёнными через :: (для класса :NewClass и метода method — NewClass::method). Это позволяет определять методы класса вне тела класса, указав нужное имя в пространстве имён. Полноценное ООП в текущей версии не реализовано (см. Классы и Статус).

2 - Типы данных

Описание системы типов, принципов автоматического вывода и преобразования между типами

2.1 - Система типов

Принципы

TrustLang имеет закрытую систему типов: любой новый тип данных обязательно наследует (расширяет) один из уже существующих. Это напоминает модель Object в Java, но без физического наследования (без боксинга простых типов в объекты). Этот подход является основой для обобщённого программирования, когда производный тип наследует набор операций «родительского» типа, и продолжает работать со всеми его наследниками.

Язык динамически типизирован: тип переменной можно указать явно или оставить автоматический вывод. Указанный тип используется для проверок совместимости при присваивании, для проверки типа возвращаемого значения функции и для управления размещением в памяти нативных типов. Автоматическое приведение возможно только между совместимыми типами; в остальных случаях требуется явное преобразование типов.

Категории типов

Типы данных разделяются на простые (скалярные, не расширяемые) и составные (контейнерные и определяемые пользователем). Кратко по категориям (подробности — на соответствующих страницах раздела):

Категория Типы Описание на странице
Целые :Int8…:Int64, беззнаковые синонимы (:Byte, :Word, :DWord), :Bool Числа и тензоры
Числа с плавающей точкой :Float16, :Float32, :Float64 Числа и тензоры
Произвольная точность рациональные m\n и :BigInteger (GMP) Числа и тензоры
Строки :StrChar (UTF-8), :StrWide Символьные строки
Диапазоны и массивы :Range, :Array (одномерный, std::vector) Диапазоны, массивы и тензоры
Словари :Dictionary (позиционные и именованные элементы) Словари и наборы
Пользовательские перечисления :Enum, варианты :Variant, кортежи :Tuple, алиасы ::= Словари и наборы
Нативные импорт и предварительное объявление C/C++-типов и шаблонов Нативные типы

Переменные могут хранить значение напрямую либо быть ссылочными (сильные/слабые ссылки, shared/weak) — см. Управление памятью.

Имена типов и конструкторы

Каждый тип имеет краткое имя, начинающееся с двоеточия (например, :Int32), и одноимённую функцию-конструктор без двоеточия. Новый экземпляр создаётся вызовом конструктора: x := Int32(5);. Типы могут быть синонимами — два типа с одинаковым кратким именем в разных пространствах имён; в этом случае требуется явная квалификация имени при вызове конструктора (см. Именование объектов).

Статус реализации

Из «объектно-ориентированных» возможностей реализованы базовые :Struct/:Class (поля, методы, наследование), типы Enum/Variant/Tuple и предварительное объявление нативных классов (см. Классы). Комплексные числа (:Complex16/32/64), многомерные тензоры (полноценные :Tensor), виртуальные методы/@[override] (полноценное ООП), корутины и чистые функции не реализованы — подробнее в Статусе реализации и ограничения.

Преобразование типов

Несмотря на динамическую типизацию, если тип переменной указан явно, автоматическое приведение типов не выполняется — для присваивания значения несовместимого типа требуется его явное преобразование.

Явное приведение вызовом типа

Явное преобразование выполняется вызовом функции с именем целевого типа (кратким именем без двоеточия): :Int32(x) читается как Int32(x) — это вызов конструктора/приведения типа.

n := Int32(3.14);      # число с плавающей точкой → целое
b := Bool(5);          # число → логическое (0/1)
f := Float64(n);       # целое → число с плавающей точкой

Приведение выполняется с контролем диапазона: если значение не помещается в целевой тип (сужение), возникает ошибка — как на этапе компиляции для известных значений, так и в рантайме для переменных. Молчаливого «обрезка»/переполнения нет.

Словарь как универсальный тип

Словарь — единственный тип, который может быть приведён к любому другому: для создания значения конкретного типа достаточно передать словарь аргументом в приведение/конструктор типа. Подробнее — в Словарях и наборах.

Преобразования между категориями

Правила и примеры преобразований для конкретных категорий описаны вместе с самими типами:

  • числа и рациональные значения — Числа и тензоры;
  • строки и их форматирование — Символьные строки;
  • диапазоны/массивы и изменение размерности — Диапазоны, массивы и тензоры;
  • нативные C/C++-типы — Нативные типы.

2.2 - Числа и тензоры

Числовые типы — простые (скалярные) типы данных TrustLang. Основы типизации описаны на странице Система типов, а массивы, диапазоны и (в перспективе) тензоры — в разделе Диапазоны, массивы и тензоры.

Целые числа

Имена целых типов соответствуют их разрядности: :Int8, :Int16, :Int32, :Int64. Целочисленный литерал получает минимальный знаковый тип, в который влезает его значение (например, 5 → :Int8), а значение, не помещающееся в :Int64, становится :BigInteger. Тип литерала можно задать явной аннотацией литерал :Type (например, 1 :Bool, 255 :Int16) — при выходе за диапазон типа возникает ошибка компиляции, а не молчаливое переполнение.

Для взаимодействия с нативным C++-кодом у целых есть беззнаковые синонимы (:Byte, :Word, :DWord, :UInt16/:UInt32/:UInt64, …), которые применяются при вызове нативных функций. В арифметике предпочтительны знаковые типы — так удаётся избежать классических проблем беззнаковой арифметики (например, вычитания, дающего огромное «отрицательное» значение).

Контроль целочисленного переполнения

Арифметика знаковых машинных целых (+, -, * и составные +=, -=, *=) контролируется на переполнение: результат операции проверяется встроенной функцией __builtin_*_overflow, и при переполнении выбрасывается программное исключение trust::IntMinus (ловится trust-блоком {- ... -} и конструкцией try), а не возникает неопределённое поведение (UB), как в C++. Сообщение исключения содержит локацию исходного кода в формате файл:строка: (как у @assert), например rational.src:8: integer overflow in '*='.

Опция -foverflow-check / -fno-overflow-check (по умолчанию включена) управляет контролем. Проверяются только знаковые машинные целые (:Int8…:Int64); беззнаковые типы по определению заворачиваются (wrap), :BigInteger/:Rational имеют произвольную точность, а /, //, % и битовые операции не переполняются и не проверяются.

Дополнительно контролируется унарный минус (-x: переполнение при -INT_MIN) и целочисленное деление /////= — предохранители от деления на ноль и от INT64_MIN / -1 (undefined behavior в C++). Все нарушения также приводят к перехватываемому trust::IntMinus.

Логический тип

Логический тип :Bool принимает только значения 0 или 1 (false/true). Он выделен в отдельную категорию (значения @true/@false в DSL — это 1 :Bool/0 :Bool) и в зависимости от операции может вести себя как целочисленный. Явная 0 :Bool/1 :Bool-аннотация создаёт именно логическое значение.

Числа с плавающей точкой

Типы с плавающей точкой соответствуют разрядности: :Float16, :Float32, :Float64 (синонимы :Single, :Double). Разряды числа можно разделять знаком подчёркивания для читаемости: 10_000.

Рациональные числа и произвольная точность

Для вычислений с неограниченной точностью используются рациональные числа: это дробь \( \frac{m}{n} \), где числитель m — целое, а знаменатель n — натуральное (больше нуля). В качестве разделителя дроби используется обратная косая черта: 1\1 — единица, -55\3 — дробь \( \frac{-55}{3} \). Арифметика рациональных чисел строится на :BigInteger (GMP) и не теряет точность; смешивание с числами с плавающей точкой требует явного преобразования.

Показ длинных чисел

Полное значение числа произвольной точности может быть очень длинным. Для показа (в логах, отчётах, диагностике) у :BigInteger есть метод display(L), возвращающий строку вида голова...хвост (N), где L — число цифр в начале и конце, а N — общее число десятичных цифр:

x :BigInteger := 123456789012345678901234567890;
@print('{}', x.display(3));   # 123...890 (30)

Если цифр немного (N <= 2L + 1), возвращается полное число. Знак выводится впереди, а N считает цифры без учёта знака.

Метод display(L) предназначен только для показа: его результат — строка, из которой нельзя восстановить точное значение числа (это не round-trip представление). Точное десятичное представление даёт обычный вывод значения ({} в форматной строке).

Аналогичный метод есть и у рациональных чисел :Rational: display(L) сокращает каждый компонент дроби независимо (числитель и знаменатель — :BigInteger), например 123...890 (30)\45...678 (5).

2.3 - Символьные строки

TrustLang поддерживает два типа строк:

  • :StrChar — универсальные байтовые UTF-8 строки;
  • :StrWide — системные (широкосимвольные) строки.

Байтовые строки :StrChar

Единичный элемент байтовой строки — один байт (точнее :Int8, восьмибитное целое со знаком). Размер строки возвращается в байтах, а доступ по индексу обращается к байту последовательности. Так как данные интерпретируются как последовательность UTF-8 символов, при изменении отдельных байт нужно соблюдать осторожность.

Системные строки :StrWide

Единичный элемент системной строки — широкий символ wchar_t, а размер возвращается в широких символах. Размер wchar_t зависит от операционной системы: в Windows один символ :StrWide занимает 2 байта, в Linux — 4. Основное назначение системных строк — упрощение работы в текстовом терминале: один символ всегда соответствует одному знакоместу без конвертации кодовых точек UTF-8.

Несмотря на разный единичный элемент, внутреннее представление у обоих типов одинаковое: данные строк хранятся в виде байтовой UTF-8 последовательности.

Форматирование строк

К любой переменной можно обратиться как к функции (указав после имени круглые скобки), создав тем самым копию/клон объекта; для строк такой вызов используется как шаблон форматирования данных.

Форматирование возможно двумя способами:

  • Строка формата в стиле printf (тип :FmtChar/:FmtWide) в текущей версии не реализована — типа :FmtChar/:FmtWide нет (см. Статус). Для нативных функций с printf-строкой используется атрибут @[format("printf", pos, ...)] (проверка параметров на этапе компиляции, пример — hello).
  • Во всех остальных случаях (любая строка по умолчанию) формат соответствует библиотеке {fmt}/std::format: порядковый номер аргумента ({0}, {1}) или пустые {}. Проверка аргументов выполняется при клонировании строки (во время компиляции и выполнения). Именованные аргументы (name = …) не реализованы.
$template := "{0}: {1}";    # формат как в {fmt}
$result := $template('value', 123);

2.4 - Словари и наборы (перечисления)

Действующие примеры с фактическим поведением текущей версии можно запустить в песочнице: словарь, словарь со смешанными типами, перечисление и вариант.

Словарь (:Dictionary)

Словарь — набор данных произвольного типа с доступом к элементам по целочисленному индексу или по имени элемента при его наличии (это похоже одновременно и на кортеж, и на структуру). Словарь всегда одномерный, но каждый элемент может содержать произвольное количество элементов любого типа, в том числе другие словари.

Литерал словаря записывается в круглых скобках с обязательной завершающей запятой: (,) — пустой словарь, (1, two='2', name=3,). Доступ к элементу — по имени через точку от имени переменной (d.name) либо по целочисленному индексу (d[0]), который начинается с 0 и может быть отрицательным (отсчёт от конца). Изменение — оператором []=; количество элементов — методом size().

Позиционный литерал без указания типа ((1, 2, 3,)) всегда создаёт словарь (:Dictionary). Словарь — единственный универсальный тип: он может быть приведён к любому другому типу, для чего достаточно передать его аргументом в приведение/конструктор целевого типа (см. Преобразование типов).

Перечисление (:Enum)

Enum — тип с ограниченным списком членов, у каждого из которых есть имя и значение. Все члены имеют единый тип значений, который выводится по общим правилам — из явных значений членов либо из явной аннотации типа. Литерал-объявление записывается в постфиксной форме (члены,):Enum или префиксной :Enum(члены) (как у типизированного кортежа); завершающая запятая обязательна.

Status ::= (OK=0, ERROR=1, BUSY=2,):Enum;   # члены с явными значениями; тип значений Int64
Color ::= (RED, GREEN, BLUE,):Enum;          # безнарные члены — автоинкремент от 0
Flag  ::= (LOW:Int8, HIGH,):Enum;            # явный тип члена задаёт тип значений Int8

Если явных значений нет, тип значений — минимальный знаковый целый по числу членов; явная аннотация name:Type задаёт тип значений принудительно (у всех членов он должен быть одинаковым). Сравнение членов выполняется по значению, а не по позиции.

Обращение к члену — через имя типа: Status.OK. Классические методы (через имя типа): count() (число членов), fromName(name) (член по имени), fromValue(value) (член по значению).

Доступ к члену (Status.OK, Data.i) и методы count()/fromName()/fromValue() реализованы (пример — перечисление и вариант).

Вариант (:Variant)

Variant — гетерогенный тип: каждый член имеет свой тип данных (аналог std::variant). Тип члена задаётся явной аннотацией (name:Type) либо выводится из его значения; для безнарного члена без типа берётся минимальный знаковый целый по позиции.

Data ::= (i=42, s='text', r=1\2,):Variant;  # типы членов: Int8, StrChar, Rational
V    ::= (X:Int64=7, Y:Rational,):Variant;  # явные типы членов

Обращение к члену — через имя типа: Data.i (тип — тип конкретного члена). Классический метод: count() (число членов).

2.5 - Классы

Тип данных :Class аналогичен словарю, но все его поля обязаны иметь имена (доступ к свойствам по индексу также возможен). При создании экземпляра класса создаётся новый тип, копирующий свойства и методы всех родителей. В отличие от словаря, состав полей класса определяется на этапе компиляции и может только расширяться относительно родительских типов.

Статус: реализованы базовые :Struct (строго POD) и :Class (наследование), генерируемые в C++ struct; полноценное ООП (виртуальные методы/override, конструкторы/деструкторы, статические члены) в текущей версии не реализовано. Из «объектно-ориентированных» типов также реализованы перечисления :Enum, варианты :Variant и кортежи :Tuple (см. Словари и наборы), а также предварительное объявление нативных C++-классов (String ::= %std::string { ... }; — см. Нативные типы) и пользовательские шаблон-классы (<T> :Box ::= :Class{...} — см. Обобщённое программирование). Актуальные границы реализации — в Статусе реализации.

Объявление :Struct/:Class — через ::= с телом, члены которого задаются оператором := (Name ::= :Base{ ... };):

Point ::= :Struct{ x:Int32 := _; y:Int32 := _; };      # строго POD; поля БЕЗ значения (`:= _`)
Animal ::= :Class{ name:Int32 := 0; speak():Int32 := { ... }; };  # Class: default допустим
Dog ::= :Animal{ age:Int32 := _; };                    # наследование (Class)
Iface ::= :Class ...;                                  # предварительное объявление (форма без тела)

Оба типа генерируются как C++ struct (все члены публичные); :Struct дополнительно получает static_assert на POD (std::is_trivial_v && std::is_standard_layout_v). Поля/методы с ведущим _ (защищённые) и __ (приватные) поддерживаются на уровне соглашения об именовании — влияют только на автодополнение, в C++ генерируются без изменения доступа. Голое имя члена (obj.field, obj.method()) транслируется в прямое обращение к члену struct.

Правила значений и объявлений:

  • member := ... — прототип метода (объявление без тела) внутри определения класса. Класс с телом (даже если все методы — прототипы) является полным определением (struct c_Name { ... };) — в C++ прототипы существуют только внутри определения, а не в forward-объявлении.
  • member := _ — отсутствие значения (поле без значения по умолчанию).
  • field:Type := <value> — поле со значением по умолчанию.
  • :Name ::= :Base ...; (форма без тела) — предварительное объявление → C++ incomplete type struct c_Name;. Имя типа при этом уже зарегистрировано и видно, поэтому позднее то же имя можно доопределить (:Name ::= :Base { ... };); повторное определение — ошибка. В C++ forward-объявление не содержит членов (ни полей, ни методов); тип неполный.
  • Self-ссылки разрешены: имя record-типа видно внутри его собственного тела (аналог C++ injected-class-name), поэтому :Node ::= :Class{ next : @[reftype("shared")@] Node := _; } корректно. Ссылки (shared/weak/unique-указатель) на неполный тип допустимы; value-поле самого себя — ошибка бесконечного размера (см. ниже).
  • field := ... недопустимо: в C++ член-данное нельзя предобъявить (оно существует только в определении).

Рекурсивные/циклические ссылки в полях запрещены статически (анализатор RefCycleHook), чтобы не допускать утечек и невыразимых типов: -Wrecursive-shared — цикл с shared-ребром (утечка refcount; разрывается weak-обратной ссылкой), -Wrecursive-unique — взаимное unique-владение двух типов, -Wrecursive-value — рекурсия по значению (value/default unique = inline, бесконечный размер). Все — default error, переключаются -Wrecursive-*=ignore|warning|error. Самоссылка unique-указателем — легальный owned-список и не диагностируется.

Для :Struct (строго POD) значение по умолчанию поля запрещено анализатором (NSDMI нарушает тривиальность): поле объявляется как field:Type := _;. Для :Class значение поля не проверяется — допустимы и := <value> (эмитится как C++ default member initializer), и := _ (без инициализатора).

Виртуальные методы (@[virtual]) и переопределение (@[override]) в текущей версии не реализованы — их использование приводит к явной ошибке компиляции (а не к молчаливому игнорированию).

Перегрузка операторов

Оператор объявляется именем-символом в обратных кавычках (лексема REFLECTION): в теле класса — как метод, на верхнем уровне модуля — как свободная функция. Тело и сигнатура — как у обычного метода.

Point ::= :Class{
    x: Int32 := _;
    `==`(o: Point): Bool := { ... };      # member → C++ operator==
    `()`(i: Int32): Int32 := { ... };     # operator()  (только member)
    `[]`(i: Int32): Int32 := { ... };     # operator[]  (только member)
};

`!=`(a: Point, b: Point): Bool := { ... };   # свободный оператор (все операнды — параметры)

Символ транслируется в C++ operator<sym> (`==` → operator==, `()` → operator()); выражения a == b / a != b для пользовательских типов разрешаются C++-перегрузкой, поэтому оператором можно пользоваться в обычных выражениях.

Использование в TrustLang-коде: a == b (сравнения), a(5) (вызов значения — оператор ()), a[i] (индексация — оператор []). Каждая форма транслируется в соответствующую C++-операцию (a(5) → a(5), a[i] → (a)[i]) и разрешается C++-перегрузкой.

Реализованы: сравнения == != < > <= >= (как member, так и свободные) и вызов/индекс () / [] (только member — требование C++; [] принимает ровно один параметр). Арность проверяется (сравнение — один параметр у member и два у свободного), повторный символ в типе запрещён.

Использование проверяется на этапе анализа: сравнение/вызов/индексация требуют объявленного оператора у типа (иначе — ошибка компиляции, а не ошибка C++), арность вызова проверяется по объявлению; конфликт «member + свободная функция» одного символа диагностируется как неоднозначность. Операторы поддерживают контракты (trust_pre/trust_post, как функции и методы). Шаблонные операторы (<T> \==`(…)`) не реализованы — явная ошибка.

2.6 - Функции

Функция определяется операторами создания объектов, имя функции должно соответствовать правилам именования и завершаться круглыми скобками. Телом обычной функции служит блок кода, находящийся в пространстве имён её определения.

У аргументов и у типа возвращаемого значения указывается тип (arg:Type).

Наборы допустимых типов

Несколько допустимых типов задаются набором типов — математическими операторами + (объединение) и - (исключение). Набор определяется один раз как именованный тип:

combi ::= :Int8 + :Int16 + :Int32;   # именованный набор

Функция, у которой параметр имеет тип-набор, разворачивается в N определений (по одному на член набора) с общим телом; вызов разрешается по типу аргумента, как при явной перегрузке:

sq(x:combi):Int64 := { @return :Int64(x) * :Int64(x); };
# эквивалентно трём определениям: sq(:Int8), sq(:Int16), sq(:Int32)

sq(:Int16(3));    # выберет определение с параметром :Int16

Набор можно указать и inline — непосредственно в позиции типа (сигл : идёт сразу перед ():

sq2(x:(:Int8 + :Int16)):Int64 := { @return :Int64(x) * :Int64(x); };

Один и тот же именованный набор может стоять и в параметре, и в возврате — тогда определения сопоставляются позиционно (i-й член набора — и для параметра, и для возврата):

combi ::= :Int8 + :Int16;
idk(x:combi):combi := { @return x; };   # 2 определения: (:Int8)->:Int8, (:Int16)->:Int16

Правила и ограничения:

  • В прототипе допустим не более одного различного набора (иначе — ошибка о комбинаторной сложности); один и тот же набор может использоваться в нескольких позициях.
  • Набор только в возврате недопустим: перегрузки различались бы лишь типом возврата (в C++ перегрузки по возврату нет). Используйте тот же набор и в параметре.
  • Inline-набор — только тип, не выражение (нельзя присвоить/передать как значение).
  • Исключение - пока не реализовано (явная ошибка).
  • Членами набора могут быть простые типы (шаблонные типы в наборе пока не поддерживаются).

TrustLang на уровне синтаксиса поддерживает несколько видов функций.

Обычные функции

Обычная функция ничем не ограничена в смысле C/C++: может содержать условия, циклы, вызовы других функций и т. д. Создаётся оператором :=:

hello(str:StrChar) := {
    @print('call: {}\n', str);
};

@main() := {
    hello('Привет, мир!');
};

Именованные и опциональные параметры

Именованные параметры позволяют передавать аргументы по имени (с префиксом «.»), а не по позиции:

func(width:Int32, height:Int32) := { ... };

func(.width=640, .height=480);
func(.height=480, .width=640);  # порядок не важен

Имя именованного аргумента не перекрывается макросом препроцессора (см. Именование объектов).

Опциональные параметры имеют значение по умолчанию и могут быть опущены при вызове: имя аргумента отделяется от значения знаком =. Сначала перечисляются обязательные параметры, затем — со значениями по умолчанию. Функция, допускающая произвольное число аргументов, заканчивает список параметров многоточием ....

Чистые функции

Чистая функция не имеет побочных эффектов: возвращает результат только по своим аргументам и не изменяет состояние программы. Синтаксис декларации ::- не реализован (см. Статус); к понятию чистоты относится и требование иммутабельности аргументов по ссылке (см. Именование объектов).

Сопрограммы (coroutines)

Сопрограмма — функция-замыкание, способная приостанавливать и возобновлять выполнение (кооперативная многозадачность). В текущей версии не реализовано — см. Статус и раздел Многопоточность и асинхронность.

Анонимные функции

Анонимная функция объявляется в месте использования и не получает собственного имени (уникального идентификатора). В TrustLang анонимная функция задаётся лямбда-выражением и представляет собой значение функционального типа std::function<...>: его можно сохранить в переменной, передать аргументом (функция обратного вызова, предикат) или вызвать на месте.

Лямбда-выражения (замыкания)

Лямбда-выражение объявляет анонимную функцию по месту применения:

[ captures ] (params) : Ret { body }
  • captures — список захватов: только имена ранее объявленных переменных, по значению (копия). Пустые скобки [] — без захвата. Ссылочный захват [&x] в текущей версии не поддерживается (диагностика об ошибке).
  • params — параметры как у обычной функции (x:Type, тип опционален).
  • : Ret — тип возврата; при отсутствии выводится из тела.
  • body — блок кода { ... }; значение блока — результат лямбды.

Лямбда-значение типизируется функциональным типом и может храниться/передаваться. Возврат значения — как у обычной функции (@return / именованная форма), лямбда внутренне имеет собственную метку возврата:

f := [](x:Int32):Int32 { @return x * x; };
y := f(5);

Немедленный вызов

Лямбду можно вызвать сразу после определения. Каноническая форма — обёрнутая:

y := ( [](x:Int32):Int32 { @return x * x; } )(5);

Прямая форма [](x){... }(5) (без обёртки) не поддерживается и выдаёт ошибку с подсказкой использовать ( lambda )(args).

Не поддерживается (первая итерация)

Ссылочный захват [&x], неявный захват [=]/[&], захват со значением/типом ([x = expr], [x:Type]) и захват некопируемых значений (эксклюзивное владение unique) — не поддерживаются и дают явную диагностику. «Замыкание по определению не может быть чистой функцией» — чистая функция (::-) в языке пока не реализована.

Переопределение и перегрузка функций

Поскольку TrustLang позволяет вызывать нативные C/C++-функции напрямую и делать вставки C++-кода, переопределение и перегрузка функций имеют свои особенности.

  • Переопределение (overriding) — реализация методом подкласса метода, объявленного в суперклассе (фундаментальный принцип ООП).
  • Перегрузка (overloading) — создание нескольких функций с одним именем, но разным набором параметров; нужный вариант выбирается на этапе компиляции по параметрам.

Переопределение (overriding)

Переопределение допускается не только для методов класса, но и для обычных функций (механизм, похожий на LD_PRELOAD, реализованный средствами самого языка). Чтобы функцию можно было переопределить, при её создании не должен быть указан признак иммутабельности. Если суперкласс объявил метод мутабельным (виртуальным), а подкласс реализует его с признаком иммутабельности, это равносильно override final (без дальнейшего переопределения):

base::func() := { ... };   # virtual
class1::func() = { ... };  # override
class2::func^() = { ... }; # override final

Переопределение идёт по имени функции без учёта аргументов, однако новая функция должна иметь аргументы, совместимые с типом аргументов исходной функции.

Перегрузка (overloading)

Перегрузка — несколько функций с одним именем и разными сигнатурами (набором типов параметров); нужный вариант выбирается статически на этапе компиляции по типам аргументов. Точный дубль сигнатуры — ошибка; если подходящего варианта нет — ошибка no matching overload, если несколько вариантов несравнимы — ambiguous.

Перегрузка свободных функций и методов пользовательских классов/Struct поддержана:

f(a:Int32):Int32 := { @return a + 1; };
f(a:Int64):Int32 := { @return 100; };

@main() := {
    x : Int32 := 5;
    @print('{}\n', f(x));        # выбран f(a:Int32)
    @print('{}\n', f(7:Int64));  # выбран f(a:Int64)
};

:C ::= :Class{
    base:Int32 := 10;
    f(a:Int32):Int32 := { @return a + 1; };   # перегрузка МЕТОДА
    f(a:Int64):Int32 := { @return base + 90; };
};

Выбор варианта — по типам аргументов: точное совпадение предпочтительнее числового расширения (промоция/конверсия), параметр :Any принимает любой тип (низший приоритет); при нескольких несравнимых лучших — ambiguous.

Перегрузку (выбор сигнатуры и допустимость/приведение аргументов) для функций и методов TrustLang всегда выполняет компилятор — и при единственной сигнатуре тоже. Делегирование C++-слою применяется только к нативным функциям/методам (их типы заданы явно нативными, а имя символа фиксировано внешней библиотекой).

Перегрузка по-прежнему возможна и для нативных функций (все типы аргументов указываются явно и являются нативными типами); нативные функции также доступны для прямого вызова из языков C/C++:

%func(arg:Int8):None := {};   # void func(int8_t)
%func(arg:Byte):None := {};   # void func(uint8_t)
%func(arg:Int64):None := {};  # void func(int64_t)

2.7 - Нативные типы

Нативные типы данных

Нативными (машинными) данными могут быть как переменные, так и функции, а имя нативных объектов начинается на символ процента “%”.

В случае переменных, это двоичные данные, которые располагаются в одной неразрывной области машинной памяти по определённому адресу и имеют строго определённый формат.

Чтобы использовать уже существующие библиотеки, нужно либо импортировать нативный объект, тем самым создав объект TrustLang, но с реализацией на другом языке, например на C/C++, либо сделать предварительное определение (декларацию) нативного объекта.

Импорт нативных объектов

Импорт — связывание trust-имени функции/переменной с именем существующей нативной функции/переменной. В отличие от предварительного объявления, импортируемая функция регистрируется под своим trust-именем, а её имя и аргументы могут отличаться от имени и аргументов импортируемой нативной функции.

Синтаксис такой же, как у создания обычных объектов, только правым операндом указывается имя нативного объекта. Типы аргументов и возвращаемого значения всегда указываются явно.

  • Если типы регистрируемой и нативной функции совпадают (преобразование не требуется), нативное имя можно указать с многоточием — оно означает, что аргументы вызова повторяют аргументы левой сигнатуры (дублировать их не нужно):

    sqr(x:Float64):Float64 := %std::sqrt...;   # аргументы как у sqr

  • В общем случае аргументы и тип импортируемой функции задаются явно; при генерации вставляется вызов правой функции, а при необходимости аргументы приводятся через static_cast:

    sqr(x:Float64):Float64 := %std::sqrt(x:Float128, true):Float128;

При импорте аргументы автоматически преобразуются к нативным типам импортируемой функции. Импорт может выполняться во время компиляции программы или во время выполнения (динамическая загрузка библиотеки).

fopen(filename:StrChar, modes:StrChar):Int64 := %fopen...;
fclose(f:Int64):Int32 := %fclose...;
fflush(f:Int64):Int32 := %fflush...;
fprintf(f:Int64, format:StrChar, ...):Int32 := %fprintf...;

Если нативная функция/переменная требует линковки внешней библиотеки, имя библиотеки указывается атрибутом @[link("имя")@] перед декларацией. Атрибут добавляет флаг -l<имя> к шагу линковки (build.conf LIBS). Существование символа/библиотеки не проверяется — ответственность линковщика. Поддерживается только статическая линковка.

@[link("m")@]
fsqrt(x:Float64):Float64 := %sqrt...;

@[link("z")@]
fcrc(crc:UInt32):UInt32 := %crc32...;

Если нативная декларация/тип требует подключения C++-заголовка, укажите его атрибутом @[include("имя")@] перед объявлением (или мнемоникой @include("имя") без ;). Голое имя → угловой инклуд #include <имя>; аргумент с ведущим "/< — директива как есть. Заголовок эмитится в сгенерированный C++ только вместе с этим объявлением:

@include("cstdlib")
%abort(x:Int32):Void := ...;   # → #include <cstdlib>

Предварительное объявление нативных объектов

Предварительное объявление (forward-declaration) — регистрация нативной функции/переменной, имя которой и есть нативный C-style идентификатор (напр. %sqrt — функция sqrt). Имя и аргументы объявляемой функции совпадают с нативной сигнатурой — никакой адаптации не выполняется. Реализация может быть расположена ниже в текущем файле или во внешней библиотеке — линковщик найдёт символ по имени на этапе сборки.

Правило линковки нативного имени: если оно без :: (напр. %sqrt, %open, %abs) — декларация линкуется как C-символ (extern "C"), что позволяет корректно вызывать функции libc/libm; если имя содержит :: (напр. %std::sqrt) — как C++-символ (extern "C" не добавляется).

Синтаксис такой же, как у создания, но нативное имя стоит слева, а справа — символ многоточия (тела нет). Типы аргументов и возвращаемого значения указываются явно.

    %open(path:StrChar, flags:Int32):Int32 := ...;
    %close(fd:Int32):Int32 := ...;
    %read(fd:Int32, buf:StrChar, cnt:SizeT):SizeT := ...;

    %fd^:Int32 := 0;
    fd = %open('foo.txt', 0);   # вызов нативной функции по имени

Другие нативные типы (статус)

Пользовательские типы Enum/Variant/Tuple описаны в Словарях и наборах.

Нативные шаблоны-типы

Любой нативный C++-шаблон-тип можно объявить в коде TrustLang (регистрация при анализе AST); заголовок C++ подключается on-use при использовании типа. Объявление — префикс типовых параметров

  • нативное C++-имя:
@include("vector")
<T> %std::vector() := ...;    # тип vector<T>, C++-имя std::vector

v: vector<Int32> := [1, 2, 3,];
# → #include <vector>  +  std::vector<int32_t> c_v = std::vector<int32_t>{1, 2, 3};

Типовой аргумент — голое имя Int32 (мягкое предупреждение о сигиле :) или явный тип :Int32/:MyClass/:MyClass<:Int8>. Если C++-имя совпадает со встроенным контейнером (std::vector/std::array от :Array), выдаётся мягкая диагностика, а инстанциация резолвится через встроенный тип. Подробнее — Generics.

Предварительное объявление нативных классов

Нативный C++-класс (не шаблон) можно использовать в коде TrustLang через предварительное объявление по аналогии с forward-объявлением функций: trust-имя класса связывается с нативным C++-именем, а члены-интерфейс (методы, поля, конструкторы, статические члены) описываются в теле { ... }. Тело класса не содержит реализации — каждый член — это forward-объявление (:= ...): класс определён в C++-заголовке, который подключается on-use через атрибут @[include].

@include("string")
String ::= %std::string {          # trust-класс String ↔ C++ std::string
    %size(): UInt64 := ...;        # метод объекта → s.size()
    %empty(): Bool := ...;         # метод объекта → s.empty()
    %c_str(): CString := ...;      # метод объекта → s.c_str()
    %data: CString := ...;         # поле объекта → s.data
};

Синтаксис:

  • String ::= %std::string { ... }; — RHS — ЛЮБОЕ имя; нативное — с ведущим % (C++-имя без %). Доверенное имя класса — слева от ::=.
  • Члены (все — forward, := ...):
    • %Name(...):Ret := ...; — метод объекта → obj.name(...);
    • @::st(...):Ret := ...; — статический метод класса (имя с ::; @:: → ns::Class::) → Cls::st(...);
    • %field:Type := ...; — поле объекта → obj.field;
    • @::static_field:Type := ...; — статическое поле → Cls::static_field;
    • %String(...):String := ...; — конструктор (имя совпадает с классом) → std::string(...).
  • Классификация: статический член — имя содержит :: (задаётся @::name); экземплярный — без ::. Правильная регистрация экземплярного члена — ведущая точка (.name); без неё — диагностика -Wclass-member-dot (по умолчанию ignore; -Wclass-member-dot=warning|error).
  • Доступ к статическому члену: Cls::name (namespace-стиль, без предупреждения) или Cls.name (как к полю) → cppName::name; доступ Cls.name выдаёт -Wstatic-member-as-field (по умолчанию warning; -Wstatic-member-as-field=ignore|error).
  • Атрибут @[include("заголовок")@] (или мнемоника @include("заголовок")) перед объявлением подключает C++-заголовок только при использовании данного типа (on-use).

C++-struct для нативного класса не генерируется — используется существующее C++-имя.

@include("string")
MyStr ::= %std::string {
    %size(): UInt64 := ...;
    %data: CString := ...;   # поле объекта → s.data
};

s: MyStr := MyStr('hello');              # конструктор → std::string("hello")
n: UInt64 := s.%size();                  # метод → (c_s).size()
d: CString := s.%data;                   # поле → (c_s).data
# → #include <string>

Предварительное объявление нативных шаблон-классов

Нативный C++-шаблон-класс объявляется так же, но с типовыми параметрами слева и явной реализацией через инстанциацию %std::pair<T1,T2> справа (основная форма):

@include("utility")
<T1,T2> Pair ::= %std::pair<T1,T2> {    # trust-шаблон Pair ↔ std::pair
    %first(): T1 := ...;                # Pair<A,B>.first
    %second(): T2 := ...;               # Pair<A,B>.second
};

p: Pair<Int32, StrChar> := ...;
# → std::pair<int32_t, std::string> + #include <utility>

Обобщённая форма <T1,T2> Pair ::= <T1,T2> %std::pair { ... } (шаблон привязывается обобщённо, без явного списка аргументов в RHS) — сахар, реализация отложена: при разборе выдаётся диагностика «not implemented»; используйте явную форму %std::pair<T1,T2>. Формат записи одинаков для нативного и не-нативного имени и отличается только наличием/отсутствием %.

Интеграция с C/C++: embed-вставки и обзор (взаимодействие)

TrustLang глубоко интегрирован с экосистемой C/C++: прямые вызовы функций, встраивание C++-кода, использование стандартной библиотеки и вызовы функций TrustLang из C++.

Готовые, запускаемые примеры — в песочнице: нативные функции, нативная линковка.

Импорт нативных функций: @extern / @forward

Мнемонические команды связывают trust-имя с нативным C/C++-символом:

@extern abs(x:Int32):Int32   # abs(x:Int32):Int32 := %abs ...
@forward open(path:StrChar, flags:Int32):Int32
  • @extern — импорт по нативному имени (trust-имя = нативное имя без префикса %).
  • @forward — предварительное объявление (имя указывается первым, тело — многоточие).

Сырая запись: %name(...):T := ...; (forward-декларация) и name(...):T := %native...; (импорт-алиас).

Встраивание C++ кода: блоки {% ... %}

{% for (int i = 0; i < 10; ++i) { printf("%d\n", i); } %}

Нативный синтаксис вставляется в выходной C++ код напрямую.

Атрибуты нативных деклараций

  • @[link("имя")] — добавить -l<имя> к линковке.
  • @[include("header")] — подключить заголовок C++ для нативной декларации/типа. Голое имя (@[include("vector")@]) → угловой инклуд #include <vector>; аргумент с ведущим "/< → директива как есть (#include "my/header.h" / #include <cstdlib>). Заголовок эмитится в сгенерированный C++ только вместе с объявлением (не глобально). Мнемоника @include("name") (без ;, перед объявлением) раскрывается в этот атрибут.
  • @[libstd] — линковать со стандартной библиотекой.
  • @[format("printf", ...)] — проверка аргументов против printf-строки формата.

Пример подключения заголовка нативной функции:

@include("cstdlib")
%abort(x:Int32):Void := ...;   # → #include <cstdlib> + extern "C" void abort(int32_t);

Линковка

Линковка нативной декларации зависит от наличия :: в нативном имени: без :: (%sqrt) — extern "C" (C-символ libc/libm); с :: (%std::sqrt) — C++-линковка без extern "C". Подробнее о генерации C++ — в Архитектуре.

Для модулей на самом TrustLang применяется другой механизм — семантический ABI: тип объекта восстанавливается компилятором языка из приложенного семантического определения, а не из декорированного имени символа. Принцип описан в Семантическом ABI модулей.

2.8 - Диапазоны, массивы и тензоры

Диапазоны, массивы и (в перспективе) тензоры — контейнерные (коллекционные) типы для работы с последовательностями и многомерными данными.

Диапазоны (:Range)

Диапазон — тип, приблизительный аналог «генератора» в Python: он поочерёдно выдает элементы в заданном интервале с заданным шагом. В тексте диапазон указывается двумя или тремя элементами через две точки: 1..5 — от единицы до пяти с шагом по умолчанию 1; шаг задаётся третьим элементом: 0..10..2. В качестве границ и шага можно использовать не только литералы, но и переменные, и рациональные числа: 0.1..$stop..0.1 — от 0.1 до $stop с шагом 0.1; 0..100:Rational — диапазон рациональных чисел.

Массивы (:Array)

Одномерные массивы поддерживаются литералами [1, 2, 3,] (→ std::vector<Elem>), конструктором :Array(...), доступом по индексу a[i] и методами массива (count, at, first, push_back, …). Переменные с типом массива могут создаваться как по значению, так и как ссылочные.

Оставшиеся позиции массива можно дозаполнить оператором ... expr ... (последним элементом) — размер берётся из размерного типа-цели: v:Int32[10] := [2, 3, ... 42 ...,]; (см. Создание значений: заполнение тензоров).

Тензоры (:Tensor)

Тензоры — многомерные массивы (на базе LibTorch). В текущей версии многомерные массивы и полноценные тензоры не реализованы (см. Статус) — реализован одномерный :Array и тип :Range.

Индексация

Доступ к элементам массива выполняется по целочисленному индексу, начиная с 0:

a := [10, 20, 30,];
x := a[0];   # 10

Отрицательные индексы (как в Python) не поддерживаются: обращение a[-1] вызывает рантайм-исключение. Диапазоны в индексе (a[1..3]), значения :None и многоточие ... в индексе также пока не реализованы.

Перебор коллекций

Перебор элементов массива, диапазона или словаря выполняется циклом @while(коллекция) с деструктуризацией текущего элемента (готовый пример — в песочнице; подробнее — Циклы).

Стандартная библиотека предоставляет тип-итератор Iterator<T> — класс, помеченный @[borrowed]. Он отображается на C++ trust::AnyIterator<T> (устранённый единый курсор) и доступен без явного импорта (загружается prelude; отключается --no-stdlib). Любая переменная типа Iterator<T> автоматически зависима от исходного объекта: использование после мутации источника — диагностика -Wborrowed (см. Контроль инвалидации ссылок). Атрибут наследуется производными типами (Iterator<Int32> и др.).

3 - Выражения и инструкции

Операторы, выражения и управляющие конструкции TrustLang

В TrustLang любая конструкция является выражением и возвращает значение, поэтому её можно вкладывать в другие выражения. Инструкции разделяются точкой с запятой ;; группа инструкций заключается в блок кода { ... }. Базовые правила блоков и выражений описаны в Синтаксисе.

Обработка аварийных ситуаций и гарантии освобождения ресурсов связаны с моделью Памяти, а операторы типизации — с Системой типов.

3.1 - Создание объектов и присваивание

Операторы создания и присваивания объектов, деструктуризация

Создание объектов

Для создания объектов в TrustLang используется несколько операторов:

  • “:=” — создаёт или присваивает значение переменной/функции (объекту по значению). Если объекта с таким именем ещё нет, он создаётся; иначе значение переприсваивается. Пример: x := 5;, hello(str) := { ... };.

  • “::=” — объявление типа (алиаса или типизированного типа), например MyInt ::= :Int32;, Status ::= (OK=0, ERROR=1, BUSY=2,):Enum;. Применять “::=” для создания значений/функций нельзя — компилятор сообщает: “cannot assign a type … to a value variable; use ‘::=’ to declare a type alias”.

    Также через ::= объявляется предварительное (forward) объявление нативного класса: String ::= %std::string { %size(): UInt64 := ...; }; — RHS — имя класса (native — с ведущим %), тело { ... } — члены-интерфейс (методы/поля/конструкторы), каждый := ... (без тела). Конструирование объекта — вызов имени класса: s: String := String('hello'); → std::string("hello"). Подробнее — Нативные типы.

Операторы “::-” и “:-” в текущей версии не реализованы; ранее они предназначались для чистых функций и значений, вычисляемых на этапе компиляции.

Присвоение нового значения

Оператор “=” применяется для присвоения нового значения уже существующим объектам. Если объект с указанным именем отсутствует, то возникает ошибка компиляции.

Оператор обмена значениями

Оператор “:=:” (swap) не создает новых переменных, а только обменивает их значения между собой. Переменные должны иметь одинаковые/совместимые типы данных, либо иметь тип :None, т. е. "_".
Используется для реализации идиомы копирования и замены (copy-and-swap idiom), так как при выполнении оператора не может быть ошибок.

В текущей реализации :=: — интринсик обмена/перемещения (используется как инструкция; результат void): a :=: b раскрывается в std::swap(a, b) (типы должны быть совместимы, не обязательно ссылки; обмен несовместимых типов — ошибка с диагностикой); форма var :=: _ — перемещение значения в discard: перемещение выполняется РЕАЛЬНО (материализуется временное, которое сразу разрушается), поэтому var остаётся в moved-from состоянии, а для владеющих ссылок (unique/shared) ресурс освобождается. См. также «Ссылочные типы».

Оператор добавления элемента

Оператор “[]=” — аналог push_back: добавляет новый элемент к контейнеру слева, увеличивая его размер на единицу. Общее правило: X []= v равносильно X.push_back(v).

  • Для словаря (Dict, в т.ч. позиционные «массивы») безымянный append добавляет позиционный элемент: d []= 999.
  • Для строк добавляет символ/строку: s []= 'd' → s.append("d").
  • Правый объект оператора должен быть совместим с типом единичного элемента левого объекта (ширина строки: узкая '...' / широкая "..." должны совпадать с типом строкового контейнера).
  • Вложенный LHS (d['x'] []= v, d[0] []= v, d.field []= v) — пока не реализован (ошибка компиляции).
  • Слияние словаря через оператор распаковки ...: d []= ... dict2 или d []= ... (a=1, b=2,) добавляет в цель все элементы словаря-операнда (аналог extend/update); размер цели растёт на число элементов (для литерала и словаря с известным размером — статически контролируется).
    d := (1, two=2,);
    d []= 999;        # добавить позиционный элемент → size 3
    d []= 'x';        # добавить ещё один элемент
    d []= ... (a=100, b=200,);  # слияние литерала → size 5 (добавлены a и b)
    d2 := (three=3, 4,);
    d []= ... d2;     # слияние переменной-словаря → size 7

    s := 'abc';
    s []= 'd';        # строка стала "abcd"
    @print('{}', s);   # > abcd

Добавление именованного элемента словаря выполняется оператором присваивания d[name] = value (установка/добавление по ключу).

Например, при определении класса :NewClass2:

    :NewClass ::= :Class{       # Базовый класс
        field1:Int32 := 1;      # поле класса
        field2:Int32 := 2;      # поле класса
        method1():Void := {};   # метод
    };

    :NewClass2 ::= :NewClass{   # наследование
        field2:Int32 := 2;      # поле field2 базового класса
        method1():Void := {};   # переопределение метода (override)
    };

    $var := 99; # Создать временную переменную $var
    {
        $var := 100; # Новая переменная перекрывает $var более высокого уровня
        @print('{}', $var)    # > 100
    }
    @print('{}', $var)    # > 99

Присваивание значения сразу нескольким переменным и оператор распаковки словаря

TrustLang поддерживает операцию присваивания значения сразу нескольким переменным, которые должны быть перечислены через запятую слева от оператора присвоения.

С правой стороны от оператора присвоения может находиться только одно значение, а для обмена значениями двух переменных, вместо записи a,b = b,a; нужно использовать оператор обмена:

    a :=: b;

В качестве правого операнда в операторе присвоения допускается использовать оператор распаковки словаря … (многоточие), который можно использовать и при передаче аргументов в функцию.

3.2 - Операторы

Арифметические операторы

Арифметические операторы TrustLang применимы к числовым типам и формам с присваиванием. Каждый бинарный оператор имеет парный аналог op=, который выполняет операцию и присваивает результат левому операнду (a += 1;):

Оператор Действие
+ / += сложение
- / -= вычитание
* / *= умножение (применимо и для повторения строк)
/ / /= деление (результат — число с плавающей точкой)
// / //= целочисленное деление с округлением к меньшему (как в Python)
% / %= остаток от целочисленного деления

Отдельного оператора возведения в степень нет (степень вычисляется функцией/повторным умножением). Арифметика рациональных чисел и :BigInteger — отдельная строгая ветка: смешивание с числами с плавающей точкой требует явного преобразования (см. Числа и тензоры).

Битовые (поразрядные) операторы

Записи .<. (сдвиг влево), .>./.>>. (сдвиг вправо), .&., .|., .^., .~. (И/ИЛИ/ИСКЛ-ИЛИ/НЕ) распознаются лексером и поддерживаются при SMT-верификации контрактов (транслируются в BV-операторы bvshl/bvashr/bvand/bvor/bvxor/bvnot). Генерация исполняемого C++-кода для них ещё не реализована (запланировано) — в .cppt оператор выводится как есть. Статус — в разделе Статус реализации.

Арифметическое сравнение

Операторы арифметического сравнения — классические <, >, <=, >=, ==, !=. Они применяются для сравнения скаляров и рациональных чисел; операторы равенства == и != позволяют сравнивать и составные значения.

Сравнение значений

  • == и != — сравнение с автоматическим приведением совместимых типов для любых объектов.
  • === и !== — точное сравнение для любых объектов (автоматического приведения не выполняется); для объектов сравниваются адреса размещения.

Сравнение типов

Операторы сравнения типов возвращают Bool и различаются строгостью проверки:

Оператор Смысл
<~ номинальная проверка: тип левого операнда совпадает с правым типом либо присутствует в его иерархии наследования
~~ утиная (структурная, нестрогая): у левого операнда присутствуют все поля образца правой части
~~~ строгая: номинальное тождество типа либо точное совпадение набора полей образца

Правый операнд — имя типа (:Class), строковый литерал с именем типа или словарь-образец ((field1=_, field2=0,); пустой словарь — (,)). Левый операнд — значение (проверяется его тип) или имя типа (:Base <~ :Derived).

dog <~ :Animal;             # тип dog — Animal или его наследник
dog ~~~ :Dog;               # точное тождество типа
:Dog <~ :Animal;            # Dog — подтип Animal (проверка на этапе компиляции)
:Animal <~ :Dog;            # ложь (обратное отношение — перестановкой операндов)
d ~~ (field1=_,);           # у d есть поле field1
d ~~~ (field1=_, field2=0,);# точный набор полей

Отрицаний у этих операторов нет — результат Bool проверяется как обычно: ветка else в if/match либо сравнение с false.

Статическая и динамическая проверка

  • Статика (основной путь): если тип левого операнда выведен на этапе компиляции, результат свёртывается в константу true/false (наследование — по реестру типов). Нулевая стоимость в генерируемом коде.
  • Динамика: проверки, требующие рантайм-типа значения (стёртые значения Any/элементы словаря с неизвестным типом), а также имя типа из строковой переменной, пока не реализованы — выдаётся явная диагностика компиляции.

3.3 - Условия и циклы

В TrustLang нет ключевого слова if: условие проверяется конструкцией, которая по смыслу соответствует математическому «следует» — два тире и угловая скобка -->. Запись легко объединяется в цепочки для проверки нескольких условий вида «else if». Ниже конструкция показана обеими формами — DSL-макросом и базовым синтаксисом (о двух формах записи см. Макросы и DSL):

Макросы DSLБазовый синтаксис
@if( условие1 ) {
    действие1
} @elif( условие2 ) действие2
@else {
    действие_иначе
};
[ условие1 ] --> { действие1 },
[ условие2 ] --> действие2,
[ ... ] --> { действие_иначе };

Для записи циклов используется оператор <-> (в базовой записи) или макросы @while/@dowhile (в DSL). Условие записывается в квадратных скобках; в зависимости от взаимного расположения условия и тела цикл бывает с предусловием (while) или с постусловием (do while). Эквивалентные формы:

Макросы DSLБазовый синтаксис
@while( cond ) {
    тело цикла
};
[ cond ] <-> {
    тело цикла
};
{
    тело цикла
} @dowhile( cond );   # постусловие
{
    тело цикла
} <-> [ cond ];   # постусловие
@while( cond ) {
    ...
} @else {
    ...    # если cond == false при входе
};
[ cond ] <-> {
    ...
}, [ ... ] --> {
    ...    # ветка else
};

Цикл с предусловием (while) поддерживает ветку else, которая выполняется, если условие входа в цикл не было выполнено ни разу.

Внимание: это отличается от аналогичной конструкции в Python, где секция else выполняется всегда, кроме прерывания цикла по break.

Перебор коллекций (foreach)

У цикла foreach нет отдельного ключа DSL — он реализуется циклом с деструктуризацией элемента и мутацией источника (оператор раскрытия списка). Пример суммирования элементов словаря:

summa := 0;
dict := (1,2,3,4,5,);
[ dict ] <-> {          # условие цикла — пока в dict есть данные
    # распаковка: первый элемент переходит в item, суффикс dict... — оставшиеся
    item, dict... := ... dict;
    summa += item;      # накопление суммы
};

Сопоставление с образцом (match)

Оператор оценки выражения (match) — приблизительный аналог операторов switch/match в других языках. Он задаётся конструкцией [ выражение ] ==> { ... } (базовый синтаксис) или макросом @match (DSL), в теле которых перечисляются ветки-условия. Эквивалентные формы:

Макросы DSLБазовый синтаксис
@match( $var ) ==> {
    @case( 1 ) { code };
    @case( 1, 2 ) { code };
    @default { code default };
};
[ $var ] ==> {
    [1] --> { code };             # $var == 1
    [1, 2] --> { code };          # ($var == 1 || $var == 2)
    [...] --> { code default };   # иначе
};

Хотя оператор внешне похож на сопоставление с образцом (pattern matching), по сути это краткая запись множественного оператора сравнения: в качестве оператора оценки можно использовать любой оператор сравнения:

  • ==> — равенство с приведением типов;
  • ===> — точное равенство;
  • ~> — проверка типа (имени класса);
  • ~~> — утиная типизация;
  • ~~~> — строгая утиная типизация.

Если в качестве оператора сравнения используется утиная типизация, оценка превращается в классическое сопоставление с образцом по полям (пример приведён на форме @match):

$value := (f1=1, f2='2',);
@match( $value ) ~~> {
    @case((f1=_,), (f1=_, f2=0,)) { ... }; # поле f2 отсутствует или является числом
    @case((f1=_, f2="",), (f1=_, f2='',)) { ... }; # поле f2 — строка
    @default { ... };
};

Переопределение функции сравнения (атрибут @[matcher("fn")])

Если сравнение по значению не сводится к == (например, сопоставление строки с регулярным выражением), функцию сравнения match можно переопределить атрибутом @[matcher("fn")], где fn — объявленная ранее функция-предикат с сигнатурой bool fn(T_value, T_pattern). В каждой ветке вместо сравнения (value == pattern) вызывается предикат fn(value, pattern); проверяемое выражение (scrutinee) вычисляется один раз во временную переменную. При заданном матчере ветки всегда порождаются как if/else-цепочка (оператор switch неприменим — шаблон не обязан быть константой).

Атрибут ставится между значением и оператором (на «сырой» форме, так как макрос @match требует оператор сразу после себя):

@func matches_regex(value:StrChar, pattern:StrChar):Bool { ... };
$s := 'foobar';
[ $s ] @[matcher("matches_regex")@] ==> {
    @case('^foo') { ... };
    @case('bar$', 'baz') { ... };
    @default { ... };
};

Семантика проверяет, что fn — объявленная функция-предикат ровно с двумя параметрами и логическим (булевским) возвратом. Атрибут @[matcher] несовместим с сопоставлением по типу (~>/~~>/~~~>).

3.4 - Менеджер контекста (with)

Групповой захват ссылок и автоматическое освобождение ресурсов (RAII)

Одиночный оператор захвата ссылки и синхронизации доступа к объекту (*ref, *ref(...)) выполняется для одного действия. Захват ссылки/объекта синхронизации — относительно медленная операция, поэтому выполнять её для каждого действия нерационально. Менеджер контекста (with) однократно захватывает сразу несколько ссылок/объектов и выполняет группу действий под общим локом, а также служит для автоматического освобождения ресурсов (RAII) при выходе из блока.

В базовом синтаксисе — оператор **( ... ), в DSL ему соответствует макрос @with (см. Keyword syntax (DSL)). Сравнение форм записи на примере захвата-блокировки ссылки:

Макросы DSLБазовый синтаксис
@with(lock = *ref) {
    ...   # критическая секция
};
**( lock = *ref ) {
    ...   # критическая секция
};

Захват и блокировка ссылок

Ссылочные переменные объявляются атрибутами @[reftype("shared")@]/@[reftype("weak")@] и транслируются в trust::Shared/trust::Weak; оператор take *ref/*^ref захватывает ссылку (lock/lock_const) и возвращает охраняемый доступ trust::Locker<T>. Подробнее о ссылочных типах и модели ссылок — в Управлении памятью.

with хранит список пар (замок, привязка) и связывает захваченные ссылки с именами внутри тела:

@with(lock = *ref) {     # захват-блокировка ссылки ref
    ...                  # критическая секция
} @else { ... };         # ошибка захвата (ref == nullptr) → else
  • with(lock = *ref) — создаёт временный замок auto __cap = ref.lock();, привязка lock автоматически разыменовывается в значение; вызов lock() бросает IntMinus при сбое → ветка else.
  • with(_ = *ref) — захват ссылки на всё тело без привязки значения.
  • with(*ref) — временный лок: снимается сразу, тело выполняется без лока.
  • Привязка ссылочной переменной без */*^ (with(v = ref)) — предупреждение компилятора.

Автоматическое освобождение ресурсов (RAII)

Кроме захвата ссылок, менеджер контекста позволяет выделять и освобождать ресурсы: при выходе из блока вызывается деструктор объекта (для объектов по значению). Освобождение происходит до попадания в ветку else, если она есть:

@with(name = expr, ...) {  # RAII-захват значений
    ...
} @else { ... };           # при исключении в инициализаторе expr

Это гарантирует закрытие файлов, освобождение захваченных ресурсов и т. п. независимо от того, как завершился вложенный код (штатно, по прерыванию или по ошибке).

Статус реализации

Формы &/&?/&&, параметр __timeout__, межпотоковая синхронизация и типы :Class/:Thread в текущей версии не реализованы (см. Статус). Работают: ссылочные переменные @[reftype(...)], захват ссылок with(...) с веткой else и RAII-захват значений with(name=expr).

3.5 - Возврат, прерывания и обработка ошибок

Последовательность команд (блок кода) можно прервать в любом месте специальными операторами прерывания. В TrustLang используются два вида прерываний, которые по смыслу соответствуют своей записи:

  • «положительное» прерывание ++ — возврат значения/сквозная передача потока (аналог return);
  • «отрицательное» прерывание -- — ошибка (аналог throw).

Прерывание может возвращать значение: ++ 'Строка' ++ — вернуть строку, -- err -- — «бросить» ошибку (примерный аналог throw err). Если значение не указано, прерывание не возвращает ничего (пустое значение).

Именованные прерывания: локальный переход и возврат

Именованные блоки кода могут выступать локальными метками передачи потока управления. Если перед оператором прерывания указать пространство имён/метку блока, то такое именованное прерывание действует только для указанного блока:

  • block ++ — break по метке block (выход из блока);
  • block -+ — continue по метке (переход на первую инструкцию блока).

Один и тот же фрагмент — именованный цикл с выходом по метке и переходом к началу блока — двумя формами:

Макросы DSLБазовый синтаксис
outer {
    @loop {
        @break outer;     # break по метке outer (как outer ++)
        @continue outer;  # continue по метке outer (как outer -+)
    };
};
outer {
    [1] <-> {
        outer ++;   # break по метке outer
        outer -+;   # continue по метке outer
    };
};

Тело функции — это блок кода, чьё имя совпадает с полным именем функции. Поэтому «положительное» прерывание по метке функции возвращает результат из неё (func_name ++ value ++); в DSL этому соответствует @return.

Перехват прерываний (try/catch)

Неименованные прерывания можно «ловить». Для перехвата используются блоки кода со специальной семантикой, которые оборачивают тело в try/catch по классу прерывания:

  • {+ ... +} — перехватывает положительные прерывания (IntPlus);
  • {- ... -} — перехватывает отрицательные прерывания (IntMinus);
  • {* ... *} — перехватывает оба типа (IntAny).

Статус реализации (важные уточнения):

  • неименованное ++ value ++ всегда бросает IntPlus (положительное/сквозное), а -- err -- — IntMinus (ошибка), независимо от наличия и глубины обработчиков;
  • именованное func ++ value ++ — обычный return из функции (метка обязана быть текущей функцией или глобальной ::);
  • неперехваченный класс пробрасывается насквозь; сквозной ++ проходит через вызовы функций до ближайшего {+}/{*};
  • перехват значения (например, через match) пока не реализован — перехваченное прерывание поглощается.

Обработка ошибок

«Отрицательное» прерывание используется для возврата ошибки лишь условно — оба вида прерываний равнозначны. Совместная обработка перехваченного значения в классическом стиле try/catch — через блоки перехвата ({*}, {-}, {+}) и оператор оценки выражения — пока не реализована: перехваченное прерывание поглощается (см. Статус).

См. также

  • Менеджер контекста with — RAII и освобождение ресурсов при выходе из блока.
  • Многопоточность и асинхронность — запланированные прерывания корутин (@co_yield/@co_await/@co_return не реализованы).
  • DSL-эквиваленты (@return, @break, @continue) — Keyword syntax (DSL).

4.1 - Управление памятью и совместный доступ

Ни один способ управления памятью не является лучшим или универсальным: в разных условиях выигрывают разные подходы:

  • Ручное управление памятью может делать всё, что угодно, кроме одного — гарантировать отсутствие ошибок.
  • Анализ владения и заимствования на этапе компиляции позволяет доказать корректность кода без дополнительных рантайм-проверок, но некоторые сценарии и алгоритмы не могут быть доказаны статически на этапе компиляции.
  • Подсчёт сильных и слабых ссылок во время выполнения удобен для разделяемого владения, но имеет ненулевую стоимость и не защищает от циклических и перекрёстных зависимостей.
  • Сборка мусора упрощает работу со сложными циклическими структурами, но имеет самые дорогие накладные расходы и недетерминированное выполнение.
  • Ни один из перечисленных способов управления памятью не включает в себя вопросы межпотоковой синхронизации доступа к памяти.

Поэтому выбирать только один способ управления памятью в языке программирования — это значит заранее ограничить его возможности и добавить лишние накладные расходы. Из этих соображений концепция управления памятью TrustLang допускает расширение реализации модели управления памятью с минимальным влиянием на синтаксис языка и определяется требованиями (гарантиями) для работы с памятью.

Модель управления памятью

  • Семантика языка делит переменные не по способу внутренней реализации, а по семантике, т. е. переменная по значению может хранить данные в куче, но при копировании должно выполняться и создание копии всех её данных, находящихся в куче.
  • Полное описание жизненного цикла объекта всегда включает в себя несколько ортогональных осей и никакая сокращённая символьная запись в принципе не может закодировать всё множество комбинаций (вид ссылки, доступ, принадлежность к региону (время жизни), наличие деструктора у объекта и т. п.). Поэтому сокращённая символьная запись типов переменных предназначена только для переменных, жизненный цикл которых компилятор может верифицировать в автоматическом режиме во время компиляции (преимущественно для локальных областей).
  • В идентичность типов данных включаются не только типы ссылок, но и способы межпоточной синхронизации доступа.
  • Так как требуется взаимодействие с C++-кодом, то от сырых указателей на данные полностью уйти нельзя, но для них вводятся жёсткие ограничения на уровне компилятора (статического анализатора), чтобы ограничить ошибки при работе с памятью.
  • Работа с памятью должна включать в себя и защиту стека от переполнения.

Текущая модель управления памятью находится на стадии тестирования и будет задокументирована в версии 0.7.0. Обсудить эти и другие концепции проекта можно на Reddit https://www.reddit.com/r/trust_lang/

4.2 - Защита стека от переполнения (stack check)

Превращение переполнения стека в перехватываемое исключение вместо аварийного завершения

В TrustLang встроена защита стека от переполнения. Перед вызовом защищаемой функции проверяется свободное место на стеке потока, и если его недостаточно — вместо аварийного завершения всего приложения (segmentation fault) создаётся программное исключение stack_overflow, которое можно перехватить и обработать внутри приложения, после чего продолжить выполнение программы.

5 - Песочница (playground)

Что такое песочница

Песочница (playground) — это интерактивная веб-страница, где можно писать код на TrustLang прямо в браузере и сразу видеть сгенерированный результат транспиляции в C++. Это «живой» пример языка с встроенным редактором и подсветкой кода, выбором примеров из списка, выводом диагностических сообщений, кросс-навигация между кодом и C++ и кнопкой для скачивания итогового build-архива.

Ссылки на состояние песочницы (URL-параметры)

Страницу песочницы можно открыть сразу в нужном состоянии, передав опциональные параметры в URL (query-string). Все параметры необязательны и без line позиция курсора не меняется:

  • file=<имя файла примера> — выбрать предопределённый файл из списка примеров (комбобокс);
  • win=src|cppt — окно, куда ставится курсор (src — исходный Trust-код, cppt — сгенерированный C++; по умолчанию src);
  • line=<n>, col=<m> — позиция курсора (строки/колонки 1-based; col по умолчанию 1);
  • toLine=<n>, toCol=<m> — конец диапазона выделения (если заданы — выделение от line:col до toLine:toCol, иначе просто установка курсора).

Копирование ссылки: при навигации по строкам внизу страницы в статус-строке выводится диапазон (→ cpp: N / → trust: N) и ссылка «🔗 copy link», клик на которую копирует в буфер обмена URL текущего состояния песочницы (выбранный файл, окно и позицию/выделение курсора), чтобы им можно было поделиться.

Статус-строка песочницы

Страница сама по себе ничего не вычисляет — она отправляет код на роутер/балансировщик (playground), который распределяет задачу транспиляции исходного кода на свободный исполнительный узел (worker), и уже тот выполняет транспиляцию Trust → C++, а результат возвращается обработанным балансировщику и отображается на странице браузера.

Внизу страницы отображается постоянный индикатор связи с балансировщиком:

  • 🟢 balancer online · workers: N — связь есть, воркеры активны;
  • 🟠 balancer online · no workers — связь есть, но свободных воркеров нет;
  • 🔴 no connection to the balancer — балансировщик недоступен (сетевой сбой или балансировщик остановлен).

Как запустить свой воркер

Вы можете помочь проекту и запустить свой узел-исполнитель за несколько минут. Для этого нужно:

  • Linux-сервер (VPS) с systemd и возможностью исходящего TCP-соединения к балансировщику (обычный интернет).
  • Дистрибутив trust-lang-*.tar.gz или deb пакет (содержит trust-playground и trust-lsp).
  • Токен воркера (64 hex-символа) — выдаются администратором.

Песочница работает по трёхуровневой схеме

браузер (статическая страница)
        │  POST /run, GET /health, POST /download
        ▼
балансировщик (playground)
        │  реестр воркеров, очередь запросов, rate-limit, статистика
        ▼
исполнительные узлы (worker)     ←  подключаются сами (исходящее соединение),
        │                             reverse long-poll за задачами
        ▼
   trust-lsp --json             ← (локальное выполнение Trust → C++)

Ключевые особенности:

  • Роутер/балансировщик не выполняет вычислений — только принимает запросы, ведёт реестр воркеров и диспетчеризует задачи. Слушает локально (127.0.0.1), наружу его отдаёт nginx по HTTPS.
  • Воркеры сами подключаются к балансировщику (исходящее соединение — двойной NAT не мешает), регистрируются по токену и выполняют транспиляцию в изолированном субпроцессе с лимитами памяти, времени и размера вывода.
  • Если свободных воркеров нет, балансировщик отвечает «нет воркеров» со ссылкой на эту инструкцию.

    ./trust-playground --token <ТОКЕН> --lsp /path/to/trust-lsp

    После чего в консоли появится сообщение settings saved to ./trust-playground.conf as defaults и запустится воркер со статистикой работы в реальном времени, а в следующий раз для запуска будет достаточно просто:

    ./trust-playground

    Или для работы в фоне:

    nohup ./trust-playground >> trust-playground-worker.log 2>&1 &

    Остановка в фоне: pkill -x trust-playground.
