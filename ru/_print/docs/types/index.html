1 - Система типов

Принципы

TrustLang имеет закрытую систему типов: любой новый тип данных обязательно наследует (расширяет) один из уже существующих. Это напоминает модель Object в Java, но без физического наследования (без боксинга простых типов в объекты). Этот подход является основой для обобщённого программирования, когда производный тип наследует набор операций «родительского» типа, и продолжает работать со всеми его наследниками.

Язык динамически типизирован: тип переменной можно указать явно или оставить автоматический вывод. Указанный тип используется для проверок совместимости при присваивании, для проверки типа возвращаемого значения функции и для управления размещением в памяти нативных типов. Автоматическое приведение возможно только между совместимыми типами; в остальных случаях требуется явное преобразование типов.

Категории типов

Типы данных разделяются на простые (скалярные, не расширяемые) и составные (контейнерные и определяемые пользователем). Кратко по категориям (подробности — на соответствующих страницах раздела):

Категория Типы Описание на странице
Целые :Int8…:Int64, беззнаковые синонимы (:Byte, :Word, :DWord), :Bool Числа и тензоры
Числа с плавающей точкой :Float16, :Float32, :Float64 Числа и тензоры
Произвольная точность рациональные m\n и :BigInteger (GMP) Числа и тензоры
Строки :StrChar (UTF-8), :StrWide Символьные строки
Диапазоны и массивы :Range, :Array (одномерный, std::vector) Диапазоны, массивы и тензоры
Словари :Dictionary (позиционные и именованные элементы) Словари и наборы
Пользовательские перечисления :Enum, варианты :Variant, кортежи :Tuple, алиасы ::= Словари и наборы
Нативные импорт и предварительное объявление C/C++-типов и шаблонов Нативные типы

Переменные могут хранить значение напрямую либо быть ссылочными (сильные/слабые ссылки, shared/weak) — см. Управление памятью.

Имена типов и конструкторы

Каждый тип имеет краткое имя, начинающееся с двоеточия (например, :Int32), и одноимённую функцию-конструктор без двоеточия. Новый экземпляр создаётся вызовом конструктора: x := Int32(5);. Типы могут быть синонимами — два типа с одинаковым кратким именем в разных пространствах имён; в этом случае требуется явная квалификация имени при вызове конструктора (см. Именование объектов).

Статус реализации

Из «объектно-ориентированных» возможностей реализованы базовые :Struct/:Class (поля, методы, наследование), типы Enum/Variant/Tuple и предварительное объявление нативных классов (см. Классы). Комплексные числа (:Complex16/32/64), многомерные тензоры (полноценные :Tensor), виртуальные методы/@[override] (полноценное ООП), корутины и чистые функции не реализованы — подробнее в Статусе реализации и ограничения.

Преобразование типов

Несмотря на динамическую типизацию, если тип переменной указан явно, автоматическое приведение типов не выполняется — для присваивания значения несовместимого типа требуется его явное преобразование.

Явное приведение вызовом типа

Явное преобразование выполняется вызовом функции с именем целевого типа (кратким именем без двоеточия): :Int32(x) читается как Int32(x) — это вызов конструктора/приведения типа.

n := Int32(3.14);      # число с плавающей точкой → целое
b := Bool(5);          # число → логическое (0/1)
f := Float64(n);       # целое → число с плавающей точкой

Приведение выполняется с контролем диапазона: если значение не помещается в целевой тип (сужение), возникает ошибка — как на этапе компиляции для известных значений, так и в рантайме для переменных. Молчаливого «обрезка»/переполнения нет.

Словарь как универсальный тип

Словарь — единственный тип, который может быть приведён к любому другому: для создания значения конкретного типа достаточно передать словарь аргументом в приведение/конструктор типа. Подробнее — в Словарях и наборах.

Преобразования между категориями

Правила и примеры преобразований для конкретных категорий описаны вместе с самими типами:

  • числа и рациональные значения — Числа и тензоры;
  • строки и их форматирование — Символьные строки;
  • диапазоны/массивы и изменение размерности — Диапазоны, массивы и тензоры;
  • нативные C/C++-типы — Нативные типы.

2 - Числа и тензоры

Числовые типы — простые (скалярные) типы данных TrustLang. Основы типизации описаны на странице Система типов, а массивы, диапазоны и (в перспективе) тензоры — в разделе Диапазоны, массивы и тензоры.

Целые числа

Имена целых типов соответствуют их разрядности: :Int8, :Int16, :Int32, :Int64. Целочисленный литерал получает минимальный знаковый тип, в который влезает его значение (например, 5 → :Int8), а значение, не помещающееся в :Int64, становится :BigInteger. Тип литерала можно задать явной аннотацией литерал :Type (например, 1 :Bool, 255 :Int16) — при выходе за диапазон типа возникает ошибка компиляции, а не молчаливое переполнение.

Для взаимодействия с нативным C++-кодом у целых есть беззнаковые синонимы (:Byte, :Word, :DWord, :UInt16/:UInt32/:UInt64, …), которые применяются при вызове нативных функций. В арифметике предпочтительны знаковые типы — так удаётся избежать классических проблем беззнаковой арифметики (например, вычитания, дающего огромное «отрицательное» значение).

Контроль целочисленного переполнения

Арифметика знаковых машинных целых (+, -, * и составные +=, -=, *=) контролируется на переполнение: результат операции проверяется встроенной функцией __builtin_*_overflow, и при переполнении выбрасывается программное исключение trust::IntMinus (ловится trust-блоком {- ... -} и конструкцией try), а не возникает неопределённое поведение (UB), как в C++. Сообщение исключения содержит локацию исходного кода в формате файл:строка: (как у @assert), например rational.src:8: integer overflow in '*='.

Опция -foverflow-check / -fno-overflow-check (по умолчанию включена) управляет контролем. Проверяются только знаковые машинные целые (:Int8…:Int64); беззнаковые типы по определению заворачиваются (wrap), :BigInteger/:Rational имеют произвольную точность, а /, //, % и битовые операции не переполняются и не проверяются.

Дополнительно контролируется унарный минус (-x: переполнение при -INT_MIN) и целочисленное деление /////= — предохранители от деления на ноль и от INT64_MIN / -1 (undefined behavior в C++). Все нарушения также приводят к перехватываемому trust::IntMinus.

Логический тип

Логический тип :Bool принимает только значения 0 или 1 (false/true). Он выделен в отдельную категорию (значения @true/@false в DSL — это 1 :Bool/0 :Bool) и в зависимости от операции может вести себя как целочисленный. Явная 0 :Bool/1 :Bool-аннотация создаёт именно логическое значение.

Числа с плавающей точкой

Типы с плавающей точкой соответствуют разрядности: :Float16, :Float32, :Float64 (синонимы :Single, :Double). Разряды числа можно разделять знаком подчёркивания для читаемости: 10_000.

Рациональные числа и произвольная точность

Для вычислений с неограниченной точностью используются рациональные числа: это дробь \( \frac{m}{n} \), где числитель m — целое, а знаменатель n — натуральное (больше нуля). В качестве разделителя дроби используется обратная косая черта: 1\1 — единица, -55\3 — дробь \( \frac{-55}{3} \). Арифметика рациональных чисел строится на :BigInteger (GMP) и не теряет точность; смешивание с числами с плавающей точкой требует явного преобразования.

Показ длинных чисел

Полное значение числа произвольной точности может быть очень длинным. Для показа (в логах, отчётах, диагностике) у :BigInteger есть метод display(L), возвращающий строку вида голова...хвост (N), где L — число цифр в начале и конце, а N — общее число десятичных цифр:

x :BigInteger := 123456789012345678901234567890;
@print('{}', x.display(3));   # 123...890 (30)

Если цифр немного (N <= 2L + 1), возвращается полное число. Знак выводится впереди, а N считает цифры без учёта знака.

Метод display(L) предназначен только для показа: его результат — строка, из которой нельзя восстановить точное значение числа (это не round-trip представление). Точное десятичное представление даёт обычный вывод значения ({} в форматной строке).

Аналогичный метод есть и у рациональных чисел :Rational: display(L) сокращает каждый компонент дроби независимо (числитель и знаменатель — :BigInteger), например 123...890 (30)\45...678 (5).

3 - Символьные строки

TrustLang поддерживает два типа строк:

  • :StrChar — универсальные байтовые UTF-8 строки;
  • :StrWide — системные (широкосимвольные) строки.

Байтовые строки :StrChar

Единичный элемент байтовой строки — один байт (точнее :Int8, восьмибитное целое со знаком). Размер строки возвращается в байтах, а доступ по индексу обращается к байту последовательности. Так как данные интерпретируются как последовательность UTF-8 символов, при изменении отдельных байт нужно соблюдать осторожность.

Системные строки :StrWide

Единичный элемент системной строки — широкий символ wchar_t, а размер возвращается в широких символах. Размер wchar_t зависит от операционной системы: в Windows один символ :StrWide занимает 2 байта, в Linux — 4. Основное назначение системных строк — упрощение работы в текстовом терминале: один символ всегда соответствует одному знакоместу без конвертации кодовых точек UTF-8.

Несмотря на разный единичный элемент, внутреннее представление у обоих типов одинаковое: данные строк хранятся в виде байтовой UTF-8 последовательности.

Форматирование строк

К любой переменной можно обратиться как к функции (указав после имени круглые скобки), создав тем самым копию/клон объекта; для строк такой вызов используется как шаблон форматирования данных.

Форматирование возможно двумя способами:

  • Строка формата в стиле printf (тип :FmtChar/:FmtWide) в текущей версии не реализована — типа :FmtChar/:FmtWide нет (см. Статус). Для нативных функций с printf-строкой используется атрибут @[format("printf", pos, ...)] (проверка параметров на этапе компиляции, пример — hello).
  • Во всех остальных случаях (любая строка по умолчанию) формат соответствует библиотеке {fmt}/std::format: порядковый номер аргумента ({0}, {1}) или пустые {}. Проверка аргументов выполняется при клонировании строки (во время компиляции и выполнения). Именованные аргументы (name = …) не реализованы.
$template := "{0}: {1}";    # формат как в {fmt}
$result := $template('value', 123);

4 - Словари и наборы (перечисления)

Действующие примеры с фактическим поведением текущей версии можно запустить в песочнице: словарь, словарь со смешанными типами, перечисление и вариант.

Словарь (:Dictionary)

Словарь — набор данных произвольного типа с доступом к элементам по целочисленному индексу или по имени элемента при его наличии (это похоже одновременно и на кортеж, и на структуру). Словарь всегда одномерный, но каждый элемент может содержать произвольное количество элементов любого типа, в том числе другие словари.

Литерал словаря записывается в круглых скобках с обязательной завершающей запятой: (,) — пустой словарь, (1, two='2', name=3,). Доступ к элементу — по имени через точку от имени переменной (d.name) либо по целочисленному индексу (d[0]), который начинается с 0 и может быть отрицательным (отсчёт от конца). Изменение — оператором []=; количество элементов — методом size().

Позиционный литерал без указания типа ((1, 2, 3,)) всегда создаёт словарь (:Dictionary). Словарь — единственный универсальный тип: он может быть приведён к любому другому типу, для чего достаточно передать его аргументом в приведение/конструктор целевого типа (см. Преобразование типов).

Перечисление (:Enum)

Enum — тип с ограниченным списком членов, у каждого из которых есть имя и значение. Все члены имеют единый тип значений, который выводится по общим правилам — из явных значений членов либо из явной аннотации типа. Литерал-объявление записывается в постфиксной форме (члены,):Enum или префиксной :Enum(члены) (как у типизированного кортежа); завершающая запятая обязательна.

Status ::= (OK=0, ERROR=1, BUSY=2,):Enum;   # члены с явными значениями; тип значений Int64
Color ::= (RED, GREEN, BLUE,):Enum;          # безнарные члены — автоинкремент от 0
Flag  ::= (LOW:Int8, HIGH,):Enum;            # явный тип члена задаёт тип значений Int8

Если явных значений нет, тип значений — минимальный знаковый целый по числу членов; явная аннотация name:Type задаёт тип значений принудительно (у всех членов он должен быть одинаковым). Сравнение членов выполняется по значению, а не по позиции.

Обращение к члену — через имя типа: Status.OK. Классические методы (через имя типа): count() (число членов), fromName(name) (член по имени), fromValue(value) (член по значению).

Доступ к члену (Status.OK, Data.i) и методы count()/fromName()/fromValue() реализованы (пример — перечисление и вариант).

Вариант (:Variant)

Variant — гетерогенный тип: каждый член имеет свой тип данных (аналог std::variant). Тип члена задаётся явной аннотацией (name:Type) либо выводится из его значения; для безнарного члена без типа берётся минимальный знаковый целый по позиции.

Data ::= (i=42, s='text', r=1\2,):Variant;  # типы членов: Int8, StrChar, Rational
V    ::= (X:Int64=7, Y:Rational,):Variant;  # явные типы членов

Обращение к члену — через имя типа: Data.i (тип — тип конкретного члена). Классический метод: count() (число членов).

5 - Классы

Тип данных :Class аналогичен словарю, но все его поля обязаны иметь имена (доступ к свойствам по индексу также возможен). При создании экземпляра класса создаётся новый тип, копирующий свойства и методы всех родителей. В отличие от словаря, состав полей класса определяется на этапе компиляции и может только расширяться относительно родительских типов.

Статус: реализованы базовые :Struct (строго POD) и :Class (наследование), генерируемые в C++ struct; полноценное ООП (виртуальные методы/override, конструкторы/деструкторы, статические члены) в текущей версии не реализовано. Из «объектно-ориентированных» типов также реализованы перечисления :Enum, варианты :Variant и кортежи :Tuple (см. Словари и наборы), а также предварительное объявление нативных C++-классов (String ::= %std::string { ... }; — см. Нативные типы) и пользовательские шаблон-классы (<T> :Box ::= :Class{...} — см. Обобщённое программирование). Актуальные границы реализации — в Статусе реализации.

Объявление :Struct/:Class — через ::= с телом, члены которого задаются оператором := (Name ::= :Base{ ... };):

Point ::= :Struct{ x:Int32 := _; y:Int32 := _; };      # строго POD; поля БЕЗ значения (`:= _`)
Animal ::= :Class{ name:Int32 := 0; speak():Int32 := { ... }; };  # Class: default допустим
Dog ::= :Animal{ age:Int32 := _; };                    # наследование (Class)
Iface ::= :Class ...;                                  # предварительное объявление (форма без тела)

Оба типа генерируются как C++ struct (все члены публичные); :Struct дополнительно получает static_assert на POD (std::is_trivial_v && std::is_standard_layout_v). Поля/методы с ведущим _ (защищённые) и __ (приватные) поддерживаются на уровне соглашения об именовании — влияют только на автодополнение, в C++ генерируются без изменения доступа. Голое имя члена (obj.field, obj.method()) транслируется в прямое обращение к члену struct.

Правила значений и объявлений:

  • member := ... — прототип метода (объявление без тела) внутри определения класса. Класс с телом (даже если все методы — прототипы) является полным определением (struct c_Name { ... };) — в C++ прототипы существуют только внутри определения, а не в forward-объявлении.
  • member := _ — отсутствие значения (поле без значения по умолчанию).
  • field:Type := <value> — поле со значением по умолчанию.
  • :Name ::= :Base ...; (форма без тела) — предварительное объявление → C++ incomplete type struct c_Name;. Имя типа при этом уже зарегистрировано и видно, поэтому позднее то же имя можно доопределить (:Name ::= :Base { ... };); повторное определение — ошибка. В C++ forward-объявление не содержит членов (ни полей, ни методов); тип неполный.
  • Self-ссылки разрешены: имя record-типа видно внутри его собственного тела (аналог C++ injected-class-name), поэтому :Node ::= :Class{ next : @[reftype("shared")@] Node := _; } корректно. Ссылки (shared/weak/unique-указатель) на неполный тип допустимы; value-поле самого себя — ошибка бесконечного размера (см. ниже).
  • field := ... недопустимо: в C++ член-данное нельзя предобъявить (оно существует только в определении).

Рекурсивные/циклические ссылки в полях запрещены статически (анализатор RefCycleHook), чтобы не допускать утечек и невыразимых типов: -Wrecursive-shared — цикл с shared-ребром (утечка refcount; разрывается weak-обратной ссылкой), -Wrecursive-unique — взаимное unique-владение двух типов, -Wrecursive-value — рекурсия по значению (value/default unique = inline, бесконечный размер). Все — default error, переключаются -Wrecursive-*=ignore|warning|error. Самоссылка unique-указателем — легальный owned-список и не диагностируется.

Для :Struct (строго POD) значение по умолчанию поля запрещено анализатором (NSDMI нарушает тривиальность): поле объявляется как field:Type := _;. Для :Class значение поля не проверяется — допустимы и := <value> (эмитится как C++ default member initializer), и := _ (без инициализатора).

Виртуальные методы (@[virtual]) и переопределение (@[override]) в текущей версии не реализованы — их использование приводит к явной ошибке компиляции (а не к молчаливому игнорированию).

Перегрузка операторов

Оператор объявляется именем-символом в обратных кавычках (лексема REFLECTION): в теле класса — как метод, на верхнем уровне модуля — как свободная функция. Тело и сигнатура — как у обычного метода.

Point ::= :Class{
    x: Int32 := _;
    `==`(o: Point): Bool := { ... };      # member → C++ operator==
    `()`(i: Int32): Int32 := { ... };     # operator()  (только member)
    `[]`(i: Int32): Int32 := { ... };     # operator[]  (только member)
};

`!=`(a: Point, b: Point): Bool := { ... };   # свободный оператор (все операнды — параметры)

Символ транслируется в C++ operator<sym> (`==` → operator==, `()` → operator()); выражения a == b / a != b для пользовательских типов разрешаются C++-перегрузкой, поэтому оператором можно пользоваться в обычных выражениях.

Использование в TrustLang-коде: a == b (сравнения), a(5) (вызов значения — оператор ()), a[i] (индексация — оператор []). Каждая форма транслируется в соответствующую C++-операцию (a(5) → a(5), a[i] → (a)[i]) и разрешается C++-перегрузкой.

Реализованы: сравнения == != < > <= >= (как member, так и свободные) и вызов/индекс () / [] (только member — требование C++; [] принимает ровно один параметр). Арность проверяется (сравнение — один параметр у member и два у свободного), повторный символ в типе запрещён.

Использование проверяется на этапе анализа: сравнение/вызов/индексация требуют объявленного оператора у типа (иначе — ошибка компиляции, а не ошибка C++), арность вызова проверяется по объявлению; конфликт «member + свободная функция» одного символа диагностируется как неоднозначность. Операторы поддерживают контракты (trust_pre/trust_post, как функции и методы). Шаблонные операторы (<T> \==`(…)`) не реализованы — явная ошибка.

6 - Функции

Функция определяется операторами создания объектов, имя функции должно соответствовать правилам именования и завершаться круглыми скобками. Телом обычной функции служит блок кода, находящийся в пространстве имён её определения.

У аргументов и у типа возвращаемого значения указывается тип (arg:Type).

Наборы допустимых типов

Несколько допустимых типов задаются набором типов — математическими операторами + (объединение) и - (исключение). Набор определяется один раз как именованный тип:

combi ::= :Int8 + :Int16 + :Int32;   # именованный набор

Функция, у которой параметр имеет тип-набор, разворачивается в N определений (по одному на член набора) с общим телом; вызов разрешается по типу аргумента, как при явной перегрузке:

sq(x:combi):Int64 := { @return :Int64(x) * :Int64(x); };
# эквивалентно трём определениям: sq(:Int8), sq(:Int16), sq(:Int32)

sq(:Int16(3));    # выберет определение с параметром :Int16

Набор можно указать и inline — непосредственно в позиции типа (сигл : идёт сразу перед ():

sq2(x:(:Int8 + :Int16)):Int64 := { @return :Int64(x) * :Int64(x); };

Один и тот же именованный набор может стоять и в параметре, и в возврате — тогда определения сопоставляются позиционно (i-й член набора — и для параметра, и для возврата):

combi ::= :Int8 + :Int16;
idk(x:combi):combi := { @return x; };   # 2 определения: (:Int8)->:Int8, (:Int16)->:Int16

Правила и ограничения:

  • В прототипе допустим не более одного различного набора (иначе — ошибка о комбинаторной сложности); один и тот же набор может использоваться в нескольких позициях.
  • Набор только в возврате недопустим: перегрузки различались бы лишь типом возврата (в C++ перегрузки по возврату нет). Используйте тот же набор и в параметре.
  • Inline-набор — только тип, не выражение (нельзя присвоить/передать как значение).
  • Исключение - пока не реализовано (явная ошибка).
  • Членами набора могут быть простые типы (шаблонные типы в наборе пока не поддерживаются).

TrustLang на уровне синтаксиса поддерживает несколько видов функций.

Обычные функции

Обычная функция ничем не ограничена в смысле C/C++: может содержать условия, циклы, вызовы других функций и т. д. Создаётся оператором :=:

hello(str:StrChar) := {
    @print('call: {}\n', str);
};

@main() := {
    hello('Привет, мир!');
};

Именованные и опциональные параметры

Именованные параметры позволяют передавать аргументы по имени (с префиксом «.»), а не по позиции:

func(width:Int32, height:Int32) := { ... };

func(.width=640, .height=480);
func(.height=480, .width=640);  # порядок не важен

Имя именованного аргумента не перекрывается макросом препроцессора (см. Именование объектов).

Опциональные параметры имеют значение по умолчанию и могут быть опущены при вызове: имя аргумента отделяется от значения знаком =. Сначала перечисляются обязательные параметры, затем — со значениями по умолчанию. Функция, допускающая произвольное число аргументов, заканчивает список параметров многоточием ....

Чистые функции

Чистая функция не имеет побочных эффектов: возвращает результат только по своим аргументам и не изменяет состояние программы. Синтаксис декларации ::- не реализован (см. Статус); к понятию чистоты относится и требование иммутабельности аргументов по ссылке (см. Именование объектов).

Сопрограммы (coroutines)

Сопрограмма — функция-замыкание, способная приостанавливать и возобновлять выполнение (кооперативная многозадачность). В текущей версии не реализовано — см. Статус и раздел Многопоточность и асинхронность.

Анонимные функции

Анонимная функция объявляется в месте использования и не получает собственного имени (уникального идентификатора). В TrustLang анонимная функция задаётся лямбда-выражением и представляет собой значение функционального типа std::function<...>: его можно сохранить в переменной, передать аргументом (функция обратного вызова, предикат) или вызвать на месте.

Лямбда-выражения (замыкания)

Лямбда-выражение объявляет анонимную функцию по месту применения:

[ captures ] (params) : Ret { body }
  • captures — список захватов: только имена ранее объявленных переменных, по значению (копия). Пустые скобки [] — без захвата. Ссылочный захват [&x] в текущей версии не поддерживается (диагностика об ошибке).
  • params — параметры как у обычной функции (x:Type, тип опционален).
  • : Ret — тип возврата; при отсутствии выводится из тела.
  • body — блок кода { ... }; значение блока — результат лямбды.

Лямбда-значение типизируется функциональным типом и может храниться/передаваться. Возврат значения — как у обычной функции (@return / именованная форма), лямбда внутренне имеет собственную метку возврата:

f := [](x:Int32):Int32 { @return x * x; };
y := f(5);

Немедленный вызов

Лямбду можно вызвать сразу после определения. Каноническая форма — обёрнутая:

y := ( [](x:Int32):Int32 { @return x * x; } )(5);

Прямая форма [](x){... }(5) (без обёртки) не поддерживается и выдаёт ошибку с подсказкой использовать ( lambda )(args).

Не поддерживается (первая итерация)

Ссылочный захват [&x], неявный захват [=]/[&], захват со значением/типом ([x = expr], [x:Type]) и захват некопируемых значений (эксклюзивное владение unique) — не поддерживаются и дают явную диагностику. «Замыкание по определению не может быть чистой функцией» — чистая функция (::-) в языке пока не реализована.

Переопределение и перегрузка функций

Поскольку TrustLang позволяет вызывать нативные C/C++-функции напрямую и делать вставки C++-кода, переопределение и перегрузка функций имеют свои особенности.

  • Переопределение (overriding) — реализация методом подкласса метода, объявленного в суперклассе (фундаментальный принцип ООП).
  • Перегрузка (overloading) — создание нескольких функций с одним именем, но разным набором параметров; нужный вариант выбирается на этапе компиляции по параметрам.

Переопределение (overriding)

Переопределение допускается не только для методов класса, но и для обычных функций (механизм, похожий на LD_PRELOAD, реализованный средствами самого языка). Чтобы функцию можно было переопределить, при её создании не должен быть указан признак иммутабельности. Если суперкласс объявил метод мутабельным (виртуальным), а подкласс реализует его с признаком иммутабельности, это равносильно override final (без дальнейшего переопределения):

base::func() := { ... };   # virtual
class1::func() = { ... };  # override
class2::func^() = { ... }; # override final

Переопределение идёт по имени функции без учёта аргументов, однако новая функция должна иметь аргументы, совместимые с типом аргументов исходной функции.

Перегрузка (overloading)

Перегрузка — несколько функций с одним именем и разными сигнатурами (набором типов параметров); нужный вариант выбирается статически на этапе компиляции по типам аргументов. Точный дубль сигнатуры — ошибка; если подходящего варианта нет — ошибка no matching overload, если несколько вариантов несравнимы — ambiguous.

Перегрузка свободных функций и методов пользовательских классов/Struct поддержана:

f(a:Int32):Int32 := { @return a + 1; };
f(a:Int64):Int32 := { @return 100; };

@main() := {
    x : Int32 := 5;
    @print('{}\n', f(x));        # выбран f(a:Int32)
    @print('{}\n', f(7:Int64));  # выбран f(a:Int64)
};

:C ::= :Class{
    base:Int32 := 10;
    f(a:Int32):Int32 := { @return a + 1; };   # перегрузка МЕТОДА
    f(a:Int64):Int32 := { @return base + 90; };
};

Выбор варианта — по типам аргументов: точное совпадение предпочтительнее числового расширения (промоция/конверсия), параметр :Any принимает любой тип (низший приоритет); при нескольких несравнимых лучших — ambiguous.

Перегрузку (выбор сигнатуры и допустимость/приведение аргументов) для функций и методов TrustLang всегда выполняет компилятор — и при единственной сигнатуре тоже. Делегирование C++-слою применяется только к нативным функциям/методам (их типы заданы явно нативными, а имя символа фиксировано внешней библиотекой).

Перегрузка по-прежнему возможна и для нативных функций (все типы аргументов указываются явно и являются нативными типами); нативные функции также доступны для прямого вызова из языков C/C++:

%func(arg:Int8):None := {};   # void func(int8_t)
%func(arg:Byte):None := {};   # void func(uint8_t)
%func(arg:Int64):None := {};  # void func(int64_t)

7 - Нативные типы

Нативные типы данных

Нативными (машинными) данными могут быть как переменные, так и функции, а имя нативных объектов начинается на символ процента “%”.

В случае переменных, это двоичные данные, которые располагаются в одной неразрывной области машинной памяти по определённому адресу и имеют строго определённый формат.

Чтобы использовать уже существующие библиотеки, нужно либо импортировать нативный объект, тем самым создав объект TrustLang, но с реализацией на другом языке, например на C/C++, либо сделать предварительное определение (декларацию) нативного объекта.

Импорт нативных объектов

Импорт — связывание trust-имени функции/переменной с именем существующей нативной функции/переменной. В отличие от предварительного объявления, импортируемая функция регистрируется под своим trust-именем, а её имя и аргументы могут отличаться от имени и аргументов импортируемой нативной функции.

Синтаксис такой же, как у создания обычных объектов, только правым операндом указывается имя нативного объекта. Типы аргументов и возвращаемого значения всегда указываются явно.

  • Если типы регистрируемой и нативной функции совпадают (преобразование не требуется), нативное имя можно указать с многоточием — оно означает, что аргументы вызова повторяют аргументы левой сигнатуры (дублировать их не нужно):

    sqr(x:Float64):Float64 := %std::sqrt...;   # аргументы как у sqr

  • В общем случае аргументы и тип импортируемой функции задаются явно; при генерации вставляется вызов правой функции, а при необходимости аргументы приводятся через static_cast:

    sqr(x:Float64):Float64 := %std::sqrt(x:Float128, true):Float128;

При импорте аргументы автоматически преобразуются к нативным типам импортируемой функции. Импорт может выполняться во время компиляции программы или во время выполнения (динамическая загрузка библиотеки).

fopen(filename:StrChar, modes:StrChar):Int64 := %fopen...;
fclose(f:Int64):Int32 := %fclose...;
fflush(f:Int64):Int32 := %fflush...;
fprintf(f:Int64, format:StrChar, ...):Int32 := %fprintf...;

Если нативная функция/переменная требует линковки внешней библиотеки, имя библиотеки указывается атрибутом @[link("имя")@] перед декларацией. Атрибут добавляет флаг -l<имя> к шагу линковки (build.conf LIBS). Существование символа/библиотеки не проверяется — ответственность линковщика. Поддерживается только статическая линковка.

@[link("m")@]
fsqrt(x:Float64):Float64 := %sqrt...;

@[link("z")@]
fcrc(crc:UInt32):UInt32 := %crc32...;

Если нативная декларация/тип требует подключения C++-заголовка, укажите его атрибутом @[include("имя")@] перед объявлением (или мнемоникой @include("имя") без ;). Голое имя → угловой инклуд #include <имя>; аргумент с ведущим "/< — директива как есть. Заголовок эмитится в сгенерированный C++ только вместе с этим объявлением:

@include("cstdlib")
%abort(x:Int32):Void := ...;   # → #include <cstdlib>

Предварительное объявление нативных объектов

Предварительное объявление (forward-declaration) — регистрация нативной функции/переменной, имя которой и есть нативный C-style идентификатор (напр. %sqrt — функция sqrt). Имя и аргументы объявляемой функции совпадают с нативной сигнатурой — никакой адаптации не выполняется. Реализация может быть расположена ниже в текущем файле или во внешней библиотеке — линковщик найдёт символ по имени на этапе сборки.

Правило линковки нативного имени: если оно без :: (напр. %sqrt, %open, %abs) — декларация линкуется как C-символ (extern "C"), что позволяет корректно вызывать функции libc/libm; если имя содержит :: (напр. %std::sqrt) — как C++-символ (extern "C" не добавляется).

Синтаксис такой же, как у создания, но нативное имя стоит слева, а справа — символ многоточия (тела нет). Типы аргументов и возвращаемого значения указываются явно.

    %open(path:StrChar, flags:Int32):Int32 := ...;
    %close(fd:Int32):Int32 := ...;
    %read(fd:Int32, buf:StrChar, cnt:SizeT):SizeT := ...;

    %fd^:Int32 := 0;
    fd = %open('foo.txt', 0);   # вызов нативной функции по имени

Другие нативные типы (статус)

Пользовательские типы Enum/Variant/Tuple описаны в Словарях и наборах.

Нативные шаблоны-типы

Любой нативный C++-шаблон-тип можно объявить в коде TrustLang (регистрация при анализе AST); заголовок C++ подключается on-use при использовании типа. Объявление — префикс типовых параметров

  • нативное C++-имя:
@include("vector")
<T> %std::vector() := ...;    # тип vector<T>, C++-имя std::vector

v: vector<Int32> := [1, 2, 3,];
# → #include <vector>  +  std::vector<int32_t> c_v = std::vector<int32_t>{1, 2, 3};

Типовой аргумент — голое имя Int32 (мягкое предупреждение о сигиле :) или явный тип :Int32/:MyClass/:MyClass<:Int8>. Если C++-имя совпадает со встроенным контейнером (std::vector/std::array от :Array), выдаётся мягкая диагностика, а инстанциация резолвится через встроенный тип. Подробнее — Generics.

Предварительное объявление нативных классов

Нативный C++-класс (не шаблон) можно использовать в коде TrustLang через предварительное объявление по аналогии с forward-объявлением функций: trust-имя класса связывается с нативным C++-именем, а члены-интерфейс (методы, поля, конструкторы, статические члены) описываются в теле { ... }. Тело класса не содержит реализации — каждый член — это forward-объявление (:= ...): класс определён в C++-заголовке, который подключается on-use через атрибут @[include].

@include("string")
String ::= %std::string {          # trust-класс String ↔ C++ std::string
    %size(): UInt64 := ...;        # метод объекта → s.size()
    %empty(): Bool := ...;         # метод объекта → s.empty()
    %c_str(): CString := ...;      # метод объекта → s.c_str()
    %data: CString := ...;         # поле объекта → s.data
};

Синтаксис:

  • String ::= %std::string { ... }; — RHS — ЛЮБОЕ имя; нативное — с ведущим % (C++-имя без %). Доверенное имя класса — слева от ::=.
  • Члены (все — forward, := ...):
    • %Name(...):Ret := ...; — метод объекта → obj.name(...);
    • @::st(...):Ret := ...; — статический метод класса (имя с ::; @:: → ns::Class::) → Cls::st(...);
    • %field:Type := ...; — поле объекта → obj.field;
    • @::static_field:Type := ...; — статическое поле → Cls::static_field;
    • %String(...):String := ...; — конструктор (имя совпадает с классом) → std::string(...).
  • Классификация: статический член — имя содержит :: (задаётся @::name); экземплярный — без ::. Правильная регистрация экземплярного члена — ведущая точка (.name); без неё — диагностика -Wclass-member-dot (по умолчанию ignore; -Wclass-member-dot=warning|error).
  • Доступ к статическому члену: Cls::name (namespace-стиль, без предупреждения) или Cls.name (как к полю) → cppName::name; доступ Cls.name выдаёт -Wstatic-member-as-field (по умолчанию warning; -Wstatic-member-as-field=ignore|error).
  • Атрибут @[include("заголовок")@] (или мнемоника @include("заголовок")) перед объявлением подключает C++-заголовок только при использовании данного типа (on-use).

C++-struct для нативного класса не генерируется — используется существующее C++-имя.

@include("string")
MyStr ::= %std::string {
    %size(): UInt64 := ...;
    %data: CString := ...;   # поле объекта → s.data
};

s: MyStr := MyStr('hello');              # конструктор → std::string("hello")
n: UInt64 := s.%size();                  # метод → (c_s).size()
d: CString := s.%data;                   # поле → (c_s).data
# → #include <string>

Предварительное объявление нативных шаблон-классов

Нативный C++-шаблон-класс объявляется так же, но с типовыми параметрами слева и явной реализацией через инстанциацию %std::pair<T1,T2> справа (основная форма):

@include("utility")
<T1,T2> Pair ::= %std::pair<T1,T2> {    # trust-шаблон Pair ↔ std::pair
    %first(): T1 := ...;                # Pair<A,B>.first
    %second(): T2 := ...;               # Pair<A,B>.second
};

p: Pair<Int32, StrChar> := ...;
# → std::pair<int32_t, std::string> + #include <utility>

Обобщённая форма <T1,T2> Pair ::= <T1,T2> %std::pair { ... } (шаблон привязывается обобщённо, без явного списка аргументов в RHS) — сахар, реализация отложена: при разборе выдаётся диагностика «not implemented»; используйте явную форму %std::pair<T1,T2>. Формат записи одинаков для нативного и не-нативного имени и отличается только наличием/отсутствием %.

Интеграция с C/C++: embed-вставки и обзор (взаимодействие)

TrustLang глубоко интегрирован с экосистемой C/C++: прямые вызовы функций, встраивание C++-кода, использование стандартной библиотеки и вызовы функций TrustLang из C++.

Готовые, запускаемые примеры — в песочнице: нативные функции, нативная линковка.

Импорт нативных функций: @extern / @forward

Мнемонические команды связывают trust-имя с нативным C/C++-символом:

@extern abs(x:Int32):Int32   # abs(x:Int32):Int32 := %abs ...
@forward open(path:StrChar, flags:Int32):Int32
  • @extern — импорт по нативному имени (trust-имя = нативное имя без префикса %).
  • @forward — предварительное объявление (имя указывается первым, тело — многоточие).

Сырая запись: %name(...):T := ...; (forward-декларация) и name(...):T := %native...; (импорт-алиас).

Встраивание C++ кода: блоки {% ... %}

{% for (int i = 0; i < 10; ++i) { printf("%d\n", i); } %}

Нативный синтаксис вставляется в выходной C++ код напрямую.

Атрибуты нативных деклараций

  • @[link("имя")] — добавить -l<имя> к линковке.
  • @[include("header")] — подключить заголовок C++ для нативной декларации/типа. Голое имя (@[include("vector")@]) → угловой инклуд #include <vector>; аргумент с ведущим "/< → директива как есть (#include "my/header.h" / #include <cstdlib>). Заголовок эмитится в сгенерированный C++ только вместе с объявлением (не глобально). Мнемоника @include("name") (без ;, перед объявлением) раскрывается в этот атрибут.
  • @[libstd] — линковать со стандартной библиотекой.
  • @[format("printf", ...)] — проверка аргументов против printf-строки формата.

Пример подключения заголовка нативной функции:

@include("cstdlib")
%abort(x:Int32):Void := ...;   # → #include <cstdlib> + extern "C" void abort(int32_t);

Линковка

Линковка нативной декларации зависит от наличия :: в нативном имени: без :: (%sqrt) — extern "C" (C-символ libc/libm); с :: (%std::sqrt) — C++-линковка без extern "C". Подробнее о генерации C++ — в Архитектуре.

Для модулей на самом TrustLang применяется другой механизм — семантический ABI: тип объекта восстанавливается компилятором языка из приложенного семантического определения, а не из декорированного имени символа. Принцип описан в Семантическом ABI модулей.

8 - Диапазоны, массивы и тензоры

Диапазоны, массивы и (в перспективе) тензоры — контейнерные (коллекционные) типы для работы с последовательностями и многомерными данными.

Диапазоны (:Range)

Диапазон — тип, приблизительный аналог «генератора» в Python: он поочерёдно выдает элементы в заданном интервале с заданным шагом. В тексте диапазон указывается двумя или тремя элементами через две точки: 1..5 — от единицы до пяти с шагом по умолчанию 1; шаг задаётся третьим элементом: 0..10..2. В качестве границ и шага можно использовать не только литералы, но и переменные, и рациональные числа: 0.1..$stop..0.1 — от 0.1 до $stop с шагом 0.1; 0..100:Rational — диапазон рациональных чисел.

Массивы (:Array)

Одномерные массивы поддерживаются литералами [1, 2, 3,] (→ std::vector<Elem>), конструктором :Array(...), доступом по индексу a[i] и методами массива (count, at, first, push_back, …). Переменные с типом массива могут создаваться как по значению, так и как ссылочные.

Оставшиеся позиции массива можно дозаполнить оператором ... expr ... (последним элементом) — размер берётся из размерного типа-цели: v:Int32[10] := [2, 3, ... 42 ...,]; (см. Создание значений: заполнение тензоров).

Тензоры (:Tensor)

Тензоры — многомерные массивы (на базе LibTorch). В текущей версии многомерные массивы и полноценные тензоры не реализованы (см. Статус) — реализован одномерный :Array и тип :Range.

Индексация

Доступ к элементам массива выполняется по целочисленному индексу, начиная с 0:

a := [10, 20, 30,];
x := a[0];   # 10

Отрицательные индексы (как в Python) не поддерживаются: обращение a[-1] вызывает рантайм-исключение. Диапазоны в индексе (a[1..3]), значения :None и многоточие ... в индексе также пока не реализованы.

Перебор коллекций

Перебор элементов массива, диапазона или словаря выполняется циклом @while(коллекция) с деструктуризацией текущего элемента (готовый пример — в песочнице; подробнее — Циклы).

Стандартная библиотека предоставляет тип-итератор Iterator<T> — класс, помеченный @[borrowed]. Он отображается на C++ trust::AnyIterator<T> (устранённый единый курсор) и доступен без явного импорта (загружается prelude; отключается --no-stdlib). Любая переменная типа Iterator<T> автоматически зависима от исходного объекта: использование после мутации источника — диагностика -Wborrowed (см. Контроль инвалидации ссылок). Атрибут наследуется производными типами (Iterator<Int32> и др.).
