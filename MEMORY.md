## Architecture

TrustLang — транспилятор высокоуровневого языка в C++. Архитектура — в `MEMORY.md` компонентов
(`include/<c>/MEMORY.md` — публичный API и правила; internal-подкаталоги — детали реализации); это
единственный источник истины о компонентах и ловушках. Пользовательская документация — `docs/content/ru`
(первоисточник), `en` — синхронный перевод.

Отладочная диагностика: `TRUST_DEBUG`/`TRUST_SCOPE` (C++) и `@__DEBUG__`/`@__DEBUG_SCOPE__` (`.src`) под
гейтом `TRUST_ENABLE_TRACE`; при 0 C++-макросы вырезаны, `.src` дают `Warning` без вывода.

## Facts and invariants

- **⚠ Видимость на сайте импорта — одно правило:** `types/site_visibility.hpp` решает «видно ли имя с сайта
  и под каким ключом»; `SymbolTable` применяет решение, `module_loader` даёт данные сайта. `_::` без доступа
  группы — невидимо (в т.ч. на сайте, первым запустившем анализ тела модуля).
- **Переполнение целых — по умолчанию вкл** (`-foverflow-check`): знаковые `+ - *`/`+= -= *=` →
  `throw trust::IntMinus`; классификацию решает `semantic` (`Binary::m_overflowCheck`), кодоген только
  читает. `//`/`%` проверяются ВСЕГДА (деление на ноль, `INT_MIN / -1`).
- **Временные переменные создаёт ТОЛЬКО анализатор** (lowering) как реальные `const VarDecl` в AST.
- **LIT-подкаталоги не перечисляются вручную:** выводятся из реальных `.src`/`.ast` через GLOB_RECURSE
  CONFIGURE_DEPENDS.
- **Опции CLI (GCC/Clang-стиль):** диагностики `ignore|warning|error`/`-W<name>=<sev>`, поведение
  `--<name>/-f<name>`, solver — `-Wsolver=`+`--solver-mode`; определены один раз (`commonAnalysisOptions`)
  и применяются центрально (`applyAnalysisArgs`) в CLI и LSP.
- **Встроенный тип — предобъявление, реализация отдельно** (`=` определение, `::=` новый тип, для встроенного
  имени запрещён); модель — `types`, реализации — `stdlib/core`, рантайм — `runtime`, ресурсы — `package`.
  Реализации builtin и библиотечные классы грузятся ЯВНО зонтичным `\std();` (модуль `std.src`: тело грузит
  `builtin/*.src`, интерфейс реэкспортирует `iterator`/`async`); prelude-автозагрузки нет, `--stdlib` — только
  корень ПОИСКА модулей (`--no-stdlib` убирает). Заголовки реализации — `@stdlib/builtin/*.hpp` (близко к array.hpp);
  **одна реализация на builtin-TypeId** (дубль — семантическая ошибка), provider-gate — в Pipeline до HIR.
- **Сравнение типов `<~`/`~~`/`~~~` — статическая свёртка в `Bool`** (номинальная/утиная/строгая); динамической
  проверки и имени типа из строки НЕТ; голая `~` — не оператор.
- **Generic/native-import:** `<T> f(...)` → C++ `template` `c_f<...>(...)`; `<T> run(...) := %native;` — алиас
  без эмиссии. Type-packs `<T...>` — только trailing; встроенных C++ FFI-синонимов нет (`Tuple<...>` — ошибка).
- **`:Tensor` — предобъявлен (`types`), реализация `tensor.trust`;** без `with-torch` — диагностика до линковки.
- **HIR — печатная форма (вход бэкендов), MIR — analysis/verification IR:** семантика материализует факты,
  `buildHir` их клонирует (codegen/solver не резолвят повторно).
- **⚠ Модуль вне C++-ABI и вне разрешения имён:** идентичность КОМПИЛЯТОРА хранит модуль
  (`\a::f`/`\b::f` различимы), но C++-символ модуль НЕ содержит (автоматический `<enc>`-namespace
  снят). **`\path::name` удалён ПОЛНОСТЬЮ** (значение/тип/цель алиаса/using; грамматика его не
  принимает): единственный механизм ввода имён — импорт `\path(...)` + области имён. Namespace- и
  module-алиасы и module-цель `using` удалены. Изоляция одноимённых экспортов — области имён
  программиста (`ns::`); коллизия одноимённых ОПРЕДЕЛЕНИЙ разных модулей диагностируется до линкера.
  `<enc>` — только имя заголовка `<enc>.hpp` и база entry `<enc>__main__`. C++-имя — единый ОБРАТИМЫЙ
  кодек (`utils::encodeIdent`/`decodeIdent`: identity для ASCII, `_u_`-маркер иначе).
- **⚠ Префиксы путей — тип первого компонента:** `\file` — файл корня, `\\module\...` — модуль-каталог,
  `\\\pkg\...` — пакет; позиционной семантики нет.

## Decisions

- **Раскладка компонента: корень — только публичный API.** Детали — в internal-подкаталогах
  (`cmake/internal_dirs.cmake`); структурные гейты среды сборки: `internal_boundary_guard`, `public_api_guard`,
  `subdir_layout_guard`, `component_deps_guard` (AGENTS.md §16).
- **Пакеты/`.deb`/VSIX — только в `Release`;** provider-пакеты — отдельные `.trust` в `share/trust`,
  линковка demand-driven.
- **Версия по режиму сборки:** `TRUST_VERSION` = SHORT (release) / FULL (dev); release — только ветка
  `release/*` + строгий annotated-тэг `v<X.Y.Z>` и чистое дерево (артефакты из чистого дерева).
- **TrustLang не владеет оптимизацией:** единственное изменение формы — lowering; safety-проверки обязаны
  сохраняться — проверка сборкой и исполнением артефакта на `-O2/-O3` (R52).
- **Целевая модель включает LLVM-бэкенд:** делегирование ABI/layout/mangling привязано к целевому контракту
  бэкенда (C++ ABI либо ABI целевой платформы); целевые факты в языковую модель не попадают
  (`ARCHITECTURE.md` R4/R37/E20).
- **Конвейер — данные, не `if`:** фазы — декларативная таблица `PIPELINE_PHASE_LIST`; бэкенды —
  `BACKEND_STAGE_LIST`.
- **Доказательства — слой `verify`:** модель обязательств/`*.trustcert` принадлежат `verify`, решатель —
  сменный `ProofBackend`; Envelope ≠ доказано.
- **⚠ Один владелец факта — единственный путь вычисления (обязательное требование архитектуры, R1–R51):**
  у факта — одно хранимое представление и один именованный аксессор владельца; второе хранилище и ordinal
  coupling запрещены; идентичность — детерминированный id владельца представления; делегированный факт
  (C++ ABI/layout/mangling) не моделируется (только предикат и проверка); проверка — в точке записи, не в
  пост-проходе по корню. Полный перечень требований — `ARCHITECTURE.md` (§3).
- **Архитектура ≠ семантика:** предметная семантика языка (займы/инвалидация, контракты) и инженерные
  политики (лимиты/fuzz/OOM) в `ARCHITECTURE.md` не входят — там только владелец фактов, уровни и границы
  (§0/§6). Требование включается только по критерию необходимости (a)–(e) §0; формальные метрики (размер
  файла, число пунктов документации) проверкой не являются — проверки такого рода в сборку не вводятся
  (AGENTS.md §15).
- **Сборка ≠ проверки (AGENTS.md §16):** система сборки содержит только проверки среды сборки (раскладка,
  зависимости компонент, публичный API); проверки архитектурных требований выполняются исключительно тестами,
  поиск маркеров/подстрок критерием не является.
