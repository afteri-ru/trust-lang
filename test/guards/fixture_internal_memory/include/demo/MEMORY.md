## Architecture

Корень фикстуры `internal_memory_guard`. Компонент `demo` существует только как тестовые данные
для CTest-гейта и не собирается: у него нет библиотечной цели (`NO_LIB`), а файлы реализации
служат лишь для подсчёта порога «малой реализации» (не более трёх файлов суммарным размером
не более 16 KiB).

Правило разделения памяти: корневой файл описывает только публичный интерфейс и общие правила
компонента, а детали реализации каждой зоны живут в её собственном `MEMORY.md`. Если зона мала,
отдельный файл памяти не создаётся — трудно-выводимые инварианты фиксируются WHY-комментариями
непосредственно в исходниках.

## Зоны

- `small/` — малая реализация без файла памяти: допустимый случай, нарушения быть не должно.
- `big/` — большая реализация без файла памяти: обязательный MEMORY.md отсутствует, это нарушение.
- `terse/` — файл памяти существует, но его размер ниже нижнего порога полезности (1000 байт),
  поэтому гейт обязан сообщить о нарушении и потребовать переноса знаний в код или README.md.

## Relations

Фикстура регистрируется как `internal_memory_guard_selftest` (свойство `WILL_FAIL`) в корневом
`CMakeLists.txt` через `trust_add_guard(... FIXTURE ...)`; положительный прогон гейта выполняется
на реальном дереве проекта.
