## Architecture

Чистый слой атрибутов: value-тип `AttrId` + дескриптор `Attr` + реестр `AttrPool` — единственная точка
регистрации. Отдельного `AttrType`-enum НЕТ: встроенные и пользовательские атрибуты идентифицируются
по имени. Разбор `@[...]` (`ast::parse_attr`) только ИЩЕТ атрибут в пуле и регистрацию не выполняет —
иначе возник бы цикл `attrs ⇄ diag`. Детали реализации — `attrs/README.md`.

## Facts and invariants

- **⚠ `AttrId` — битовая маска, не индекс:** bits 0–23 — индекс в пуле, bits 24–31 — флаги обработки
  (builtin/analyzer/codegen/manual; 27–30 reserved). Атрибут без analyzer- и codegen-флага —
  «необработанный»: `-Wunhandled-attr` при любом использовании в AST; `-Wunknown-attributes` —
  незарегистрированное имя в `@[...]`.
- **Признак built-in выводится из `MapperRange` регистрации** (валидный диапазон = пользовательский),
  отдельного bool-поля нет. Регистрация уникальна по имени: повтор возвращает существующий `AttrId`.
- `manual`-бит ставится при ПРИВЯЗКЕ атрибута к узлу, не при регистрации.
- Дескриптор хранит параметры как `string_view` в SourceMapper: владение текстом не копируется.
- **⚠ Аргументы читаются ТОЛЬКО через `attr_args.hpp`:** `firstAttrArg` (`nullptr` при отсутствии
  атрибута/аргументов/пустом первом) и `includeDirective` — единственное место формы `#include`
  (пустой заголовок — `EXPECT`, молчаливой пустой директивы нет). Функции шаблонны по узлу, поэтому
  `attrs` не зависит от `ast`.

## Relations

- Разбор `@[...]` → `AttrId` и привязка к узлам — `ast`; владелец `AttrPool` — `Context` (`session`).
