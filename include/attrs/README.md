# Attrs - система атрибутов

## Назначение

Чистый слой атрибутов TrustLang: идентификаторы (`AttrId`), дескрипторы (`Attr`), реестр (`AttrPool`)
и канонические имена встроенных атрибутов (`attr::*`). Не зависит от AST; используется `ast`
(привязка атрибутов к узлам), `types` (атрибуты на типе) и `diag::Context` (владение пулом).

## Особенности реализации

- **`AttrId`** (`uint32_t`) - битовая маска: bits 0-23 - индекс в `AttrPool`; bits 24-31 - флаги
  обработки (builtin/analyzer/codegen/manual). Атрибут без analyzer/codegen - «необработанный»
  (`-Wunhandled-attr`).
- **Нет `AttrType`-enum** - встроенные и пользовательские атрибуты хранятся единообразно и
  идентифицируются по имени. Имя уникально: повторная регистрация возвращает существующий `AttrId`.
- **`AttrPool`** - единственная точка регистрации/поиска (без `AttrPoolView`); built-in
  регистрируются конструктором (`registerBuiltinAttrs`).
- **Признак built-in выводится из `MapperRange`** регистрации: валидный диапазон = пользовательский,
  невалидный = встроенный.
- **Разбор `@[...]`** - `attr_parser` (в `ast`): `parse_attr` только ищет атрибут в пуле, выдаёт
  диагностику для неизвестного имени/несовпадения параметров; регистрация выполняется отдельно
  (`register_attr`/`register_builtin_attr`).
