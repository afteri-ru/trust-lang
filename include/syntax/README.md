# Syntax - Лексический и синтаксический анализ

## Назначение

Преобразует исходный текст программы в синтаксическое дерево `Term` - универсальный узел, из которого компонент `pipeline` через конвертацию строит AST. Объединяет лексический анализ (Flex), макропроцессинг и синтаксический анализ (Bison).

## Особенности реализации

- **Конвейер** - `Scanner (lexer.l) → Macro → Parser (parser.y) → Term`. Раскрытие макросов встроено в поток парсера (`Parser::GetNextToken`), а не является отдельной стадией: лексер подаёт термины в буфер, после чего `Macro` раскрывает их до передачи в грамматику.
- **Term / TermID** - универсальный узел; `TermID` из единого X-макроса `TERMS` (все TermID, нереализованные - с `Kind=Unimplemented`) + `SYMBOL_TOKENS` (символьные терминалы). Секция `%token` в `parser.y` генерируется из этих макросов на этапе configure.
- **Документирующие комментарии** - токен `DOCUMENT` сохраняет полный текст (включая маркеры `/**`, `///`, `##`); хвостовой вариант `///<` / `##<` - отдельный токен `DOCUMENT_INLINE` (Term остаётся `TermID::DOCUMENT`). Оба в AST конвертируются в leaf-узел `Document`.
- **Унифицированное представление** - все последовательности (верхний уровень модуля и вложенные `{ ... }`-блоки) строятся из единого нетерминала `expression` и хранятся в едином поле `Term::m_sequence` (`SequenceType`).
- **Создание терминов** - `Term::Create` имеет две перегрузки: копирующую (`std::string`) для ручного создания и view-перегрузку (`const char*, len` → `std::string_view`) для лексера, где текст живёт в `SourceMapper`.
- **Грамматика** - без reduce/reduce и без shift/reduce-конфликтов (`%expect 0`).
