## Architecture

Bison-грамматика и `Parser`: сборка Term-дерева, восстановление после ошибок, прагмы/предопределённые
макросы в `GetNextToken`. Входы грамматики — `syntax/grammar/`.

## Facts and invariants

- **Семантические ошибки разбора → `Severity::Error`, НЕ Fatal:** пайплайн (в LSP) продолжает на частичном
  AST. Fatal/throw — только ошибки безопасности.
- **⚠ Восстановление после синтаксической ошибки — на границах ОПЕРАТОРА и ЧЛЕНА КЛАССА:** `sequence: error` /
  `class_props: error` дают ПУСТУЮ `SEQUENCE` с диапазоном ошибки; накопленные операторы сохраняются.
  `yyerrok` НЕ вызывается; `sequence separator error` несовместима (S/R на `error`). Лимит ошибок — у
  `DiagnosticEngine`, `Parser` счётчик не ведёт; после лимита `YYABORT`.
- **⚠ Ловушка позиции ошибки:** брать из `Parser::m_recent`, а НЕ `tokenStartOffset()`/`m_current_pos`:
  `GetNextToken` упреждающе буферизует термины, курсор «убежал» вперёд.
- **Унифицированная последовательность:** верхний уровень и вложенные блоки — из единого нетерминала;
  `AppendBlock` сохраняет границу области видимости (иначе объявления «протекают» в охватывающий скоуп).
- **⚠ `class_props` — СОБСТВЕННЫЙ SEQUENCE-контейнер, НЕ связь через `m_right`:** `m_right` члена — его
  RHS/тело; связывать список членов через `m_right` нельзя (рвало тела методов/инициализаторы).
- **⚠ Forward-объявление класса:** `ELLIPSIS` — маркер в `m_sequence`; `native_class_fwd` — RHS любое имя
  (native с `%`). Dot-члены — dedicated `class_member` (ведущая '.' — экземплярный член), не общий
  `assign_lval`.
- **⚠ `tmpl_ctor` — явная конструкция шаблон-типа в позиции значения** (`:Box<Int32>(...)`): отдельное
  правило даёт РОВНО один дополнительный S/R на `type_class • LT`. Затрагивает только `:`-формы.
- **⚠ Лямбда: `LAMBDA`/`LAMBDA_CALL` — НЕ токены:** захваты в `m_sequence` (НЕ в `m_args` — туда позже пишутся
  параметры), параметры — `m_args`, тело — `m_right`. Форма `lambda(args)` грамматикой принимается ради явной
  диагностики.
- **`FILLING` — Kind `Filling` (класс `Sequence`);** правило `arg` общее для всех `args`.
- **Оператор-объявление — функция с СИСТЕМНЫМ именем** (`__eq__`, `__getitem__`); отдельного операторного
  нетерминала нет. `REFLECTION` — только embed-выражения. Контракты едины для функций/методов/операторов.
- **⚠ Операторы сравнения типов:** `<~` — ОТДЕЛЬНЫЙ лексерный токен (обходит ловушку `:T<...` =
  шаблон-аргументы); `~~`/`~~~` — `OPERATOR_DUCK`. `~` больше нигде не существует (`TILDE` — только
  деструктор).
- **⚠ Наборы типов (`:A + :B`) — без новых конфликтов:** `type_set_expr: types | … PLUS types | … MINUS
  types`; RHS `::=` и inline `:(:A + :B)`. Ведущий `:` перед `(` ОБЯЗАТЕЛЕН (иначе конфликт с вызовом/словарём).
  Guard «`m_id = TYPE`» ОБЯЗАН исключать `TYPE_SET`.
- **⚠ `%expect 4` не «подгоняется»:** конфликты 1-4 задокументированы в шапке `parser.y.in`;
  `type_item` vs `type_item_tmpl` — намеренный «инвертированный» шаблон: в операнд-позиции `<` обязан
  оставаться сравнением (`1:Bool < var`). Конфликт 4 (`native • LT`) — shift в аргументы шаблона
  реализации (`Complex32 = %std::complex<float> { };`); reduce (сравнение нативного имени) не используется.
- **⚠ Границы унификации «аргументы vs шаблон»:** голое имя в `<>` — ТИП-аргумент, в `()` — ЗНАЧЕНИЕ; `args` и
  `template_args` не сводимы в один нетерминал без запрета голых выражений-аргументов.
