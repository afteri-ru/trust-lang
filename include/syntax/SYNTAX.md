# SYNTAX - Правила синтаксиса управляющих конструкций

В этом файле зафиксированы синтаксические правила условных операторов, циклов,
операторов прерывания (break/continue/return/throw) и оператора сопоставления
(match), а также их транспиляция в C++.

> Правила токенизации операторов (`-->`, `<->`, `==>`, `++`, `--`, `-+`, `+-`) -
> в `include/syntax/lexer.l`. Правила грамматики - в `include/syntax/parser.y`.
> Расположение узлов в полях объектов и детали реализации - в `MEMORY.md`.

## 1. Условный оператор (`if` / `else-if` / `else`)

Оператор `-->` (токен `FOLLOW`).

```text
[ условие ] --> тело
[ условие1 ] --> тело1 , [ условие2 ] --> тело2 , ... , [ ... ] --> тело_else
```

- `[ ... ] --> тело` - ветка `if` (первая) или `else-if` (последующие через `,`).
- `, [ ... ] --> тело` - ветка `else` (пустые скобки `[...]` - метка «иначе»).

Пример:
```python
[x > 0] --> { a := 1; }, [x < 0] --> { b := -1; }, [...] --> { c := 0; };
```

Транспиляция в C++:
```cpp
if ((x > 0)) { std::any a = 1; } else if ((x < 0)) { std::any b = -1; } else { std::any c = 0; }
```

## 2. Циклы (`while` / `do-while` / `while-else`)

Оператор `<->` (токен `REPEAT`).

```text
[ условие ] <-> тело                # while
[ условие ] <-> тело , [ ... ] --> тело_else   # while-else
тело <-> [ условие ]                # do-while
```

Пример:
```python
[z < 10] <-> { z := z + 1; };                 # while
[z < 10] <-> { z := z + 1; }, [...] --> { z := -1; };  # while-else
{ z := z - 1; } <-> [z > 0];                  # do-while
```

Транспиляция в C++:
```cpp
_tl1_continue: while ((z < 10)) { std::any z = (z + 1); } _tl1_break:;
_tl2_continue: do { std::any z = (z - 1); } while ((z > 0)); _tl2_break:;
```

## 3. Операторы прерывания: break / continue / return / throw

Все операторы прерывания - «интеррапты»: `exit_part` в грамматике
(`interrupt | interrupt значение interrupt`). Одиночный оператор - прерывание
без значения; оператор с обрамляющим значением - прерывание со значением.

| Оператор | Токен | Синтаксис | Транспиляция |
|---|---|---|---|
| **break** | `INT_PLUS` (`++`) | `++` (безымянный) | `break;` |
| **break** (именованный) | `INT_PLUS` | `имя :: ++` | `goto <имя>_break;` |
| **continue** | `INT_REPEAT` (`-+` / `+-`) | `-+` (или `+-`) | `continue;` |
| **continue** (именованный) | `INT_REPEAT` | `имя :: -+` | `goto <имя>_continue;` |
| **return** | `INT_PLUS` (`++`) | `++ значение ++` | `return значение;` |
| **return void** | `INT_PLUS` | `++ _ ++` | `return;` |
| **throw** | `INT_MINUS` (`--`) | `-- значение --` | `throw значение;` |

> **goto - только для именованных прерываний.** Безымянные break/continue транслируются в обычные
> C++ `break;`/`continue;` (передают управление ближайшему циклу). `goto` используется только для
> именованных break/continue (передача управления между вложенными блоками/циклами).

> **Функция - top-level именованный блок.** Имя функции является меткой блока всей функции:
> `return значение` внутри `func_name` эквивалентен `func_name:: ++ значение ++` (оба → `return значение;`),
> а именованный break на имя функции `func_name:: ++` → `return;` (void-возврат из функции).
> Void-return записывается как `++ _ ++` (служебный символ `_` - зарезервированное значение void);
> транслируется в `func_name:: ++` (без `_`) → `return;`.

> **Расположение continue-метки.** Для именованного блока `имя:: { ... }` continue-метка
> `<имя>_continue` ставится первым циклом в теле блока - ПЕРЕД циклом (после инициализации блока),
> чтобы `goto <имя>_continue` просто переоценивал условие цикла, не повторяя инициализацию.


Перед break/continue (и return/throw) может быть опционально указано имя блока
(префикс области/метки):

```text
имя :: ++          # break из именованного блока/цикла
имя :: -+          # continue к началу именованного цикла
имя :: ++ значение ++   # return с меткой
```

Пример:
```python
[z < 10] <-> { ++; -+; };   # break и continue внутри цикла
%f():Int32 ::= { ++ 42 ++; };   # return 42
%g():None ::= { ++ _ ++; };     # return void
```

Транспиляция (goto по меткам начала/выхода цикла):
```cpp
_tl1_continue: while ((z < 10)) { goto _tl1_break; goto _tl1_continue; } _tl1_break:;
int32_t f() { return 42; }
void g() { return; }
```

> Различение break и return: одиночный `++` (без второго `++`) - это **break**;
> `++ значение ++` (два оператора `++`) - это **return**. Void-return записывается
> явно как `++ _ ++` (служебный символ `_`), а не одиночным `++`.

## 4. Оператор сопоставления (`match`)

Оператор `==>` (токен `MATCHING`).

```text
[ значение ] ==> {
    [ шаблон1 ] --> тело;
    [ шаблон1, шаблон2 ] --> тело;   # несколько шаблонов - логическое ИЛИ
    ...
    [ ... ] --> тело_по_умолчанию;   # else
};
```

Пример:
```python
[x] ==> {
    [1] --> { y := 1; };
    [2, 3] --> { y := 2; };
    [...] --> { y := 0; };
};
```

Транспиляция в C++: значение предварительно вычисляется во временную переменную,
затем последовательно сравнивается с шаблонами через связанные `if / else-if / else`:
```cpp
auto _match1 = x;
if (_match1 == 1) { std::any y = 1; }
else if (_match1 == 2 || _match1 == 3) { std::any y = 2; }
else { std::any y = 0; }
```

## 5. Единое правило раскладки управляющих конструкций

`FOLLOW` (`if`), `WHILE`, `DOWHILE` и `MATCHING` (`match`) используют одинаковые
роли полей терма синтаксического дерева:

| Поле | Роль |
|---|---|
| `m_left` | условие (или значение для match) |
| `m_right` | `else` (для if/while) / match_body (для match) |
| `m_sequence` | тело в `[0]`; для `elseif` - branch-термы с `[1..]` |

Детали размещения узлов и транспиляции - в `MEMORY.md`.

## 6. Блоки и области видимости

Последовательность операторов может быть оформлена как **одно единое выражение**
заключением в фигурные скобки `{ ... }`. Различаются следующие виды блоков (по метке
перед открывающей `{`):

### 6.1. Безымянный блок кода - `{ ... }`

Блок без метки: группировка операторов в одно выражение. **Разрешён ТОЛЬКО внутри тела
функции/класса**; на верхнем уровне модуля - невалиден (диагностика).

```rust
%f():None := {
    { x:Int32 := 1; y:Int32 := 2; };
};
```
```cpp
void f() {
    {
        int32_t x = 1;
        int32_t y = 2;
    }
}
```

### 6.2. Именованный блок-метка - `name { ... }`

Перед `{` стоит **одно имя (идентификатор) БЕЗ `::`**. Используется только внутри функций
как метка блока для передачи управления (break/continue/goto). Вне функции - невалиден.
Метки `name_break:`/`name_continue:` добавляет lowering.

### 6.3. Область имён - `ns:: { ... }` (с `::`)

Перед `{` используется `::` (отдельно или как разделитель между именами). Это **определение
области имён**. Разрешена только начиная с верхнего уровня модуля; области имён могут
вкладываться друг в друга, но **не могут быть внутри функций/классов**. Экспортируются как
обычно (квалифицированно).

```rust
ns:: { x:Int32 := 1; };
```
```cpp
namespace ns {
    int32_t x = 1;
}
```

Вложенные области имён:
```rust
ns:: { sub:: { y:Int32 := 2; }; };
```
```cpp
namespace ns {
    namespace sub {
        int32_t y = 2;
    }
}
```

### 6.4. Глобальная область - `:: { ... }`

Обращения внутри - к глобальным именам (например `::func`). Эмитится без namespace-обёртки
(содержимое - на глобальном уровне).

```rust
:: { x:Int32 := 1; };
```
```cpp
int32_t x = 1;
```

### 6.5. Анонимная область имён - `_ { ... }`

Перед `{` стоит `_`. Подавляет экспорт глобальных имён и функций из **всех** областей имён
внутри неё (может включать вложенные области имён). Эмитится как анонимный C++ namespace.

```rust
_ { x:Int32 := 1; };
```
```cpp
namespace {
    int32_t x = 1;
}
```

### 6.6. Экспорт

Из модуля экспортируются **все top-level объявления/определения** (переменные, функции, типы),
расположенные на верхнем уровне модуля в **не анонимной области имён** (глобальная `::` и
именованные `ns::`; для `ns::` - с квалификацией, например `ns::x`). Из анонимной области `_` и
из локальных (внутри функций и блоков кода) - не экспортируются.

**Фильтр интерфейса при импорте.** Аргументы оператора загрузки `\module(mod, masks)` - список
масок (glob: `*` - любая последовательность, `?` - один символ; перечисление через запятую = OR),
применяемых к экспортируемым именам модуля. На сайте импорта в генерируемый C++ попадают **только**
подходящие под маски экспорты (forward-объявления), а не полное тело модуля. Без аргументов
(`\module(mod)`) импортируются все экспорты. Пример: `\module(utils, calc*, db*)` импортирует
только имена, начинающиеся с `calc` или `db`.

| Метка перед `{` | Вид | Допустимый контекст | C++ |
|---|---|---|---|
| *(нет)* | безымянный блок кода | только внутри функции/класса | `{ ... }` |
| `name` (без `::`) | именованный блок-метка | только внутри функции | `{ ... }` + `name_break:`/`name_continue:` |
| `ns::` | область имён | верхний уровень модуля (вложенность ок) | `namespace ns { ... }` |
| `::` | глобальная область | верхний уровень | содержимое без обёртки |
| `_` | анонимная область имён | верхний уровень модуля | `namespace { ... }` |

### 6.7. Сравнение блоков Trust и C++

| Trust | C++ | Соответствие / отличие |
|---|---|---|
| безымянный блок кода `{ ... }` (внутри функции) | compound statement `{ ... }` | Скоуп и «не протекает наружу» совпадают. Отличие: в Trust блок - **выражение** (грамматика `Expression := ... | '{' Sequence '}'`), в C++ это **statement**, не выражение (у `{ ... }` нет значения). |
| именованная метка `label { ... }` + `label ++` / `label -+` | метки `label:` + `goto`; `break`/`continue` только по ближайшему циклу/switch | В C++ **нет** именованного break/continue из произвольного блока. Trust эмулирует их синтетическими метками `label_break:`/`label_continue:` + `goto` (текущий компилятор clang++-22 не поддерживает нативный C++26 `break label;`/`continue label;`). |
| область имён `ns:: { ... }` | `namespace ns { ... }` | Область видимости, вложенность, запрет внутри функций - совпадают. Отличие: в C++ `::` - оператор доступа к члену, а не маркер блока; вложенные имена `ns::sub:: { ... }` (эмитятся как `namespace ns::sub { }`) требуют C++17. |
| глобальная область `:: { ... }` | унарный `::` (обращение к глобальному) | Идея «глобального» совпадает, но в C++ `::` - **оператор**, а не блок-обёртка; «глобальная область внутри функции» в C++ невыразима. |
| анонимная область имён `_ { ... }` | `namespace { ... }` (anonymous namespace) | Совпадает (internal linkage ⇒ не экспортируется из единицы трансляции). Отличие: в C++ `_` - обычный **идентификатор** (`namespace _ { }` - именованное, внешнее), а в Trust `_` всегда скрытая область. |

**Противоречия модели Trust ↔ C++ (общие):**

1. **Блок = выражение vs statement** - Trust трактует `{ ... }` как выражение, C++ - как statement без значения.
2. **Именованный break/continue** - в C++ (до C++26) отсутствуют; эмулируются ручными goto-метками.
3. **`::` - блок vs оператор** - одинаковый синтаксис имеет разные роли: в Trust это метка глобальной области, в C++ - оператор разрешения области.
4. **`_` - скрытая область vs идентификатор** - в C++ `_` обычное имя, в Trust - всегда анонимная область имён.
5. **Глобальная область внутри функции** - заявленная возможность Trust невыразима в C++ (нельзя объявить глобальные имена изнутри функции).

## 7. Ссылочные типы данных

Ссылочные типы выражают владение временем жизни объекта и доступ к нему (двухосевая модель,
см. `types/REFType.md`). Вид ссылки кодируется в `TypeKind` (`RefType`) и задаётся ЛИБО атрибутом
`@[reftype("...")]`, ЛИБО символическим сиглам. **Позиция определяет смысл символа:**

### 7.1. Слева от `:=`/`=` - вид ссылки переменной

**Терминология:** `&&`/`&*`/`&?` - это **маркеры/операторы ссылки**, а НЕ «сиглы» (сигл - первый
символ ИМЕНИ: `$`, `%`, `@`, `:` и т.п.; ссылка частью имени не является). Каждый маркер начинается
с `&`; второй символ задаёт вид: `&&`=shared, `&*`=unique, `&?`=weak. Одиночные `&`/`*` в позиции
объявления НЕ используются (в выражениях это операторы address-of/разыменования).

Вид ссылки задаётся маркером ПЕРЕД именем переменной; при явной аннотации типа она обязана быть
**согласована** - тип тоже должен нести тот же маркер (`&& x : && Int32`), либо тип опускается
(авто-вывод pointee из инициализатора).

| Декларация | Вид | C++-тип |
|------------|-----|---------|
| `&& x : && Int32` (маркер у имени и у типа, согласованы) | shared | `trust::Shared<int32_t>` |
| `&& x := 5` (маркер, без типа - авто-вывод pointee) | shared | `trust::Shared<...>` |
| `&& x := 5:Int32` (маркер, тип через аннотацию литерала) | shared | `trust::Shared<int32_t>` |
| `&* u : &* Int32` / `&* u := 10` | unique | `std::unique_ptr<int32_t>` |
| `&? w : &? Int32 := & x` / `&? w := & x` | weak | `trust::Weak<trust::Shared<int32_t>>` |
| `x : Int32` | value | `int32_t` |

**Несогласованные формы - ошибка** (маркер обязан быть и у переменной, и у типа, либо типа нет):
- `x : &&Int32` - маркер только у типа, переменная не объявлена ссылочной → ошибка;
- `&& x : Int32` - маркер у переменной, но аннотация типа - обычное значение → ошибка;
- `&& x : &* Int32` - маркеры у переменной и у типа РАЗНЫЕ → ошибка `reference kind mismatch`.

Маркер ПЕРЕД именем переменной превращается в атрибут `@[reftype("...")]` на объявлении (терм
`ptr lval` / `take lval`, разворачивается в term_to_ast); маркер перед именем типа - в
`RefMakeExpr`/`RefTakeExpr` (резолвится `resolveType`). Без явного типа pointee выводится из
инициализатора (авто-дедукция).

Вид ссылки из значения нельзя получить: `&? z := & y` для `y : Int32` (value) - ошибка.

```trust
&& x : && Int32 := 5;   # trust::Shared<int32_t> c_x(5)
&& x := 5:Int32;        # то же (авто-вывод, аннотация литерала)
&* u := 10:Int32;       # std::unique_ptr<int32_t> c_u = std::make_unique<int32_t>(10)
&? w := & x;            # trust::Weak<trust::Shared<int32_t>> (weak из shared)
```
Запись одиночными маркерами `&`/`*` в позиции объявления ссылки недопустима (shared → `&&`,
unique → `&*`); одиночные `&`/`*` остаются только операторами в выражениях (см. 7.2).

### 7.2. Справа/в выражении - взятие ссылки и доступ к значению

| Оператор | Смысл |
|----------|-------|
| `& expr` | Взятие ссылки (address-of/borrow). Допустимо ТОЛЬКО для переменной, объявленной как ссылочная; **weak получается ТОЛЬКО из shared** (`& shared_var`). `&` от unique или не-ссылки - ошибка. |
| `* expr` | Доступ к ДАННЫМ ссылочного операнда (семантика `std::reference_wrapper<T>::get()` - ссылка на данные). Для shared/weak - через локер (`*(ref.lock())`, lock() бросает на истёкшей); для unique/ptr - `trust::checked_deref(c_u.get())` (БЕЗ UB на `nullptr`). `*` от value - ошибка. |
| `a :=: b` | Swap - интринсик обмена (`std::swap(a, b)`), возвращает `&a`; типы должны быть совместимы (не обязательно ссылки). Обмен САМИХ ссылок РАЗНЫХ видов (`a :=: b` для unique и shared) - ошибка; обмен ЗНАЧЕНИЙ между любыми ссылками - `*a :=: *b` (std::swap данных). |
| `var :=: _` | Перемещение значения в discard (`std::move(var)`). |

```trust
@main() := {
    && x := 5;
    w := & x;             # слабая ссылка из shared (address-of)
    print('{}', *w);      # доступ к данным (для weak - через lock)
    *x = 9;               # мутация через shared
    && a := 1:Int32;
    && b := 2:Int32;
    a :=: b;              # swap ссылок (std::swap)
    *a :=: *b;            # swap значений внутри ссылок (std::swap данных)
    p : Int32 := 1;
    q : Int32 := 2;
    p :=: q;              # swap значений (std::swap)
    p :=: _;              # перемещение в discard (std::move)
}
```

### 7.3. Контракт value-vs-reference (диагностика)

- Арифметика/сравнение над ссылками - **ошибка** (в языке отсутствует класс ссылочной арифметики;
  сырые указатели - только для интеграции с C++). Диагностика + fixit `*<name>`.
- Копирование ссылки в **значение** (`z : Int32 := x`, где `x` - ссылка) - **ошибка** + fixit
  `*x`.
- **Weak из unique** - ошибка (разные оси владения shared/weak ↔ unique).
- Взятие `&` от не-ссылочной переменной - ошибка; weak - только из shared.
- `:=:` требует совместимых типов операндов.
