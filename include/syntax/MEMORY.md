## Architecture

Синтаксический анализ: Scanner (Flex, lexer.l) → Macro → Parser (Bison) → `Term`-дерево.
Раскрытие макросов — не отдельная стадия: лексер подаёт термины в буфер `m_macro_analisys_buff`,
`Macro` раскрывает их до грамматики Bison. Обработка прагм и предопределённых макросов вынесена из
`Parser` в `PredefMacroResolver`/`PragmaEvaluator` (Parser держит их членами, вызывает в
`GetNextToken`). Алгоритмика макропроцессора — свободные функции (`syntax/macro_split.hpp`):
`macro_arg_parser`/`macro_matcher`/`macro_expander`/`macro_validator`; `Macro` — реестр скоупов.

**ЕДИНСТВЕННЫЕ источники списков макросов/прагм — x-macro** `syntax/predef_macro_x.hpp`
(`TRUST_VALUE_MACROS` + `TRUST_CONTEXT_MACROS`) и `syntax/pragma_macro_x.hpp` (`TRUST_PRAGMA_MACROS`).
Из них генерируются enum, таблицы имён/описаний и авто-стрингификация. Реестры и доки в
`Context::macroDocs` строятся из x-macro ОДИН раз. Неизвестный макрос (`@__...__`) — диагностика
«not implemented»; прагма в `expandPredefMacro` — без ошибки (её ведёт `pragmaEval`).

## Facts and invariants

- **Ловушка (каждое `<<EOF>>`-правило ОБЯЗАНО заканчиваться `yyterminate()`):** иначе Flex, не получив
  return в `<<EOF>>`, вызывает `yylex` снова на том же EOF → бесконечный цикл на незакрытых `/* */`,
  `/** */`, `{% %}`, `@@@...@@@`, raw-string, `` ` ``. Строковые состояния (`state_STRCHAR`/`STRWIDE`)
  своего `<<EOF>>` НЕ имеют — они падают на глобальный (return END), но при незакрытой строке без `\n`
  ошибка не репортится.
- **Семантические ошибки разбора → `Severity::Error`, НЕ `Fatal`:** они не бросают исключение, и
  пайплайн (в LSP `allow_semantic_on_errors`) может продолжить до анализатора на частичном AST.
  `Fatal`/throw остаются только для ошибок безопасности (переполнение стека макросов, циклические
  модули, внутренняя логика). После мягкого отчёта обеспечен корректный `return`/`continue`.
- **Ловушка (позиция синтаксической ошибки — НЕ flex-курсор):** `Parser::error()` не должен брать
  позицию из `tokenStartOffset()`/`m_current_pos`: `GetNextToken` упреждающе буферизует термины до `;`,
  поэтому flex-курсор к моменту ошибки «убежал» вперёд. Корректная позиция — из реально потреблённых
  bison-токенов `Parser::m_recent` (`RecentTokens`). Пропущенный разделитель лежит в промежутке
  [конец последнего токена, начало неожиданного]; многострочный промежуток схлопывается в точку.
- **Атрибуты `@[...]@`: макро-имена внутри НЕ раскрываются** (`m_in_attr`). Это нужно, чтобы имя
  встроенного атрибута, совпадающее с именем keyword-макроса (напр. `func_const`), не раскрывалось
  (иначе бесконечная рекурсия). Явный `@`-макрос внутри атрибута — ошибка. `]@` лексится как
  `ATTR_COMPLETE`, не `UNKNOWN`. Предохранители от самовоспроизведения: лимиты `kMacroExpansionLimit`/
  `kMacroNestingLimit` (constexpr в `parser.h`), т.к. самовоспроизведение идёт через границы чтений
  парсера и `m_macro_depth` его не ловит.
- **Унифицированная последовательность (`Term::m_sequence`):** верхнеуровневая `sequence` модуля и
  вложенные `{...}`-блоки строятся из единого нетерминала `expression` и хранятся в `m_sequence`
  (`SequenceType = std::vector<TermPtr>`). `AppendBlock` сохраняет границу области видимости в AST
  (иначе объявления «протекают» в охватывающий скоуп). Пустые `';'` разрешены; `Sequence` из одних
  пустых операторов возвращает пустую `SEQUENCE`-терм, чтобы не попадать в AST как `SEMICOLON`.
- **`Term::Create`:** копирующая (безопасна для локальных строк) и non-copy (string_view, используется
  в лексере, где текст живёт в `SourceMapper` и должен пережить Term). Для намеренного обрезания в
  parser.y — явная копия.
- **Форматтер не должен терять исходник после ошибки лексера:** незакрытая строка/комментарий
  «съедают» хвост файла; в `Emitter::run()` хвостовой зазор от последнего токена до EOF при
  `parseGap == verbatim` сохраняется вербатим.
