# Макросы в NewLang

## Обзор

Макросы - это механизм текстовой подстановки, выполняемый на этапе MMProcessor (между лексером и синтаксическим анализатором). Bison-парсер не видит макросов - они полностью раскрываются до его запуска.

## Определение макроса

Определение макроса состоит из трёх частей:

```
@@ <имя_макроса> @@ <оператор> <тело> ;
```

- `@@` - открывающий и закрывающий маркер имени макроса (токен `MACRO_SEQ`)
- `<имя_макроса>` - одно или несколько имён (NAME, NATIVE), разделённых пробелами. **Первая лексема является ключом поиска.** Полное имя макроса - набор всех лексем (NAME/NATIVE) между `@@ ... @@`.
- `<оператор>` - оператор создания/присвоения: `:=`, `:-` или `=`
- `<тело>` - см. ниже
- `;` - завершающая точка с запятой

### Уникальность имени

Макрос идентифицируется **полным набором лексем имени**, а не только первой лексемой:

- `@@ MY MACRO @@ := a;` и `@@ MY OTHER @@ := b;` - **разные** макросы, оба регистрируются
- `@@ MY MACRO @@ := a;` и `@@ MY MACRO @@ := b;` - **переопределение** (ошибка)
- Вызов `@MY MACRO` раскроется только если полное имя совпадает (MY + MACRO)

Это отличается от старого поведения, где только первая лексема была ключом, а остальные игнорировались.

### Тело макроса

Тело может быть трёх типов:

1. **Выражение** (до `;`):

   ```
   @@ MACRO @@ := term;
   ```

   При вызове `@MACRO;` будет подставлено `term`.

2. **Последовательность токенов** (в `@@ ... @@`):

   ```
   @@ MACRO @@ := @@ do_something(42) ; @@;
   ```

   Тело - это последовательность лексем, которая будет подставлена "как есть".

3. **Символьная строка** (в `@@@ ... @@@`):

   ```
   @@ MACRO @@ := @@@ text body @@@;
   ```

   Тело - строка, в ней обычной regexp заменой заменяются все вхождения аргументов и шаблонов, после чего строка обрабатывается лексером и результат его работы вставляется на место раскрытия макроса.

   > **Важно:** последовательность `@@@` внутри тела не может быть частью данных, так как она закрывает блок. Если необходимо включить `@@@` в тело, используйте тело-последовательность (`@@ ... @@`) вместо строки.

## Имя макроса

Имя макроса состоит из одной или нескольких лексем (NAME, NATIVE), разделённых пробелами:

```
@@ name @@ := body;
@@ name name2 @@ := body2;
```

Первая лексема (в примерах `name`) является ключом для поиска в таблице.
Макросы `@@ NAME1 NAME2 @@` и `@@ NAME1 NAME3 @@` - разные макросы, так как полный набор лексем различается.

## Образцы - макрос-шаблон

В имени макроса после первой лексемы могут присутствовать образцы - токены с префиксом `$` (LOCAL).
Образец может быть заменён **любым одиночным токеном** при вызове. Это не аргументы в традиционном смысле, а сопоставление с образцом (pattern matching):

```
@@ FUNC $name @@ := call(@$name);
```

- `$name` - образец. При вызове `@FUNC(val);` любой токен на месте `$x` подставится как `val`
- Один образец соответствует ровно одному токену

## Аргументы макроса

Макрос может принимать аргументы в круглых скобках. Синтаксис:

> **Примечание:** образцы (`$name`) и аргументы в скобках могут сосуществовать в одном макросе. Приоритет произвольный - они не пересекаются: внутри скобок располагаются только аргументы, вне скобок - образцы. Скобки могут быть только одни.

```
@@ twice ( $x ) @@ := @$x @$x;
```

- Скобки `(` и `)` - маркер начала и конца списка аргументов
- Внутри скобок может быть любое выражение (несколько токенов) из парных вложенных скобок разных видов, включая обычные скобки, но одним аргументом считается вся последовательность токенов между скобками и запятыми верхнего уровня, т.е. внутри вложенных скобок запятые игнорируются и являются частью аргумента.
- При вызове аргументы передаются в скобках: `@twice(42);`

## Вызов макроса

Макрос вызывается через токен `@name` (MACRO):

```
@macro;
@FUNC(val);
@MY MACRO;
@twice(42);
@FUNC(val1, val2);
```

Правила сбора аргументов:

- Для макросов с аргументами в скобках `(...)` - собираются токены между `(` и `)`
- Для макросов-шаблонов (с образцами) - собираются токены от `@name` до `;`
- Для макросов без образцов - аргументы не собираются

При вызове макроса с многословным именем (`@MY MACRO`) проверяется совпадение **всех** лексем имени из определения макроса с последующими токенами в месте вызова.

### Подстановка в теле

В теле макроса можно ссылаться на образцы/аргументы следующими способами:

| Синтаксис | Токен | Описание |
|-----------|-------|----------|
| `@$name` | MACRO_ARGNAME | По имени образца |
| `@$N` | MACRO_ARGPOS | По номеру (1-based) |
| `@$*` | MACRO_ARGUMENT | Все аргументы в круглых скобках с замыкающей запятой: `(a, b, c, )` |
| `@$...` | MACRO_ARGUMENT | Все аргументы через запятую без скобок: `a, b, c` |
| `@$#` | MACRO_ARGCOUNT | Количество аргументов |
| `@$$` | MACRO_PATTERN | Все шаблоны сопоставления |

Пример:

```
@@ SWAP $a $b @@ := @$2 @$1;  @SWAP x y;   # → y x (шаблон, тогда как @$$ содержит [$a => 'y', $b => 'y'] )
@@ TWICE ( $x ) @@ := @$x @$x;  @TWICE(42);   # → 42 42 (аргументы)
```

## Операции над макросами

В теле макроса и в месте вызова доступны следующие операции:

### Конкатенация (`@##`, токен `MACRO_CONCAT`)

Оператор `@##` объединяет два соседних токена в один в месте вызова макроса:

```
@@ concat $a $b @@ := @$a @## @$b;
@concat hello world;    # → helloworld, а `@$$` содержит [$a => 'hello', $b => 'world']

@@ concat2 (a, b) @@ := @$a @## @$b;
@concat2(hello, world); # → helloworld
```

### Преобразование в строку (`@#`, `@#'`, `@#"`, токен `MACRO_TOSTR`)

Оператор `@#` преобразует результат подстановки в строковый литерал.

Варианты различаются по тексту лексемы (анализируется MMProcessor после лексера):

- `@#'value` - строка в одинарных кавычках (StrChar)
- `@#"value` - строка в двойных кавычках  (StrChar)
- `@#value` - строковое представление токена (строка системы, по умолчанию StrChar)

```
@@ show $x @@ := @#' @$x;
@show 42;   # → "42" (StrChar)
```

### Escape для символа или макроса (`$\`, токен `MACRO`)

Подавляет обработку лексемы препроцессораом: `$\macro_name;` оставляет `macro_name` как литерал (не вызывает макрос):

```
$\macro_name;  # → macro_name (литерал, без раскрытия)
```

### Удаление макроса (`@@@@`, токен `MACRO_DEL`)

> **Важно:** `@@@@` распознаётся как единая последовательность (без пробелов). Порядок правил в лексере: `@@@@` ^ `@@` ^ `@@@`. Это обеспечивает корректный приоритет: `@@@@` (удаление) распознаётся раньше, чем `@@` (маркер имени) или `@@@` (начало строки).

Удаляет ранее определённый макрос:

```
@@@@ macro_name;
```

## Область видимости макросов

**Все макросы стека живут строго в одной области видимости.** Имя макроса уникально на весь стек модулей: затенение не допускается. Скоупы (внутренние списки) служат только для группировки макросов по модулям, чтобы при выходе из модуля можно было удалить все макросы, созданные в нём.

### Правила

1. **Создание** (`:=`): если макрос не найден ни в одном скоупе - создаётся в **верхнем (текущем)** скоупе.
2. **Переопределение** (`:=` - создаёт/переопределяет; `=` - только переопределяет): поиск по всему стеку; если найден - обновляется **в том скоупе, где был определён ранее**. Диагностика `MacroRedefined` - по опции `macro-redefined`. Для `=` при отсутствии макроса - ошибка «макрос не существует».
3. **Раскрытие** (`@foo`): поиск по всему стеку. В силу уникальности имён найденный макрос ровно один.
4. **Удаление** (`@@@@ name`): поиск по всему стеку, удаление из скоупа, где макрос определён.
5. **`PopScope()`**: при выходе из модуля удаляются только макросы, **созданные** в этом скоупе; переопределённые макросы остаются в своих исходных скоупах.

### Пример

Стек: `[0] = dsl`, `[1] = модуль A`, `[2] = модуль B` (верхний).

- `@foo` определён в dsl и в модуле A (два независимых определения).
- В модуле B выполняется `@foo := new_body`:
  - поиск при переопределении идёт **сверху вниз**: первый найденный - в модуле A → обновление в скоупе A;
  - диагностика (ошибка/предупреждение/игнорирование) - по опции `macro-redefined`;
  - при раскрытии виден обновлённый макрос (из A); затенения нет, т.к. копий имени в стеке нет.

### Управление стеком скоупов

- `PushScope()` - добавить пустой скоуп перед загрузкой нового модуля.
- `PopScope()` - удалить верхний скоуп после завершения обработки модуля (удаляет только созданные в нём макросы).

## Наследование макросов

`Macro` хранится в `Context` (`Context::setMacro` / `Context::macro`) и загружается один раз на верхнем уровне (например, встроенный `trust/dsl.src` через `Pipeline::loadDslMacros`). Каждый `Parser` (включая вложенные, создаваемые через `Parser::ParseTerm`) наследует уже существующий `Macro` из `Context` - повторная загрузка dsl не выполняется.

Исключение - специальный случай «без раскрытия макросов»: `Parser(..., macro_expand = false)` или `Parser::ParseTerm(..., macro_expand = false)` создаёт парсер с `m_macro = nullptr`. Это используется при разборе идентификаторов определений макросов (`Macro::MakeMacroId`) и в тестах.

## Рекурсия макросов

Макрос может вызывать другие макросы в своём теле (рекурсивное раскрытие). Глубина рекурсии ограничена `MAX_RECURSION_DEPTH = 100`.

Пример:

```
@@ A @@ := B;   # A → B
@@ B @@ := 42;  # B → 42
@A;             # → 42 (A → B → 42)
```

## Примеры

### Простой макрос

```
@@ hello @@ := "Hello, World!";
@hello;
# → разворачивается в: "Hello, World!";
```

### Макрос-шаблон (с образцами)

```
@@ twice $x @@ := @$x @$x;
@twice 42;
# → разворачивается в: 42 42;
```

### Макрос с аргументами в скобках

```
@@ twice ( $x ) @@ := @$x @$x;
@twice(42);
# → разворачивается в: 42 42;
```

### Макрос с многословным именем

```
@@ MY NAME @@ := result;
@MY NAME;
# → разворачивается в: result;
```

### Макрос с телом-последовательностью

```
@@ if(...) @@ := @@ [ @$... ]--> @@;
@if(cond, action);
# → разворачивается в: [ cond ]--> action;
```

### Макрос с телом-строкой

```
@@ version @@ := @@@ 1.0.0 @@@;
@version;
# → разворачивается в: "1.0.0" (StrChar)
```

## Предопределённые макросы

Все предопределённые макросы имеют формат `@__NAME__`. При вызове они раскрываются в соответствующий литерал (StrChar или IntLiteral). Если встречен макрос вида `@__XXX__`, отсутствующий в списке - выдаётся ошибка компиляции.

### Идентификация версии

Эти макросы раскрываются в те же данные, которые определены в `version.h` при компиляции проекта:

| Макрос | Тип | Описание |
|--------|-----|----------|
| `@__TRUST_VERSION_MAJOR__` | IntLiteral | Основной номер версии |
| `@__TRUST_VERSION_MINOR__` | IntLiteral | Минорный номер версии |
| `@__TRUST_VERSION_PATCH__` | IntLiteral | Номер патча |
| `@__TRUST_VERSION__` | StrChar | Версия в формате "X.Y.Z" |
| `@__TRUST_GIT_HASH__` | StrChar | Короткий хеш Git-коммита |
| `@__TRUST_VERSION_FULL__` | StrChar | Версия с Git-хешем: "X.Y.Z-<hash>" |
| `@__TRUST_DATE_BUILD__` | StrChar | Дата сборки в формате "YYYY-MM-DD" |

### Данные, связанные с текущим файлом

| Макрос | Тип | Описание |
|--------|-----|----------|
| `@__FILE__` | StrChar | Полный путь к текущему файлу |
| `@__FILE_NAME__` | StrChar | Имя текущего файла (без пути) |
| `@__MODULE_NAME__` | Name | Имя текущего модуля (файл без расширения) относительно главного файла; разделители каталога заменяются на `_` |
| `@__LINE__` | IntLiteral | Номер текущей строки в файле |
| `@__FILE_LINE__` | IntLiteral | Номер текущей строки (синоним `@__LINE__`) |
| `@__FILE_MD5__` | StrChar | 16-символьный hex-хеш (64-bit) содержимого файла |
| `@__FILE_TIMESTAMP__` | StrChar | Временная метка файла в ISO-формате |

### Контекстные макросы (область имён и функция)

Макросы, значение которых зависит от контекста (текущая область имён и функция). Раскрываются
в семантическом анализаторе (в обходе `NameResolutionPass`), т.к. для них нужна информация о
вложенности и текущей функции.

| Макрос | Поведение |
|--------|-----------|
| `@::` | Полное имя текущей области имён (аналог `@__NAMESPACE__`). Как `NAME`-аналог: `@:: foo` создаёт полное имя `ns::foo` следующего идентификатора. При стрингификации (`@# @::`) - строка `"::ns::name::"` (глобальная область → `"::"`). |
| `@__NAMESPACE__` | То же, что `@::` (полное имя текущей области имён). |
| `@__FUNCTION__` | Краткое имя текущей функции (без namespace и `%`). Как `NAME`-аналог может быть меткой перехода (`@__FUNCTION__ ++/--`). При стрингификации - строка с именем функции. |
| `@__FUNCSIG__` | Сигнатура функции - всегда строковый литерал, напр. `"ns::func():Void"`. |
| `@__FUNCDNAME__` | Декорированное имя функции (`utils::name_to_cpp` от полного имени). Как `NAME`-аналог; при стрингификации - строка. |

- `@__FUNCTION__`/`@__FUNCSIG__`/`@__FUNCDNAME__` допустимы только внутри функции (иначе
  диагностика ошибки).
- Стрингификация помечается ведущими маркерами `@#` (строка), `@#'` (символьный литерал),
  `@#"` (строка); маркеров может быть несколько. Склейку нескольких литералов выполняет
  `@##` (`MACRO_CONCAT`).



| Макрос | Тип | Описание |
|--------|-----|----------|
| `@__DATE__` | StrChar | Текущая дата как в C++ `__DATE__`: "Mmm dd yyyy" |
| `@__TIME__` | StrChar | Текущее время как в C++ `__TIME__`: "hh:mm:ss" |
| `@__TIMESTAMP__` | StrChar | Дата/время в формате asctime: "Fri 19 Aug 13:32:58 2016" |
| `@__TIMESTAMP_ISO__` | StrChar | Текущая дата/время в ISO 8601: "2013-07-06T00:50:06Z" |

### Гигиенические имена

| Макрос | Тип | Описание |
|--------|-----|----------|
| `@__HYGIENIC__(ident)` | Ident | Генерирует гигиеническое имя: к последней части `ident` добавляет суффикс `__G<counter>_`. При повторном вызове с тем же `ident` в пределах одного дерева раскрытия макросов возвращает то же имя. Счётчик глобальный, начинается с 1. |

Пример использования в гигиеническом макросе:

```
@@ swap $a $b @@ := @@
    var @__HYGIENIC__(tmp) = @$a;
    @$a = @$b;
    @$b = @__HYGIENIC__(tmp);
@@;
```

Первое раскрытие `@swap x y;`:

```
    var tmp__G1_ = x;
    x = y;
    y = tmp__G1_;
```

Второе раскрытие `@swap p q;`:

```
    var tmp__G2_ = p;
    p = q;
    q = tmp__G2_;
```

Вложенные макросы используют один и тот же счётчик, что гарантирует отсутствие коллизий между именами в графе раскрытия.

Также поддерживаются квалифицированные имена: `@__HYGIENIC__(MyType::tmp)` → `MyType::tmp__G1_`.

### Счётчик

| Макрос | Тип | Описание |
|--------|-----|----------|
| `@__COUNTER__` | IntLiteral | Монотонно возрастающий глобальный счётчик, начиная с 1. |

### Контекстные проверки

| Макрос | Тип | Описание |
|--------|-----|----------|
| `@__LEXEME_NEXT__` | - | Директива для проверки следующей лексемы после раскрытия макроса |

## Контекстные ограничения (`@__LEXEME_NEXT__`)

`@__LEXEME_NEXT__` - служебная директива (прагма), используемая в **теле** макроса для проверки контекста **в месте раскрытия**.

`@__LEXEME_NEXT__` должна быть **последним элементом** в теле макроса.

### Синтаксис

```trust
@@ MACRO_NAME @@ := ... @__LEXEME_NEXT__(SEMICOLON, RPAREN, LBRACE);
```

Где в скобках перечисляются **допустимые лексемы**, которые могут следовать за раскрытием макроса:

- **Имена лексем без кавычек** (например `SEMICOLON`, `RPAREN`, `NAME`, `LBRACE`) - проверка по типу токена (`ParserToken::Kind`)
- **Строковые литералы** (например `";"`, `"{"`, `"===>"`) - проверка по тексту токена

### Семантика

После полного раскрытия макроса проверяется следующая лексема в исходном потоке:

1. Если список непустой, а после раскрытия макроса больше нет лексем - ошибка.
2. Если следующая лексема не совпадает ни с одним из перечисленных - ошибка.
3. Если совпадает - макрос считается корректно использованным.

### Примеры

**Корректное использование:**

```trust
@@ assert $x @@ := @__LEXEME_NEXT__(SEMICOLON);
@assert(condition);  # ✓ - после макроса идёт ;
```

**Ошибка:**

```trust
@@ assert $x @@ := @__LEXEME_NEXT__(SEMICOLON);
@assert(condition)  # ✗ - после макроса нет ; (ожидается конец строки или другой токен)
```

**Несколько допустимых вариантов:**

```trust
@@ FOR_EACH $x $body @@ := ...
    @__LEXEME_NEXT__(SEMICOLON, RPAREN, RBRACE);
```

После раскрытия `@FOR_EACH ... ;` может идти `;`, `)` или `}`.

**Строковые литералы для точного текста:**

```trust
@@ MY_OP $x @@ := @__LEXEME_NEXT__("===>");
# После раскрытия должна быть лексема с текстом "===>"
```

## Управление опциями компилятора (`@__OPTION_PUSH__`, `@__OPTION__`, `@__OPTION_POP__`)

Эти встроенные макросы (прагмы) позволяют временно менять severity диагностических опций компилятора из исходного кода:

- `@__OPTION_PUSH__;` - сохраняет текущий набор опций (аналог `#pragma push`).
- `@__OPTION__("<имя_опции>", "<значение>");` - устанавливает severity опции. `<значение>` - одно из: `fatal`, `error`, `warning`, `remark`, `note`, `ignore`.
- `@__OPTION_POP__;` - восстанавливает предыдущий набор опций (аналог `#pragma pop`).

### Пример

```trust
@__OPTION_PUSH__;
@__OPTION__("macro-redefined", "ignore");   # разрешить переопределение макросов

@@ true @@ ::= 1;                            # переопределение не вызовет ошибки

@__OPTION_POP__;                             # опция "macro-redefined" восстановлена
```

- `"ignore"` полностью отключает диагностику для указанной опции.
- Если `@__OPTION_POP__;` вызван без соответствующего `@__OPTION_PUSH__;` - выдаётся ошибка.
- Неизвестное имя опции или неизвестное значение severity - ошибка компиляции.

### Условная подстановка по feature-флагу (`@__OPTION_TRUE__`, `@__OPTION_FALSE__`, `@__OPTION_IIF__`)

Булевые feature-флаги (`OPTIONS_FLAGS`, например `assert`, включаются через `-Wassert`/`-Wno-assert`) можно проверять из исходного кода условными прагмами:

- `@__OPTION_TRUE__("<имя_флага>", <лексема>...);` - срабатывает, если флаг **включён**: прагма заменяется лексемами, переданными после имени флага.
- `@__OPTION_FALSE__("<имя_флага>", <лексема>...);` - срабатывает, если флаг **выключен**: прагма заменяется лексемами, переданными после имени флага.
- `@__OPTION_IIF__("<имя_флага>", <true>, <false>);` - принимает ровно **три** аргумента: если флаг **включён**, прагма заменяется `<true>`, иначе - `<false>`.
- Если флаг не зарегистрирован - ошибка компиляции.
- Если прагма не срабатывает, она удаляется из текста (ничего не вставляется).

```trust
@__OPTION_TRUE__("assert", @assert_checked);      # включить проверку, если задан -Wassert
@__OPTION_FALSE__("assert", @assert_skipped);     # иначе - пропустить
@__OPTION_IIF__("assert", @assert_checked, @assert_skipped);  # то же самое в одной прагме
```

#### Макросы `assert`/`verify` (проверка утверждений)

Встроенный DSL (`trust/dsl.src`) определяет два макроса рантайм-проверки утверждений:

```trust
assert(cond);   # проверка утверждения
verify(cond);   # то же, но условие вычисляется даже при -Wno-assert
```

- Оба принимают ровно один аргумент - выражение-условие.
- Управляются булевым флагом `assert` (`-Wassert` / `-Wno-assert`; по умолчанию выключен):
  - `-Wassert` - условие проверяется; при провале печатается сообщение `file:line: <выражение>`
    (строкифицированное условие) и процесс завершается через `trust::trust__abort__`.
  - `-Wno-assert` - `assert` раскрывается в пустой оператор (ничего), условие НЕ вычисляется;
    `verify` раскрывается в `(cond)` (условие вычисляется, но проверки/диагностики нет).
- Стек вызовов при провале управляется флагом `backtrace` (`-Wbacktrace` / `-Wno-backtrace`).

Реализация (последовательные ветки `@__OPTION_TRUE__`/`@__OPTION_FALSE__` с «сырым» содержимым):
```trust
@@ assert( $cond ) @@ ::= @@
@__OPTION_TRUE__("assert" (@$cond) || %trust::trust__abort__( @__FILE_NAME__, @__FILE_LINE__, @# @$cond, @__OPTION_IIF__("backtrace", 1, 0) ))
@__OPTION_FALSE__("assert")
@@;
@@ verify( $cond ) @@ ::= @@
@__OPTION_TRUE__("assert" (@$cond) || %trust::trust__abort__( @__FILE_NAME__, @__FILE_LINE__, @# @$cond, @__OPTION_IIF__("backtrace", 1, 0) ))
@__OPTION_FALSE__("assert" ( @$cond ))
@@;
```
- `@__OPTION_TRUE__("flag" <content>)` - содержимое берётся «сырым» (токены до закрывающей скобки, без
  разбивки по запятым и без пре-парсинга); при срабатывании вставляется как есть, поэтому
  преdef-макросы (`@__FILE_LINE__` и т.п.) раскрываются на сайте вызова (локация корректная).
- `@__OPTION_FALSE__("flag" <content>)` - аналогично для выключенного флага.
- Проверка «вызвать ли abort» - через C++ short-circuit `(cond) || trust__abort__(...)`:
  условие явно заключено в скобки `(@$cond)` (не полагаясь на транспилер), а
  `trust::trust__abort__` (`[[noreturn]] bool`, без параметра-условия) вызывается ТОЛЬКО когда
  `cond` ложно; при истинном `cond` вызов пропускается (short-circuit).
- `trust__abort__` (в `trust/assert.hpp`) - единая точка abort: печатает `file:line: expr` и завершает
  процесс (с опциональным стеком вызовов). Использование макроса автоматически подключает этот
  заголовок (runtime-символы).

#### Запятая внутри аргумента (`@\,`)

Лексема `@\,` (`COMMA_LEXEME`) используется, когда нужно вставить **обычную запятую** в место, где запятая не должна разделять аргументы прагмы или макроса. При раскрытии (в теле макроса или при подстановке аргумента прагмы `@__OPTION_TRUE__`/`@__OPTION_FALSE__`/`@__OPTION_IIF__`) `@\,` превращается в обычную `,`:

```trust
@__OPTION_IIF__("assert", print(@\,), nop(@\,));   # вставить запятую как значение аргумента
@@ comma_list @@ ::= @@ [ a @\, b ] @@;            # [ a , b ] после раскрытия
```

### Опция `"macro-redefined"`

Управляет поведением при переопределении уже существующего макроса:

| Значение | Поведение |
|----------|-----------|
| `"fatal"` (по умолчанию) | Переопределение - фатальная ошибка |
| `"error"` / `"warning"` / и т.д. | Переопределение разрешено, но выдаётся диагностика указанного уровня |
| `"ignore"` | Переопределение разрешено без диагностики |
