# Правила формирования идентификаторов (имён объектов)

Каждый объект имеет своё уникальное *внутреннее имя* с помощью которого компилятор языка однозначно связывает объект с данными в памяти компьютера.

Идентификатор состоит из одного или нескольких фрагментов (простых имён или специальных лексем), разделённых пробельными символами или квалификаторами имён. Пробельные символы служат разделителями фрагментов, но не являются частью идентификатора.

## Правила формирования идентификаторов

### Простое имя (лексема NAME в лексере)

Простое имя — это неразрывная последовательность любых букв (включая Unicode), цифр и символа `_`. Цифра не может быть первым символом имени. Имена регистрозависимы. Максимальная длина простого имени — 63 символа. Простые имена являются минимальным компонентом для всех остальных имён.

*Простое имя в названии модуля может содержать только **строчные буквы**, цифры и символ `_`. Символ `_` не может быть первым или последним в имени модуля. Данное ограничение проверяется в макропроцессоре при анализе идентификаторов и является компромиссом для совместимости имён файлов в разных типах файловых систем.*

### Квалифицированное имя

Квалифицированное имя — это простое имя, перед которым стоит один из квалификаторов (сигилов):

- ‘@’ — префикс «собачка» используется для указания имени макроса (обрабатывается макропроцессором на уровне отдельных лексем до анализа AST).
- ‘$’ — знак доллара обозначает имя временного объекта, время жизни которого ограничено текущей областью видимости, что контролируется компилятором автоматически.
- ‘::’ — двойное двоеточие разделяет пространства имён и одновременно является признаком персистентного объекта, значение которого сохраняется после выхода из текущей области видимости. Если имя начинается на ‘::’, то область его видимости будет глобальной и он будет доступен по этому имени из других модулей программы.
- ‘.’ — префикс «точка» используется для указания имени поля модуля или класса (связывает время жизни с текущим объектом). Символ '.' перед именем может быть использован перед аргументами в определении или при вызове функции, чтобы его нельзя было перекрыть макросом. В качестве имени поля можно указать цифру, т.е. `.0` `.1` или `.99`, но это означает обращение к полю по его индексу, в том случае, когда индекс может быть проверен во время компиляции.
- ‘\’ — обратный слеш в начале идентификатора обозначает имя программного модуля и используется для разделения имён каталогов при указании иерархии размещения программных модулей в файловой системе. Одиночный символ ‘\’ в начале имени обозначает относительную иерархию расположения модулей, двойной ‘\\’ — абсолютную, тройной ‘\\\’ — системное расположение (может быть настроено опциями).
- ‘:’ — двоеточие перед именем обозначает имя типа, чтобы его нельзя было перекрыть макросом.
- ‘%’ — префикс «знак процента» указывается для нативных имён переменных и функций.

### Специальные (зарезервированные) имена

Специальные имена — это комбинации символов, которые имеют строго определённый смысл:

- Аргументы функций, к которым можно обращаться по порядковому номеру. Номерной аргумент функции начинается на символ доллара ‘$’ (как временное имя), после которого идёт порядковый номер аргумента (`$1`,`$2`, …, `$N`).

- К аргументам функции можно обратиться как к словарю, например для их перебора в цикле, который имеет специальное имя`$*`.

- Нумерация аргументов начинается с единицы, а имя `$0` обозначает текущий объект для метода класса.

- Специальное имя `$$` обозначает родительский объект для класса.

- Специальная неизменяемая виртуальная переменная компилятора `$^` содержит результат выполнения последнего выражения, оператора или блока кода.

- Макрос `@::` раскрывается в текущую область имён.

- Специальный макрос `@#`, `@#"` или `@#'` преобразовывает следующий за ним термин в символьную строку (стрингификация), а макрос `@##` соединяет (выполняет конкатенацию) двух символьных строк в одну.

Например:

```trust
# Имя файла filename.src в каталоге dir
ns:: { # пространство имен ns
    name:: {
        ns_str :=  @#  @::; # Строка с областью имен "::ns::name::"
        mod_str :=  @# @__MODULE_NAME__; # Строка с именем модуля "\\dir\filename"
        full_str := @#  @module @##  @# @::; # "\\dir\filename::ns::name::"
    };
};
```

Для раскрытия специального имени требуется контекст AST, который доступен только во время работы анализатора и имеющейся у него информации (имени модуля, области имён, метода класса и т.д.)

Полный идентификатор — это идентификатор, который не содержит в себе фрагментов специальных имён. Нормализованный идентификатор — это полный идентификатор, разрешённый в соответствии с алгоритмом разрешения имён (все специальные имена раскрыты, квалификаторы приведены к канонической форме).

### Разрешение имен (name lookup) {#name-lookup}

Если имя объекта не содержит квалификатора, оно является *простым*.

И когда *TrustLang* встречает *простое* имя объекта без квалификатора, то в дело вступает алгоритм разрешения имён (name lookup), который связывает *простое* имя, встретившееся в исходном тексте программы, с конкретным типом, декларацией или созданным объектом по его полному имени.

Разрешение *простых* имён *без квалификатора* (*name lookup*, или поиск имени функции/переменной) происходит всегда в строго определённом порядке:

- в первую очередь происходит поиск имени среди имен макросов
- далее выполняется поиск имени среди локальных объектов до объектов текущего модуля, а в случае вызова функции выполняется статическое разрешение имен при перегрузке функций
- в последнюю очередь выполняется поиск среди статических объектов с постепенным расширением пространства имён области поиска от текущей до глобальной

Такая последовательность разрешения имён всегда предоставляет возможность переопределить глобальные/локальные объекты или имена аргументов у функций для уже существующего кода без его серьёзных изменений.

Например, для имени `name` в области имен **`ns`** поиск происходит в следующей последовательности:
`@name` -> `$name` -> `%name` -> `ns::name` -> `::ns::name` -> `::name`, а для имени аргумента `arg` проверяется только `@arg`:

```trust
    ns:: {
        name(arg="value");
    };
```

И в то же время, всегда остаётся возможность указать конкретный объект независимо от работы алгоритма разрешения *простых* имён. Достаточно указать квалификатор в имени объекта в явном виде.

Например, обратиться к глобальному объекту **name** из пространства имён **ns** из примера выше, нужно по полному имени объекта `::ns::name`, а именованный аргумент *'**.** arg'* не может быть заменён макросом `@arg`, если такой будет определён:

```trust
    ::ns::name(.arg="value");
```

## Внутреннее имя (идентификатор)

Каждый объект имеет своё внутреннее имя, уникальное в рамках текущего модуля, с помощью которого компилятор языка однозначно связывает объект с данными в памяти компьютера. Внутреннее имя объекта можно создать только для полного (нормализованного) идентификатора.

Внутреннее имя формируется во время анализа синтаксического дерева программы и включает в себя имя объекта и его квалификатор в соответствии с алгоритмом разрешения имён. У статических объектов и типов внутреннее имя включает в себя полную иерархию области имён.

Кроме этого, все квалификаторы объектов переносятся в конец имени, что и является отличительным признаком внутреннего имени (последний символ должен быть “$”, “:” или “%”). Символ иммутабельности `^` не входит во внутреннее имя.

Квалификатор `::` может находиться как перед именем (глобальная видимость), так и после имени. Запись `name::` без `::` перед именем означает, что статический объект с областью видимости модуль/пакет, а не глобальной, и снаружи модуля к нему обратиться нельзя. Например, `var:: := 0;` объявляет статический объект `var` модуля.

Примеры внутренних имён:

```trust
var := 0;       # `var::`   - Статический объект модуля (время жизни = модуль)
$var := 0;      # `var$`    - Thread_local объект модуля (видимость модуль/пакет, время жизни = поток)
::var := 0;    # `::var::` -  Глобальный статический объект (глобальная видимость)
@::var := 0;   # `var::`   - Статический объект модуля (видимость модуль/пакет)
var:: := 0;   # `var::`   - Статический объект модуля (видимость модуль/пакет)
%var := 0;      # `var%`    - Нативная переменная (по умолчанию видимость модуль/пакет)


::type ::= :Type;     # `::type::` - Глобальное имя типа и конструктор класса (глобальная видимость)
:: cls ::= Class(){};  # `::cls:::`

:type ::= :Type;         # `::type:::`   - Тип  (глобальная видимость)
@:: :type ::= :Type;     # type:::       - Тип  (видимость модуль/пакет)
:cls ::= Class(){};      # `::cls:::`    - Конструктор класса (глобальная видимость)
@:: :cls ::= Class(){};  # `cls:::`      - Конструктор класса (видимость модуль/пакет)

%func() := {};          # `func%`      - Нативная функция  (видимость модуль/пакет)
::%func() := {};        # `::func%`    - Нативная функция  (глобальная видимость)

{   # Неименованный блок кода модуля (префикс `1::` означает номер блока)

    var  := 0;      # `var$`        - Локальный объект (до конца области видимости)
    $var := 0;      # `var$`        - Локальный объект (до конца области видимости)
    @::var = 0;     # `1::var::`    - Статический объект (нет экспорта)

    :type ::= :Type;     # `1::type:::` - внутренний тип (нет экспорта)
    :cls ::= Class(){};  # `1::cls:::`  - внутренний класс (нет экспорта)
    %func() := {};      # `1::func%` - Нативная функция (нет экспорта)
};

ns {                    # область имен `ns`
    @::var := 0;       # `ns::var::`       - статический объект в текущей области видимости
    ::other::var := 0; # `::other::var::`  - глобальный статический объект (глобальная видимость)
    ::%func() := {};    # `::ns::func%`     - Глобальная нативная функция  (глобальная видимость)
};
```

### Предварительное объявление {#forward-declaration}

В тексте программы можно ссылаться только на реально существующие (созданные) объекты.

Но для тех случаев, когда требуется сослаться на объект, который создан в другом модуле или будет создан позже, можно сделать предварительное объявление, при котором компилятор регистрирует имя и тип объекта без его реального создания.

За счет предварительного объявления можно ссылаться только на статические объекты (типы данных) или локальные поля класса о которых компилятор ещё не знает, но которые будут определены в процессе компиляции позже.

Для предварительного объявления можно использовать [внутреннее имя](/ru/docs/arch/mangling/) или полное квалифицированное имя, которое должно будет в точности совпадать с именем объекта при его последующем создании.

Для предварительного объявления используется точно такой же синтаксис, как и при реальном создании объекта, только справа от оператора создания должно быть указано многоточие.

Область видимости предварительного объявления соответствует области видимости его размещения, а не реальной области видимости объекта, который будет впоследствии создан.

```trust

    # Предварительное определение переменной модуля
    # Действует для всего модуля

    var_module:Int32 := ...;

    func() ::= {

        # Предварительное объявление с помощью DSL
        # (действует только внутри тела функции)
        @declare( func2(arg:Int32):Int32 );

        var_module = func2(var_module);
        @return var_module;
    };


    func2(arg:Int32):Int32 ::= {
        @return $arg*$arg;
    }

```

### Неизменяемые объекты

`TrustLang` поддерживает динамическую иммутабельность (константность). Это свойство может быть не только свойством типа, но и свойством лексического объекта (самих данных) и означает, что объект может стать неизменяемым не только в момент создания (определения), но и при одной из последующих операций присваивания/изменения значения.

Для придания объекту свойства иммутабельности (невозможности изменять своё значение в дальнейшем) используется символ `^` (каретка, «крышечка»/«домик») после имени объекта. Символ `^` не влияет на внутреннее имя объекта и является краткой формой записи атрибута `immutable`.

## Манглинг внутренних имён

Внутреннее имя уникально только в рамках одного модуля, но внутренние имена в разных модулях могут пересекаться.

Манглинг внутренних имён предназначен для объединения нескольких модулей в рамках одной программы и используется как способ кодирования имени функции, структуры, класса или другого типа данных при передаче дополнительной семантической информации от компилятора компоновщику. Внутреннее имя объекта после манглинга является корректным идентификатором для языков C/C++, что позволяет обращаться к объектам TrustLang из внешних библиотек и приложений на языке реализации (C/C++) по семантически похожему имени (в отличие от манглинга имён в C++).

Манглинг внутреннего имени заключается в замене каждого символа двоеточия на символ `$`.

При манглинге к внутренним именам объектов добавляется специальный префикс, который кодирует имя компилируемого модуля. У главного модуля приложения имя модуля отсутствует.

При манглинге внутреннего имени, имя модуля раскрывается как относительное имя файла по отношению к каталогу с главным файлом программы. Так как имя модуля, согласно правилам синтаксиса, может содержать только строчные буквы, цифры и символ `_` (кроме первого и последнего символа), то разделитель каталогов (обратный слеш `\`) заменяется на символ `$`, а начало и конец имени модуля отмечаются комбинациями символов `_$` и `$_` соответственно.

Так как переменной с именем из одного подчёркивания `_` быть не может, то начало имени на `_$` служит отличительным признаком манглинга внутреннего имени объекта.

```trust

# Если текущий файл "\dir\file";
# тогда манглинг внутренних имён будет следующим

var := 0;      # `_$dir$file$_var$$` или `_$$_var$$` для главного модуля
$var := 0;      # `_$dir$file$_var$` или `_$$_var$` для главного модуля
::var := 0;    # `_$dir$file$_$$var$$` или `_$$_$$var$$` для главного модуля и т.д.
var:: := 0;    # `_$dir$file$_var$$` или _$$_var$$` для главного модуля и т.д.
```

## Примеры идентификаторов

```trust
    \\std(); # Загрузка модуля стандартной библиотеки

    %printf(format:FmtChar, ...):Int32 := %printf...; # Объявление нативной функции

    $value := 1; # Создание переменной
    %printf("$value = %i\n std::value = %i", $value, \std::value); # Вызов нативной функции

    ns::func(): Any := ...; # Предварительное объявление функции без аргументов, которое возвращает любое значение
    ns::func(... :Integers ): Void := {}; # Функция с произвольным числом аргументов любых целочисленных типов без возвращаемого значения
    
    <T> min(arg1:T, arg2:T):T := { # Шаблонная функция
        @if( arg1 < arg2 ) {
            @return arg1; 
        }
        @return arg2;
    }; 

    $result := min<:Int32>(10, 20); # Вызов шаблонной функции

    <T:Integer> # Ограничение на допустимые типы шаблона
    make_vector(size:Int32, value:T): T[] := { # Шаблонная функция возвращает динамический массив указанного размера
        @return Vector[size](value);
    }

    make_tensor(size:Int32, value:Int32):Int32[1][] := { # Функция возвращает двухмерный тензор :Int32
        @return Tensor[1][size](value);
    }

```
