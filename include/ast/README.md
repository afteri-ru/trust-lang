# AST - Abstract Syntax Tree

## Назначение

Универсальные типы для представления последовательности токенов (Sequence) и иерархии узлов AST. Обеспечивает единый формат данных для передачи между этапами конвейера: Lexer → Term → Parser → TermToAstConverter → AST.

## Особенности реализации

- **Синтаксический вход** - AST строится из дерева `Term` (`syntax`), которое создаёт лексер/парсер; отдельных типов `Lexeme`/`SyntaxToken`/`SyntaxSeq` в AST нет.
- **Иерархия AST** - `AstNodeBase` (kind, `MapperRange`) → `AstNodeAttr` (+attrs) → специализированные узлы. Текст узла - mixin `HasText` (НЕвладющий view в пул строк `StringInterner` компиляции), подключаемый через `WithText<Base>`: наличие `WithText` в базе и есть «узел несёт текст». В обобщённом коде текст читается `as_text()`/`requiredText()`; у остальных узлов метода `text()` нет (compile-time). `Sequence` (верхний уровень файла) текста не несёт; именованные области - `ScopeBlock` (Block) и `ModuleNode` (`WithText<Sequence>`). `Binary` хранит глиф только в `m_op`, `TryCatchStmt` - вид перехвата в `TryKind`, `RefMakeExpr` - сигил в `m_sigilKind`. `HasText` хранит spelling терма КАК ЕСТЬ; правило имени (срез `:` у TypeName, хвостового `^` кроме `$^`, `attr::ReadOnly`) применяет ТОЛЬКО создание name-node через `assignNameFromRaw` (`IdentName`/`IdentType`/`Decl`-семейство/`ArgNode`). Для не-имён (`^^`, тело строки) текст не меняется. `text()` невиртуальный. Документирующий комментарий - leaf-узел `Document` (`RawText`): `text()` возвращает интернированный текст комментария. Virtual-аксессор `as_sequence()` даёт обходчикам доступ к `m_body` Sequence-узлов без kind-`static_cast`.
- **Все тексты AST — интернированные view:** spelling носителей, `AstNodeBase::documentation` и `DebugStmt::args` — невладеющие view в пул строк `StringInterner`; единственные точки записи — `WithText`/`HasText::set_text_interned`, `AstNodeBase::setDocumentation` и конверсия `DebugStmt::args`; все они используют единый `internedTextSlot` (пустое написание не интернируется, иначе `internText`).
- **Единый dump-формат** - `detail::dumpQuotedName` (token_base.hpp) формирует заголовок `Name 'text'` для `IdentName/IdentType/ArgNode/ModuleNode/Decl::dump`; имя выводится однократно.
- **Две группы конструкторов (правило)** - (1) терм-конструктор `X(Kind, TermPtr)` - данные (text/дети) читаются из `Term` только на входе и материализуются в поля узла, используется `TermToAstConverter`; (2) manual-конструктор без `TermPtr` - для синтетики/тестов, текст интернируется, `range()` невалиден. Нормализация имени (`:` у TypeName, `^`) выполняется ОДИН раз в `assignNameFromRaw` при создании name-node (view-trim до интернирования), поэтому raw spelling идентификатора в пул не попадает. Текст интернируется при конвертации у узлов-носителей (WithText/HasText); исходный буфер SourceMap в AST не удерживается.
- **Система атрибутов** - value-типы (`AttrId`, `Attr`) и реестр `AttrPool` вынесены в отдельный компонент `attrs` (`attrs/attr.hpp`, `attrs/attr_pool.hpp`). `AttrId` (`uint32_t`) содержит битовую маску: bits 0–23 = индекс в `AttrPool`, bits 24–31 = флаги обработки (builtin/analyzer/codegen/manual). Разбор `@[...]` - `attr_parser.hpp` (здесь, в `ast`): `parse_attr(ctx, range, name, params)` только ищет атрибут в пуле; регистрация выполняется отдельно (`register_attr`/`register_builtin_attr`). Канонические имена встроенных атрибутов - `attr::*` в `attrs/attr_builtin.hpp` (в т.ч. `format` - компиляйт-тайм проверка printf-формата для нативных функций, см. `semantic/format_check.hpp`).
- **Поток данных** - Flex/Lexer → Term → Macro/Parser (Term) → `TermToAstConverter` → AST (`AstNode`); Term не сохраняется в узлах.
- **Иерархия узлов** - общие поля (`kind`, `range`, `attrs`) в базовых классах, текст - только у носителей (`WithText`), специализированные данные - в конкретных классах узлов.
- **Единая диспетчеризация (kind-dispatch)** - `include/ast/kind_dispatch.hpp` выводит перечень из `PARSER_TOKEN_KINDS` (77 kinds + `END`) и задаёт: `kindCategory` (контекст `Any/StmtOnly/ExprOnly`), `hasAllKindHandlers<C>()` (полнота набора `visit_<Kind>`), `dispatchEmit(node, self, expected)` (исчерпывающий switch; `END` - FAULT), `faultUnexpectedKind` и `skipNode` (`kParserKindSlotCount`/`kindIndex` - в `token.hpp`, рядом с перечнем kinds). Два вида потребителей: *exhaustive consumer* (кодоген) - типизированные `visit_<Kind>` + `static_assert(hasAllKindHandlers<C>())`, statement/expression-контекст проверяется категорией; *partial pass* (семантика) - ОДНА таблица обработчиков размером `kParserKindSlotCount`, default `doTraverse` и переопределения только реальных действий (эталон - `NameResolutionPass::semaActions()`), `END` - явный reject. Каждый слот таблицы заполнен: «ничего не делать» выражается явным `skipNode`, «недопустим здесь» - `faultUnexpectedKind`. Новый kind в `PARSER_TOKEN_KINDS` обязан получить категорию; полнота кодогена проверяется `static_assert`, обход детей идёт по класс-таблице слотов (`node_slots_x.hpp`, CTest `ast_slots_guard`), partial pass по построению получает default-обход (осознанная политика partial pass). Дублирование диспетчеризации вне allowlist и `if/switch` по kind внутри `KIND_DISPATCH_GUARD_BEGIN/END` ловит CTest `kind_dispatch_guard`.
- **Типизированный доступ без RTTI** - `AstNodeBase::is<T>()`/`as<T>()` (token_base.hpp/ast_nodes.hpp) на основе kind→класс из `PARSER_TOKEN_KINDS` через `std::is_base_of_v`; работают и для базовых классов (`is<IdentName>()` для `IdentType`/`VarDecl`). `as<T>()` при неверном kind бросает `FAULT` (не возвращает nullptr). Заменяет `dynamic_cast`/`static_pointer_cast` по AST в анализаторе и кодогене. Trust-контракты объявления - `trustContracts()`/`hasTrustProperty(PropertyKind)`.
- **Цели переходов** - `convert/jump_targets.hpp` (`JumpTargetsT<Target>`, реэкспорт через `clone.hpp`) - единое правило `break`/`continue` именованных блоков для HIR-lowering (`Target=std::string`) и CFG (`Target=std::size_t`): pending continue потребляет первый `while`/`do-while` в теле блока, `break <имя_функции>` = void-return, единый формат goto-меток. Сама трансформация — в `ir/hir/lowering`.
- **Клон дерева** - `clone.hpp` (`cloneTrees`): глубокий клон по каноническому реестру `kind→класс` (shallow-copy + `forEachSlot`-visitor'ы: все владеемые слоты, затем ремап невладеющих ссылок по строкам `NonOwn*` класс-таблицы). Каждый клон получает `origin` (узел исходной AST) — единственное хранимое направление соответствия. База HIR-билдера: lowering работает на клоне, исходная AST не мутируется.
- **Материализованный тип-имя** - `IdentName::resolvedTypeId` (`TypeId`): семантика записывает разрешённый тип (аннотация, тип-операнд доступа, объявление `TypeDecl`, база алиаса, callee-конструктор; полная инстанциация) прямо в узел, кодоген рендерит его без повторного резолва имени.

- **Единый источник состава узла** - `node_slots_x.hpp` (класс-таблица `AST_SLOT_CLASSES` + строки `X(shape, field, walk, filter)`) и `slot_engine.hpp` (`AstSlotVisitor`, эмиссия строк, `AST_SLOT_METHOD`). `forEachSlot` класса генерируется из таблицы; `collectChildren`/`children()` и клон/ремап — generic-visitor'ы над ним. Политика, зависящая от kind, — данные строки (`SkipKinds`, `ListDeduped`). CTest `ast_slots_guard` ловит поле-слот вне таблицы и отсутствующий `AST_SLOT_METHOD`.
- **Machine-checked реестр классов** - перечень классов ПРОИЗВОДИТСЯ из `AST_SLOT_CLASSES`; `static_assert` (token.hpp) гарантируют, что каждый kind маппится на класс из канонического списка (запрет «нового класса под новый kind») и что в списке нет мёртвых классов.
