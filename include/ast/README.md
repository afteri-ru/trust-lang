# AST - Abstract Syntax Tree

## Назначение

Универсальные типы для представления последовательности токенов (Sequence) и иерархии узлов AST. Обеспечивает единый формат данных для передачи между этапами конвейера: Lexer → MMProcessor → ParserAST.

## Особенности реализации

- **Token/Sequence** - `SyntaxToken` как `std::variant<Lexeme, AstNodePtr>`, объединяющий лексемы лексера и узлы AST в единый тип последовательности (`SyntaxSeq = std::vector<SyntaxToken>`).
- **Иерархия AST** - `AstNodeBase` (kind, text, range) → `AstNodeAttr` (kind, text, range, attrs) → специализированные узлы. Документирующий комментарий - leaf-узел `Document` (kind=Document, класс `AstNodeAttr`): `text()` возвращает полный текст комментария (string_view, включая маркеры `/**`, `///`, `///<`) из `m_term`, без нормализации и `lower()`. Промежуточный `HasText` (в `token_base.hpp`) - **единый** носитель локального текста (`m_text`/`text()`): Literal, Sequence/ScopeBlock/ModuleNode, ArgNode, ContextMacro и IdentName (через него - IdentType/Decl/VarDecl/FuncDecl); далее - Binary, CallExpr, JumpStmt, ControlFlow и др. Virtual-аксессор `as_sequence()` даёт обходчикам доступ к `m_body` Sequence-узлов без kind-`static_cast`.
- **Единый dump-формат** - `detail::dumpQuotedName` (token_base.hpp) формирует заголовок `Name 'text'` для `IdentName/IdentType/ArgNode/ModuleNode/Decl::dump`; имя выводится однократно.
- **Две группы конструкторов (правило)** - у каждого узла ровно две семьи конструкторов, не смешиваются: (1) терм-конструктор `X(Kind, TermPtr)` - данные (text/дети) читаются из `m_term`, используется TermID-visitor `TermToAstConverter`; (2) manual-конструктор без `TermPtr` - для ручного/синтетического создания (тесты, lowering, временные анализатора), `range()` возвращает невалидный range, `text()` - EXPECT. Гибриды вида `Binary(k, term, left, right)` / `HasText(k, text, term)` запрещены. Нормализация текста (`:` у TypeName, `^`) выполняется терм-конструкторами (`normalizeTermText`), признак `^`→`attr::ReadOnly` применяется единым хелпером `applyReadonlyFromCaret` (и конвертером `convertAttrsToNode`, и `IdentName`). **Конвертер НЕ мутирует исходный Term:** расширенный охват statement'а (для Binary/control-flow/VarDecl/FuncDecl/MatchStmt) вычисляется на лету в override'ах `range()` по узлам-детям (см. `spanOfNodes` в `ast_nodes.cpp`); нереализованные TermID (без Kind) сообщают `Severity::Error` и отбрасываются.
- **Система атрибутов** - value-типы (`AttrId`, `Attr`) и реестр `AttrPool` вынесены в отдельный компонент `attrs` (`attrs/attr.hpp`, `attrs/attr_pool.hpp`). `AttrId` (`uint32_t`) содержит битовую маску: bits 0–23 = индекс в `AttrPool`, bits 24–31 = флаги обработки (builtin/analyzer/codegen/manual). Разбор `@[...]` - `attr_parser.hpp` (здесь, в `ast`): `parse_attr(ctx, range, name, params)` только ищет атрибут в пуле; регистрация выполняется отдельно (`register_attr`/`register_builtin_attr`). Канонические имена встроенных атрибутов - `attr::*` в `attrs/attr_builtin.hpp` (в т.ч. `format` - компиляйт-тайм проверка printf-формата для нативных функций, см. `semantic/format_check.hpp`).
- **Поток данных** - последовательность проходит через конвейер: Flex/Lexer → Sequence → MMProcessor (трансформация) → Sequence → ParserAST.
- **God-class устранён** - старый универсальный `AstNode` заменён на иерархию с распределением полей по специализированным классам.
- **Единая диспетчеризация (kind-visitor)** - `include/ast/kind_visitor.hpp` (`KindVisitor` + `dispatchKind`) генерируется из `PARSER_TOKEN_KINDS` и устраняет цепочки `if(kind)→static_cast` в обходах. Потребители (`SemanticAnalyzer`, `CppTranspiler`) наследуют **абстрактный** `KindVisitor` и реализуют все `visit_<Kind>`: добавили kind в `PARSER_TOKEN_KINDS`, не обработали - не компилируется. `KindVisitorDefault` (notImplemented-заглушки) определяется в тестах (`visit_test.cpp`), в продуктовом коде не используется.
- **Типизированный доступ без RTTI** - `AstNodeBase::is<T>()`/`as<T>()` (token_base.hpp/ast_nodes.hpp) на основе kind→класс из `PARSER_TOKEN_KINDS` через `std::is_base_of_v`; работают и для базовых классов (`is<IdentName>()` для `IdentType`/`VarDecl`). `as<T>()` при неверном kind бросает `FAULT` (не возвращает nullptr). Заменяет `dynamic_cast`/`static_pointer_cast` по AST в анализаторе и кодогене. Trust-контракты объявления - `trustContracts()`/`hasTrustProperty(PropertyKind)`.
- **Machine-checked реестр классов** - `AST_NODE_CLASS_LIST` + `static_assert` (token.hpp) гарантируют, что каждый kind маппится на класс из канонического списка (запрет «нового класса под новый kind») и что в списке нет мёртвых классов.
