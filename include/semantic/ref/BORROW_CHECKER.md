# Анализ инвалидации производных представлений (borrow-checker)

> Спецификация модели `BorrowFlowPass` (`include/semantic/borrow_flow.hpp`).
> Связанные документы: `types/type/REFType.md` §14 (жизненный цикл), `semantic/README.md`,
> `docs/content/ru/docs/safety/borrowing.md`.

## 1. Модель

**TrustLang не реализует модель заимствования Rust.** Здесь нет «займа» как сущности языка:
нет эксклюзивных/разделяемых займов, two-phase borrow, loan-liveness и правила
«aliasing XOR mutability». `borrow` — имя механизма; проверяется
**инвалидация производного представления при мутации/перемещении источника**.

- **Источник (`source`, owner)** — объект/переменная, в чьи данные смотрит представление.
- **Производное представление (`dependent view`)** — сущность, адресующая данные источника:
  view-объект (`iterator`/`span`), результат `@[borrowed]`-метода, нативная ссылка/указатель
  (`ptr`/`ref`), наблюдатель `&?` (`weak`), полученный из `shared`.
- **Инвалидация** — мутация/перемещение/сброс источника делает ранее полученное представление
  недействительным (dangling или протухшим).
- **Правило языка**: пока живо производное представление, мутировать/перемещать источник
  нельзя. Диагностика выдаётся **в точке мутации**, а не при последующем использовании.
- **Освобождение представления**: `dep = _;`, перепривязка (`dep = other;`), выход из скоупа
  объявления представления (fallthrough, `break`, `continue`, `return`, `throw`).
- **Порядок**: представление, рождённое **после** мутации, действительно; инвалидируются только
  представления, рождённые **до** неё (эпоха мутаций).

## 2. Терминология: три механизма

| Термин | Что это | Реализация |
|---|---|---|
| `@[borrowed]` / `-Wborrowed` | контракт «объект держит view в чужие данные»; запрет мутации источника при живых зависимых. Ставится на класс/тип, метод или переменную; БЕЗ атрибута авто-трекинга нет | `semantic/borrow_flow.hpp` (`BorrowFlowPass`) |
| `-Wborrow-*` | тот же механизм инвалидации, но для представлений, полученных из **умных ссылок** (`&?` из `shared`) | `semantic/borrow_flow.hpp` (`BorrowFlowPass`) |
| `Shared::borrow()` / `SharedBorrowedRef` | **runtime**-наблюдатель над `weak_ptr`; истечение проверяется в рантайме (`valid()`/`access()`); к статическому анализу не относится | `runtime/trust/trusted-cpp.hpp` |

`unique` — монопольное владение: alias/заёма/наблюдателя у него НЕТ (`& u` — ошибка,
`types/type/REFType.md` §15.2), поэтому правила R4/R6 к `unique`-представлениям неприменимы.

## 3. Какие представления отслеживаются

- `@[borrowed]`-контракт (`BorrowFlowPass`): класс/тип (все переменные типа зависимы,
  атрибут наследуется производными типами), метод (его результат зависим от объекта),
  переменная (явно зависима).
- Нативные ссылки `@[reftype("ptr"|"ref")]` — в зоне `NativeRefHook` (D3–D7).
- weak-наблюдатель (`BorrowFlowPass`): переменная с `@[reftype("weak")]`/`&?`,
  инициализированная оператором `&` от `shared`-владельца. Значение-копии (в т.ч. `obj[i]`)
  представлениями НЕ являются.

## 4. Правила

Обозначения: `source` — источник, `view` — представление, `region(X)` — регион жизни X
(`scope < thread < program`, выводится из `Storage`; `types/type/REFType.md` §14.3).

- **R1 (lifetime, `borrow-region-mismatch`)** — `region(view) ≤ region(source)`; представление
  не должно переживать источник. Нарушение: `@[thread_local]`-view от локального источника.
  Для refcount-наблюдателя (`weak`) выход за регион источника **не UB** (истечение
  безопасно, доступ бросает) — проверка контракта регионов, а не гарантия памяти.
  Нативные ссылки ограничены правилами D3–D7 (`NativeRefHook`).
- **R4 (source moved/reset, `borrow-owner-moved`)** — move/swap/reset источника при живом
  представлении (`x :=: _`, `@swap`, `x :=: y`).
- **R6 (source mutated, `borrow-owner-mutated`)** — запись в источник (`=`, compound, `++/--`,
  запись в поле/элемент, не-const метод) при живом представлении. Для `shared`-источника
  мутация разрешена (разделяемые данные, refcount-семантика) — см. `shared_mutation_ok.src`.

## 5. Что нарушением НЕ является

- Мутация `shared`-источника при живом `weak`-наблюдателе — штатное refcount-поведение.
- Значение-копия (`obj[i]`, копирование объекта) — не представление.
- `@[lifetime(<area>)]` не расширяет модель: аннотация описывает область жизни view
  (`types/type/REFType.md` §14.2). Для `scope|thread|program` область сверяется с регионом места
  (`borrow-region-mismatch`); `self|param|var|named|_` задаются источником и не проверяются.

## 6. Область (ограничения)

- **Поток живости intra-procedural**: одна функция/лямбда — отдельный CFG/dataflow.
  Межпроцедурные эффекты не моделируются: параметры передаются по значению, поэтому вызов
  не мутирует места вызывающего. Мутация источника через не-const метод объекта
  (`obj.m(...)`) учитывается на receiver'е.
- Детекция представлений структурная (инициализатор/аннотация/атрибут).
- Живость per-path (may-анализ на CFG), освобождение — `dep = _;`, перепривязка, выход из
  скоупа на ВСЕХ путях (fallthrough/`break`/`continue`/`return`/`throw`, LIFO ScopeExit).
  Для weak-представлений дополнительно — точность «последнего использования» (backward liveness).
- Escape: возврат или сохранение в non-view место **@[borrowed]**-представления —
  диагностика `borrow-escape` (weak-наблюдатель безопасен: refcount).
- `@[lifetime(area)]` (нативные виды): area `scope|thread|program` сверяется с регионом места.
- Временные значения / full-expression lifetime не моделируются; `obj[i]` — копия значения,
  не представление.
- Захват представления лямбдой не моделируется: тело лямбды — отдельный CFG, захват по
  значению виден как чтение в точке создания.
- `borrow-static-unproven` (R5) не реализован и в диагностиках отсутствует.

## 7. Реализация и интеграция

- `BorrowFlowPass` (`include/semantic/borrow_flow.hpp`, `src/semantic/ref/borrow_flow.cpp`) —
  flow-проход `Pipeline` ПОСЛЕ DA, по MIR (CFG строится по понижённой форме). Идентичность
  места — узел объявления HIR (PlaceId), а не bare-имя; одноимённые переменные не смешиваются.
- `NativeRefHook` (`semantic/nativeref.hpp`) отвечает только за нативные (сырые) ссылки D3–D7;
  трекинг `@[borrowed]` перенесён в flow-проход.
- Lowering представлений решает `RefTakeExpr::m_lowering` (`src/semantic/typer/ref_typer.cpp`);
  кодоген только печатает (`types/type/REFType.md` §15.4).

## 8. Вне области текущего состояния

Межпроцедурные эффекты свободных функций (параметры по значению их не передают),
временные значения и lifetime extension, представления внутри агрегатов как объект
последующего анализа. Модель намеренно не вводит займы/aliasing-XOR-mutability Rust.
