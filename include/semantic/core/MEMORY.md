## Architecture

Ядро обхода: `NameResolutionPass` (`core/name_resolution.hpp`) владеет обходом и скоуп-стеком и издаёт
события; анализаторы подключаются через `InlineAnalysisHook`. `SemanticPassRunner` — упорядоченный реестр
хуков. `AnalysisContext` — агрегат без вычислительной логики: `SymbolTable` + `NamespaceScope`
(позиция в скоуп-стеке), `TypeResolution` (резолв типов/модульных ссылок), `ExprFacts` (type-state
выражения в поле узла), `AnalysisState` (LSP-проекция, module-набор, счётчики). `captureLastResult` —
пре-семантический проход. Детали — `semantic/README.md`.

## Facts and invariants

- **⚠ `resolveTypeRef` и разрешает, и МАТЕРИАЛИЗУЕТ факт в узле аннотации** (`IdentName::resolvedTypeId`):
  identity пишется в `resolvedTypeId`, полный тип с квалификаторами — в `IdentType::resolvedState`
  (ОДИН раз; повторный резолв использует кэш). Анализаторы не переприменяют attrs аннотации — только
  attrs узла объявления (`applyRefAttrs`). Кодоген читает тип из узла и не резолвит имя. Тип-имена
  в позициях `Ident` материализует `recordTypeName`.
- **`captureLastResult` — ПРЕ-семантический проход** (`$^` переписывается до ядра).
- **⚠ `@__CHECK_AREA__` удаляется В семантике:** узел обрабатывается по единому скоуп-стеку создателей
  областей и заменяется пустым узлом (иначе FAULT в транспиляторе).
- **⚠ whole-if/whole-match:** `IfStmt`/`MatchingStmt` открывают скоуп ХВОСТОМ (`doBranch`: вокруг обхода
  условий/паттернов/тел), а НЕ в группе `doScopeContainer` — та возвращается до `typeExpr` и теряет
  scrutinee-пост-обработку match. Отдельные elseif/else/case НЕ заявляются.
- **⚠ Оператор `... = X` (using) — регистрация областей ПОИСКА, а не импорт:** пути накапливаются до
  конца области (`... = _` — явная ошибка, сброса нет); голое `n` пробует `prefix::n`, и текст ссылки
  НОРМАЛИЗУЕТСЯ на `prefix::n` (иначе кодоген эмитит плоский C++-символ). Область проверяется на ВЫХОДЕ
  из скоупа, поэтому порядок `using`/объявлений внутри блока не важен. Область — ТОЛЬКО namespace
  (тип владеет ЧЛЕНСКИМ скоупом и отклоняется); только TRUST-имена.
- **⚠ Файлы/импорт и маски:** `ModuleNode` открывает скоуп программы, сайт импорта SCOPE-TRANSPARENT;
  файл не namespace-сегмент. Объявления импортированного файла регистрируются в текущем скоупе
  ПОЛНОСТЬЮ, но исключённое маской имя получает file-local ключ. Импорт НЕ транзитивен; повтор под тем
  же ключом видимости — дубль.
- **⚠ Модульная ссылка `\path::name`:** резолв — ТОЛЬКО `TypeResolution::resolveModuleRef`
  (`findVisibleFromModule`): имя обязано быть экспортом указанного модуля и видимым на сайте; тип берётся
  из РАЗРЕШЁННОГО символа (не из текста), иначе аннотация без типа → ICE в HIR. Тексты — единая точка
  `reportModuleRefError`.
- **⚠ Имя-алиас (`f :- ...;`) — объявление ФАЙЛА, а не безусловный экспорт:** file-private и
  локальный/блочный алиас в экспорт-поверхность НЕ входят. Модульный алиас (`\m :- \lib;`) —
  spelling→ModuleIndex в загрузчике, новой идентичности нет.
- **⚠ Неоднозначное голое имя:** диагностируется на сайте ИСПОЛЬЗОВАНИЯ (единая точка
  `reportAmbiguousName`); `resolve` НЕ возвращает неоднозначную плоскую привязку, а `resolveTypeRefImpl`
  сообщает `ambiguous type name` до текстового резолва. Материализация `resolvedTypeId` у ОБЪЯВЛЕНИЯ идёт
  через `lookupTypeName` (там guard не нужен — ключ идентичности своего модуля).
- **⚠ duplicate-import:** ключ `(файл, depth, импорт, нормализованные маски)`; ОДНО сообщение на сайт
  импорта (для группы — не по части); разные маски/scope допустимы; ключи чистятся при exit scope.
- **⚠ Namespace/private:** при выходе из `::`/`name::` объявления переносятся в корневой файловый скоуп
  под `namespacePath()`. `__::` — file-private: ключ `(moduleIndex,name)`, виден всему файлу; `resolve`
  в файловом скоупе пробует private-ключ текущего файла, затем exported — private не протекает в
  импортёр. `_::` (protected) получает плоскую привязку ТОЛЬКО при доступе группы
  (`canAccessProtected`), иначе имя невидимо с сайта — правило `types/names.hpp`
  (доступ вычисляется ОДИН раз на часть сайта и передаётся и в `pushImportScope`, и в `bindImportedModule`).
  `namespacePath()` кэшируется по `(depth, creator текущего скоупа)`.
- **⚠ Инварианты хуков/опций:** `declareOrComplete` НЕ перемещает `Symbol` (копирует) — `onDeclare` видит
  полноценный Symbol; `-q` подавляет только Warning/Note; feature-флаг и DiagId НЕ могут делить cli-имя.
- **⚠ Класс-скоуп открывается/закрывается ТОЛЬКО через `NameResolutionPass::enterScope/exitScope`**
  (фреймы синхронны со скоуп-стеком). Прямой `symbols().push/pop` ЗАПРЕЩЁН (рассинхронизирует хуки).
- **⚠ Лямбда — особый путь в `analyzeNode`, НЕ `analyzeFuncDecl`:** имя НЕ регистрируется в объёмлющем
  скоупе; захваты резолвятся ДО открытия скоупа лямбды; локальные имена нормализованы в `$name`.
  Захват только по значению; у лямбды есть синтетическая метка-имя → `@return v;` валидируется по
  `currentFunc()` и понижается в `return`.
- **Ловушка ContextMacroExpander:** обход детей — через `collectChildren` (ссылки на слоты для замены);
  мутирующий `onNode` возвращает true, если заменён.
- **⚠ trust-контракты:** `collectChildren()` их не отдают — ядро обрабатывает явно; severity `-Wsolver`
  действует только когда `--solver-mode` НЕ задан. Правила Pre/Post и защита от авто-вывода —
  `verify/MEMORY.md` (авторитетная копия).
- **⚠ `bareLocalName` (срезает `$`) ≠ `utils::bareName` (срезает `%`/`^`):** разные домены имён
  (локальные переменные vs ключ метода); не смешивать.
- **⚠ `1:Bool < 5` парсится как СРАВНЕНИЕ** (ловушка шаблон-аргументов, учитывается в резолве типов).
