## Architecture

Семантика **однопроходная**: имя обязано быть объявлено до использования (forward references
исключены синтаксисом). Ядро — `NameResolutionPass` (драйвер, НЕ хук: владеет обходом и
скоуп-стеком, издаёт события); анализаторы подключаются через `InlineAnalysisHook`, всегда
подключён `ContextMacroExpander`. Пайплайн: Parser → SemanticPassRunner → [успех] → CppTranspiler.
Тяжёлая логика — в анализаторах, разделяющих `AnalysisContext`; типы выражений кешируются.

## Facts and invariants

- **Общие продукты анализа вынесены в `include/analysis`:** `SymbolTable`/`Symbol`/`SymbolIndex` — там
  (разделяются с кодогеном); здесь — драйвер обхода (`NameResolutionPass`), анализаторы и `AnalysisContext`.
- **Владелец поведенческих флагов (solver/stack-check) — semantic;** value-типы режимов и
  `analysis::BehavioralModes` — в `analysis/modes.hpp`; единая точка разрешения —
  `semantic::behavioralModesFromOptions` (передаётся в кодоген как данные).
- **lowering переносит анализирующую логику в AST** (транспилятор — только кодогенератор):
  statement-выражения → `SemicolonStmt`, именованные break/continue → goto/метки, break по имени
  функции → синтетический void-return. Синтетические узлы имеют невалидный range.
- **⚠ `@__CHECK_AREA__` маркер удаляется В семантике** (до транспилятора не доходит; иначе FAULT):
  `CheckAreaStmt` обрабатывается по ЕДИНОМУ скоуп-стеку создателей областей и заменяется пустым
  узлом. Текущая область = список `AreaKind` по creator-скоупам от внутреннего к глобальному
  (module-скоуп есть всегда).
- **⚠ whole-if/whole-match:** `IfStmt`/`MatchingStmt` открывают скоуп ХВОСТОМ (вокруг
  handleNode+analyzeChildren в analyzeNode, НЕ в ранней enterScope-группе — та возвращается до
  typeExpr и теряет scrutinee-пост-обработку match). Creator: If→AreaKind::If, Match→AreaKind::Match.
  Отдельные elseif/else/case НЕ заявляются.
- **Оператор `... = X` (using) — регистрация областей ПОИСКА, а не импорт:** регистрирует пути как
  префиксы поиска в текущем скоупе и заменяется пустым узлом; голое `n` пробует `prefix::n`.
  Только TRUST-имена (нативные `%std::…` не резолвит). Требует персистентных квалифицированных
  символов: статические члены регистрируются глобально (скоуп класса pop-ается).
- **trust-контракты:** `collectChildren()` их не отдают — ядро обрабатывает явно. Единая точка по
  двум ортогональным опциям: severity `-Wsolver` (только когда `--solver-mode` НЕ задан) и
  поведенческий `--solver-mode`. export/calculate НЕ генерируются здесь. В Pre имя самой функции -
  ошибка; в Post — имя функции = возврат.
- **Защита от авто-вывода:** тип с trust-условиями не выводится автоматически — ошибка с
  требованием явной аннотации.
- **⚠ enum:** члены сравниваются по значению, но type-safe (нельзя `Weight.ZERO == 0`). Enum —
  единый тип у членов; Variant — каждый член своего типа.
- **Тип переменной — монотонное расширение:** `x := expr` — тип из инициализатора, по присвоениям
  join. Невозможный вывод — явно `std::any`; INVALID с инициализатором = ошибка вывода. Голый
  тип-имя справа в `:=` — ошибка (тип через `::=`).
- **⚠ классификация операторов:** `isCompoundAssignOp` — ЯВНЫЙ список `op=` (`+=`,…), НЕ по
  суффиксу `=`. Иначе `==`/`<=`/`>=` трактовались бы как составные присваивания и расширяли тип
  LHS до Bool.
- **⚠ Контроль переполнения — классификация в семантике (`Binary::m_overflowCheck`):** `typeBinaryResult`
  решает для `+ - *`/`+= -= *=` (предикат `isOverflowCheckableOp` из `ast/binary_op.hpp`), возможна ли
  детекция переполнения (знаковые машинные целые операнды/результат), и пишет `optional<bool>`. Кодоген
  признак только читает. unsigned wrap/BigInteger/Rational/не-целые/Bool-продвижение → `false`;
  узел вне класса → `nullopt`. Формула — по `lt`/`rt`/`result` (не по Bool-продвинутым `elt`/`ert`).
- **Auto-Bool vs явный Bool:** auto-Bool (Bool в НЕтипизированной переменной) продвигается до
  максимального Int в составной числовой арифметике; явный `:Bool` так не расширяется (ошибка).
  Буквальные 0/1 — Int8.
- **Константность:** `^`/`@[readonly@]` ставит бит на тип символа; запись в константную — ошибка.
- **Сужение:** проверяется только в явно-типизированную цель по ширине (inferred-цели — нет).
  Цель-ссылка + значение — валидно (обёртка), weak из значения — ошибка; источник-ссылка +
  цель-значение — ошибка; обе ссылки — оси и pointee совпадают. Для `@[reftype]`-пути цель брать из
  `Symbol::type`.
- **⚠ `literal :Type` — ЕДИНЫЙ решатель** для всех путей: выбор типа + причина, БЕЗ диагностики и
  БЕЗ fallback (невалидный → INVALID). `resolveType` сам НЕ диагностирует. ЕДИНСТВЕННЫЙ репортёр —
  `typeExpr`; провизионные читатели решают тем же решателем, но НЕ репортят (иначе дубли/тишина).
- **Деструктуризация `t1..tN := [...]:`** — точная привязка по арности; вложенная не
  поддерживается; rest-цель == источник — `pop_front`; аннотация типа на rest-цели — Error.
- **Методы:** `findMethod` односто­ронний (обычное имя находит и обычный, и `%native`); инвариант
  «одна форма имени».
- **⚠ Перегрузка — ЕДИНЫЙ резолвер; TrustLang резолвит АНАЛИЗАТОР ВСЕГДА:** для TrustLang-функций
  и Record-методов `resolveOverload` (`types/overload_resolve.hpp`) применяется ВСЕГДА — в т.ч. при
  ЕДИНСТВЕННОЙ сигнатуре (выбор и допустимость аргументов определяет компилятор, не C++). Результат —
  `CallExpr::resolvedSignature` (+ `resolvedCalleeSuffix` при >1 сигнатуре); для методов —
  `Binary::resolvedMethodSuffix` (Record-методы, >1 сигнатура). Повторный резолв по имени запрещён.
  C++-делегирование — ТОЛЬКО для НАТИВНЫХ (`%`/импорт-алиас/нативный класс): имя фиксировано внешней
  библиотекой и не манглируется. `overloadConversionRank` ЗЕРКАЛИТ неявные C++-конверсии (сужение,
  BigInt/Rational, производный→базовый); `INVALID`-тип (нетипизированный параметр) = `Any`. Многоточие
  в аргументах — только при единственной сигнатуре (иначе явная ошибка); `analyzeCallFilling` читает
  `resolvedSignature`.
- **⚠ Два РАЗНЫХ кейса многоточия (не путать):** (1) ВАРИАТИВНЫЙ ПРОТОТИП `f(a:T, ...)` —
  «произвольное число аргументов в последней позиции»: кодируется `FunctionTypeData::variadicType`
  (=Any), а НЕ лишним параметром (`buildFuncType` ПРОПУСКАЕТ `...`); перегрузка резолвится по типам
  аргументов, лишние матчатся `variadicType`. (2) РАЗВОРОТ многоточия в АРГУМЕНТАХ вызова
  `f(a, ... expr ...)` / `f(a, ...)` (Fill/Repeat) — capacity-driven МАТЕРИАЛИЗАЦИЯ
  (`semantic/ellipsis`): нужна КОНКРЕТНАЯ сигнатура (число/типы позиций), поэтому допустима только
  при ЕДИНСТВЕННОЙ сигнатуре (иначе явная ошибка).
- **`@[format("printf", strIdx, firstToCheck)]`** — индексы 1-based (GCC); `%s` ожидает
  `const char*`, StrChar требует `.c_str()`.
- **`@[borrowed]` — отслеживание инвалидации view в ДАННЫЕ:** атрибут на классе/методе/переменной
  делает переменную зависимой; БЕЗ атрибута ничего не отслеживается (значение-копии и умные ссылки
  не зависимые). Атрибут КОПИРУЕТСЯ при создании/присваивании. Любая мутация источника (assign ИЛИ
  не-const метод) инвалидирует зависимые, рождённые ДО мутации. «Зависимая» решается СТРУКТУРНО по
  инициализатору/типу; ⚠ имена — «bare» (без `$`).
- **Нативная ось ссылок — только явный `@[reftype("ptr"|"ref")]`; маркеры `%&`/`%*` и узлы
  NativeRef* УДАЛЕНЫ.** `*` — общий оператор разыменования; `&` в выражении — address-of (weak из
  shared).
- **Единая точка «заявленный вид → тип»:** вид (`@[reftype]`/маркер) применяется к базовому типу;
  `kValue` → оборачивает, совпадающий → без изменений, иначе mismatch-error. `w := & x` (weak без
  маркера) — ошибка.
- **⚠ маркеры ссылки — НЕ «сиглы», позиция определяет смысл:** `&&`=unique, `&*`=shared, `&?`=weak.
  Вид задаётся РОВНО В ОДНОЙ позиции: у ТИПА (сигл при resolveType ИЛИ `@[reftype]` на узле типа)
  ИЛИ у ПЕРЕМЕННОЙ только при ОПУЩЕННОМ типе. Один вид в ОБЕИХ позициях → `-Wref-kind-dup`;
  РАЗНЫЕ → mismatch; вид у переменной при ЯВНОМ типе → ошибка. Вид у типа надо учитывать ОБОИМИ
  способами (сигл + attr) — иначе рассинхрон. Без явного типа pointee выводится из инициализатора.
- **Ловушка ContextMacroExpander:** обход детей — через `collectChildren` (ссылки на слоты для
  замены); мутирующий `onNode` возвращает true если заменён.
- **Стек:** ⚠ `@__OPTION__("stack-check","off")` сбрасывает enabled и значение → режим обязан быть
  kOff при отключённом флаге. `StackCheckInferHook` (recursion/auto): граф вызовов; auto →
  `add_attr(stack_check)` на рекурсивный FuncDecl.
- **Нативные шаблоны-типы:** регистрируются абстрактным шаблоном (НЕ как функция); резолв
  `vector<Int32>` интернирует инстанциацию; дубль C++-имени со встроенным — Warning. ⚠ `1:Bool < 5`
  парсится как СРАВНЕНИЕ.
- **Forward-объявление классов/шаблон-классов (`X ::= %std::...{...};`)** — узел `ClassDecl` (RHS —
  любое имя, native = `%`), обрабатывается из analyzeTypeDecl (узел-ребёнок в analyzeNode — no-op,
  иначе двойная регистрация). Регистрирует тип (kNativeClass/kNativeTemplate), биндит trust-имя;
  методы и поля (VarDecl-члены) — через `addMethod` (ключи `%...`); **поле без явного типа или
  не-найденное — ERROR, НЕ `Any`**. **Члены:** статический — имя с `::` (`Cls.field` → `cppName::name`
  + `-Wstatic-member-as-field`; `Cls::name` — без предупреждения), экземплярный — без `::`
  (правильная регистрация — ведущая `.`, иначе `-Wclass-member-dot`). `@__CLASS__`/`currentClass()` —
  из скоуп-стека. Шаблонность ВЫВОДИТСЯ из `m_template`, НЕ флагом. Обобщённая форма → «not
  implemented».
- **⚠ UNKNOWN-тип не должен доходить до кодогенерации:** при INVALID_TYPE_ID — явная диагностика +
  FAULT (вместо тихого `auto`). Абстрактные типы (Tuple/Range/Array/Dict) легитимно дают `auto` —
  это НЕ UNKNOWN.
- **⚠ транспилятору локальные символы недоступны:** семантика сохраняет на узлах тип результата
  `& x` (weak), вид операнда `*ref` и lowering — иначе кодоген не выберет `*(c.lock())` vs
  `checked_deref(...)`.
- **`*` — БЕЗ UB на nullptr:** unique/ptr — через `trust::checked_deref` (бросает `IntMinus`);
  shared/weak — `*(ref.lock())`.
- **swap `:=:` — интринсик** (`Binary(AssignOp)`, `isSwapOp`): `a :=: b` → std::swap (типы
  СОВМЕСТИМЫ, не обязательно ссылки); `var :=: _` → std::move. Нужна явная ветка до общей типизации.
- **⚠ нетипизированная локальная `x := _;` — монотонный вывод по записям:** записи дают конкретный
  C++-тип; запись НЕСОВМЕСТИМОЙ категории → Error с требованием `x:Any := _`. Без
  записей/использований → Error «cannot infer type» при выходе скоупа (НЕ `-Wunused-variable`).
  Нелокальная untyped `:= _` → Error «requires an explicit type». Типизированные `x:T := _` не
  затрагиваются.
- **⚠ unique — move-only:** копирование (init/присваивание) — ошибка; перенос — только `a :=: b` /
  `a :=: _`; swap исключён.
- **⚠ Record-типы (Struct/Class) — единый анализ:** `:Struct` → POD-группа, `:Class`/пользовательский
  → классы (наследование). **`baseClasses` — ОТДЕЛЬНОЕ поле дескриптора, НЕ `baseType`**: иначе
  `getCanonicalTypeId()` схлопнул бы производный в базовый. `analyzeNode` для члена-объявления —
  no-op (не обходить повторно). Struct не наследует — ошибка.
  - **Значения полей:** forward `:= ...` для поля — ошибка. Struct: default ЗАПРЕЩЁН (NSDMI ломает
    тривиальность), только `:= _`. Class: значение не проверяется.
  - **Шаблон-классы:** класс-скоуп до резолва баз; параметры — template-param типы; базы —
    `resolveType` (не `findType`); конструктор `Box(...)` типизируется по типу-цели контекста.
  - **`@[virtual]`/`@[override]`** — встроенные, НЕ реализованы: явная ошибка «not implemented».
- **Borrow-checker (v1) — ВСЕГДА подключён** (флага вкл/выкл НЕТ; настраиваются только уровни
  `-Wborrow-<name>=<sev>`): per-frame регионы из `Storage` (Local→scope, thread_local→thread,
  Static/Global→program) и правила R1 (region-mismatch)/R4 (owner-moved)/R6 (owner-mutated). R5
  УДАЛЁН вместе с заёмом `unique` (`& u` запрещён). Per-frame эпоха адресуется по фрейму
  ОБЪЯВЛЕНИЯ переменной; R6 — только для `unique`.
- **Инварианты хуков/опций:** `declareOrComplete` НЕ перемещает `Symbol` (копирует) — `onDeclare`
  видит полноценный Symbol; `-q` подавляет только Warning/Note; feature-флаг и DiagId НЕ могут
  делить cli-имя.
- **Класс-скоуп открывается/закрывается ЧЕРЕЗ `NameResolutionPass::enterScope/exitScope`** (фреймы
  синхронны со скоуп-стеком). Прямой `symbols().push/pop` ЗАПРЕЩЁН (рассинхронизирует хуки).
- **Валидация операторов — единая `semantic::validateOperatorDecl` (`semantic/operator_check.hpp`):**
  вызывается из `analyzeFuncDecl` (СВОБОДНЫЕ операторы), `record_decl_analyzer` (user Class/Struct) и
  `class_decl_analyzer` (нативные классы) - у членов иначе объявление принималось бы МОЛЧА. Форма
  member/free — `AnalysisContext::insideTypeBody()`. Проверяются: шаблонность
  (`template operators are not implemented`), символ из `types/operator_registry.hpp`
  (`not implemented` иначе), allow_member/allow_free, обязательный тип возврата, арность (member — на
  один параметр меньше free; `[]` — ровно 1; `()` — без ограничения). Дубликат символа в типе —
  явная ошибка анализатора типа (перед `addMethod`, который делает FAULT). `-Wclass-member-dot` на
  операторов не действует.
- **⚠ Регистрация/резолв операторов (единый источник на форму):** member-оператор живёт ТОЛЬКО в
  таблице методов типа (`TypeRegistry::addMethod`) - `analyzeFuncDecl` для него НЕ регистрирует символ в
  скоупе (иначе `resolve("==")` внутри метода класса путал бы member-оператор со свободным → ложный
  «ambiguous»); свободный оператор - обычная функция: символ в скоупе (модуль/namespace), резолв
  использования через `symbols().resolve(sym)`. Отдельной таблицы операторов НЕТ.
  - **Сравнения над record/native-типами** (`typeBinaryResult`, CompareOp): требуется объявленный
    оператор (member на LHS `findMethodInfo(lc,sym)` ИЛИ свободный из таблицы символов); member+free одного символа —
    ошибка «ambiguous»; нет оператора — «no matching operator»; результат = `returnType`.
  - **Вызов значения `a(args)`** (`typeCallNode`): при record/native callee резолвится оператор `()`
    (арность/многоточие — как у метода), результат = `returnType`; нет `()` — ошибка. НЕ перехватываются
    именованные функции/значения функц. типа и вызов-конструктор по имени типа (`findType`).
  - **Индексация `a[i]`** — `AccessResolver::resolveSubscriptOperatorAccess` (объявленный `[]`): тип =
    `returnType`, `lhsType`=тип объекта (кодоген → `(obj)[idx]`); record/native БЕЗ `[]` — явная ошибка
    (в словарный `.at()` не уходим); `void operator[]` в выражении — ошибка.
- **Лямбда — особый путь в `analyzeNode`, НЕ `analyzeFuncDecl`:** имя НЕ регистрируется в
  объёмлющем скоупе; захваты резолвятся ДО открытия скоупа лямбды. Локальные имена нормализованы в
  `$name` (резолв захвата пробует оба). Тип значения ставит `typeExpr` ЯВНО (ранний return в ветке
  FuncDecl пропускает общий пост-порядковый вызов). Захват только по значению. У лямбды есть
  синтетическая метка-имя → `@return v;` валидируется относительно `currentFunc()` и понижается в
  `return`; безымянный `++ v ++` остаётся `throw IntPlus`.
- **Замыкающее многоточие в списках (Fill/Repeat/Spread) — ЕДИНЫЙ примитив**, общий для аргументов
  вызова и элементов массива. Fill/Repeat capacity-driven: семантика МАТЕРИАЛИЗУЕТ список, поэтому
  кодоген о многоточии НЕ знает (`visit_Filling`/`visit_Ellipsis` → FAULT). Capacity — из типа-цели
  либо `paramTypes` вызываемого (у метода с `T→Elem`). Spread не материализуется → диагностика
  пост-проходом. ⚠ аргументы вызова метода анализируются ОТДЕЛЬНО (MemberAccess уходит с ранним
  return). Диагностика сопровождается «diagnose-then-discard», чтобы не давать каскад.
- **Отладочная диагностика:** `@__DEBUG__` — только фильтр сообщений `TRUST_DEBUG` (с эхом);
  `@__DEBUG_SCOPE__` — дамп состояния независимо от фильтра. Полное описание — корневой `MEMORY.md`.
- **⚠ Рекурсивные ссылки в полях:** имя record-типа видно в собственном теле (declareRecord ДО
  анализа полей; `defineRecord` доопределяет), forward (`:Name ::= :Base ...;`) доопределяется позже.
  Анализатор `RefCycleHook` (finalize-постпроход) строит граф по полям/базам с видами рёбер
  inline/heap-inline/unique-ptr/shared и делает ТРИ независимых анализа по ПОДМНОЖЕСТВАМ рёбер
  (цикл лежит в SCC своего подмножества): (1) shared-ребро внутри SCC полного графа → `-Wrecursive-shared`;
  (2) нетривиальная SCC подграфа ТОЛЬКО inline-рёбер → `-Wrecursive-value` (бесконечный размер);
  (3) SCC≥2 подграфа ТОЛЬКО unique-указательных рёбер → `-Wrecursive-unique`. Полно по всем циклам
  (одиночная классификация по объединению рёбер SCC маскировала inline-подцикл при наличии unique-ребра).
  Self-ссылка `unique`-указателем — легальный список. `weak/ptr/ref/locker` невладеющие; элементы
  `:Array` (std::vector) — heap-inline (не размер: self-вектор легален), `:Range` — view (ребра нет).
  Шаблон-инстанс разворачивается по полям; self-инстанциация абстрактного шаблона схлопывается на шаблон.
