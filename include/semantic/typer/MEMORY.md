## Architecture

`ExprTyper` — фасад над профильными типизаторами (`VarTyper`/`CallTyper`/`MethodCallTyper`/
`ContainerTyper`/`BinaryTyper`/`RefTyper`); общий доступ к сервисам драйвера и проверкам присваивания
даёт `TyperBase`; `AccessResolver` отвечает за доступ к полям/элементам. Перегрузка — единый
`resolveCall` (`types/call.hpp`), привязка аргументов — `call_binding`, приведения —
`arg_casts`, многоточие — `ellipsis`, наборы типов — `type_set`.

## Facts and invariants

- **⚠ `materializeArgCasts`:** после ядра и ДО lowering заполняет `CallExpr`/`Binary::argCasts` по
  выбранной сигнатуре; кодоген только печатает. Для `Binary` — только `emitOperatorDispatch`. Второго
  вывода приведения нет.
- **⚠ Обход type-графа — ЕДИНЫЙ исчерпывающий** (`types/types.hpp`): перечень type-полей
  `TypeData` не дублируется по потребителям. Списковость позиции pack'а выводится из ВИДА РОДИТЕЛЯ.
- **⚠ enum:** члены сравниваются по значению, но type-safe (нельзя `Weight.ZERO == 0`). Enum — единый тип
  у членов; Variant — каждый член своего типа.
- **Тип переменной — монотонное расширение:** `x := expr` — тип из инициализатора, по присвоениям join;
  невозможный вывод — явно `std::any`. Голый тип-имя справа в `:=` — ошибка (тип через `::=`).
- **⚠ Наборы типов (`:A + :B`, исключения `-`) — только валидация комбинаций:** ведущий `-`; `-` только
  для подтипа начального типа ветки; дубль корня; исключение чужого/более широкого типа; составной член
  (шаблон/кортеж/ссылка) внутри набора. Определение `::=`, возврат и параметр набором — явная ошибка
  «not implemented yet» (разворота в N определений нет).
- **⚠ классификация операторов:** `isCompoundAssignOp` — ЯВНЫЙ список `op=`, НЕ по суффиксу `=`, иначе
  `==`/`<=` трактовались бы как составные присваивания и расширяли тип LHS до Bool.
- **⚠ Контроль переполнения — классификация в семантике (`Binary::m_overflowCheck`):** `typeBinaryResult`
  решает для `+ - *`/`+= -= *=`, возможна ли детекция (знаковые машинные целые), и пишет
  `optional<bool>`; unsigned wrap/BigInteger/Rational/не-целые → `false`, вне класса → `nullopt`.
- **Bool в арифметике запрещён** (`+ - *`, `+= …`, `++`/`--`): авто-продвижения Bool нет. `true`/`false`
  = `1:Bool`/`0:Bool`; литералы 0/1 — Int8.
- **Константность:** `^` — `QualType::isConst()` (type-state, не identity); `@[readonly]` — type-level const.
  Поле записи хранит объявленный `QualType`, поэтому `const`-поле типизируется как const и запись в него —
  ошибка.
- **Сужение:** проверяется только в явно-типизированную цель по ширине (inferred-цели — нет).
  Цель-ссылка + значение валидно (обёртка), weak из значения — ошибка; источник-ссылка + цель-значение —
  ошибка; обе ссылки — оси и pointee совпадают.
- **⚠ `literal :Type` — ЕДИНЫЙ решатель** для всех путей: выбор типа + причина, БЕЗ диагностики и БЕЗ
  fallback (невалидный → INVALID). ЕДИНСТВЕННЫЙ репортёр — `typeExpr`; провизионные читатели решают тем
  же решателем, но НЕ репортят (иначе дубли/тишина).
- **⚠ Generic-функции/шаблонный native-import:** типовые параметры активируются в
  `TypeResolution::m_templateParamScopes` (НЕ в SymbolTable) до `analyzeFuncDecl`; `resolveTypeRef` сначала
  смотрит этот стек. Вызов разрешается единым `resolveCall`; generic-методы/операторы/лямбды — явная
  ошибка. Type-packs: `<T...>` — один trailing pack-параметр; pack-значение в теле запрещено; в возврате
  pack допустим только в списковом контексте. Non-trailing, zip, pack в class-шаблонах — явные ошибки.
- **⚠ нетипизированная локальная `x := _;` — монотонный вывод по записям:** несовместимая категория →
  Error с требованием `x:Any := _`; без записей/использований → Error «cannot infer type» при выходе
  скоупа (НЕ `-Wunused-variable`); нелокальная untyped `:= _` → Error «requires an explicit type».
- **⚠ Перегрузка — ЕДИНЫЙ резолвер; TrustLang резолвит АНАЛИЗАТОР ВСЕГДА:** для TrustLang-функций и
  Record-методов `resolveCall` применяется ВСЕГДА, в т.ч. при ЕДИНСТВЕННОЙ сигнатуре. Результат —
  `CallExpr::resolvedSignature` (ЭФФЕКТИВНАЯ сигнатура), имя/суффикс — от ОБЪЯВЛЕННОЙ и тоже всегда.
  Повторный резолв по имени запрещён. `overloadConversionRank` ЗЕРКАЛИТ неявные C++-конверсии; `INVALID`
  и параметр `:Any` = низший ранг; `Any→Any` exact, `Any→concrete` not viable.
- **⚠ Нативные (`%`) вызовы:** для нативных МЕТОДОВ анализатор проверяет арность и типы; для НАБОРА
  перегрузок функции он же выбирает сигнатуру; для единственной конверсию выполняет C++. Имя нативного
  символа НЕ манглируется; перегрузка C-символа (`extern "C"`) запрещена явной диагностикой; нативное
  C++-имя (`%lib::f`) перегружается.
- **⚠ Разрешение вызываемого — один вход на способ подготовки аргументов:** позиционные формы —
  `resolveCallablePositional` + `CallFailureText` (тексты неуспеха принадлежат ФОРМЕ); свободные
  функции/методы — `resolveCallOverload`/`...WithTemplates`; именованные/default/многоточие —
  `gatherBoundCandidates` + `reportBound*`.
- **⚠ Привязка аргументов (`typer/call_binding.hpp`):** позиционные/именованные (`.name=`) раскладываются
  по `CallableParamInfo`; все кандидаты ранжируются ЕДИНЫМ `resolveCall`; результат — `CallExpr::boundArgs`
  в порядке параметров. Default остаётся в C++-объявлении; пропуск default перед явным аргументом, default
  со ссылкой на параметр, named-аргументы native/конструктора и generic с named/опущенными default —
  явные ошибки.
- **⚠ Два РАЗНЫХ кейса многоточия:** (1) ВАРИАТИВНЫЙ ПРОТОТИП `f(a:T, ...)` кодируется
  `FunctionTypeData::variadicType` (=Any), а НЕ лишним параметром; (2) РАЗВОРОТ многоточия в АРГУМЕНТАХ
  — capacity-driven МАТЕРИАЛИЗАЦИЯ (`typer/ellipsis`): нужна КОНКРЕТНАЯ сигнатура, поэтому только при
  ЕДИНСТВЕННОЙ (иначе явная ошибка).
- **⚠ Замыкающее многоточие (Fill/Repeat/Spread) — ЕДИНЫЙ примитив** для аргументов вызова и элементов
  массива. Fill/Repeat семантика МАТЕРИАЛИЗУЕТ (capacity из типа-цели/paramTypes), кодоген многоточия НЕ
  знает; Spread не материализуется — диагностика пост-проходом. ⚠ аргументы метода анализируются
  ОТДЕЛЬНО (ранний return MemberAccess); диагностика «diagnose-then-discard» (без каскада).
- **⚠ Эффективные сигнатуры набора — ЕДИНЫЙ примитив `effectiveMethodSignatures`:** подставляет T→Elem
  для Range/Array/Tensor и типовые аргументы native-template, СОХРАНЯЯ порядок (индекс выровнен с
  набором) — на этом держится C++-суффикс по `chosenIndex`. `INVALID` в позиции — инстанциация
  невозможна, диагностирует вызывающий.
- **⚠ Валидация операторов — единая `validateOperatorDecl`:** вызывается из `analyzeFuncDecl`
  (СВОБОДНЫЕ), `record_decl_analyzer` и `class_decl_analyzer` — у членов иначе объявление принималось бы
  МОЛЧА. Форма member/free — `insideTypeBody()`. Проверяются шаблонность (не реализована), имя из
  `types/call.hpp`, allow_member/allow_free, обязательный тип возврата, арность (member — на
  один параметр меньше; `[]` — ровно 1). Дубликат — по ЭФФЕКТИВНОЙ сигнатуре; postfix dummy — ровно
  `Int32`. Свободный оператор обязан иметь ≥1 параметр пользовательского типа.
- **⚠ Объявленные операторы разрешаются ДО numeric/ref-веток единой точкой `resolveUserOperator`:** вход —
  операнды в ИСХОДНОМ порядке (получатель первый), `postfix` (dummy `Int32` в аргументах, но не в тексте
  диагностики). Внутри member + free → ОДИН набор кандидатов, member несёт неявный object-параметр →
  один `resolveCall`; формы ранжируются одной шкалой (C++ [over.match.oper]). Guard — ЛЮБОЙ операнд
  пользовательского типа (`5 == p` законен); built-in/numeric решает вызывающий.
- **⚠ Регистрация/резолв операторов (единый источник на форму):** member-оператор живёт ТОЛЬКО в
  таблице методов типа под dunder-именем; `analyzeFuncDecl` имя в скоупе НЕ регистрирует (иначе
  `resolve("__eq__")` внутри класса путал бы его со свободным → ложный «ambiguous»); свободный оператор —
  обычная функция. Отдельной таблицы операторов НЕТ. **⚠ Свободный оператор живёт в модуле типа одного из
  операндов:** у operator-функции нет синтаксиса модульной квалификации, иное размещение сделало бы имя
  неоднозначным без способа разрешения; кодоген изолирует оператор namespace'ом модуля.
  `a(args)` для record/native резолвится в `__call__`, `a[i]` — в `__getitem__` (без него — явная ошибка,
  в `.at()` не уходим).
- **⚠ Native single-signature операторы/методы НЕ обходятся:** `[]`, `()`, унарные/бинарные всегда
  проходят единый конвейер; C++-делегация — только native free функций с C-linkage и единственной
  сигнатурой. Статические перегрузки native-класса — набор сигнатур, C++-имя фиксировано без суффикса.
- **⚠ Унарный оператор: member и free разрешаются РАЗДЕЛЬНО:** если жизнеспособны обе формы — явная
  ошибка ambiguous; ранги между формами не сравниваются (у member неявный `this` не входит в `argTypes`).
- **⚠ const-форма метода — отдельный ключ `^`:** при отсутствии const-формы поиск возвращает не-const
  вариант; const-correctness вызовов как проверка не реализована.
- **⚠ C++-вставка `{% ... %}`: модуль имён из резолва.** `RawText::embedNames` заполняет семантика;
  кодоген конвертирует маркер через namespace модуля. `$`-локальные не квалифицируются.
