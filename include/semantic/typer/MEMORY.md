## Architecture

`ExprTyper` — фасад над профильными типизаторами (Var, Call, MethodCall, Container, Binary, Ref); общий
доступ к сервисам драйвера и проверкам присваивания — `TyperBase`; `AccessResolver` — доступ к
полям/элементам. Перегрузка — единый `resolveCall` (`types/call.hpp`); привязка аргументов, приведения,
многоточие, наборы типов — отдельные зоны (`typer/call_binding`, `arg_casts`, `ellipsis`, `type_set`).

## Facts and invariants

- **⚠ `materializeArgCasts`:** после ядра и ДО lowering заполняет `CallExpr`/`Binary::argCasts` по выбранной
  сигнатуре — кодоген только печатает. Для `Binary` — только `emitOperatorDispatch`. Второго вывода нет.
- **Обход type-графа — ЕДИНЫЙ исчерпывающий** (`types/types.hpp`): перечень type-полей не дублируется по
  потребителям; списковость pack'а — из ВИДА РОДИТЕЛЯ, не из поля.
- **Enum:** члены сравниваются по значению, но type-safe (`Weight.ZERO == 0` нельзя); Enum — единый тип у
  членов, Variant — каждый член своего типа.
- **Тип переменной — монотонное расширение** (`x := expr` — тип из инициализатора, join по присвоениям);
  невозможный вывод — явно `std::any`. Голый тип-имя справа в `:=` — ошибка (тип через `::=`).
- **⚠ Наборы типов (`:A + :B`, исключения `-`) — только валидация комбинаций:** ведущий `-`; `-` лишь для
  подтипа начального типа; дубль корня; исключение чужого/более широкого типа; составной член в наборе.
  Определение `::=`, возврат и параметр набором — явная ошибка (разворота в N определений нет).
- **⚠ `isCompoundAssignOp` — ЯВНЫЙ список `op=` , НЕ по суффиксу `=`** (иначе `==`/`<=` трактовались бы как
  составные и расширяли тип LHS до Bool).
- **⚠ Контроль переполнения — классификация в семантике (`Binary::m_overflowCheck`):** `typeBinaryResult`
  решает для `+ - *`/`+= -= *=`, возможна ли детекция (знаковые машинные целые), пишет `optional<bool>`;
  unsigned wrap/BigInteger/Rational/не-целые → `false`, вне класса → `nullopt`.
- **Bool в арифметике запрещён** (`+ - *`, `+=…`, `++`/`--`); `true`/`false` = `1:Bool`/`0:Bool`, литералы 0/1 — Int8.
- **Константность:** `^` — `QualType::isConst()` (type-state, не identity); `@[readonly]` — type-level const.
  Поле записи хранит объявленный `QualType` → const-поле типизируется как const, запись в него — ошибка.
- **Сужение** — только в явно-типизированную цель по ширине (inferred-цели — нет). Цель-ссылка + значение ок
  (обёртка), weak из значения — ошибка; источник-ссылка → цель-значение — ошибка; обе ссылки — оси/pointee совпадают.
- **⚠ `literal :Type` — ЕДИНЫЙ решатель** всех путей (выбор типа + причина) БЕЗ диагностики и БЕЗ fallback
  (невалидный → INVALID). ЕДИНСТВЕННЫЙ репортёр — `typeExpr`; провизионные читатели решают им же, но не репортят.
- **⚠ Generic-функции/шаблонный native-import:** типовые параметры активируются в
  `TypeResolution::m_templateParamScopes` (НЕ SymbolTable) до `analyzeFuncDecl`; `resolveTypeRef` сначала
  смотрит этот стек. Type-packs `<T...>` — один trailing; pack-значение в теле запрещено; в возврате — только
  списковый контекст. Non-trailing/zip/pack в class-шаблонах — явные ошибки.
- **⚠ нетипизированная локальная `x := _;` — монотонный вывод по записям:** несовместимая категория → Error
  с требованием `x:Any := _`; без записей/использований → Error «cannot infer type» при выходе скоупа (НЕ
  `-Wunused-variable`); нелокальная untyped `:= _` → Error «requires an explicit type».
- **⚠ Перегрузка — ЕДИНЫЙ резолвер; применяется ВСЕГДА**, в т.ч. при единственной сигнатуре. Результат —
  `CallExpr::resolvedSignature` (ЭФФЕКТИВНАЯ), имя/суффикс — от ОБЪЯВЛЕННОЙ. Повторный резолв по имени запрещён.
  `overloadConversionRank` зеркалит неявные C++-конверсии; `INVALID` и параметр `:Any` = низший ранг;
  `Any→Any` exact, `Any→concrete` not viable.
- **⚠ Нативные (`%`) вызовы:** для метода анализатор проверяет арность/типы; для НАБОРА перегрузок выбирает
  сигнатуру; для единственной конверсию делает C++. Имя нативного символа НЕ манглируется; перегрузка
  C-символа (`extern "C"`) — запрещена, C++-имя (`%lib::f`) — перегружается.
- **⚠ Привязка аргументов (`typer/call_binding`):** позиционные/именованные (`.name=`) раскладываются по
  `CallableParamInfo`; все кандидаты ранжируются ЕДИНЫМ `resolveCall`; результат — `CallExpr::boundArgs` в
  порядке параметров. Default остаётся в C++-объявлении; пропуск default перед явным аргументом, default со
  ссылкой на параметр, named у native/конструктора, generic с named/опущенными default — явные ошибки.
- **⚠ Два РАЗНЫХ кейса многоточия:** (1) вариативный прототип `f(...)` кодируется
  `FunctionTypeData::variadicType` (=Any), НЕ лишним параметром; (2) разворот в АРГУМЕНТАХ — capacity-driven
  материализация (`typer/ellipsis`), нужна КОНКРЕТНАЯ сигнатура → только при ЕДИНСТВЕННОЙ (иначе ошибка).
- **⚠ Замыкающее многоточие (Fill/Repeat/Spread) — ЕДИНЫЙ примитив** для аргументов вызова и элементов
  массива. Fill/Repeat семантика МАТЕРИАЛИЗУЕТ (capacity из типа-цели/paramTypes), кодоген многоточия НЕ
  знает; Spread не материализуется — диагностика пост-проходом. ⚠ аргументы метода анализируются ОТДЕЛЬНО
  (ранний return MemberAccess); диагностика «diagnose-then-discard» (без каскада).
- **⚠ Эффективные сигнатуры набора — `effectiveMethodSignatures`:** подставляет T→Elem для Range/Array/Tensor
  и типовые аргументы native-template, СОХРАНЯЯ порядок (индекс выровнен с набором) — на этом держится
  C++-суффикс по `chosenIndex`. `INVALID` в позиции — инстанциация невозможна, диагностирует вызывающий.
- **⚠ Валидация операторов — единая `validateOperatorDecl`:** из `analyzeFuncDecl` (СВОБОДНЫЕ),
  `record_decl_analyzer`, `class_decl_analyzer` — у членов иначе объявление принималось бы МОЛЧА. Форма
  member/free — `insideTypeBody()`. Дубликат — по ЭФФЕКТИВНОЙ сигнатуре; postfix dummy — ровно `Int32`;
  свободный оператор обязан иметь ≥1 параметр пользовательского типа.
- **⚠ `resolveUserOperator` — единая точка ДО numeric/ref-веток:** вход — операнды в ИСХОДНОМ порядке, postfix
  (dummy `Int32`). member + free → ОДИН набор кандидатов (member несёт неявный object-параметр), ранжируются
  одной шкалой (C++ [over.match.oper]). Guard — ЛЮБОЙ операнд пользовательского типа (`5 == p` законен).
- **⚠ Регистрация/резолв операторов:** member-оператор живёт ТОЛЬКО в таблице методов под dunder-именем;
  `analyzeFuncDecl` имя в скоупе НЕ регистрирует (иначе `resolve("__eq__")` внутри класса путал его со
  свободным → ложный ambiguous); свободный оператор — обычная функция; отдельной таблицы операторов НЕТ.
  ⚠ **Свободный оператор живёт в модуле типа одного из операндов** (нет синтаксиса модульной квалификации);
  кодоген изолирует его namespace'ом модуля. `a(args)`/`a[i]` → `__call__`/`__getitem__` (без него — ошибка).
- **⚠ Native single-signature операторы/методы НЕ обходятся:** всегда проходят единый конвейер; C++-делегация —
  только native free c C-linkage и единственной сигнатурой. Статические перегрузки native-класса — набор
  сигнатур, C++-имя фиксировано без суффикса.
- **⚠ Унарный оператор: member/free разрешаются РАЗДЕЛЬНО** — обе жизнеспособные формы → явный ambiguous;
  ранги между формами не сравниваются (у member неявный `this` не входит в `argTypes`).
- **⚠ const-форма метода — отдельный ключ `^`:** нет const-формы → возвращается не-const вариант;
  const-correctness вызовов не проверяется.
- **⚠ C++-вставка `{% ... %}`:** `RawText::embedNames` заполняет семантика; кодоген конвертирует маркер через
  trust-namespace имени. `$`-локальные не квалифицируются.
