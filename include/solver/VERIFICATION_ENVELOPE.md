# Область проверки (verification envelope)

Документ фиксирует, какой код компилятор **умеет** проверять, а какой — нет, и как это
отражается в диагностиках и результате. Область проверки — граница доверия: внутри неё
результат `нарушений не найдено` означает, что нарушения нет; вне её проверка **не
выполнялась**, и такой результат нельзя считать доказательством.

## Что входит в область проверки

| Категория | Условия |
|---|---|
| Функции | Есть тело; параметры и результат имеют моделируемый тип |
| Скалярные значения | `Bool`, знаковые/беззнаковые целые (BitVec), `Float*` (Real) |
| Массивы | Известная статическая длина (литерал или `Array` с известной размерностью) |
| Управление | `if`/`else` (любая форма, включая отсутствие `return` в ветке), `return`, `break`/`continue`/`goto`, короткое замыкание `&&`/`||` |
| Циклы | `while`/`do-while` с инвариантом (элемент MIR `Invariant` с привязкой `loopNode`) или `z3_unroll(N)`/`-fsolver-loop-unroll` |
| Вызовы | Функция TrustLang **с контрактом**: аксиома `∀params. pre → post`, предусловие проверяется в точке вызова |
| Условия | `pre`/`post`/`assert`/`invariant` и термы, поддержанные `SmtOp` |

## Что вне области проверки

| Категория | Пример | Причина |
|---|---|---|
| Нативные вызовы | `abs(...)`, `@[link]`-функции | нет модели/аксиомы семантики |
| Вызов без контракта | `g(x)`, если у `g` нет `pre/post` | нет аксиомы: результат не связан с телом |
| Ссылки владения | `shared`/`weak`/`unique` в контракте | нет модели владения и aliasing |
| Динамические значения | `:Any`/словари в условиях | значение неизвестной природы |
| Generic-параметры | `T` внутри контракта | нет параметрической модели |
| Строки/тензоры | строковые и тензорные операции в условиях | нет модели памяти/операций |
| Неподдерживаемые операторы | неподдержанный вид выражения/оператора/терма | нет кодирования в SMT |
| Циклы без инварианта | `while` без `invariant` и без unroll | тело цикла не участвует в VC |
| `match`/`with`/`try` | Switch/Dispatch-терминатор CFG | нет модели ветвления по шаблонам/исключений |
| Исключения | `throw`/`try` | нет модели исключительных путей |
| Перемещение/сброс | `a :=: b`, `x :=: _` | нет модели владения |
| Запись в проекцию | `a[i] := x`, `p.f := x` | нет модели массива/записи в памяти (чтение моделируется) |
| `append`/деструктуризация | `a += x`, `(x, y) := ...` | нет модели длины/кортежа |
| Частичное тело | неподдерживаемый вид оператора | VC тела была бы неполной |

## Механизм

- Проверка вне области → диагностика `-Wverify-envelope` (severity: `ignore|warning|error`,
  по умолчанию `warning`); VC этой функции **не выдаётся** и учитывается в
  `SmtScript::outsideEnvelopeCount`.
- Тело исполняется символически по **MIR** (единая производная форма): состояние — значения
  мест (`flow::PlaceId`), циклы — индукция по инварианту (assert на входе и на back-edge, havoc
  mod-set) или bounded unrolling; каждая инвариант-цель и каждое утверждение тела — отдельная
  изолированная проверка (с видом обязательства в отчёте), в которую входит предусловие функции.
- Внутренняя ошибка кодирования (нарушение инвариантов HIR/MIR, чтение места без значения) —
  `Severity::Error`; экспорт прерывается, C++-бэкенд не запускается.
- Аксиома контракта функции строится независимо от тела и применяется к целям ДРУГИХ функций
  (собственная аксиома свою VC не доказывает).
- Профиль доказательств: `--solver-mode=calculate -Wverify-envelope=error` — любая
  непроверяемая конструкция делает проверку неуспешной.

## Как расширять область

1. Цикл: добавить `@[ invariant --> ... @];` перед циклом или `z3_unroll(N)`.
2. Нативный вызов: добавить модель (аксиому) — отдельный этап развития.
3. Немоделируемый тип: сузить до скалярного в контракте.
