# target — контракт цели

Компонент владеет **целевыми C++-фактами**, которые не должны находиться в языковой модели
(`types`/`ast`): целевой платформенный контракт (`TargetInfo`: triple, стандарт C++, features, провайдер
сборки), C/C++-имя нативной привязки и C++-суффикс сигнатуры объявления (`DeclCppFacts`),
C++-имя типа/целевые `#include`/библиотеки линковки/C++-имя нативного шаблона (`CppTypeFacts`),
привязки нативных методов (`MethodDelegates`) и таблица рантайм-символов (`runtime_symbols.hpp`).
C++-рендеринг — в кодогене (`transpiler/type`), порт чтения фактов — `TypeCppFactsView`.
(R37/E20; владелец строк §4 — `ARCHITECTURE.md`, «Целевой контракт».)

- Владелец времени жизни — **per-run** `TargetContract` (создаёт `Pipeline`).
- Порт доступа для потребителей — `Context::target()` (невладеющая ссылка, как `Context::types()`).
- Компонент **не зависит** от `types`/`ast`: целевые факты живут здесь, языковая модель к ним не
  обращается (R4/R34/R37). Языковая модель хранит только `target`-нейтральные факты/предикаты.
