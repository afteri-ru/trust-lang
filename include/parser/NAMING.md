# Правила формирования идентификаторов (имен объектов).

Идентификатор (имя) объекта может быть простым, квалифицированным или специальным, а также состоять из комбинаций этих фрагментов. Идентификатор состоит из одного или нескольких фрагментов (имён), разделённых пробельными символами или квалификаторами имён. Пробельные символы служат разделителями фрагментов, но не являются частью идентификатора. Последовательность соединения фрагментов определяется правилами формирования идентификаторов.

Идентификатор может быть нормализованным, не нормализованным и внутренним.

## Правила формирования имен

### Простое имя

Простое имя — это последовательность любых букв (включая Unicode), цифр и символа `_`. Цифра не может быть первым символом имени. Имена регистрозависимы. Максимальная длина имени — 64 символа.

Название модуля может содержать только *строчные буквы*, цифры и символ `_`. Символ `_` не может быть первым или последним в имени модуля.

### Квалифицированное имя

Квалифицированное имя — это простое имя, перед которым стоит один из квалификаторов имён:
- ‘@’ — префикс «собачка» используется для указания имени макроса.
- ‘$’ — знак доллара обозначает временное имя. Вне блока область видимости такого имени ограничена модулем/пакетом, внутри блока — до конца текущей области видимости.
- ‘::’ — двойное двоеточие разделяет пространства имён и является признаком персистентного объекта, значение которого сохраняется после выхода из текущей области видимости. Если имя начинается на ‘::’, то область его видимости будет глобальной и он будет доступен из других модулей программы. 
- ‘.’ — префикс «точка» используется для указания имени поля модуля или класса (ограничивает область видимости только текущим объектом). Символ '.' перед именем также может быть использован в определении или при вызове функции для явного указания имени аргумента, который нельзя перекрыть макросом.
- ‘\’ — обратный слеш в начале имени обозначает имя программного модуля. Он также используется для разделения имён каталогов при указании иерархии размещения программных модулей в файловой системе. Одиночный символ ‘\’ в начале имени обозначает относительную иерархию расположения модулей, а двойной ‘\\’ — абсолютную.
- ‘:’ — двоеточие перед именем термина обозначает имя типа (конструктор класса).
- ‘%’ — префикс «знак процента» указывается для нативных имён переменных и функций.

Квалификаторы могут комбинироваться. Например, составной квалификатор `@::` (префикс макроса `@` + `::`) используется для указания статического объекта в текущей области имён. В контексте макроса `@::` раскрывается в текущую область имён.

### Специальное имя

Специальные имена — это номерные аргументы функций, к которым можно обращаться не только по имени аргумента, но и по его порядковому номеру. Номерной аргумент функции начинается на символ доллара ‘$’ (как временное имя), после которого идёт порядковый номер аргумента (`$1`, `$2`, …, `$N`).

Нумерация аргументов идёт с единицы. Имя `$0` обозначает текущий объект для метода класса, а двумя символами `$$` обозначается родительский объект.

К аргументам функции можно обратиться как к словарю, например для их перебора в цикле, который имеет специальное имя `$*`.

Специальная неизменяемая виртуальная переменная компилятора `$^` содержит результат выполнения последнего выражения, оператора или блока кода.

### Специальные имена макросов

К специальным именам относятся зарезервированные имена макросов, которые раскрываются препроцессором или на этапе анализа AST. Макрос `@\\` содержит полное имя текущего модуля. Макрос `@::` раскрывается в текущую область имён. 
Макрос `@#` преобразовывает следующий за ним термин в символьную строку (стрингификация), а макрос `@##` соединяет (выполняет конкатенацию) двух символьных строк в одну.

Например:

```trust
# Имя файла filename.src в каталоге dir
ns:: { # пространство имен ns
    name:: {
        ns_str :=  @#  @::; # Строка с областью имен "::ns::name::"
        mod_str :=  @#  @\\; # Строка с именем модуля "\\dir\filename"
        full_str := @#  @\\ @##  @# @::; # "\\dir\filename::ns::name::"
    };
};
```

### Неизменяемые объекты

Синтаксис реализует динамическую иммутабельность (константность). Причём это свойство может быть не только свойством типа, но и свойством лексического объекта, т.е. данных. Это означает, что объект может стать неизменяемым не только в момент создания, но и при одной из последующих операций присвоения/изменения значения.

Для придания объекту свойства иммутабельности (невозможности изменять своё значение в дальнейшем) используется символ ‘^’ (карет, «крышечка»/«домик») после имени объекта.

Символ `^` не влияет на внутреннее имя объекта и на его манглинг.

## Нормализованные и не нормализованные идентификаторы

Имена могут быть нормализованными и не нормализованными. Нормализованное имя — это имя, которое не содержит в себе фрагментов специальных имён и признака иммутабельности. Для конвертации ненормализованного имени в нормализованное требуется контекст AST, который доступен только во время работы анализатора, который при нормализации имени раскрывает оставшиеся специальные имена на основании имеющейся у него информации (имени модуля, области имён, метода класса и т.д.)


## Внутреннее имя (идентификатор)

Каждый объект имеет своё внутреннее имя, уникальное в рамках текущего модуля, с помощью которого компилятор языка однозначно связывает объект с данными в памяти компьютера. Внутреннее имя объекта можно создать только для нормализованного идентификатора.

Внутреннее имя формируется во время анализа синтаксического дерева программы и включает в себя имя объекта и его квалификатор в соответствии с алгоритмом разрешения имён. У статических объектов, типов и классов внутреннее имя объекта включает в себя полную иерархию области имён.

Кроме этого, все квалификаторы объектов переносятся в конец имени, что и является отличительным признаком внутреннего имени (последний символ должен быть “$”, “:” или “%”). Символ иммутабельности `^` не входит во внутреннее имя.

Примеры внутренних имен:

```trust
var := 0;       # `var::`   - Локальный объект модуля (по умолчанию)
$var := 0;      # `var$`    - Локальный объект модуля (видимость модуль/пакет)
::var ::= 0;    # `::var::` -  Глобальный статический объект (глобальная видимость)
@::var ::= 0;   # `var::`   - Статический объект модуля (видимость модуль/пакет)
%var := 0;      # `var%`    - Нативная переменная (по умолчанию видимость модуль/пакет)


:: :type := :Type;     # `::type:::` - Глобальные тип и конструктор класса (глобальная видимость)
:: :cls := Class(){};  # `::cls:::`

:type := :Type;         # `::type:::`   - Тип  (глобальная видимость)
@:: :type := :Type;     # type:::       - Тип  (видимость модуль/пакет)
:cls := Class(){};      # `::cls:::`    - Конструктор класса (глобальная видимость)
@:: :cls := Class(){};  # `cls:::`      - Конструктор класса (видимость модуль/пакет)

%func() := {};          # `func%`      - Нативная функция  (видимость модуль/пакет)
::%func() := {};        # `::func%`    - Нативная функция  (глобальная видимость)

{   # Не именованный блок кода модуля

    var  := 0;      # `var$`        - Локальный объект (до конца области видимости)
    $var := 0;      # `var$`        - Локальный объект (до конца области видимости)
    @::var = 0;     # `1::var::`    - Статический объект (нет экспорта)

    :type := :Type;     # `1::type:::` - внутренний тип (нет экспорта)
    :cls := Class(){};  # `1::cls:::`  - внутренний класс (нет экспорта)
    %func() := {};         # `1::func%` - Нативная функция  (нет экспорта)
};

ns {                    # область имен `ns`
    @::var ::= 0;       # `ns::var::`       - статический объект в текущей области видимости
    ::other::var ::= 0; # `::other::var::`  - Глобальный статический объект (глобальная видимость)
    ::%func() := {};    # `::ns::func%`     - Глобальная нативная функция  (глобальная видимость)
};
```

## Манглинг внутренних имён

Внутреннее имя уникально только в рамках одного модуля, но внутренние имена в разных модулях могут пересекаться.

Манглинг внутренних имён предназначен для объединения нескольких модулей в рамках одной программы и используется как способ кодирования имени функции, структуры, класса или другого типа данных при передаче дополнительной семантической информации от компилятора компоновщику. Это C++-манглинг: внутреннее имя объекта после манглинга является корректным идентификатором для языков C/C++, что позволяет обращаться к объектам NewLang из внешних библиотек и приложений на языке реализации (C/C++) по семантически похожему имени (в отличие от манглинга имён в C++).

Манглинг внутреннего имени заключается в замене каждого символа двоеточия на символ `$`, а у имени типа квалификатор заменяется тремя символами `$`, т.е. `:::` → `$$$`.

При манглинге к внутренним именам объектов добавляется специальный префикс, который кодирует имя компилируемого модуля. Имя текущего модуля находится в переменной препроцессора `@\\` и по умолчанию содержит имя файла модуля (у главного модуля приложения имя модуля отсутствует).

При манглинге внутреннего имени имя модуля раскрывается как относительное имя файла по отношению к каталогу с главным файлом программы. Так как имя модуля, согласно правилам синтаксиса, может содержать только строчные буквы, цифры и символ `_` (кроме первого и последнего символа), то разделитель каталогов (обратный слеш `\`) заменяется на символ `$`, а начало и конец имени модуля отмечаются комбинациями символов `_$` и `$_` соответственно.

Так как локальной переменной с одним подчёркиванием `_` в качестве имени быть не может, то начало имени на `_$` служит отличительным признаком манглинга внутреннего имени объекта.

```trust

# Если текущий файл "\dir\file";
# тогда манглинг внутренних имён будет следующим

var := 0;      # `_$dir_file$_var$$` или `_$$_var$$` для главного модуля
$var := 0;      # `_$dir_file$_var$` или `_$$_var$` для главного модуля
::var ::= 0;    # `_$dir_file$_$$var$$` или _$$_$$var$$` для главного модуля и т.д.

```
