## Конвейер компиляции (Pipeline)

- **Получение (чтение) данных:** Чтение исходного кода для анализа из строки или главного файла программы и инициализация контекста компиляции (`Context` из модуля `diag`).
- **Компиляция макросов по умолчанию (DSL):** Встроенные макросы из `include/parser/dsl.src` компилируются в `MacroTable` через `MMProcessor::compileFromSource()`. Поведение управляется аргументом `--dsl`:
  - по умолчанию (без `--dsl`) — используется встроенный DSL (данные встроены через `#embed`);
  - `--dsl` без аргумента — макросы по умолчанию отключены, выводится сообщение;
  - `--dsl <file>` — загрузка макросов из указанного файла.
  Созданная `MacroTable` передаётся в `MMProcessor::process()`.
- **Лексический анализ** - Входной поток символов разбивается на минимальные смысловые единицы — лексемы (`Lexeme`) с помощью класса `Lexer`  из модуля `parser`.
- **Макропроцессинг** (`MMProcessor` из модуля `parser`) Формирует из отдельных лексем идентификаторы, загружает модули и раскрывает макросы. Он оперирует на уровне сопоставления шаблонов в потоке лексем с сохранением состояния (фактически выполняя трансформацию поддеревьев AST).
- **Синтаксический анализ (`Parser`):** Парсер на основе `Bison` принимает поток лексем, проверяет его на соответствие формальному синтаксису языка и строит абстрактное синтаксическое дерево (AST). На данном этапе типы данных не анализируются и допустимость операций не проверяется — выполняется исключительно синтаксический контроль.
- **Семантический анализ (Semantic Analysis):** Проверка *смысла* программы:
  - Построение таблицы символов (`Symbol Table`).
  - Создание структур данных и типов.
  - Инстанцирование шаблонов (`Template Instantiation`).
  - Проверка типов (`Type Checking`): приведение типов, поиск неявных преобразований, валидация сигнатур.
  - Разрешение областей видимости (`Scope Resolution`).
  - **Система эффектов (Effect System):** Проверка ограничений на побочные эффекты функций (чистота, ввод-вывод, исключения).
  - Доказательство корректности программы (`Trust Checking`): статический анализ на отсутствие циклических и висячих ссылок на уровне типов данных, проверка статических ограничений, контрактов, а также маркировка объектов атрибутами.
- **Оптимизация и унификация AST:** Удаление мёртвого кода (`Dead Code Elimination`), свёртка констант (`Constant Folding`), вынос инвариантов из циклов и инлайнинг функций.
- **Генерация C++ кода:** Преобразование оптимизированного AST в исходный код на C++ с сохранением и установкой соответствующих атрибутов.
- **Компиляция C++ кода:** Компиляция сгенерированного кода с помощью `clang` или `gcc` в объектные файлы и сборка статической библиотеки.
- **Компоновка (Linking):** Линкер объединяет статическую библиотеку программы с системными библиотеками, создавая исполняемый файл и/или динамическую библиотеку.
