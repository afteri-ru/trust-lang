## Architecture

Оркестрация загрузки и реестр модулей; предмет — только ИСХОДНИКИ. `parseSourceModule()` рекурсивно
вызывает Parser и сразу конвертирует Term→AST. ЧИСТАЯ политика пути (резолв `\file`/`\\group`/`\\\pkg`,
форма файл/каталог/любая, обход группы, каноникализация, `TRUST_PACKAGE_PATH`) — `module_path_policy`, без
`Context` и без диагностик (ошибка строкой). Поиск/извлечение пакетов — `PackageStore` (кэш
`<packageCacheDir>/<name>-<md5-12>/`). Установка интерфейса файла (штамп модуля, блок интерфейса, реэкспорт,
экспорт-набор) — `interface_install` в ФИКСИРОВАННОМ порядке шагов (мутируют `AstNodeBase::visibility`,
порядок наблюдаем в C++). Загрузчик — единственная точка фатального выхода и диагностики цикла.
`import_exports` связывает сайты импорта с файлами; spelling-карты — состояние загрузчика.
Реализация — internal-подкаталоги `loader/` (фасад `ModuleLoader`), `exports/` (экспорт-набор и импорт),
`path/`, `package/`, `interface/`, `registry/`.

## Facts and invariants

- **⚠ Модуль объявления:** `stampModuleLevelNode` ставит `module` ТОЛЬКО объявлениям уровня модуля. Модуль —
  группировка, не namespace: импорт вставляет объявления в ТЕКУЩИЙ скоуп, `::` области явные; повторная
  регистрация того же узла идемпотентна.
- **⚠ `syntax`/`ast` НЕ зависят от `module_loader`** — только `module_api/module_resolver.hpp`
  (`no_module_loader_guard`).
- **⚠ Видимость:** top-level — exported; `__::` — private (module-qualified ключ, anonymous namespace);
  `_::` — protected (та же группа/пакет). `installFileInterface` исключает внеблочные объявления из
  экспорт-набора: не-exported → private; record, завершающий forward из интерфейса, помечается
  `isExportImplementation` (видимость/ключи НЕ меняются — тот же TypeId) и не публикуется (виден forward).
  `_::` фильтруется импортом и публикуется заголовком (`canAccessProtected`).
- **⚠ Реэкспорт = импорт в блоке интерфейса:** маска-фильтр набора владельца добавляется в экспорт-набор;
  владелец не меняется; реэкспорт ТРАНЗИТИВЕН.
- **⚠ Загрузка/импорт:** файл парсится один раз; duplicate-import — Error только при том же файле + scope +
  масках; `findLoaded` загрузку НЕ инициирует (только уже загруженные модули).
- **⚠ Ссылка/загруженность — ТОЛЬКО spelling-домен:** `lookupSpelling` (карта импортов scope активного
  модуля; вне загрузки — однозначный поиск); путь ФС — лишь cycle-детект. Spelling
  scope-относителен: один spelling в разных корнях — разные файлы; scope root фиксирует ПЕРВАЯ загрузка.
- **⚠ Пакетная идентичность — из логического имени** (`packageNameOf`); пути внутри пакета сохраняют пакетный
  заголовок. Пакет один (`trust.toml`, `name` = идентичность).
- **⚠ Пакет сверяется с версией ABI-контракта рантайма:** `PackageStore::resolveRoot` отвергает пакет, чей
  `[build].runtime-abi` не совпадает с `kRuntimeAbiVersion` компилятора (R48) — чужой рантайм не допускается молча.
- **⚠ Маски — `utils::ImportMasks`:** единственный парсер/матчер. РЕШЕНИЕ о видимости принимает не загрузчик
  и не `ImportMasks`, а `types/names.hpp`; проекция сайта (`siteProjection`) — ДАННЫЕ, не второе правило.
  Несовпавшие — `-Wunmatched-mask`, пустой — `-Wempty-import` (namespace-алиас считается совпавшим);
  непопадание — по ОБЪЕДИНЁННОМУ набору сайта; protected — только по ДОСТУПНЫМ частям.
- **⚠ Заголовок модуля НЕ содержит имени пакета:** контракт заголовка — путь ОТНОСИТЕЛЬНО scope root
  (`\\builtin\rational;`, `\tensor;`), поэтому файл модуля переносим между пакетами. Пакетную
  квалификацию добавляет загрузчик: логическое имя пакетного модуля = `\\\pkg\<путь>` (различает
  одинаковые внутренние пути разных пакетов и служит доменом `_::`); проверка заголовка — по
  относительной проекции, реестр — по квалифицированной.
- **Префиксы — тип ПЕРВОГО компонента:** `\` файл, `\\` группа, `\\\` пакет; `\\dir` — нерекурсивно `.src`;
  `\\\pkg()` — first-level модули + корневые `.src`; `dir.src` + `dir/` — ошибка; build-каталог — не корень.
- **⚠ `--stdlib` = корень распакованного stdlib в путях ПОИСКА модулей:** pipeline добавляет его в
  `setModuleSearchPaths`; модули stdlib адресуются КОРОТКО (`\std();`, `\\builtin\string();`), `--no-stdlib`
  корень убирает. Пакетный префикс (`\\\stdlib\…`) остаётся вторым способом адресации.
- **⚠ Идентичность — логический путь:** заголовок либо сохранённый путь от scope root; ФС повторно не
  читается. Заголовок `\path;` — статический контракт, без него импорт — ошибка.
- **Раздельная компиляция:** `.cppt` — при out-of-line определениях ЛИБО record, скрытом forward'ом; имя
  `<stem>-<md5[0..12]>.cppt`; `@[include]`/`@[link]` — в TU импортёра; `ModuleInterfaceFacts` — один раз.
- **⚠ Относительные якоря:** `\$$` — self-файл; `\\$$`/`\\\$$` — каталог/пакет (пусто для корня);
  standalone-импорт запрещён.

## Decisions

- **⚠ Интерфейс модуля НЕ сериализуется между прогонами:** факты пересчитываются каждый запуск; в
  цельно-программной модели тела семантируются в каждой сборке, повторный `--run` коротко замыкается
  `toolchain::runCacheValid` (драйвер `builddriver`). Сводка
  интерфейса (P3) — только при по-юнитовой/инкрементальной сборке.
