## Architecture

Оркестрация загрузки модулей и реестр. Интегрирован с syntax Parser: `parseSourceModule()`
рекурсивно вызывает Parser (`expand_module=true`); `ensureLoaded()` резолвит `<name>.trust`
(заглушка) или `<name>.src` и вызывает `parseSourceModule()`. Идентификация модулей — ТОЛЬКО по
индексу (`ModuleRegistry`); `moduleId` используется лишь при загрузке для детекции циклических
зависимостей.

**Владение:** `ModuleLoader` (по значению владеет `ModuleRegistry`) — владелец **Pipeline**
(`unique_ptr`), внедряется в `Context` невладеющим указателем (`Context::setLoader`). Обратная
ссылка `m_ctx` — невладеющая `Context&`; цикл по ссылкам, но безопасен (единый владелец —
Pipeline, `Context` живёт не меньше loader-а). Не копируется/не перемещается.

## Facts and invariants

- **Необъявленная связь syntax ↔ module_loader:** `syntax/parser.cpp` при обработке import сам
  вызывает `m_ctx.loader()` (`ensureLoaded`/`body`/`indexOf`), но `syntax_lib` не линкует
  `module_loader_lib` — символы используются транзитивно через `Context`. Разрыв инкапсуляции.
  Целесообразно перенести обработку import в module_loader.
- **Детекция цикла:** запись существует, но тело ещё не заполнено → модуль в процессе загрузки →
  FAULT. Выход индекса за границы → FAULT.
- **Экспорт:** по умолчанию экспортируются ВСЕ top-level объявления в НЕ анонимных областях имён
  (глобальная `::`, именованные `ns::` — с квалификацией); из анонимной `_` и локальных — нет.
- **Раздельная компиляция:** каждый импортированный `.src`-модуль — отдельный `.cppt` (полное
  тело), линкуется с главным (`SRC_MODULES` в Makefile). На сайте импорта — только forward-decl
  экспортов; `__trust_get_exports`/экспорт-таблица встраиваются ТОЛЬКО в главный файл (иначе дубли
  при линковке). Динамическая библиотека `.trust` — экспорт-таблица главного файла включает символы
  модулей (адреса через extern в линкованном `.so`); `__trust_exports` имеет поле `decls` — строку
  перечисления экспортируемых имён для будущего парсинга бинарного модуля.
- **Интерфейс:** `ModuleRecord::m_interface` — «полный» экспорт (заполняет анализатор);
  `ModuleNode::m_exports` — отфильтрованный интерфейс конкретного сайта импорта (по маскам
  `\module(mod, masks)`; пустой список = все экспорты).
