# Analysis - контракт анализа для бэкендов

## Назначение

Header-only контракт между анализатором и его потребителями-бэкендами: поведенческие режимы
компилятора и классификация рантайм-проверок. Правила анализа — `semantic`, структура тела — `ir`,
символы и видимость — `symbols`.

## Состав

- **`modes.hpp`** - `BehavioralModes`, `SolverMode`, `StackCheckMode`, `SolverLoopMode`, имена нативных
  функций контроля стека и чистые предикаты. Владелец `FlagKind` — `semantic`; значения разрешаются им
  (`semantic::behavioralModesFromOptions`) и передаются как ДАННЫЕ.
- **`runtime_checks.hpp`** - `RuntimeCheckKind`/`runtimeCheckOf(node)`: единый предикат «какая
  рантайм-проверка нужна узлу» (переполнение по `Binary::m_overflowCheck`, деление/остаток на ноль,
  разыменование null по `TakeLowering`). Кодоген и верификатор не выводят это повторно.

## Принцип

Компонент расположен НИЖЕ `semantic` и `transpiler`: кодогенерация получает режимы данными и не зависит
от анализатора и от `diag::Options`.
