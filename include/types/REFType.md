# Модель ссылок: архитектура и сравнение подходов

Документ описывает модель ссылочных типов в Trust: кодирование вида ссылки в `TypeId`/`TypeKind`,
причины выбора, ограничения и сравнение с C/C++ и другими языками. Связанные источники:
`types/MEMORY.md` (битовая структура `TypeKind`), `types/TYPE.md` (формат таблицы `RefType`),
`types/type_id.hpp`, `types/registry.hpp` (`RefTypeData`), `semantic/MEMORY.md`,
`ast/attr_builtin.hpp` (атрибут `reftype`).

---

## 1. Постановка

Ссылка - способ доступа к объекту, находящемуся в другом месте памяти. В Trust модель ссылок
строится вокруг **одного признака ссылки на объявление** (`RefType`, плоский enum в `TypeKind`).
Возможные виды:

| Значение | Имя | Семантика |
|----------|-----|-----------|
| 0 | `kValue` | владение значением (без ссылки) |
| 1 | `kShared` | совместное владение |
| 2 | `kWeak` | слабая (не владеющая) ссылка |
| 3 | `kUnique` | исключительное владение |
| 4 | `kPtr` | сырой указатель (`*`), только через атрибут |
| 5 | `kMptr` | указатель на член (`::*`), `MemberPointerTypeData` |
| 6 | `kRef` | ссылка (`&`), только через атрибут |
| 7 | `kRref` | rvalue-ссылка (`&&`), только через атрибут |
| 8 | `kPtrPtr` | указатель на указатель (`**`) |
| 9 | `kLocker` | охраняемый доступ к reference-wrapper (`Shared`/`Weak`): RAII-охранник (результат `lock()/lock_const()`) |

**Двухосевая модель.** `RefType` смешивает две независимые оси: **владение временем жизни**
(`value`/`shared`/`weak`/`unique`) и **доступ к объекту** (сырой `&`/`*` против охраняемого
`locker`). `kLocker` — охраняемый доступ **только** к reference-wrapper (`trust::Shared`/`trust::Weak`),
результат `lock()/lock_const()`. Сырые ссылки (`ptr`/`ref`/`rref`) и `unique_ptr` локера **не имеют**
— это другая идеология (прямой доступ без guard). Null-безопасность — отдельная ось (контракт типа),
а не guard-объект.

**Центральное правило:** один признак ссылки на объявление. Это **осознанное решение** для
упрощения понимания системы ссылочных типов (а не следствие 4-битного поля). Читатель и
компилятор всегда видят ровно один признак, без «лесенок» `ref<ref<ref<T>>>` в одной строке.
Вложенные модели выражаются **цепочкой отдельных ссылочных типов** (каждый уровень - отдельно
объявленный тип).

## 2. Кодирование

`RefType` - 4 бита (биты 16–19) в `TypeKind` (uint32). Значения 0–8 заняты, 9–15 зарезервированы.
Хелперы: `getRefType`/`withRefType` (`types/typekind.hpp`), строковые имена
`refTypeName`/`refTypeFromString` (для атрибута `@[reftype("...")]` и диагностики).

Применение признака к типу:

- **Fast-path (первая ссылка).** Первая ссылка на тип **без признака** (вид `kValue`) кодируется
  **битом**: `withRefType(type, kind)` - дёшево, без обращения к реестру. Например
  `@[reftype("ptr")] :Int32` → `TypeKind{Group=Integers, Data=32, RefType=kPtr}`.
- **Вложенность (ссылка на ссылочный тип).** Если базовый тип уже несёт признак (например нужно
  `shared<ptr<Int32>>`), создаётся **составной узел** реестра `RefTypeData{pointeeType}` через
  `TypeRegistry::getOrCreateRefType(kind, pointee)`. Вид несёт сам `TypeKind` узла
  (`Group::kReftype`, `RefType=kind`), `pointeeType` - тип, на который ссылается узел.

Узел интернируется структурно через `TypeKey{kind, children}` (аналогично
`MemberPointerTypeData`/`ArrayTypeData`/`FunctionTypeData`), поэтому одинаковый
`(вид, pointee)` даёт один `TypeId`, а `ptr<Int32>` ≠ `shared<Int32>` ≠ `Int32`.

### Источник признака: атрибут `@[reftype("...")]`

Вид ссылки задаётся атрибутом `@[reftype(<имя>)]` **перед переменной/типом**. Имя - одно из
мнемонических: `value/shared/weak/unique/ptr/mptr/ref/rref/ptrptr/locker`. Неизвестное имя или
отсутствие параметра - **диагностика ошибки** (без тихого fallback).

**Форма записи.** Параметры атрибутов хранятся как текст, поэтому имя вида можно указывать
**без кавычек** (`@[reftype(ptr)]` - рекомендуется, как `#[repr(C)]`/`@safe` в других языках)
или **в строке** (`@[reftype("ptr")]`) - обе формы эквивалентны. Битовая раскладка `TypeKind`,
где хранится `RefType` (биты 16–19), - в разделе «Битовая структура TypeKind» документа `TYPE.md`.

## 3. Как это сделано в других языках

### C / C++

- Синтаксические формы - **разные типы**: `T`, `T*`, `T&`, `T&&`, `T::*` - отдельные категории.
- Владение **ортогонально** синтаксису и выражается обёртками: `shared_ptr<T>`, `unique_ptr<T>`,
  `weak_ptr<T>`, `optional<T*>`.
- Вложение/совмещение - через композицию обёрток (`shared_ptr<T*>`): ось владения и ось
  «указателя» комбинируются. На практике в крупных проектах «shared-владение указателем»
  реализуется обёртками с custom deleter (`std::shared_ptr<FILE>(f, &fclose)`), type-erased
  `shared_ptr<void>`, интрузивным счётчиком (Qt `QSharedDataPointer`, OpenCV `cv::Ptr`,
  Chromium `scoped_refptr`), полиморфным `shared_ptr<Base>`.

### Rust

- `&T`/`&mut T` (заимствование) и `*const T`/`*mut T` (сырые указатели) - синтаксические
  категории; владение - `Box<T>`, `Rc<T>`/`Arc<T>`, `Weak<T>`.
- `&T` и `T` - **разные типы**; гарантии (эксклюзивность/алиасинг) даёт borrow-checker.

### Go / C# / D

- Указатели/ссылки - синтаксическая категория типа (`*T`, `ref`); владение-модель отдельно
  либо отсутствует.

### Вывод

Общий паттерн языков - **синтаксическая форма и владение разделены**. Trust сознательно
упрощает до **одного плоского признака** + **цепочек отдельных ссылочных типов** для
вложенности. Это даёт ясность («один маркер на тип») ценой отказа от совмещения осей в одном
объявлении.

## 4. Безопасность

Прямые операции с **сырыми** C++-видами (`ptr/ref/rref/mptr/ptrptr`) в Trust **запрещены** по
вопросам безопасности. Сырые виды применяются **только** через атрибут `@[reftype("...")]`.
Классические операторы (`&`, `*`, `&&`) дают **безопасные** виды (`shared/weak/unique/value`).
Это снимает неоднозначность символов: `&`/`*` однозначно отображаются на безопасные виды, сырые
виды достижимы только явно.

## 5. Ограничения (что нельзя)

1. Нельзя в **одном** объявлении сделать ссылку на ссылку на ссылку - признак ссылки один.
2. Признак ссылки - только один на тип-объявление.
3. «Совмещённое владение» в C++-смысле (`shared_ptr<T*>`) в одном объявлении **не выражается** -
   только цепочкой отдельных ссылочных типов (`Shared := @[reftype("shared")] :Ptr`).
4. **Предопределённые уровни-сокращения:** `kPtr` (`T*`, 1 уровень) и `kPtrPtr` (`T**`, 2 уровня)
   покрывают самые частые случаи одним маркером. Произвольная/более глубокая вложенность
   (`T***`, `shared<ptr<T>>`) - цепочкой типов.

### Nullability (без отдельного бита)

«Может быть пусто» **не требует отдельного бит-признака**:

- Сырые указатели (`kPtr`, `kPtrPtr`) и smart-виды (`kShared/kWeak/kUnique`) nullable «из
  коробки» - это врождённое свойство вида, а не отдельная ось.
- Когда нужен «нет значения» у не-ссылочного типа - это **тип-обёртка** в реестре
  (`optional<Int32>`, `optional<ptr<T>>`), как `std::optional`/`Maybe<T>`, а не квалификатор.

## 6. Реализовано

- `RefType` (плоский, 9 значений) + `refTypeName`/`refTypeFromString` (`types/typekind.hpp`).
- `withRefType`/`getRefType` (fast-path бит).
- `RefTypeData{pointeeType}` + `TypeDataKind::kRefType` + `TypeRegistry::getOrCreateRefType`
  (`types/registry.hpp`, `types/registry.cpp`), группа `Group::kReftype`.
- Атрибут `@[reftype("...")]` (`attr::Reftype`, `ast/attr_builtin.hpp`, `attr_builtin.cpp`).
- Трансляция в `NameResolutionPass::analyzeVarDecl`: fast-path бит / узел для вложенности,
  диагностика неизвестного вида (`semantic/name_resolution.cpp`).
- Кодогенерация C++-имени: `TypeRegistry::getCppTypeName` эмитит `T*`/`T&`/`T&&`/`T**`,
  `trust::Shared<T>` (kShared)/`trust::Weak<trust::Shared<T>>` (kWeak)/`std::unique_ptr<T>`
  (kUnique)/`trust::Locker<T>` (kLocker), `MemberType Class::*` (mptr) и рекурсивно для вложенных
  `RefTypeData`-узлов; `CppTranspiler::collectTypeIncludes` добавляет `@trust/trusted-cpp.hpp`
  для shared/weak и `#include <memory>` для unique (`types/registry.cpp`,
  `transpiler/type_emit.cpp`).
- **Спецслучай C-строки**: `StrChar + ptr + const` (`fmt: @[reftype(ptr)@] StrChar^`) - это
  `const char*` (а не `const std::string*`): `TypeRegistry::applyRefType` (единый источник
  fast-path/вложенности для семантики и транспилятора), спецправило в `resolveCppTypeId`
  (`types/registry.cpp`, `transpiler/transpiler.cpp`).
- **Тип `CString`** (`const char*`): встроенный невладеющий тип C-строки (`types/type_names.hpp`,
  `registerBuiltinType(type::CString, ..., "const char*")`). Результат нативного метода
  `StrChar.%c_str(): CString` - явная конверсия `s.c_str()` → `(c_s).c_str()`.
- **Методы типов**: реестр нативных методов на встроенных типах в `TypeRegistry`
  (`TypeDescriptor::methods` - `std::map<std::string, TypeId>` имя → функциональный тип,
  `addMethod`/`findMethod`); метод и функция - одно и то же (сигнатура = `FunctionTypeData`);
  нативность метода - по `%` в имени (`%c_str`), при генерации вставляется идентификатор без `%`;
  поиск ОДНОСТОРОННИЙ (обычное имя `c_str` находит и нативный `%c_str`; нативное - только
  точное). `addMethod` обеспечивает инвариант «одна форма имени» (вторая форма/точный дубль -
  EXPECT). Семантика проверяет наличие метода, число аргументов и тип возврата ДО генерации
  (`NameResolutionPass::handleMethodCall`).
- Тесты: `test/unit/types/reftype_test.cpp`, `test/unit/types/type_method_test.cpp`.

### Символический синтаксис ссылок (реализовано)

Помимо атрибута `@[reftype("...")]` ссылочные типы задаются символическими **маркерами/операторами**
(НЕ «сиглы» - сигл это первый символ ИМЕНИ, ссылка частью имени не является). **Позиция определяет
смысл** (см. `include/syntax/SYNTAX.md` «Ссылочные типы»):

- **Слева от `:=`/`=` - маркер ссылки (должен быть СОГЛАСОВАН)**:
  - маркер ПЕРЕД именем переменной (`&& x : && Int32`, `&* u := 10`, `&? w := & x`), при явном типе
    тип обязан нести тот же маркер (`&& x : && Int32`), либо тип опускается (авто-вывод pointee из
    инициализатора: `&& x := 5`);
  - несогласованные формы - ошибки: `x : &&Int32` (маркер только у типа), `&& x : Int32` (маркер у
    переменной, тип - значение), `&& x : &* Int32` (разные маркеры, `reference kind mismatch`).
  Терм `ptr lval` (`&&`/`&*`/`&?` → OPERATOR_PTR) разворачивается в
  `TermToAstConverter::visit_CREATE_NAME`: имя берётся из lval, маркер превращается в атрибут
  `@[reftype("...")]` на объявлении (вид ссылки - часть ТИПА, маркер задаёт его у переменной);
  дальше работают стандартные `applyRefAttrs` (семантика, включая проверку согласованности с видом
  у типа и недвойное применение при совпадении) и reftype-ветка `DeclEmitter` (кодоген).
  Кодогенерация: shared/weak - конструктор `trust::Shared/Weak<...>(init)` (для address-of-инициализатора
  `& x` - копирующая `= <init>`, чтобы избежать most-vexing-parse), unique -
  `std::unique_ptr<PoT> x = std::make_unique<PoT>(init)`; для авто-вывода pointee берётся из
  выведенного типа (getPointeeType).
- **Справа/в выражении**:
  - `& expr` (address-of/borrow) - взятие ссылки; допустимо ТОЛЬКО для ссылочной переменной,
    weak получается ТОЛЬКО из shared (`& shared_var`); unique → ошибка, не-ссылка → ошибка.
    Типизация - `ExprTyper` (case `RefMakeExpr`), тип результата (weak) сохраняется в
    `RefMakeExpr::m_resultType` (транспилятору локальные символы недоступны), кодоген - эмиссия
    `trust::Weak<...>(c_x)` (`ExprEmitter::visit_RefMakeExpr`).
  - `* expr` - доступ к ДАННЫМ ссылочного операнда (семантика std::reference_wrapper<T>::get() -
    ссылка на данные). Для shared/weak - `*(ref.lock())` (под защитой/через weak; lock() бросает на
    истёкшей ссылке); для unique/ptr - `trust::checked_deref(c_u.get())` / `trust::checked_deref(c_p)`
    (БЕЗ UB на nullptr: `trust::checked_deref` бросает `trust::IntMinus` на нулевом указателе).
    Вид операнда (m_opRefKind) ставит семантика в `RefTakeExpr`, кодоген - `ExprEmitter::visit_RefTakeExpr`.
  - `a :=: b` - swap (интринсик `std::swap`), возвращает `&a`; типы должны быть совместимы
    (не обязательно ссылки). `var :=: _` → `std::move(var)` (перемещение в discard). Грамматика
    `assign_seq: assign_items SWAP assign_items`, узел `Binary(AssignOp)` с текстом `:=:`
    (term_to_ast `visit_SWAP`), семантика - `typeBinaryResult` (`utils::isSwapOp`), кодоген -
    `ExprEmitter::emitBinaryOpRaw`.
- **Контракт value-vs-reference** (`ExprTyper::checkAssignmentNarrowing` + `typeBinaryResult`):
  копирование ссылки в значение - ошибка + fixit `*<name>`; weak из unique - ошибка (ось
  владения); арифметика/сравнение над ссылками - ошибка (нет ссылочной арифметики) + fixit
  `*<name>`; swap - ошибка при несовместимых типах.

## 7. Итог

Модель Trust - **один признак ссылки на объявление** (плоский `RefType`) + **цепочки отдельных
ссылочных типов** для вложенности. Это осознанное упрощение ради ясности и безопасности
(сырые виды изолированы и достижимы только явно). Модель согласована с C/C++ в части
«синтаксические формы - разные типы» и «value/shared/weak/unique ↔ значение и умные указатели»,
но отказывается от совмещения осей в одном объявлении.
