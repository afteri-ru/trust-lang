# STAT.md — статистика и метрики продуктивности

Критерии анализа итоговых логов задач (`.tasklog/*.md`), метрики продуктивности и методика мониторинга трендов.

---

## 1. Классификация задач

| Статус | Определение | Автоматический признак |
|--------|------------|----------------------|
| `completed` | Есть TaskComplete, повторных открытий нет | 1 запись TaskComplete |
| `reopened` | TaskComplete было ≥2 (задача переоткрывалась после "завершения") | ≥2 записи TaskComplete |
| `interrupted` | Нет TaskComplete, есть обсуждение плана | нет TaskComplete, есть plan_mode_respond |
| `not_started` | Только UserPromptSubmit, обсуждения нет | 0 plan_mode_respond, нет TaskComplete |

---

## 2. Причины доработок (для статуса `reopened`)

Причины извлекаются из переписки между первым и последним TaskComplete.

| Причина | Признак в логе |
|---------|---------------|
| Не проверены тесты/сборка | UserRespond после TaskComplete: "тесты", "сборка", "не компилируется" |
| Не понята семантика типа | UserRespond: "Range это тоже строка", "неправильное поведение" |
| Неполный рефакторинг (забыты связанные файлы) | UserRespond: ссылка на конкретный файл/символ |
| Расширение scope | UserRespond: "добавь ещё...", "а как насчёт..." |
| Не прочитаны связанные структуры | UserRespond: "А их аргументы?", "А это поле?" |

---

## 3. Причины прерывания (для статуса `interrupted` / `not_started`)

Причины извлекаются из **последних 3–5 реплик** планирования в логе.

| Паттерн последнего UserRespond | Вывод о причине |
|---|---|
| Пользователь дал уточнение/вопрос, ответа агента нет | Обсуждение оборвано (ручное прерывание / переключение) |
| "что если...", "а можно..." — агент отвечает, пользователь снова уточняет | Архитектурный поиск без консенсуса |
| Пользователь указал на неверное понимание задачи агентом | Недопонимание требований |
| Последнее сообщение — от агента (plan_mode_respond), ответа нет | Агент ожидает одобрения, пользователь не вернулся |
| Дубликат формулировки другой задачи | Дублирование |
| Только UserPromptSubmit, нет реакции агента | Задача вброшена, не начата |

## 4. Метрики и формулы

| Метрика | Формула | Ориентир | Текущее (04.08.2026) |
|---------|---------|----------|---------------------|
| `reopen_rate` | reopened / completed | <20% | 47% |
| `interruption_rate` | (interrupted + not_started) / всего | <15% | 22% |
| `plan_adoption` | с планом / всего задач | >85% | 77% |
| `active_time` | Σ интервалов < 30 мин между записями | — | — |
| `break_time` | Σ интервалов ≥ 30 мин между записями | — | — |
| `plan_iterations` | медиана plan_mode_respond на задачу | 3 | 3 |
| `tool_calls_per_task` | строк в `.tools.log` | — | — |
| `tool_failure_rate` | failed вызовов / всего вызовов в `.tools.log` | — | — |


Длительность задачи из `TaskComplete Nm Ms` — это календарное время, включая ночные перерывы. Правильная оценка активного времени:
Все ISO-таймстампы в логе задачи сортируются; соседние интервалы классифицируются по порогу 30 минут.

## 6. Примечания

- Дублирование диалога в `-plan.md` и `.md` удваивает статистику — при подсчёте итераций учитывать только основные `.md` (не `*-plan*.md`).
- `.tmp` файлы — снапшоты незавершённых задач, не анализируются как отдельные задачи.
- Для полного анализа tool-вызовов требуется `.tools.log` (пишется хук PostToolUse).
