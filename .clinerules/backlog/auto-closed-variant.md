# Auto → замкнутый `variant` без RTTI (закрытое множество типов)

> status: backlog — будущая задача (согласована отдельно; реализация НЕ входит в текущую задачу)
> area: types / semantic / codegen
> architecture: R26, E1, E4
> источник: диалог по `.clinerules/backlog/unified-stdlib-runtime.md` (стадия A1), `.tasklog/1794240962985.md`

## Контекст

Стадия A1 (см. `.tasklog/1794240962985.md`) реифицирует внутренний sentinel вывода как `Auto`:
`Auto` разрешается в семантике либо в конкретный тип, либо в `Any` (RTTI/`std::any`), и НЕ должен
доживать до кодогена (FAULT). `Any` при этом становится обычным материализуемым типом
(`Group::kAny`, cppName `std::any`, `<any>`), гейтится явной загрузкой `\any();`.

## Идея фичи (A2)

Когда набор возможных типов значения `Auto` **замкнут и известен на этапе компиляции**, разрешать
его не в `Any` (RTTI), а в **замкнутый `std::variant<…>`** без RTTI. Например, enum с значениями
типов `{Int32, StrChar}` → `std::variant<int32_t, std::string>` вместо `std::any`.

Фундамент уже есть: `VariantTypeData` / `registerVariantType` / `type_category::Variant`
(`include/types/type/`, `src/types/registry/named_type_registrar.cpp`).

## Что потребуется (черновой объём)

1. Анализ замкнутости: определить, что множество возможных типов значения конечно и известно
   (напр. все элементы enum / все ветви источника деструктуризации).
2. Построение variant-типа из набора и его регистрация в `types`.
3. Семантика операций над variant: доступ/матчинг/приведение (что можно делать с variant-значением).
4. Кодоген `std::variant` (включая `<variant>`, on-use include через provider/`@[include]`).
5. Диагностики: если множество раскрыть нельзя — fallback на `Any` (и требование `\any();`) либо
   явная ошибка (по решению дизайна).
6. Тесты: закрытые наборы (без RTTI) и открытые (RTTI); отсутствие регрессий по существующим
   widening-кейсам.
7. docs ru/en + MEMORY.

## DoD (будущей задачи)

- `make build` без ошибок; `timeout 900 make test` — 100%.
- Замкнутые наборы типов не используют RTTI (`std::any`) в сгенерированном C++.
- Никаких silent fallback: неразрешимый набор → `Any` + требование `\any();` (или диагностика).
