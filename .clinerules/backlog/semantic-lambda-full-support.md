# Лямбды: полная поддержка (вывод возврата, функциональный тип, захваты)

> status: backlog
> area: syntax / ast / semantic / types / transpiler / docs
> architecture: R1, R2, R9, R39, E6; L3 (ссылочный захват) зависит от предметного документа займов
> (`semantic/ref/BORROW_CHECKER.md`), а не от `ARCHITECTURE.md` (§6)

## Контекст (проверено по коду)

- Лямбда — это `FuncDecl` с `isLambda()`; и синтетическим именм для внутренней идентификации 
    не истрируется в скоупе и не эмитится как C++-функция (`src/ast/ast_decl.cpp:159-206`).
- Захваты: поддержан только `[name]` по значению. `[&x]`, `[=]`, `[&]`, `[name = expr]`,
  `[x:Type]` распознаются и отвергаются явной диагностикой.

## Цель

Сделать лямбды полноценными объектами: выводить тип возврата из тела, поддержать аннотации 
и ссылочный/неявный захват с проверкой займа на этапе анализа.

## Этапы

### L1. Вывод типа возврата из тела

1. Правило: последнее выражение тела либо типы `@return`; при неоднозначности/невозможности
   вывода — ошибка с требованием явной аннотации. Trust-условия автоматически не выводятся.
2. Кодоген: `std::function<Ret(...)>` должен совпасть с дедуцируемым типом C++-лямбды.
3. Синхронизировать `docs/content/{ru,en}/docs/` если там есть раздел о лямбдах.

**DoD L1**

- `f := [](x:Int32){ @return x*x; };` → `std::function<int32_t(int32_t)>`.
- Неоднозначность/невозможность вывода — явная диагностика (без тихого void).
- lit (codegen + diag).

### L2. Функциональный тип параметра/переменной

1. Синтаксис функционального типа: `(Int32) -> Int32` либо `Func<:Int32, :Int32>`
   (выбрать при реализации); переиспользовать `FunctionTypeData` и рендер `std::function<...>`.
2. Семантика: `resolveType` функционального типа в позиции аннотации; совместимость сигнатур
   при передаче лямбды/функции; вызов параметра-значения.
3. Диагностика при несовпадении сигнатур.

**DoD L2**

- `apply(f : <функциональный тип>) := { @return f(1); }; apply([](x:Int32):Int32 { @return x+1; });`
  компилируется и работает (`--run`).
- Несовпадение сигнатуры лямбды и типа параметра — явная ошибка.
- lit (codegen + e2e + diag).

### L3. Ссылочный и неявный захват

1. Семантика `[&x]`/`[&*x]` только при валидном займе (регион/владение) по borrow-checker;
   согласовать с `applyRefAttrs`/`refAxisOf`.
2. Кодоген C++-захвата по ссылке (`[&c_x]`) с учётом манглинга и модели владения trust-ссылок;
   для `shared`/`weak`/`unique` определить смысл `&x`.
3. Неявный `[=]`/`[&]` и init-capture `[name = expr]` — реализовать либо дать точную диагностику.

**DoD L3**

- `[&x]` компилируется при валидном займе и даёт явную ошибку при невалидном.
- `[=]`/`[&]`/`[name = expr]` — либо реализованы, либо точная диагностика.
- Сквозной пайплайн parser → semantic → codegen; lit (codegen + diag).
