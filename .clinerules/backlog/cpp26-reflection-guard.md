# Беклог: Использование рефлексии C++26 вместо cmake-скрипта тестов

> Статус: **отложено** — ожидает поддержки рефлексии (P2996, C++26) в тулчейне проекта.
> Действующий механизм: `cmake/check_ast_slots.cmake` + негативная фикстура
> `test/guards/fixture_ast_slots` (CTest `ast_slots_guard`, `ast_slots_guard_selftest`).
> История и мотивировка текущего решения — `.tasklog/1793703140758.md`.

## Предмет

`ast_slots_guard` проверяет два инварианта, которые **сейчас невыразимы типами**:

1. каждое поле-слот узла (`AstNodePtr`, `std::vector<AstNodePtr>`, `std::optional<...>`,
   `const AstNodeBase*`, `const FuncDecl*`, их списки) объявлено строкой класс-таблицы
   (`include/ast/node_slots_x.hpp`);
2. каждый класс с непустыми строками объявляет `forEachSlot` (`AST_SLOT_METHOD`), а не
   наследует пустую базовую реализацию.

Причина: в C++ нет перечисления нестатических полей класса, поэтому сравнивать «объявления
полей» с таблицей можно только текстовым сканированием.

## Что даст рефлексия (и чего не даст)

| Инвариант | Выразимо через `std::meta` | Замена |
|---|---|---|
| (1) поле-слот объявлено в таблице | да: `nonstatic_data_members_of(^^T)` + фильтр по типу + сверка имени со строками таблицы | `static_assert` (compile-time) |
| (2) класс объявляет `forEachSlot` | да: `members_of(^^T)` возвращает только члены, объявленные в `T` | `static_assert` |
| `kind_dispatch_guard` | **нет** — проверяет паттерны кода (`switch/case` по kind) | остаётся текстовым |
| `name_domains_guard` | **нет** — проверяет использование строк/API доменов имён | остаётся текстовым |

Важно: **таблица `node_slots_x.hpp` остаётся**. Она несёт не только перечень полей, но и
классификацию/политику (`Traversed/Internal`, `SkipKinds`, `ListDeduped`), которая из типа поля
не выводится. Рефлексия заменяет только **проверку покрытия**, а не саму модель слотов.

## Предусловия

- Тулчейн с поддержкой рефлексии (`<meta>`, оператор `^^`, `-freflection`/эквивалент);
  на момент создания задачи `clang++-22` её не имеет — проверено.
- Повышение `CMAKE_CXX_STANDARD` до версии с рефлексией (отдельное решение по стандарту).
- Feature-detect макрос (например `__cpp_reflection`) + CMake-гейт `TRUST_HAS_REFLECTION`
  на переходный период, чтобы сборка не зависела от версии компилятора.

## Оценка и риски

- **Выгода**: инвариант проверяется компилятором (быстрее, раньше, без текстового сканирования);
  минус один CTest-механизм и одна фикстура.
- **Риски**: зрелость рефлексии в компиляторе, рост времени компиляции AST-заголовков,
  качество диагностик `static_assert` (потребуется `consteval`-сообщения с именем поля).
- **Не делать раньше**: без рефлексии единственные альтернативы — declare-once макросы
  (поле объявляется вместе с метаданными; отклонено из-за макро-заголовков) и кодоген из схемы
  (лишний build-step).

## Промежуточный вариант (без рефлексии)

Правило (2) можно перевести на компиляцию уже сейчас: посчитать строки макроса (`ROWS(COUNT)`
с `+1` на строку → `kSlotRowCount<cls>`) и в `AST_SLOT_METHOD` выставлять признак
`kSlotsDeclared = true`; затем `static_assert(kSlotRowCount<cls> == 0 || cls::kSlotsDeclared)`.
Правило (1) всё равно останется текстовым. Делать только если regex-guard окажется хрупким:
это +~10 строк макрос-счётчика ради снятия одного правила.
