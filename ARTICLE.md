# TrustLang: язык программирования, который не пытается заменить C++, а делает его проще

*Техническая статья для блога проекта. Версия 0.6.0.*

> **Аннотация.** TrustLang — высокоуровневый язык общего назначения с безопасным управлением
> памятью, реализованный как **транспилятор в C++**. Вместо того чтобы строить изолированный
> рантайм и бэкенд, он переводится в читаемый C++ и использует всю мощь C/C++ экосистемы
> «из коробки». В статье — идея, ключевые особенности, система типов, модель памяти,
> отличия от C++, Rust, Go, Python и Java, а также инструменты, поставляемые вместе с языком.

---

## Вступление: проблема «вечно усложняющегося синтаксиса»

У каждого нового поколения языков программирования синтаксис становится сложнее. Свежие
версии C++ добавляют новые ключевые слова и конструкции, повышая порог входа и стоимость
сопровождения легаси-кода. Есть и обратная сторона: языки с простым синтаксисом часто
заставляют отказываться от чего-то важного — производительности, контроля памяти, интеграции
с существующим кодом.

TrustLang предлагает другой путь: **не изобретать всё с нуля, а переиспользовать лучший из
существующих компилируемых языков — C++ — и скрыть его сложность**, добавив при этом
гарантии безопасности, которые невозможно нарушить случайно.

---

## Философия: надстройка над C++, а не изолированный мир

Основной тезис: язык должен быть «тонким слоем» над C++.

- Компилятор TrustLang **не генерирует машинный код** и не строит свой виртуальный рантайм —
  он производит **исходный код на C++**, который затем собирается штатным C++-тулчейном.
- Поэтому доступна **вся C/C++ экосистема**: стандартная библиотека, существующие библиотеки,
  инструменты сборки, отладчики.
- Программист получает **высокоуровневый синтаксис и безопасность**, но при необходимости
  может «спуститься» до чистого C++ внутри одного выражения.

Это радикально снижает порог входа для C/C++-разработчиков и не требует переписывания
существующих библиотек.

## Полная интеграция с C++: пять уровней

### 1. Прямая вставка нативного C++ кода

Конструкция `{% ... %}` переносит C++-код в сгенерированную программу **как есть** —
без FFI, без обёрток, без генерации прокси. Код внутри вставки — это обычный C++.

```trust
{% int x = 42; %};
{% printf("x = %d\n", x); %};   // чистый C++, как если бы вы писали в .cpp
```

### 2. Использование trust-переменных внутри C++-вставок

Внутри `{% ... %}` можно напрямую ссылаться на переменные TrustLang через маркеры
`$name` (локальная) и `@name` (глобальная / `::`). Транспилятор автоматически конвертирует
их в корректные C++-идентификаторы:

```trust
msg :StrChar := 'Hello';
{% printf("%s\n", $msg); %};        // $msg  →  c_msg  (trust-переменная напрямую)
{% auto v = @std::vector<int>; %};  // v -> %cpp_v
```

Фактически это «окно» между двумя мирами: переменные TrustLang становятся обычными
C++-переменными с предсказуемыми именами.

### 3. Прямой вызов C/C++ функций (нативный импорт)

Нативные имена с ведущим `%` — это **уже C++-символы рантайма**. Транспилятор срезает `%`
и оставляет имя без изменений, поэтому вызов резолвится напрямую в символ C++ на этапе
компоновки:

```trust
fopen(filename:StrChar, modes:StrChar):FileHandler ::= %fopen...;
fclose(f:FileHandler):Int32                       ::= %fclose...;
```

Здесь `%fopen → fopen`, `%std::max → std::max`. **Никакого FFI**: без врапперов, без таблиц
динамических вызовов, без описания сигнатур вручную. Даже встроенные макросы языка устроены
так же: `print(...)` разворачивается в `%trust::trust__print__(...)`, а `@assert` — в
`%trust::trust__abort__(...)`.

### 4. Обратный вызов TrustLang-кода из C++

Экспорт-интерфейс модуля ABI-стабилен: сгенерированный код содержит таблицу
`__trust_get_exports`/`__trust_export_entries` (имя → адрес), а точка входа —
`extern int <модуль>__main__()`. Это позволяет вызывать функции TrustLang из C++ и других языков.

### 5. Прозрачный и читабельный генерируемый C++

Манглинг имён предсказуем и обратим:

| trust-имя        | C++-имя            | Правило                       |
|------------------|--------------------|-------------------------------|
| `x`, `MyInt`     | `c_x`, `c_MyInt`   | `c_` для простых ASCII-имён   |
| `std::vector`    | `cpp_std$$vector`  | `cpp_` + `$` вместо `::`      |
| `привет`         | `ru_privet`        | `ru_` + транслитерация        |
| прочий UTF-8     | `u8_...`           | `u8_` + HEX-кодирование       |
| `%add`, `%max`   | `add`, `max`       | нативные — как есть (срез `%`)|

Это делает сгенерированный код читаемым, детерминированным и проверяемым. А встроенный
**source map (trust ↔ C++)**, помещаемый в ELF-секцию `.debug_trust_map`, позволяет LSP/DAP
навигировать между исходным кодом TrustLang и сгенерированным C++ и отлаживать в обоих файлах.

## Безопасная модель памяти без сборщика мусора

Одна из главных целей языка — исключить ошибки управления памятью на этапе компиляции:

- **Нет сборщика мусора** — управление памятью детерминированное (сильные/слабые ссылки),
  что важно для производительности и встраиваемых сценариев.
- **Нет «null-указателя»** в привычном понимании — концепция пустого указателя скрыта
  в деталях реализации, что исключает целый класс ошибок (null-dereference).
- **Гонки данных и висячие ссылки** выявляются на этапе компиляции (Trust Checking).

В сочетании с рантайм-проверками это даёт «безопасность по умолчанию», не требуя при этом
сборщика мусора и не замедляя обычный путь выполнения.

## Система типов: статическая строгость + безопасная динамика

TrustLang сочетает статическую и динамическую типизацию:

- **Статическая типизация «условно-строгая»**: неявных «грязных» приведений нет, но есть
  безопасные автоматические расширения. Например, целое число может быть расширено
  до вещественного или рационального, но не наоборот.
- **Авто-вывод в наименьший тип**: числовые литералы выводятся в минимально достаточный
  целочисленный тип (Bool/Int8/...), а при составной арифметике тип автоматически расширяется
  (например, `Bool → Int64`).
- **Динамическая типизация через `std::any`**: если тип не выводится статически, переменная
  становится `std::any`; операции над `any`-операндами безопасно оборачиваются
  в `std::any_cast<CommonType>` — без UB и «мусорных» значений, как в JS/Python:

  ```trust
  x:Any := 5;              // → std::any c_x = 5;
  y := x + 2;              // → std::any_cast<int32_t>(c_x) + 2
  ```

- **Проверка диапазона при сужении**: явный каст `:Type(expr)` превращается
  в `trust::checked_cast<Type>` с рантайм-проверкой выхода за границы типа.

Такой подход даёт удобство динамических языков там, где это уместно, и безопасность
статических там, где это критично.

## Выразительные управляющие конструкции

Ряд конструкций редко встречается в компилируемых языках и реализован в TrustLang «из коробки»:

- **`while ... else`** — ветка, выполняемая, если цикл не выполнился ни разу (как в Python,
  но в компилируемом языке; в C++ отсутствует).
- **`match` с несколькими шаблонами** в одном `case`:

  ```trust
  @match(x) ==> {
      @case(1) { y := 1; };
      @case(2, 3) { y := 2; };   // несколько шаблонов в одной ветке
      @default { y := 0; };
  };
  ```

- **Именованные блоки-метки** с `break label`/`continue label` — аналог labeled break из Java;
  в C++ такой возможности нет вплоть до C++26 (P2552).
- **Псевдо-переменная `$^`** — «результат последней операции/блока» (особенность дизайна
  языка, конструкция распознаётся на уровне AST).

## Встроенные «тяжёлые» типы данных

Обычно поддержка рациональных чисел или тензоров — это внешние библиотеки. В TrustLang
они **встроены в синтаксис**:

- **Рациональные числа произвольной точности** (GMP) с собственным литералом `num\den`.
  Вычисление факториала `1000!` — это буквально несколько строк на «чистом» языке.
- **Тензоры** (LibTorch) как базовый тип, поддерживаемый синтаксисом без подключения
  дополнительных библиотек.

Это делает научные и математические вычисления «родными» для языка, а не результатом
подключения сторонних инструментов.

---

## Синтаксис без обязательных ключевых слов + DSL

Базовый синтаксис TrustLang строится на **грамматических правилах, а не на ключевых словах**.
Привычный вид (`if`, `while`, `match`, `return`) обеспечивается **макросами** (`@if`, `@while`,
`@match`, `@return`, ...), которые можно адаптировать под конкретную предметную область или исолпьзовтаь для этого национальные алфавиты (DSL-подход). Преимущества:

- **Сигилы-квалификаторы имён** кодируют назначение объекта прямо в имени:
  `@` макрос, `$` временная переменная, `::` статическое/глобальное, `\` модуль,
  `:` тип/конструктор, `%` нативный импорт, `^` константность.
- **Раздельные операторы**: `:=` — *создание* переменной, `=` — *присваивание*. Это исключает
  случайное создание переменной вместо присваивания (частая ошибка в Python) и упрощает
  статический анализ.

## Модули и пространства имён

- Пространства имён: глобальная `::`, именованная `ns::`, анонимная `_` (внутренняя компоновка).
- Модули `\module(...)` с glob-масками импорта (`*`/`?`), компиляция модулей в отдельные
  единицы компиляции, экспорт-интерфейс модуля, детекция циклических зависимостей.
- ABI-стабильный экспорт для динамической загрузки и обратного вызова из C++.

---

## Инструменты разработчика «из коробки»

Релиз поставляется не только с компилятором, но и с полноценной средой:

- **`trust-lsp`** — языковой сервер: переход к определению, hover, inlay hints, document links,
  инкрементальная синхронизация.
- **`trust-dap`** — сервер отладки через GDB/MI с трансляцией позиций trust↔C++.
- **VS Code-расширение** — подсветка синтаксиса и интеграция с LSP.
- **Solver (SMT-LIB 2)** с опциональной интеграцией Z3 — прототип формальной верификации.

Это снимает главный барьер для новичков: язык «из коробки» поддерживает подсветку,
автодополнение, переход к определениям и отладку.

## Сравнение с другими языками

| Критерий | TrustLang | C++ | Rust | Go | Python | Java |
|----------|-----------|-----|------|----|--------|------|
| Генерация | транспиляция в C++ | машинный код | машинный код | машинный код | интерпретация | байткод JVM |
| Интеграция с C/C++ | прямая (вставки, `%`-импорт, без FFI) | родная | через FFI/unsafe | через cgo | через ctypes/cffi | через JNI |
| Сборщик мусора | нет (безопасное управление) | ручное | нет (ownership) | да | да | да |
| Null-указатель | скрыт | есть (UB) | есть (Option) | есть (nil) | есть (None) | есть (null) |
| Типизация | статич. строгая + безопасная динамика (`std::any`) | статическая | статическая | статическая | динамическая | статическая |
| Динамическая типизация | встроенная (`std::any`) | нет | нет | ограничено | да | ограничено |
| `while … else` / match-несколько-шаблонов | да | нет (до C++26) | частично | нет | while-else есть | нет |
| Рациональные числа/тензоры встроенные | да | нет | нет | нет | частично (Decimal) | нет |
| Инструменты в комплекте | LSP+DAP+VS Code | разнородные | частично | частично | разнородные | IDE |
| Порог входа для C/C++ разработчика | низкий | — | высокий | средний | низкий | средний |

**Главное отличие от Rust**: TrustLang не вводит систему владения (borrow checker), а
использует сильные/слабые ссылки и контроль на этапе компиляции, оставаясь при этом
без GC. **Главное отличие от Go/Java**: не нужен сборщик мусора. **Главное отличие от Python**:
компилируемость, строгая типизация и глубокая интеграция с C++, без FFI-прокладок.

## Архитектура

Конвейер компиляции разделён на чёткие этапы:

```
исходник → лексический/синтаксический анализ (Flex/Bison) → макропроцессинг/DSL
        → конвертация в AST → семантический анализ → генерация C++ → сборка (Makefile)
```

Ключевые решения:

- **Компонентная архитектура**: `syntax`, `ast`, `types`, `semantic`, `transpiler`, `solver`,
  `diag`, `pipeline`, `runtime`, `lsp`, `dap`, `vscode` — статические библиотеки с явными
  зависимостями.
- **Единый `Context`** — точка доступа к диагностике, исходнику, типам и атрибутам.
- **Source map (trust↔C++)** — первоклассная сущность, основа прозрачности и отладки.
- **Makefile + `build.conf`** генерируются рядом с `.cppt` — сборку можно повторить вручную.
- **Многоуровневое тестирование**: CTest + GTest (unit) + LIT (CLI + FileCheck) + тесты VS Code.

Проект разрабатывается с помощью AI-агентов (agent-driven development), что накладывает
требование к детерминированности и проверяемости каждого этапа.

## Пример: факториал 1000! рациональными числами

```trust
@main() := {
    fact :Rational := 1\1;          # рациональное число
    mult := 1;                      # счётчик (Bool → Int64 при +=1)

    @while( mult <= 1000 ) {
        fact *= mult;
        mult += 1;
    };

    # Проверка результата включена по умолчанию (@assert)
    @assert( fact == 40238726007709377354370243392... );
    print('{}', :StrChar(fact));    # 2568-значное значение 1000!
}
```

Этот пример входит в `examples/rational.src` и проходит end-to-end сборку и запуск.

## Установка и запуск

```sh
cmake -B _build && cmake --build _build --target package
tar -xzf _build/dist/trust-lang-<version>-<hash>-linux-x86_64.tar.gz
trust -q -o hello hello.src && ./hello
```

CLI: `--emit-cpp/--emit-ast/--emit-tokens` (отладка), `-c/-a/-l/-m` (объект/статические/
динамические/модуль), `--run` (собрать исполняемый файл и запустить его),
`--link-runtime static|shared`, `--no-dsl/--dsl <file>`.

> Windows: рекомендуется WSL2 (POSIX/ELF-тулчейн); нативная сборка — отдельная задача.

## Ограничения и дорожная карта

Текущая версия 0.6.0 — **первый рабочий релиз**: компилируются и запускаются отдельные
текстовые примеры. В стадии прототипа или запланировано:

- ООП (классы, наследование, «утиная типизация»);
- итераторы и циклы по коллекциям;
- многозадачность (вытесняющая/кооперативная, async);
- полноценные тензоры (опциональная сборка `WITH_TORCH`);
- формальная верификация (Trust Checking / SMT + Z3);
- REPL-режим интерпретатора;
- нативный Windows (без WSL2).

## Заключение

TrustLang — это попытка ответить на вопрос «а что, если не усложнять, а переиспользовать?».
Вместо изолированного мира — полная интеграция с C++ без FFI; вместо сборщика мусора —
безопасное управление памятью с контролем на этапе компиляции; вместо ещё одного
«велосипеда» в синтаксисе — грамматика, которую можно адаптировать под свою предметную область.

Первый рабочий релиз уже позволяет компилировать и запускать примеры, поставляется
с LSP/DAP/VS Code и дистрибутивом-архивом. Приглашаем попробовать и присоединиться
к развитию проекта.
