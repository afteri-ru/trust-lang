## Architecture

Каталог публичного сайта проекта (Hugo + тема Docsy); первоисточник — `docs/content/ru`, `content/en` —
его синхронный перевод. Единая генерация — `docs/site_build.sh` (фрагменты песочницы из `examples/*.src`
через `trust-lsp --html`, затем `hugo`). Технические детали сборки сайта — `docs/README.md`.

Публикуется только публичная документация: рабочие и промежуточные материалы принадлежат
`MEMORY.md` компонентов и бэклогу; в `docs/content` материалы разработки не публикуются.

## Facts and invariants

- **Правило «одно место» (обязательное):** каждая возможность/технология описана в ОДНОЙ канонической
  странице; в остальных местах — краткая выжимка + ссылка. Дублирование правила/примера/таблицы между
  страницами — баг. Это не «одна страница на всю документацию»: у разных технологий свои источники.
- **Код-примеры длиннее 2–3 строк не дублируются:** выжимка + ссылка в песочницу на существующий
  `examples/*.src`; если фича реализована, а примера нет — пример добавляется в `examples/`, а не «в доку».
- **Страницы описывают ТОЛЬКО реализованный синтаксис;** статус и границы — только в `status.md`.
  Баннеры `{{< unreleased >}}`/`pageinfo` внутри страниц НЕ используются; допустим только layout-баннер
  уровня сайта (`partials/dev-notice.html`, раздел docs, ru, при `[params.dev_notice].enabled`).
- **Полные перечни опций CLI и диагностик не дублируются:** источник — `trust --help`, `trust -Whelp`
  и ховеры/quick-fix LSP; в docs — концепция + указатель.
- **Архитектура — один стабильный файл** (`architecture.md`), без подстраниц и только стабильные факты.
  Детали реализации (конвейер, mangling, прагмы, кодоген) в docs НЕ документируются — их источник код.
  Отдельной страницы про ABI/предкомпилированные файлы нет.
- Актуальная версия в текстах — из `VERSION`; «0.6.x»-подобные расхождения — ошибка.

## Decisions

- **`*_index.md` — краткая навигация + общие для раздела факты,** размещаемые один раз;
  фундаментальное понятие — ссылкой, без пересказа.
- **Канонические страницы-источники:** память — `safety/memory.md`; защита стека —
  `safety/stack_check.md`; инвалидация производных представлений (`@[borrowed]`, `-Wborrow-*`) —
  `safety/borrowing.md` (это НЕ модель заимствования Rust); макросы/DSL — `syntax/macros.md`; система
  типов — `types/_index.md`; C/C++ — `types/native.md`; файлы/группы/пакеты — `syntax/hierarchy.md`;
  верификация — `safety/verification.md`; инструменты — `sandbox.md`; статус — `status.md`.
- **Нет категории «итераторы»:** перебор — цикл с деструктуризацией элемента (канонический пример —
  `operators/flow.md`, правила — `operators/create.md`).
- **Сравнение с аналогами — только в блоге** (`blog/comparison/`, `blog/language-design/`).
- Раздел «Архитектура» — appendix для разработчиков, вне «пути новичка»; карта возможностей —
  `docs/content/ru/docs/_index.md`, главная — позиционирование + карточки-отличия со ссылками.
