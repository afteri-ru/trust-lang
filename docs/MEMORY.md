## Architecture

Сайт — Hugo + тема Docsy (конфиг `docs/hugo.toml`), контент — `docs/content/` (первоисточник
пользовательской документации — ТОЛЬКО `content/ru`; `content/en` — его синхронный перевод). Единая генерация —
`docs/site_build.sh`: собирает фрагмент песочницы из `examples/*.src` через `_build/trust-lsp --html …`,
затем `hugo`; локальная среда — `docs/site_playground_run.sh`. Примеры песочницы = файлы
`examples/*.src`; URL встраивания в документацию — `/ru/playground/?file=<имя>`.

## Facts and invariants

- **Правило «одно место» (обязательное):** каждая возможность/технология полностью описана в ОДНОЙ
  канонической странице-источнике. Это НЕ «одна страница на всю память»: управление памятью, контроль
  инвалидации C++-ссылок и защита стека — разные технологии, у каждой свой источник. В остальных
  местах — краткая выжимка + ссылка. Дублирование одного правила/примера/таблицы между страницами —
  баг документации.
- **`content/ru` — единственный первоисточник документации;** `content/en` — синхронный перевод ru
  (не источник и не правится в одиночку). Англоязычные страницы НЕ ссылаются на русскоязычные
  первоисточники: `ru.wikipedia` → `en.wikipedia`, ссылки на habr.com/ru и подобные русскоязычные
  сайты удаляются (текст остаётся), front matter `link:` с русскоязычным URL не переносится.
- **Код-примеры длиннее 2–3 строк не дублируются** в тексте: выжимка + ссылка в песочницу
  `/ru/playground/?file=<имя>` на существующий `examples/*.src`. Если подходящего примера нет, а фича
  реализована — пример добавляется в `examples/` (не только «в доку»). Короткие сниппеты (1–3 строки)
  допустимы инлайн.
- **Страницы описывают ТОЛЬКО реализованный синтаксис:** нереализованные возможности не
  описываются как рабочие, их статус и границы — только в `status.md`. Баннеры
  (`{{< unreleased >}}`, `pageinfo`) и исторические HTML-комментарии в страницах НЕ используются;
  допустим только **layout-баннер уровня сайта** — `partials/dev-notice.html`, подключаемый в
  `layouts/docs/baseof.html` (раздел docs, ru) при `[params.dev_notice].enabled`.
- **Полные перечни опций CLI и диагностик не дублируются:** их источник — сам инструмент
  (`trust --help`, `trust -Whelp`) и ховеры/quick-fix LSP; в docs — краткое концептуальное описание +
  указатель. Частный случай правила «одно место».
- **Архитектура — один стабильный файл** (`architecture.md`), без подстраниц; в нём только стабильные
  факты (транспиляция в C++, сборочный каталог `.cppt` + `Makefile`, авто-подключение рантайм-заголовков,
  верификация SMT). Детали внутренней реализации (конвейер, mangling, прагмы, кодогенерация) в docs НЕ
  документируются — их источник код; исключение — **принцип** семантического ABI/манглинга имён в
  двоичных файлах описан концептуально на канонической странице `sabi.md` (детали реализации —
  по-прежнему в коде).
- Раздел «Архитектура» — appendix для разработчиков (высокий weight), вне «пути новичка» (О проекте →
  песочница → syntax/types/operators → safety → инструменты).
- **Каноническая «карта возможностей» — `docs/_index.md`;** главная страница — позиционирование +
  краткие карточки-отличия со ссылками на страницы-источники (безопасность памяти — тремя отдельными
  карточками); полный пересказ концепций на главной не повторяется.
- Актуальная версия в текстах — из `VERSION`; расхождения вида «0.6.x» — ошибка.

## Decisions

- **Индексная страница раздела (`*_index.md`) — краткая навигация + общие для раздела факты,** которые
  размещаются один раз и НЕ дублируются в каждой странице. Фундаментальное понятие, подробно описанное
  отдельно, в `_index.md` — ссылкой, без пересказа.
- **Списки возможностей на главной и в блоге — выжимка + ссылка на каноническую сводку**
  (`docs/_index.md`), а не полный пересказ.
- **Канонические страницы-источники по темам:** модель памяти — `safety/memory.md`; защита стека —
  `safety/stack_check.md`; контроль инвалидации ссылок — `safety/invalidation.md`; макросы/DSL —
  `syntax/macros.md`; система типов — `types/type_system.md`; интеграция C/C++ — `types/native.md`;
  семантический ABI/линковка модулей — `sabi.md`; верификация — `safety/verification.md`;
  инструменты — `sandbox.md`. Правило
  «DSL ↔ базовый синтаксис» — в `syntax/macros.md`.
- **Нет отдельной категории «итераторы»:** перебор коллекций — цикл с деструктуризацией элемента;
  канонический пример — в `operators/flow.md`, правила деструктуризации/rest — в `operators/create.md`.
- **Системные имена/предопределённые макросы/константы** — единый источник `syntax/macros.md`;
  соответствие «DSL ↔ базовый синтаксис» тоже там, а не в `operators/_index.md`.
- **Сравнение с аналогами — только в блоге** (`blog/comparison/`, эссе `blog/language-design/`); в
  справочнике docs сравнение с другими языками не дублируется.
- **Уведомление о разработке — layout-баннер, а не текст страниц:** `layouts/partials/dev-notice.html`
  выводится вверху страниц раздела docs (ru) при `[params.dev_notice].enabled` в `hugo.toml`;
  снимается после синхронизации документации с версией 0.7.0. Дублировать текст по страницам
  запрещено (правило «одно место»).
