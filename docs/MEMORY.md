## Architecture

Сайт собран на Hugo + тема Docsy; конфиг — `docs/hugo.toml`, контент — `docs/content/`
(`content/ru` — исходник на русском, `content/en` — перевод). Разделы пользовательской
документации лежат в `docs/content/ru/docs/` (overview, getting-started, syntax, types,
operators, tooling, architecture, contribute). Единая генерация сайта —
`docs/site_build.sh`: собирает фрагмент песочницы из `examples/*.src` через
`_build/trust-lsp --html … --examples-dir ../examples` и затем `hugo`. Локальная среда —
`docs/site_playground_run.sh`.

Код-примеры песочницы = файлы `examples/*.src` (репозиторий); URL для встраивания в
документацию — `/ru/playground/?file=<имя>` (см. `docs/content/ru/docs/sandbox.md`).

Левый сайдбар раздела `docs` (список разделов) можно скрыть/показать кнопкой-«табом»
у левого края на десктопе (`>= xl`): маркер `.td-docs-layout` на `.row` в
`layouts/docs/baseof.html`, правила в `assets/scss/_styles_project.scss`, логика и
состояние (localStorage, ключ `trust-docs-sidebar-hidden`) в
`docs/static/js/sidebar-collapse.js` (подключён через `hooks/body-end.html`).
Прогрессивное улучшение: без JS / ниже `xl` / при печати остаётся штатная колонка.

## Facts and invariants

- **Правило «одно место» (обязательное):** каждая возможность/конструкция синтаксиса
  полностью описана **только в одном месте** (страница-источник). Во всех остальных
  местах — краткая выжимка «для контекста» + ссылка на источник. Дублирование одного и
  того же правила/примера/таблицы между страницами — баг документации, а не «удобство».
- `content/ru` — источник правды пользовательской документации; `content/en` — перевод.
  Структура разделов ru и en должна совпадать; рассинхрон структуры — баг.
- Код-примеры длиннее 2–3 строк **не дублируются** в тексте: вместо кода даётся выжимка
  + ссылка в песочницу `/ru/playground/?file=<имя>` на существующий `examples/*.src`.
  Если подходящего примера нет, а фича реализована — пример добавляется в `examples/`
  (не только «в доку»). Короткие иллюстративные сниппеты (1–3 строки) допустимы инлайн.
- Нереализованный синтаксис **не описывается как рабочий**: статус и границы реализации —
  только в `overview/status.md`; страницы-заглушки используют метку `{{< unreleased … >}}`
  и ссылаются на `status.md`, а не разворачивают полный нерабочий справочник.
- **Полные перечни опций CLI и диагностик не дублируются в документации**: их источник —
  сам инструмент (`trust --help`, `trust -Whelp`) и ховеры/quick-fix LSP. В docs — только
  краткое концептуальное описание и указатель на справку. Это частный случай правила
  «одно место»: источник таких списков — приложение, а не сайт.
- **Архитектура — один стабильный файл** (`docs/architecture/_index.md`), без подстраниц.
  В нём только стабильные факты (транспиляция в C++, сборочный каталог `.cppt` + `Makefile`,
  авто-подключение рантайм-заголовков, верификация SMT). Детали внутренней реализации
  (конвейер, mangling, прагмы, кодогенерация) в docs **НЕ** документируются — при активной
  разработке они меняются; их источник — код и комментарии к нему.
- Раздел «Архитектура» — **appendix для разработчиков**: расположен в конце документации
  (высокий weight), вне «пути новичка» (overview → getting-started → syntax/types/operators →
  tooling).
- Главная страница (`content/ru/_index.html`) — только цель проекта и один малый пример;
  концепции/возможности она не повторяет, а ссылается на `docs/overview/*`.
- Актуальная версия в текстах — из `VERSION` (0.6.0); расхождения вида «0.6.x» — ошибка.

## Decisions

- **Индексная страница раздела (`*_index.md`) — описание фундаментальных (общих для всего раздела) понятий + ручной список/таблица ссылок на страницы раздела (без автогенерации индекса).** Факты, общие для всех страниц раздела (например: операторы разделяются точкой с запятой `;`; выражение и блок кода возвращают значение), размещаются на индексной странице и НЕ повторяются в каждой странице раздела.


- **Каноническая сводка возможностей — `docs/content/ru/docs/overview/features.md`**
  («карта»: фича → кратко + ссылка на страницу-источник). Списки возможностей в
  `concepts.md`, `comparison.md` и на главной сводятся к выжимке + ссылке на неё.
- Канонические страницы-источники по темам (при отсутствии дублирующих копий): память —
  `syntax/memory.md`; макросы/DSL — `syntax/dsl.md`, `syntax/macros.md`; система типов —
  `types/type_system.md`; интеграция C/C++ — `syntax/cpp-interop.md` + `types/native.md`;
  верификация (AoRTE/Z3) — `syntax/proof.md` (единственная подробная страница);
  инструменты — `tooling/_index.md` (одна страница: описания возможностей, без перечней
  опций каждого инструмента).
- **Нет отдельной категории «итераторы»**: итераторы — обычные классы (не отдельный тип
  языка). Перебор коллекций описан в `types/containers.md` и `operators/while.md`;
  страница `types/iters.md` удалена.
- **Системные имена/предопределённые макросы/константы** — единый источник `syntax/dsl.md`;
  отдельной `architecture/sysprop.md` нет (удалена: устаревшая копия dsl + легаси
  интерпретаторной объектной модели).
- `operators/_index.md` — чистый навигационный индекс; соответствие «DSL ↔ базовый
  синтаксис» описывается один раз в `syntax/dsl.md`, а не повторяется в _index.
- Сравнение с аналогами живёт в `overview/comparison.md` (таблица) и в блоге `blog/comparison/`
  (развёрнутые статьи); между ними — только ссылки, без дублирования таблиц.
