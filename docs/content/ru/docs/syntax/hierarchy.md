## Пространства имён

*TrustLang* поддерживает пространства имён; разделитель, как и в C++, — двойное двоеточие `::`.
Область имён может быть указана как для отдельного идентификатора, так и для целого
[блока кода](../operators/#block).

В отличие от `namespace` в C++, области имён в *TrustLang* служат не только для организации кода
логическими группами и избежания конфликтов имён: имя, в котором явно указана область имён, относится
к **статическим** объектам (память под которые выделяется на этапе компиляции).

Глобальное имя не может быть перекрыто макросом или локальной переменной при
[разрешении имён (name lookup)](naming/#name-lookup). Чтобы создать глобальную (статическую)
переменную, достаточно записать её имя с глобальным квалификатором `::var`. Для использования
пространства имён в блоке кода его указывают перед открывающей фигурной скобкой; в таком именованном
блоке завершающие `::` можно не писать.

```
::var := 0;    # имя глобальной переменной (не может быть перекрыто)

ns {           # равнозначно ns::
    var := 0;      # имя ns::var (может быть перекрыто макросом/локальной переменной)
    @::var := 0;   # имя глобальной переменной ::ns::var

    name:: {
        var  := 0;   # обращение к переменной ns::var
        var2 := 0;   # имя переменной ns::name::var2
        ::var = 1;   # переменная из глобального пространства имён
    };
};
```

## Модули

*TrustLang* реализует программные модули и пакеты: идея иерархического расположения файлов в
каталогах файловой системы (как в Python), но разделитель имён — не точка, а обратная косая черта `\`.

Имя модуля может содержать только строчные английские буквы, цифры и символ подчёркивания (кроме
первой и последней позиций). Ограничение связано с прямым отображением имён модулей на объекты
файловой системы: у разных файловых систем могут различаться кодировки и требования к регистру.

Под модулем понимается **файл** с исходным кодом (расширение `*.src`). Модули хранят часто используемые
функции, классы, константы и т.п. Их условно делят на модули и программы: программы предназначены для
непосредственного запуска, модули — для импорта в другие программы (функционально они не отличаются).

### Объекты модуля {#thread-local}

Все объекты, определённые внутри одного модуля без указания глобального пространства имён, видны
только в рамках текущего файла и в модулях, подключённых после его определения.

Время жизни статических и локальных переменных верхнего уровня модуля одинаково и ограничено временем
жизни самого модуля, но для многопоточности они различаются: **статическая** переменная модуля всегда
существует в единственном экземпляре для всех потоков, а **локальная** переменная модуля — своя для
каждого потока (аналог `thread_local` в C++11).

### Импорт модулей {#import}

Относительное имя модуля начинается с одного символа `\` и указывает на файл относительно текущего
модуля. Абсолютное имя начинается с `\\` и указывает на файл относительно каталога текущего
исполняемого файла (или каталогов поиска модулей, которые можно переопределить, например, аргументами
командной строки).

Проще всего импортировать модуль, записав его имя со скобками как вызов функции; в скобках можно
передать аргументы инициализации модуля, список импортируемых функций и т.д. Если перед именем модуля
стоит символ препроцессора (`@\dir\module()`), модуль импортирует не только код, но и свои макросы
(только при статической загрузке).

Загрузка модулей возможна статически или динамически (по аналогии со статической и динамической
линковкой библиотек):

- `\dir\module()` — статическая загрузка по относительному пути;
- `@\dir\module()` — статическая загрузка с импортом макросов;
- `\\root\dir\module()` — статическая загрузка по абсолютному пути;
- `\( "каталог\файл" )` — динамическая загрузка во время выполнения (при динамической линковке
  макросы импортировать нельзя).

При динамической загрузке компиляция модуля и все проверки выполняются во время выполнения приложения;
статическая загрузка позволяет выявить возможные ошибки на этапе компиляции.

## Пакеты {#package}

Пакет — это каталог, который включает другие каталоги и модули и содержит дополнительный файл
`__init__.src`. Пакеты используются как дополнение к пространствам имён и позволяют работать с модулями
через указание уровня вложенности. В отличие от Python и Java, где модули/пакеты *заменяют* пространства
имён, в *TrustLang* модульная структура и области имён используются одновременно и при указании полного
имени объединяются: `\root\dir\module::ns::name::var`, где `root` и `dir` — каталоги относительно
текущего модуля, `module` — имя файла (`root/dir/module.src`).

Файл `__init__.src`, в отличие от Python, не может быть пустым — он должен в явном виде загружать
входящие в пакет модули:

```
\simper();
\compper();
\annuity();
```

Импорт пакетов использует тот же синтаксис, что и импорт модулей. Пример пакета `fincalc`
(`__init__.src` + модули `simper.src`, `compper.src`, `annuity.src`):

```
\fincalc();                 # импорт всего пакета
\fincalc\simper();          # импорт одного модуля
sp := \fincalc\simper();    # импорт модуля с псевдонимом
\fincalc\simper(__import__="fv");  # импорт конкретной функции
```

## Пространства имён и классы

В *TrustLang* не применяется декорирование (манглинг) имён по типам аргументов. Методы классов
(когда ООП будет реализовано) получают уникальные идентификаторы по аналогии с Python: глобальная
функция с именем класса и метода, объединёнными через `::` (для класса `:NewClass` и метода `method` —
`NewClass::method`). Это позволяет определять методы класса вне тела класса, указав нужное имя в
пространстве имён. Полноценное ООП в текущей версии не реализовано (см. [Классы](../types/class/) и
[Статус](../status/)).
