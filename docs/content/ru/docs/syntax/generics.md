Обобщённое программирование (generic programming) позволяет писать алгоритмы и структуры данных,
работающие с разными типами, независимо от их конкретного вида. Разные языки реализуют эту парадигму
по-своему; сравнительный анализ подходов в других языках опубликован в отдельной
[статье блога](/ru/blog/comparison/generics/).

В *TrustLang* обобщения в текущей версии реализуются через **типовые параметры** и их подстановку в
объявлениях нативных шаблонов-типов и методов коллекций/диапазонов. Модель «обобщённой
функции-диспетчера» с рантайм-диспетчеризацией по типам и отдельным синтаксисом шаблонов пока
не реализована (см. раздел «Что не реализовано» ниже).

## Нативные шаблоны-типы {#native-template}

Нативный C++-шаблон-тип объявляется с префиксом типовых параметров и нативным C++-именем
(мнемоника `@include` добавляет объявлению атрибут `@[include]`):

```trust
@include("vector")
<T> %std::vector() := ...;    # объявляет тип vector<T> с C++-именем std::vector

v: vector<Int32> := [1, 2, 3,];
# → #include <vector>
# → std::vector<int32_t> c_v = std::vector<int32_t>{1, 2, 3};
```

Использование `vector<Int32>` (в аннотациях: объявления, параметры, возвраты) интернирует конкретную
инстанциацию, а C++-заголовок подключается **on-use** — только при реальном использовании типа. Если
C++-имя совпадает со встроенным контейнером (`std::vector`/`std::array` для `:Array`), выводится мягкая
диагностика, и тип резолвится через встроенный `:Array`. Типовой аргумент пишется как `Int32`
(с предупреждением о сигиле `:`) или явным типом `:Int32`/`:MyClass`/`:MyClass<:Int8>` (вложенные
шаблоны).

### Тип-алиас на шаблон

Оператор `::=` принимает ТОЛЬКО тип (тип-имя, типизированный шаблон, `Enum`/`Variant` из словаря), а не
произвольное выражение. Поэтому алиас на шаблон пишется как тип-имя:

```trust
copy ::= :vector<Int32>;
x:copy := [1, 2, 3,];
# → using c_copy = std::vector<int32_t>;
```

## Нативные шаблон-классы (forward-объявление) {#native-template-class}

Нативный C++-шаблон-класс с интерфейсом членов объявляется через `::=` с типовыми параметрами слева
и **явной реализацией** `%std::pair<T1,T2>` справа:

```trust
@include("utility")
<T1,T2> Pair ::= %std::pair<T1,T2> {   # trust-шаблон Pair ↔ std::pair
    %first(): T1 := ...;               # Pair<A,B>.first
    %second(): T2 := ...;              # Pair<A,B>.second
};

p: Pair<Int32, StrChar> := ...;
# → std::pair<int32_t, std::string> + #include <utility>
```

Обобщённая форма `<T1,T2> Pair ::= <T1,T2> %std::pair { ... }` (шаблон привязывается без явного списка
аргументов в RHS) — сахар, реализация **отложена** (диагностика «not implemented»); используйте явную
`%std::pair<T1,T2>`. Формат записи одинаков для нативного и не-нативного имени (отличается только `%`).
Подробнее — [Нативные типы](../types/native/).

## Ограничения оператора `::=`

Не-тип в RHS `::=` (`func(...) ::= { }`, `name ::= '123'`, `term ::= term2(arg)`) — ошибка: `::=`
создаёт тип, у него нет арифметики/выражений. Форма «класс-с-телом» (`func(arg) ::= Class(){...}`)
в текущей версии не реализована (планируется).

## Что не реализовано

- Типовые value-параметры (`array<Int32, 4>`) и ограничения типовых параметров (`T:Integer`) — в разработке.
- Обобщённая «функция-диспетчер» (приём любых нетипизированных аргументов, рантайм-диспетчеризация
  выбора реализации по типам, специализации `<:T1-T2>`/`<:T1+T2>`, JIT-специализация) не реализована;
  концепция описана в [статье блога](/ru/blog/comparison/generics/), статус — в
  [Статусе реализации](../status/).
