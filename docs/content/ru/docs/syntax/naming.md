В качестве имен объектов и названий типов данных можно использовать буквы, цифры и знаки подчеркивания в любых комбинациях, при условии, что первый символ имени не является цифрой. 

Имя не может состоять из единственного знака подчеркивания, так как это специальный термин, который используется в служебных целях.

Для избежания коллизий имен можно использовать [пространство имен](/ru/docs/syntax/hierarchy/) 
и [файловую структуру кода](/ru/docs/syntax/hierarchy/), которые *TrustLang* поддерживает одновременно.
Допускается [переопределение](/ru/docs/types/funcs/#overriding) и [перегрузка](/ru/docs/types/funcs/#overload) функций.

При [создании объектов](/ru/docs/operators/create/) имя идентификатора может содержать один или несколько специальных символов — квалификаторов 
(или [сигилов](https://en.wikipedia.org/wiki/Sigil_(computer_programming))), за которыми закреплено определённое значение.

### Квалификаторы имён {#sigil}
- '**@**' — префикс *собачка* используется для указания имени [макроса](/ru/docs/syntax/macros/),
        который обрабатывается препроцессором до начала синтаксического анализа исходного текста программы.
- '**$**' — знак доллара в начале имени объекта обозначает *временное* имя, время жизни которого [ограничено семантикой языка](/ru/docs/safety/memory/#rules).
- '**::**' — двойное двоеточие разделяет [пространства имён](/ru/docs/syntax/hierarchy/)
        и является признаком *постоянного* объекта, значение которого сохраняется после выхода из текущей области видимости.
        Если имя начинается с '**::**', то область его видимости будет глобальной и он будет доступен из других файлов программы.
- '**.**' — префикс *точка* используется при обращении к полю файла или класса (ограничивает область видимости только текущим объектом).
        Префикс *точка* также может быть использован при определении или вызове функции для указания имени аргумента,
        который нельзя перекрыть макросом препроцессора.
- '**\\**' — *обратная косая черта* в начале имени обозначает путь файла или группы:
        `\file` — файл в корне проекта, `\\group\...` — группа-каталог, `\\\pkg\...` — пакет;
        далее разделитель — одиночный `\`. См. [файлы, группы и пакеты](/ru/docs/syntax/hierarchy/).
- '**:**' — двоеточие в начале термина обозначает имя [типа](/ru/docs/types/) данных или конструктор [класса](/ru/docs/types/class/), который всегда является *постоянным*
- '**%**' — префикс *знак процента* указывается для [нативных имён переменных и функций](/ru/docs/types/native/)

### Разрешение имен (name lookup) {#name-lookup}
Если имя объекта не содержит [квалификатора](/ru/docs/syntax/naming/#sigil), оно является *простым*.

Когда *TrustLang* встречает *простое* имя объекта без квалификатора, 
в дело вступает алгоритм разрешения имён (name lookup), который связывает *простое* имя, встретившееся в исходном тексте программы,
с его декларацией или созданным объектом.

Разрешение *простых* имен *без квалификатора* (*name lookup*, или поиск имени функции/переменной) происходит всегда в строго определённом порядке:
- в первую очередь происходит поиск имени среди макросов
- в случае вызова функции выполняется статическое разрешение имен при [перегрузке функций](/ru/docs/types/funcs/#overload)
- далее выполняется поиск имени среди локальных объектов до объектов текущего файла
- в последнюю очередь выполняется поиск среди статических объектов с постепенным расширением пространства имен области поиска от текущей до глобальной

Такая последовательность разрешения имён всегда предоставляет возможность переопределить 
глобальные/локальные объекты или имена аргументов у функций для уже существующего кода без его серьёзных изменений.

Например, для имени `name` в области имён **`ns`** поиск происходит в следующей последовательности: 
`@name` → `%name` → `$name` → `ns::name` → `::ns::name` → `::name`,
а для имени аргумента `arg` проверяется только `@arg`:
```python
    ns:: {
        name(arg="value");
    };
```

И в то же время всегда остаётся возможность указать конкретный объект независимо от работы алгоритма разрешения *простых* имён.
Достаточно указать [квалификатор](/ru/docs/syntax/naming/#sigil) в имени объекта в явном виде. 

Например, обратиться к глобальному объекту **name** из пространства имён **ns** из примера выше нужно по полному имени объекта `::ns::name`,
а именованный аргумент *'**.** arg'* не будет заменён макросом `@arg`, если такой будет определён:
```python
    ::ns::name(.arg="value");
```

### Расширение поиска пространства имён {#using}

Для разрешения *простых* имён *без квалификатора* в нескольких областях имён используется
синтаксическая конструкция `... = ns, ns::sub;` (без DSL), а при использовании
[DSL](/ru/docs/syntax/macros/) — ключевое слово-макрос `using namespace ns;` (стиль C++;
равнозначно `@using namespace ns;`). Цель — **путь области имён** (namespace), а не значение/функция
и не тип: все короткие имена из указанных областей участвуют в поиске. Статические члены типа
адресуются квалифицированно (`MyStr::count`, `MyStr.count`) и в расширенный поиск не включаются.

Цель может быть квалифицирована модулем: `... = \lib::ns;` — путь ищется в экспорт-наборе
указанного модуля (одноимённые области разных модулей не сливаются).

Области имён указываются в порядке поиска. Расширенный поиск привязан к **текущей области
видимости** (блок/функция/файл): пути накапливаются, действуют до конца области и не отменяются
отдельным оператором — `... = _;` является ошибкой. Ограничить поиск раньше конца области можно
вложенным блоком. Квалифицированное имя (`ns::name`) доступно всегда и от расширенного поиска
не зависит. Имя области обязано существовать: неизвестная (ошибочно написанная) область —
ошибка компиляции. Если в ОДНОЙ области поиска несколько целей содержат одно короткое имя,
**наборы перегрузок сливаются** (модель C++/D/Ada): выбор — по аргументам вызова. Ошибка
возникает только когда вызов действительно неоднозначен (одинаковые/равно-приводимые сигнатуры)
либо имя не является вызываемым; всегда остаётся явная квалификация (`\lib::ns::f(1)`).

### Предварительное объявление {#forward-declaration}
В тексте программы можно ссылаться только на реально существующие (созданные) объекты.
Но для тех случаев, когда требуется сослаться на объект, который создан в другом файле или будет создан позже,
можно сделать предварительное объявление, при котором компилятор регистрирует имя и тип объекта без его реального создания.

За счет предварительного объявления можно ссылаться только на статические объекты (типы данных), 
или локальные поля класса, о которых компилятор ещё не знает, но которые будут определены в процессе компиляции позже. 

Для предварительного объявления используется полное квалифицированное имя, которое должно
в точности совпадать с именем объекта при его последующем создании.

Для предварительного объявления используется такой же синтаксис, как и при реальном [создании](/ru/docs/operators/create/) объекта,
только справа от оператора создания должно быть указано многоточие.

Область видимости предварительного объявления соответствует области видимости его размещения, 
а не реальной области видимости объекта, который будет впоследствии создан.

```python

    # Предварительное определение переменной файла
    # Действует для всего файла
    var_module:Int32 := ...;

    func() := {
        @return func2(var_module);
    };

    func2(arg:Int32):Int32 := {
        @return $arg*$arg;
    }

    var_module:Int32 := 1;
```

### Имена аргументов, специальные и системные имена {#args}
Обозначение имен аргументов у функций очень похоже на обращение к аргументам в bash-скриптах, 
где "**$1**" или "**$name**" — порядковый номер или имя соответствующего аргумента.

Зарезервированное имя "**$0**" обозначает текущий объект, а именем "**$$**" обозначается родительский объект.

Все аргументы функции собраны в одном словаре со специальным именем **$\***

Неизменяемая виртуальная переменная компилятора "**$^**" содержит результат выполнения последнего оператора или блока кода.


### Неизменяемые объекты {#immutable}
TrustLang реализует динамическую [иммутабельность](https://en.wikipedia.org/wiki/Immutable_object).
Это свойство лексического объекта, а не свойство типа данных и означает, 
что объект может стать неизменяемым не только в момент создания, 
но и в будущем при одной из операций присвоения/изменения значения.

Для придания объекту свойства иммутабельности (невозможности изменять свое значение далее по тексту программы),
используются символ '**^**' *карет* (крышечка/домик) после имени объекта.

```python
    val := 0; # Create mutable variable
    val = 1; # Set new value 
    val^ = 2; # Set unchangeable value 
    val = 3; # Error  !!!
```

Свойство иммутабельности у аргументов функций зависит от типа функции.
У [чистых функций](/ru/docs/types/funcs/#pure) аргументы, передаваемые по ссылке (владеющие переменные), всегда иммутабельные.
Свойство мутабельности у остальных аргументов указывается при определении функции на общих основаниях:

```python
    func( arg1^:Int32, arg2:Int32) := {
        arg1 = 1;    # Error (arg1 - immutable)

        arg2 = 1;    # OK
        arg2^ = 2;    # OK - set immutable value
        arg2 = 3;    # Already error
    }
```
### Иммутабельность вызовов и атрибуты

Признак неизменяемости может относиться и к вызовам функций. Чистота функции задаётся атрибутами объявления (`@[func_pure@]`/`@[func_const@]`/`@[constexpr@]`), а принудительное вычисление на этапе компиляции (`cube^(...)`) в текущей версии **не реализовано** — см. [Функции](../types/funcs/) и [Статус](../status/). Атрибуты объектов (в т.ч. реальная форма `@[имя(...)]` перед объявлением) описаны в разделе [Макросы](macros/) и [Взаимодействие с C/C++](../types/native/).
