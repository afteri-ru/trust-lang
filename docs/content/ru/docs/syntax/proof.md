TrustLang предоставляет **статическую проверку динамических выражений** — формальный анализ
AoRTE («Absence of Run-Time Errors») по принципу gnatprove в Ada: компилятор проверяет
корректность **пользовательских** утверждений на этапе компиляции, а не доказывает
правильность программы в целом.

Анализ не даёт ложных срабатываний, хотя возможны ложные отрицательные: если ошибок при
компиляции нет — проблем в проверяемых местах нет; указание на возможную ошибку не всегда
соответствует действительности (инструмент может ошибаться).

## Trust-конструкции (пред-/пост-условия и утверждения)

Предусловия, постусловия и утверждения задаются тремя мнемониками DSL-макросов (или их
«сырыми» маркерными эквивалентами):

- предусловие `trust_pre( <логическое выражение> )` ↔ `@( <выражение> @)`;
- постусловие `trust_post( <логическое выражение> )` ↔ `@< <выражение> @>`;
- утверждение `trust_assert( <логическое выражение> )` ↔ `@{ <выражение> @}`.

Правила размещения:

- пред- и пост-условия указываются после имени функции в её определении;
- утверждение — после имени переменной/типа либо автономным оператором `@{ ... @};` в теле;
- в предусловии доступны имена параметров, но использование имени самой функции — ошибка;
- в постусловии имя функции означает возвращаемое значение и доступно наряду с параметрами;
- тип, на котором задано утверждение, нельзя выводить автоматически (`x := ...`) — нужна
  явная аннотация (`x :T := ...`).

## Как это проверяется

Trust-конструкции компилятор проверяет двумя способами:

- **рантайм-проверки** — условия встраиваются в код как проверки (единый механизм
  `@assert`/trust-условий);
- **SMT-верификация (Z3)** — по условиям генерируется задача (SMT-LIB 2, `.smt2`) и либо
  выгружается для внешнего решателя, либо выполняется автоматически с сообщением
  контрпримера при нарушении.

Поведение задаётся опциями `-Wsolver` и `--solver-mode`; значения и вспомогательные флаги
перечислять здесь не нужно — они доступны в справке `trust --help` / `trust -Whelp`.

## Примеры

### Контракты функций

Предусловие `trust_pre`, постусловие `trust_post`:

```trust
func(x:Int32):Int32
    trust_pre( x > 0 )          # предусловие
    trust_post( func > x )      # постусловие; func - возвращаемое значение
:= { x + 1 };
```

### Циклы и инварианты

Цикл верифицируется индукцией по явному инварианту перед циклом:

```trust
@{ invariant --> i >= 0 @};        # инвариант перед циклом
@while ( i < n ) { ... };
```

Ограниченное разворачивание цикла (пер-циклово) — термином `z3_unroll(N)` внутри контракта
инварианта:

```trust
@{ invariant --> z3_unroll(3) @};  # развернуть цикл на 3 итерации
@while ( cond ) { ... };
```

### Кванторы и вспомогательные значения

`z3_forall(i, P)` / `z3_exists(i, P)` — кванторы по связанной переменной `i` (объявленной
ранее); `z3_old(x)` — начальное значение, `z3_result` — результат:

```trust
trust_post( z3_forall(i, 0 <= i and i < count) => arr[i] > 0 )
```

## Ограничения и статус

Реализована SMT-проверка **контрактов функций** (пред-/пост-условия и утверждения; целые
→ BitVec; тело кодируется как SSA). Пока не реализованы ветвления/циклы в теле,
автономные/тип/переменные утверждения, вызовы в условиях, массивы (фаза 2). Подробнее — в
[Статусе реализации и ограничения](../status/).
