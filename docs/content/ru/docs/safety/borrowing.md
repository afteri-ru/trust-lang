Контроль инвалидации защищает от **висячих/протухших представлений** (`dangling`): представление
(указатель, итератор, view), полученное из данных объекта, становится недействительным, когда эти
данные меняются. *TrustLang* отслеживает такие производные переменные и сообщает об **изменении
источника при живых зависимых** — на этапе компиляции, а не во время выполнения.

> **Важно: это не модель заимствования Rust.** В TrustLang нет «заёма» как сущности языка:
> нет эксклюзивных/разделяемых займов, two-phase borrow, loan-liveness и правила
> «aliasing XOR mutability». `borrow` — имя механизма; проверяется **инвалидация
> производного представления при мутации/перемещении источника**. Полная спецификация —
> `include/semantic/ref/BORROW_CHECKER.md` в исходниках.

## Модель

- **Источник** (owner) — объект, из данных которого получено представление.
- **Производное представление** (dependent view) — переменная, адресующая данные источника:
  view-объект (итератор/span), результат `@[borrowed]`-метода, нативная ссылка/указатель,
  `&?`-наблюдатель (`weak`) из `shared`.
- **Инвалидация**: мутация/перемещение/сброс источника делает ранее полученное представление
  недействительным. Поэтому диагностика выдаётся **в точке мутации**, а не при последующем
  использовании.
- **Освобождение**: `dep = _;`, перепривязка (`dep = other;`) или выход представления из области
  видимости.
- **Порядок**: представление, рождённое **после** мутации, действительно — инвалидируются только
  представления, рождённые до неё.
- **Анализ flow-sensitive**: живость представлений вычисляется по CFG (ветвления, циклы,
  `break`/`continue`/`return`/`throw`); для `&?`-наблюдателей учитывается последнее
  использование. Одноимённые переменные в разных скоупах не смешиваются.
- **Escape**: возврат `@[borrowed]`-представления или сохранение его в не-view место
  диагностируется как `borrow-escape`; `&?`-наблюдатель безопасен (refcount).

## Три разных механизма

| Механизм | Что контролирует | Диагностика |
|---|---|---|
| Атрибут `@[borrowed]` | контракт «объект держит view в чужие данные»; контракт задаётся классом/типом, методом или переменной | `-Wborrowed=ignore\|warning\|error` |
| Представления умных ссылок | `&?`-наблюдатель из `shared`: мутация/перемещение источника при живом наблюдателе | `-Wborrow-owner-mutated`, `-Wborrow-owner-moved`, `-Wborrow-region-mismatch`, `-Wborrow-escape` |
| `Shared::borrow()` | **runtime**-наблюдатель (`SharedBorrowedRef`): истечение проверяется в рантайме (`valid()`/`access()`) | — (не статический анализ) |

## Что отслеживается атрибутом `@[borrowed]`

- **класс/тип**, помеченный `@[borrowed]` (по контракту держит view/указатель на чужие данные —
  любая переменная такого типа зависимая). Атрибут **наследуется производными типами**
  (специализации/алиасы, напр. `Iterator<T>`); отдельная пометка методов не требуется;
- **метод**, помеченный `@[borrowed]` (возвращает view во внутренние данные — результат зависим
  от объекта);
- **переменная**, помеченная `@[borrowed]` (явно объявляет переменную зависимой).

Авто-трекинга по форме выражения НЕТ: значение-копии (в т.ч. `obj[i]` — **копия** элемента) не
являются зависимыми. Для умных ссылок (`shared`/`weak`) их представления отслеживает отдельный
анализатор (`-Wborrow-*`); `unique` — монопольное владение, представлений/alias у него нет.

## Что нарушением НЕ является

- Мутация `shared`-источника при живом `weak`-наблюдателе — штатное refcount-поведение
  (наблюдатель истекает безопасно, `-Wborrow-owner-mutated` для `shared` не срабатывает);
- значение-копия (`obj[i]`, копирование объекта) — не представление;
- истечение `weak`/`SharedBorrowedRef` — это runtime-проверка (`valid()`/`access()`), а не
  статическая инвалидация.

## Примеры

Контракт `@[borrowed]` можно повесить на переменную (явная зависимость), на класс/тип (все
переменные типа зависимы) или на метод (его результат зависим от объекта):

```trust
a := [1, 2, 3,];
@[borrowed@] w := a;        # w зависим от a
a = [4, 5, 6,];             # ОШИБКА -Wborrowed: мутация источника при живом представлении
```

Снятие зависимости — переприсваиванием независимым значением:

```trust
a := [1, 2, 3,];
b := [9, 9, 9,];
@[borrowed@] w := a;
w = b;                      # зависимость снята
a = [4, 5, 6,];             # OK
```

Представление от `shared` (`&?` — weak-наблюдатель); move/сброс источника при живом
наблюдателе — `-Wborrow-owner-moved`:

```trust
&* x := 5;
&? w := & x;
x :=: _;                    # ОШИБКА: перемещение источника при живом представлении
```

## Регионы и время жизни

Область жизни представления не должна превышать область жизни источника
(`borrow-region-mismatch`). Регион выводится из места хранения: локальная/временная — `scope`,
`@[thread_local]` — `thread`, статическая/глобальная — `program`. Для refcount-наблюдателя
выход за регион источника не является UB (истечение безопасно) — это проверка контракта;
нативные ссылки ограничены правилами D3–D7.

> **Статус.** Оператор `&` определён только для `shared` (→ weak-наблюдатель); у монопольного
> `unique` заём ЗАПРЕЩЁН (`& u` → ошибка; допустимы только move/swap). Анализ
> flow-sensitive (CFG, ветвления/циклы/ранние выходы); межпроцедурные эффекты не
> моделируются (параметры передаются по значению).

Тесты: `test/lit/.../borrowed/value_copy_not_tracked.src` (значение-копия не отслеживается);
diagnostics инвалидации — `test/lit/.../borrow/*`.
