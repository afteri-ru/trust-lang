TrustLang предоставляет **статическую проверку динамических выражений** — формальный анализ
AoRTE («Absence of Run-Time Errors») по принципу gnatprove в Ada: компилятор проверяет
корректность **пользовательских** утверждений на этапе компиляции, а не доказывает
правильность программы в целом.

Анализ не даёт ложных срабатываний, хотя возможны ложные отрицательные: если ошибок при
компиляции нет — проблем в проверяемых местах нет; указание на возможную ошибку не всегда
соответствует действительности (инструмент может ошибаться).

## Trust-конструкции (пред-/пост-условия и утверждения)

Предусловия, постусловия и утверждения задаются тремя мнемониками DSL-макросов (или их
«сырыми» маркерными эквивалентами):

- предусловие `trust_pre( <логическое выражение> )` ↔ `@{ pre --> <выражение> @}`;
- постусловие `trust_post( <логическое выражение> )` ↔ `@{ post --> <выражение> @}`;
- утверждение `trust_assert( <логическое выражение> )` ↔ `@{ check --> <выражение> @}`;
- инвариант `trust_invariant( <логическое выражение> )` ↔ `@{ invariant --> <выражение> @}`.

Правила размещения:

- пред- и пост-условия указываются после имени функции в её определении;
- утверждение — после имени переменной/типа либо автономным оператором `@{ <kind> --> ... @};` в теле;
- в предусловии доступны имена параметров, но использование имени самой функции — ошибка;
- в постусловии имя функции означает возвращаемое значение и доступно наряду с параметрами;
- тип, на котором задано утверждение, нельзя выводить автоматически (`x := ...`) — нужна
  явная аннотация (`x :T := ...`).

## Как это проверяется

Trust-конструкции компилятор проверяет двумя способами:

- **рантайм-проверки** — условия встраиваются в код как проверки (единый механизм
  `@assert`/trust-условий);
- **SMT-верификация (Z3)** — по условиям генерируется задача (SMT-LIB 2, `.smt2`) и либо
  выгружается для внешнего решателя, либо выполняется автоматически с сообщением
  контрпримера при нарушении.

Поведение задаётся опциями `-Wsolver` и `--solver-mode`; значения и вспомогательные флаги
перечислять здесь не нужно — они доступны в справке `trust --help` / `trust -Whelp`.

### Как читать результат (простые слова)

Решатель отвечает служебными словами `sat`/`unsat`; для человека они означают:

| Ответ | Что это значит |
|---|---|
| `unsat` | **нарушений не найдено** — при всех допустимых входах требования выполняются |
| `sat` | **найдено нарушение** — ниже показаны входные значения (пример нарушения) |
| `unknown` | **проверить не удалось** — решатель не дал ответа |
| проверка не выполнялась | код вне области проверки (см. ниже) или решатель недоступен |

`sat`/`unsat` — протокол SMT-LIB 2 (Z3): они остаются в `.smt2` и указываются в скобках рядом
с обычной формулировкой, чтобы не требовать знания теории.

Каждое сообщение о нарушении привязано к источнику (`file:line`) и указывает **вид
обязательства**: постусловие, утверждение, инвариант цикла (вход/сохранение), предусловие
вызова или утверждение типа.

## Область проверки

Не любой код можно проверить. Нативные вызовы без модели, ссылки владения (`shared`/`weak`/
`unique`), `:Any`, generic-параметры, строки/тензоры и циклы без инварианта **не участвуют**
в доказательстве; также вне области: `match`/`with`/`try`, исключения (`throw`), обмен/сброс
(`a :=: b`, `x :=: _`), `append`, деструктуризация и запись в поле/элемент (`a[i] := x`,
`p.f := x`). Если такой код встречается, компилятор выдаёт диагностику
`-Wverify-envelope` (по умолчанию `warning`) и **не** считает условие проверенным: такая
проверка пропускается и учитывается отдельно. Профиль доказательств —
`--solver-mode=calculate -Wverify-envelope=error` (любая непроверяемая конструкция делает
проверку неуспешной). Полный список — `include/solver/VERIFICATION_ENVELOPE.md`.

## Примеры

### Контракты функций

Предусловие `trust_pre`, постусловие `trust_post`:

```trust
func(x:Int32):Int32
    trust_pre( x > 0 )          # предусловие
    trust_post( func > x )      # постусловие; func - возвращаемое значение
:= { x + 1 };
```

### Циклы и инварианты

Цикл верифицируется индукцией по явному инварианту перед циклом:

```trust
@{ invariant --> i >= 0 @};        # инвариант перед циклом
@while ( i < n ) { ... };
```

Ограниченное разворачивание цикла (пер-циклово) — термином `z3_unroll(N)` внутри контракта
инварианта:

```trust
@{ invariant --> z3_unroll(3) @};  # развернуть цикл на 3 итерации
@while ( cond ) { ... };
```

### Кванторы и вспомогательные значения

`z3_forall(i, P)` / `z3_exists(i, P)` — кванторы по связанной переменной `i` (объявленной
ранее); `z3_old(x)` — начальное значение, `z3_result` — результат:

```trust
trust_post( z3_forall(i, 0 <= i and i < count) => arr[i] > 0 )
```

## Ограничения и статус

Реализованы: контракты функций (пред-/пост-условия, утверждения; целые → BitVec; тело — символьное исполнение по MIR (CFG)),
ветвления (`if`/`else` → `ite`), циклы с инвариантом-индукцией или разворачиванием `z3_unroll(N)`,
межпроцедурные вызовы (аксиома контракта), массивы (`select`/`store`), автономные/переменные и
тип-утверждения, битовые операторы. Непокрытые конструкции в доказательстве не участвуют.
Подробнее — в [Статусе реализации и ограничения](../status/).
