Функция определяется операторами [создания объектов](../operators/create/), имя функции должно
соответствовать [правилам именования](../syntax/naming/) и завершаться круглыми скобками. Телом обычной
функции служит [блок кода](../syntax/concept/#block), находящийся в пространстве имён её определения.

У аргументов и у типа возвращаемого значения указывается тип (`arg:Type`).

## Наборы допустимых типов {#type-sets}

> ⚠ **В текущей версии не реализовано.** Объявление набора (`Name ::= :A + :B`) и параметр-набор
> дают диагностику «type set definitions are not implemented yet». Описанная ниже модель — целевой
> контракт, а не текущее поведение.

Несколько допустимых типов задаются **набором типов** — математическими операторами
`+` (объединение) и `-` (исключение). Набор определяется один раз как именованный тип:

```python
combi ::= :Int8 + :Int16 + :Int32;   # именованный набор
```

Функция, у которой параметр имеет тип-набор, **разворачивается в N определений** (по одному на
член набора) с общим телом; вызов разрешается по типу аргумента, как при явной перегрузке:

```python
sq(x:combi):Int64 := { @return :Int64(x) * :Int64(x); };
# эквивалентно трём определениям: sq(:Int8), sq(:Int16), sq(:Int32)

sq(:Int16(3));    # выберет определение с параметром :Int16
```

Набор можно указать и **inline** — непосредственно в позиции типа (сигл `:` идёт сразу перед `(`):

```python
sq2(x:(:Int8 + :Int16)):Int64 := { @return :Int64(x) * :Int64(x); };
```

Один и тот же именованный набор может стоять и в параметре, и в возврате — тогда определения
сопоставляются **позиционно** (i-й член набора — и для параметра, и для возврата):

```python
combi ::= :Int8 + :Int16;
idk(x:combi):combi := { @return x; };   # 2 определения: (:Int8)->:Int8, (:Int16)->:Int16
```

**Правила и ограничения:**

- В прототипе допустим **не более одного различного набора** (иначе — ошибка о комбинаторной
  сложности); один и тот же набор может использоваться в нескольких позициях.
- Набор **только в возврате** недопустим: перегрузки различались бы лишь типом возврата (в C++
  перегрузки по возврату нет). Используйте тот же набор и в параметре.
- Inline-набор — **только тип**, не выражение (нельзя присвоить/передать как значение).
- Исключение `-` пока **не реализовано** (явная ошибка).
- Членами набора могут быть простые типы (шаблонные типы в наборе пока не поддерживаются).

*TrustLang* на уровне синтаксиса поддерживает несколько видов функций.

## Обычные функции {#func}

Обычная функция ничем не ограничена в смысле C/C++: может содержать условия, циклы, вызовы других
функций и т. д. Создаётся оператором `:=`:

```python
hello(str:StrChar) := {
    @print("call: {}\n", str);
};

@main() := {
    hello("Привет, мир!");
};
```

## Именованные и опциональные параметры {#named-params}

**Именованные параметры** позволяют передавать аргументы по имени (с префиксом «.»), а не по позиции:

```python
func(width:Int32, height:Int32) := { ... };

func(.width=640, .height=480);
func(.height=480, .width=640);  # порядок не важен
```

Имя именованного аргумента не перекрывается макросом препроцессора (см.
[Именование объектов](../syntax/naming/)).

**Опциональные параметры** имеют значение по умолчанию и могут быть опущены при вызове: имя аргумента
отделяется от значения знаком `=`. Сначала перечисляются обязательные параметры, затем — со значениями
по умолчанию. Функция, допускающая произвольное число аргументов, заканчивает список параметров
многоточием `...`.

> **Ограничение текущей реализации:** значение по умолчанию не может ссылаться на другой
> параметр (C++-ограничение для default-аргументов); именованные аргументы для generic-функций
> не поддержаны, именованные аргументы native-функций и конструкторов — явная диагностика.
> Default-выражение генерируется как обычное C++-выражение (без overflow-обёрток)
> (см. [Статус](../status/)).

## Чистые функции {#pure}

Чистая функция не имеет побочных эффектов: возвращает результат только по своим аргументам и не
изменяет состояние программы. Чистота выражается **атрибутами** объявления, а не отдельным
синтаксисом: `@[func_pure@]` → C++ `__attribute__((pure))`, `@[func_const@]` →
`__attribute__((const))`, `@[constexpr@]` — вычисление на этапе компиляции; автоматическая
**проверка** чистоты компилятором не реализована (см. [Статус](../status/)). К понятию чистоты
относится и требование иммутабельности аргументов по ссылке (см.
[Именование объектов](../syntax/naming/)). Оператор `:-` — алиас имени, `::-` — алиас типа
(см. [Иерархию модулей](../syntax/hierarchy/#func-alias)).

## Обобщённые функции (generic functions) {#generic}

Функция может быть параметризована типами: `<T> identity(x: T): T := { @return x; };`.
Типовые аргументы выводятся по фактическим типам аргументов вызова; явные типовые аргументы в
синтаксисе вызова не предусмотрены. C++-код генерируется как `template <typename T>` с явной
подстановкой выведенных аргументов (`c_identity<int32_t>(...)`).

Шаблонный **native-import** объявляет обобщённый алиас на C++-функцию-шаблон:
`<T> run(t: AsyncTask<:T>): T := %trust::sync_wait...;` — C++-функция не эмитится, вызов
переписывается в `trust::sync_wait(...)`, а тип результата выводится унификацией.

### Пакеты типов (`<T...>`) {#packs}

Функция может принимать переменное число типов: `<T...>`. Параметр-пакет объявляется
замыкающим `xs: T...`; C++-код генерируется как `template <typename... T>` и `T... xs`.
Вызов подставляет конкретные типы: `count()` → `c_count()`, `count(1:Int32)` →
`c_count<int32_t>(1)`, `count(1:Int32, 2:Int32)` → `c_count<int32_t, int32_t>(1, 2)`.

C++-`std::tuple` — **не встроенный синоним**: он объявляется пользователем/библиотекой как
native class template:

```trust
@include("tuple")
<T...> StdTuple ::= %std::tuple<T...> { };

<T...> makeStdTuple(xs: T...): StdTuple<T...> := %std::make_tuple...;
```

`StdTuple<...>` — FFI-тип (`std::tuple<...>`), у него нет возможностей встроенного
`Tuple(...)` (имена элементов, литерал, destructuring). Встроенный `Tuple` не является
шаблоном: `Tuple<...>` — ошибка.

Ограничения текущей версии:

- generic-методы, generic-операторы и generic-лямбды не поддерживаются (явная ошибка);
- использование generic-функции как значения (указателя) не поддерживается;
- типовой параметр, встречающийся только в типе возврата, не выводится (ошибка);
- арифметика/доступ к полям по `T` без constraints не поддерживаются;
- поддерживается только один замыкающий пак; non-trailing pack, zip нескольких паков,
  fold/sizeof, pack-значения в теле функции и pack-параметры в class-шаблонах — не
  поддерживаются (явная диагностика);
- `Array<T...>` невалиден: `Array` параметризуется типом и размерностью.

## Сопрограммы (coroutines) {#coro}

Сопрограмма — функция-замыкание, способная приостанавливать и возобновлять выполнение (кооперативная
многозадачность). В текущей версии **не реализовано** — см. [Статус](../status/) и раздел
[Многопоточность и асинхронность](../safety/concurrency/).

## Анонимные функции {#anonymous}

Анонимная функция объявляется в месте использования и не получает собственного имени (уникального
идентификатора). В *TrustLang* анонимная функция задаётся [лямбда-выражением](#lambda) и
представляет собой **значение функционального типа** `std::function<...>`: его можно сохранить в
переменной, передать аргументом (функция обратного вызова, предикат) или вызвать на месте.

## Лямбда-выражения (замыкания) {#lambda}

Лямбда-выражение объявляет анонимную функцию по месту применения:

```python
[ captures ] (params) : Ret { body }
```

- **`captures`** — список захватов: только **имена** ранее объявленных переменных, **по значению**
  (копия). Пустые скобки `[]` — без захвата. Ссылочный захват `[&x]` в текущей версии **не
  поддерживается** (диагностика об ошибке).
- **`params`** — параметры как у обычной функции (`x:Type`, тип опционален).
- **`: Ret`** — тип возврата; при отсутствии выводится из тела.
- **`body`** — блок кода `{ ... }`; значение блока — результат лямбды.

Лямбда-значение типизируется функциональным типом и может храниться/передаваться. Возврат значения —
как у обычной функции (`@return` / именованная форма), лямбда внутренне имеет собственную метку
возврата:

```python
f := [](x:Int32):Int32 { @return x * x; };
y := f(5);
```

### Немедленный вызов {#iiife}

Лямбду можно вызвать сразу после определения. Каноническая форма — **обёрнутая**:

```python
y := ( [](x:Int32):Int32 { @return x * x; } )(5);
```

Прямая форма `[](x){... }(5)` (без обёртки) **не поддерживается** и выдаёт ошибку с подсказкой
использовать `( lambda )(args)`.

### Не поддерживается (первая итерация)

Ссылочный захват `[&x]`, неявный захват `[=]`/`[&]`, захват со значением/типом
(`[x = expr]`, `[x:Type]`) и захват некопируемых значений (эксклюзивное владение `unique`) —
**не поддерживаются** и дают явную диагностику. «Замыкание по определению не может быть чистой
функцией» — проверка чистоты для замыканий не реализована (чистота задаётся атрибутами объявления).

## Переопределение и перегрузка функций {#redefinition}

Поскольку *TrustLang* позволяет вызывать нативные C/C++-функции напрямую и делать
[вставки C++-кода](../syntax/concept/#block), переопределение и перегрузка функций имеют свои особенности.

- **Переопределение (overriding)** — реализация методом подкласса метода, объявленного в суперклассе
  (фундаментальный принцип ООП).
- **Перегрузка (overloading)** — создание нескольких функций с одним именем, но разным набором
  параметров; нужный вариант выбирается на этапе компиляции по параметрам.

### Переопределение (overriding) {#overriding}

Переопределение допускается не только для методов класса, но и для обычных функций (механизм, похожий
на `LD_PRELOAD`, реализованный средствами самого языка). Чтобы функцию можно было переопределить, при её
создании не должен быть указан признак иммутабельности. Если суперкласс объявил метод мутабельным
(виртуальным), а подкласс реализует его с признаком иммутабельности, это равносильно `override final`
(без дальнейшего переопределения):

```python
base::func() := { ... };   # virtual
class1::func() = { ... };  # override
class2::func^() = { ... }; # override final
```

Переопределение идёт **по имени функции** без учёта аргументов, однако новая функция должна иметь
аргументы, [совместимые](generics/) с типом аргументов исходной функции.

### Перегрузка (overloading) {#overload}

Перегрузка — несколько функций с одним именем и **разными сигнатурами** (набором типов параметров);
нужный вариант выбирается **статически** на этапе компиляции по типам аргументов. Точный дубль
сигнатуры — ошибка; если подходящего варианта нет — ошибка `no matching overload`, если несколько
вариантов несравнимы — `ambiguous`. Перегрузка по одному возвращаемому типу невозможна (C++ не
различает такие функции): такое объявление диагностируется как дубль.

Операторы — такие же системные функции (`__eq__`, `__getitem__`, `__call__`, ...): наборы их
сигнатур разрешаются тем же алгоритмом (см. [Перегрузка операторов](class/#operators)).

Перегрузка **свободных функций и методов** пользовательских классов/Struct поддержана:

```python
f(a:Int32):Int32 := { @return a + 1; };
f(a:Int64):Int32 := { @return 100; };

@main() := {
    x : Int32 := 5;
    @print("{}\n", f(x));        # выбран f(a:Int32)
    @print("{}\n", f(7:Int64));  # выбран f(a:Int64)
};

:C ::= :Class{
    base:Int32 := 10;
    f(a:Int32):Int32 := { @return a + 1; };   # перегрузка МЕТОДА
    f(a:Int64):Int32 := { @return base + 90; };
};
```

Выбор варианта — по типам аргументов: точное совпадение предпочтительнее числового расширения
(промоция/конверсия), параметр `:Any` принимает любой тип (низший приоритет); при нескольких
несравнимых лучших — `ambiguous`.

`:Any` — **конкретный тип** (`std::any`). Параметр `:Any` принимает любой тип с низшим приоритетом;
совпадение `Any`↔`Any` — точное. Any-значение **не** приводится неявно к конкретному параметру (такая
передача — ошибка выбора перегрузки). Явная конверсия на call-site — типизированная конструкция
`:T(expr)` / `(expr):T`: для Any-операнда кодогенерация эмитит `trust::any_to<T>` (runtime-проверка
совместимости, несовпадение — исключение, без silent fallback). В generic-функции
голый типовой параметр (`<T> f(x:T)`) может быть выведен как `:Any` (`T := Any`); для структурного
параметра (`Array<T>`) аргумент `:Any` не подходит по форме.

Перегрузку (выбор сигнатуры и допустимость/приведение аргументов) для функций и методов
**TrustLang всегда выполняет компилятор** — и при единственной сигнатуре тоже. Для нативных
**методов** анализатор проверяет и арность, и типы аргументов; для нативной **функции** с
единственной сигнатурой конверсию аргументов выполняет C++ (перегрузки нативных функций
разрешает анализатор — см. ниже).

Перегрузка нативных целей ограничена моделью линковки. Цель без `::` (`%name`) имеет C-сцепление
(`extern "C"`) — у C-символа одно C++-имя, поэтому **перегрузка такого имени запрещена**
(явная диагностика компиляции, а не невалидный C++). Цель с `::` (`%lib::name`) перегружается
естественно: анализатор выбирает сигнатуру (для типа результата и проверки аргументов), а
конкретную C++-перегрузку C++ выбирает по тем же типам — имя символа при этом НЕ манглируется:

```trust
parse(x:Int32):Int32 := %mylib::parse...;    # C++-символ (C++ linkage)
parse(x:StrChar):Int32 := %mylib::parse...;  # перегрузка того же C++-имени
```

### C++-имена и идентичность сигнатур {#signature-identity}

C++-имя функции/метода строится из **идентичности объявления**: `c_<имя>` + детерминированный
суффикс позиционной сигнатуры (встроенные representation-алиасы раскрыты, пользовательский алиас
остаётся номинальным — см. ниже; template-параметры кодируются по позиции в списке объявления).
Суффикс — проекция той же сегментной identity, что используют проверки дублей и выбора перегрузки
(одна реализация: `FunctionIdentity`). Суффикс применяется **всегда** (кроме entry-функции,
операторов и нативных имён), поэтому:

- перегрузки не зависят от того, перегружено ли имя в текущем файле/скоупе;
- forward-объявление и определение одной функции дают одно C++-имя; согласованное переименование
  template-параметра (`<T> f(T)` → `<U> f(U)`) допустимо;
- объявления, различающиеся позициями используемых template-параметров (`<T,U> g(T,U)` и
  `<U,T> g(T,U)`), — разные перегрузки;
- template-параметр, не встречающийся в сигнатуре, диагностируется (его нельзя вывести при вызове).

Позиционная канонизация совпадает с правилом C++ `[temp.over.link]`: имена template-параметров в
identity **не входят**, поэтому согласованное переименование (`<T> f(T)` ↔ `<U> f(U)`) — одно
объявление; но **позиции использования** входят, поэтому `<T,U> g(T,U)` (паттерн `(1,2)`) и
`<U,T> g(T,U)` (паттерн `(2,1)`) — разные шаблонные функции (C++ также считает их разными
перегрузками; суффикс дополнительно даёт им разные C++-имена).

**Пользовательский алиас (`::=`) — отдельный тип Trust.** В C++ он реализуется через `using`, но для
перегрузки и идентичности это **новый номинальный тип**: `f(a:MyInt)` и `f(a:Int32)` — две разные
перегрузки (у них разные C++-имена). Поэтому вызов без явной аннотации/каста может быть
неоднозначным: литерал `1` имеет тип `Int8`, и promotion к `MyInt` и к `Int32` имеет одинаковый ранг
(диагностика `ambiguous`). Присваивание и передача аргумента между алиасом и его базой разрешены
как конверсия представления (для числовых — по underlying). Встроенные алиасы (`Integer`, `String`, `Byte`, …) — representation aliases,
они прозрачны. Для **нативных** C++-имён (`%lib::f`) алиасы неразличимы (внешний C++): два таких
объявления с одинаковой C++-сигнатурой — диагностика `duplicate declaration`.

Нативные C++-имена (`%lib::f`) не манглируются: конкретную перегрузку выбирает C++, поэтому
аргументы вызова приводятся к объявленным типам параметров.
