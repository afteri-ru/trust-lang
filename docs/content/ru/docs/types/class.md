Тип данных `:Class` аналогичен словарю, но все его поля обязаны иметь имена (доступ к свойствам по
индексу также возможен). При создании экземпляра класса создаётся новый тип, копирующий свойства и
методы всех родителей. В отличие от словаря, состав полей класса определяется на этапе компиляции
и может только расширяться относительно родительских типов.

**Статус:** реализованы базовые `:Struct` (строго POD) и `:Class` (наследование), генерируемые в C++
`struct`; полноценное ООП (виртуальные методы/override, конструкторы/деструкторы, статические члены)
в текущей версии не реализовано. Из «объектно-ориентированных» типов также реализованы перечисления
`:Enum`, варианты `:Variant` и кортежи `:Tuple` (см. [Словари и наборы](dicts/)), а также
предварительное объявление нативных C++-классов (`String ::= %std::string { ... };` — см.
[Нативные типы](native/)) и пользовательские **шаблон-классы** (`<T> :Box ::= :Class{...}` — см.
[Обобщённое программирование](generics/#class-template)). Актуальные границы реализации — в
[Статусе реализации](../status/).

Объявление `:Struct`/`:Class` — через `::=` с телом, члены которого задаются оператором `:=`
(`Name ::= :Base{ ... };`):

```python
Point ::= :Struct{ x:Int32 := _; y:Int32 := _; };      # строго POD; поля БЕЗ значения (`:= _`)
Animal ::= :Class{ name:Int32 := 0; speak():Int32 := { ... }; };  # Class: default допустим
Dog ::= :Animal{ age:Int32 := _; };                    # наследование (Class)
Iface ::= :Class ...;                                  # предварительное объявление (форма без тела)
```

Оба типа генерируются как C++ `struct` (члены публичны по умолчанию); `:Struct` дополнительно
получает `static_assert` на POD (`std::is_trivial_v && std::is_standard_layout_v`). C++-доступ
методов и полей задаётся **standalone-маркерами** в теле класса (см.
[Видимость членов](#member-visibility)). Ведущие `_`/`__` в ИМЕНИ члена остаются соглашением об
именовании (влияют на автодополнение) и доступ не ограничивают. Голое имя члена (`obj.field`,
`obj.method()`) транслируется в прямое обращение к члену `struct`.

### Вариант наследования {#inheritance-access}

В списке родительских классов вариант наследования задаётся **standalone-маркером** — обычным
элементом списка, который действует на ВСЕ последующие базы до нового переключения (порядок
перечисления сохраняется):

| Маркер | C++ | Макрос |
|---|---|---|
| `::` | `public` | `public` |
| `_::` | `protected` | `protected` |
| `__::` | `private` | `private` |

Маркеры совпадают с маркерами видимости области имён
(см. [Иерархия](../syntax/hierarchy/#visibility)).

```python
:A ::= :Class{ a:Int32 := _; };
:B ::= :Class{ b:Int32 := _; };
:D ::= __::, :A, ::, :B{ };    # struct D : private A, public B
:E ::= protected, :A{ };       # struct E : protected A
```

Дефолт без маркера — **`public` для всех типов**; `private`/`protected` задаются только явным
маркером. Поэтому реализации встроенных типов пишут публичный базис явно
(`StrChar = %trust::StrChar, ::, %std::string { ... }`). Иное имя-область в позиции маркера
(`foo::`) — ошибка компиляции.

### Видимость членов {#member-visibility}

C++-доступ **методов и полей** задаётся в теле класса таким же **standalone-маркером** — отдельным
членом, который действует на ВСЕ последующие методы/поля до нового переключения:

| Маркер | C++ | Макрос |
|---|---|---|
| `::` | `public` | `public` |
| `_::` | `protected` | `protected` |
| `__::` | `private` | `private` |

Маркеры те же, что у областей имён и варианта наследования. Маркер — обычный член тела, поэтому
завершается `;`. Дефолт — **`public`**. Члены эмитируются в C++ **в порядке объявления** (метод может
стоять до поля): при смене уровня кодоген печатает секцию `public:`/`protected:`/`private:`.

```python
Animal ::= :Class{
    name:Int32 := 1;
    speak():Int32 := { return name; };   # public (дефолт)
    __::;                                # с этого места — private
    secret:Int32 := 2;
    hidden():Int32 := { return secret; };
    _::;                                 # с этого места — protected
    prot():Int32 := { return 3; };
    ::;                                  # снова public
    open():Int32 := { return 4; };
};
```

Иное имя-область в позиции маркера (`foo::;`) — ошибка компиляции.

**Проверка доступа.** Обращение к `private` члену вне его класса и к `protected` члену вне класса и его
наследников — ошибка компиляции (как в C++), а не отложенная ошибка C++. Внутри класса доступен любой
собственный член; `protected` член базового класса доступен наследнику только через объект типа
наследника (`o.prot()` при `o` типа наследника).

Правила значений и объявлений:

- `member := ...` — **прототип метода** (объявление без тела) внутри определения класса. Класс с телом
  (даже если все методы — прототипы) является **полным определением** (`struct c_Name { ... };`) —
  в C++ прототипы существуют только внутри определения, а не в forward-объявлении.
- `member := _` — **отсутствие значения** (поле без значения по умолчанию).
- `field:Type := <value>` — поле со значением по умолчанию.
- `:Name ::= :Base ...;` (форма **без тела**) — **предварительное объявление** → C++ incomplete type
  `struct c_Name;`. Имя типа при этом уже зарегистрировано и видно, поэтому **позднее то же имя можно
  доопределить** (`:Name ::= :Base { ... };`); повторное *определение* — ошибка. В C++ forward-объявление
  не содержит членов (ни полей, ни методов); тип неполный.
- **Self-ссылки разрешены:** имя record-типа видно внутри его собственного тела (аналог C++
  injected-class-name), поэтому `:Node ::= :Class{ next : @[reftype("shared")@] Node := _; }` корректно.
  Ссылки (`shared`/`weak`/`unique`-указатель) на неполный тип допустимы; value-поле самого себя —
  ошибка бесконечного размера (см. ниже).
- `field := ...` недопустимо: в C++ член-данное нельзя предобъявить (оно существует только в определении).
  Общее различие форм объявления/алиаса — в таблице
  [Объявление, определение и алиас](../operators/create/#declaration-vs-alias).

**Рекурсивные/циклические ссылки в полях** запрещены статически (анализатор `RefCycleHook`), чтобы не
допускать утечек и невыразимых типов: `-Wrecursive-shared` — цикл с `shared`-ребром (утечка refcount;
разрывается `weak`-обратной ссылкой), `-Wrecursive-unique` — взаимное `unique`-владение двух типов,
`-Wrecursive-value` — рекурсия по значению (`value`/default `unique` = inline, бесконечный размер). Все —
default `error`, переключаются `-Wrecursive-*=ignore|warning|error`. Самоссылка `unique`-указателем —
легальный owned-список и не диагностируется.

Циклы **загрузки модулей** запрещены (граф импорта — DAG), поэтому взаимно рекурсивные
**номинальные типы в разных модулях** напрямую не выражаются. Runtime-циклы данных (ссылки между
объектами) при этом разрешены; для взаимных типов используйте общий третий модуль с типами,
forward-handle или `:Any` на одной из сторон.

Для **`:Struct`** (строго POD) значение по умолчанию поля **запрещено** анализатором (NSDMI нарушает
тривиальность): поле объявляется как `field:Type := _;`. Для **`:Class`** значение поля не проверяется —
допустимы и `:= <value>` (эмитится как C++ default member initializer), и `:= _` (без инициализатора).

Виртуальные методы (`@[virtual]`) и переопределение (`@[override]`) в текущей версии **не реализованы** —
их использование приводит к явной ошибке компиляции (а не к молчаливому игнорированию).

## Перегрузка операторов {#operators}

Оператор объявляется **обычной функцией с системным именем** (`__eq__`, `__ne__`, `__lt__`, `__gt__`,
`__le__`, `__ge__`, `__call__`, `__getitem__`, `__deref__`, `__inc__`, `__dec__`): в теле класса —
как метод, на верхнем уровне файла — как свободная функция. Тело и сигнатура — как у обычного метода.

```python
Point ::= :Class{
    x: Int32 := _;
    __eq__(o: Point): Bool := { ... };       # member → C++ operator==
    __call__(i: Int32): Int32 := { ... };    # operator()  (только member)
    __getitem__(i: Int32): Int32 := { ... }; # operator[]  (только member)
};

__ne__(a: Point, b: Point): Bool := { ... }; # свободный оператор (все операнды — параметры)
```

Имя `__...__` зарезервировано за компилятором: объявлять можно только зарегистрированные системные
функции операторов; неизвестное `__frob__` — явная ошибка. Символ (`==`, `[]`, `()`, …) остаётся
сахаром в выражениях: `a == b` эквивалентно `__eq__(a, b)`, `a[i]` — `__getitem__(a, i)`,
`a(5)` — `__call__(a, 5)`. Прямые вызовы `__eq__(a,b)` / `a.__eq__(b)` также допустимы.

Кодогенерация: системное имя **никогда** не попадает в C++ (идентификаторы с `__` зарезервированы) —
оно транслируется в `operator<sym>` (`__eq__` → `operator==`, `__getitem__` → `operator[]`,
`__call__` → `operator()`). Выбор перегрузки всегда выполняет анализатор; при наборе из нескольких
сигнатур аргументы явно приводятся к объявленным типам (`static_cast`), поэтому C++ не выбирает
перегрузку повторно.

Перегрузка — обычный **набор сигнатур** одного системного имени: разные типы параметров разрешены
(в т.ч. несколько `__eq__`, `__getitem__`, `__call__` в одном типе). Точный дубль сигнатуры — ошибка;
перегрузка по одному возвращаемому типу невозможна (C++-совместимость). Реализованы сравнения
`== != < > <= >=` (member и свободные), вызов/индекс `()`/`[]` (**только member**; `[]` принимает ровно
один параметр), `*`, prefix/postfix `++`/`--`; постфиксный dummy обязан быть `Int32` (эмитится как C++
`int`). Свободный оператор обязан иметь хотя бы один параметр пользовательского типа.

Использование проверяется на этапе анализа: сравнение/вызов/индексация требуют объявленного оператора
у типа (иначе — ошибка компиляции, а не ошибка C++). Member- и свободная формы одного символа
образуют **один набор перегрузок**: выбор выполняется по обычным правилам конверсий (C++), поэтому
обе формы конкурируют на равных, а неоднозначность возникает только при несравнимых лучших
кандидатах. Операторы поддерживают **контракты** (`trust_pre`/`trust_post`, как функции и методы).
Шаблонные операторы (`<T> __eq__(...)`) не реализованы — явная ошибка.
