## Нативные типы данных
Нативными (машинными) данными могут быть как переменные, так и функции. Нативное имя записывается
с ведущим символом процента "**%**" и допускается **только справа** — как цель объявления:
при импорте trust-имя задаётся **слева** (`sqr(x:Float64):Float64 := %std::sqrt...;`).

В случае переменных, это двоичные данные, которые располагаются в одной неразрывной области машинной памяти 
по определённому адресу и имеют строго определённый формат.

Чтобы использовать уже существующие библиотеки, нужно либо импортировать нативный объект, 
тем самым создав объект TrustLang, но с реализацией на другом языке, например на C/C++,
либо сделать предварительное определение (декларацию) нативного объекта.

## Импорт нативных объектов {#import}

**Импорт** — связывание **trust-имени** функции/переменной с **именем существующей нативной**
функции/переменной. В отличие от [предварительного объявления](#native), импортируемая функция
регистрируется под **своим** trust-именем, а её **имя и аргументы могут отличаться** от имени
и аргументов импортируемой нативной функции.

Синтаксис такой же, как у [создания](/ru/docs/operators/create/) обычных объектов, только правым операндом
указывается имя нативного объекта. Типы аргументов и возвращаемого значения всегда указываются явно.

- Если типы регистрируемой и нативной функции совпадают (преобразование не требуется), нативное имя
  можно указать с **многоточием** — оно означает, что **аргументы вызова повторяют аргументы левой
  сигнатуры** (дублировать их не нужно):

  ```trust
  sqr(x:Float64):Float64 := %std::sqrt...;   # аргументы как у sqr
  ```

- В общем случае аргументы и тип импортируемой функции задаются **явно**; при генерации вставляется
  вызов правой функции, а при необходимости аргументы приводятся через `static_cast`:

  ```trust
  sqr(x:Float64):Float64 := %std::sqrt(x:Float128, true):Float128;
  ```

При импорте аргументы автоматически преобразуются к нативным типам импортируемой функции. Импорт может
выполняться во время компиляции программы или во время выполнения (динамическая загрузка библиотеки).

```python
fopen(filename:StrChar, modes:StrChar):Int64 := %fopen...;
fclose(f:Int64):Int32 := %fclose...;
fflush(f:Int64):Int32 := %fflush...;
fprintf(f:Int64, format:StrChar, ...):Int32 := %fprintf...;
```

Если нативная функция/переменная требует линковки внешней библиотеки, имя библиотеки
указывается атрибутом `@[link("имя")@]` перед декларацией. Атрибут добавляет флаг `-l<имя>`
к шагу линковки (build.conf `LIBS`). Существование символа/библиотеки **не проверяется** —
ответственность линковщика. Поддерживается только статическая линковка.

```trust
@[link("m")@]
fsqrt(x:Float64):Float64 := %sqrt...;

@[link("z")@]
fcrc(crc:UInt32):UInt32 := %crc32...;
```

Если нативная декларация/тип требует подключения C++-заголовка, укажите его атрибутом
`@[include("имя")@]` перед объявлением (или мнемоникой `@include("имя")` без `;`). Голое имя →
угловой инклуд `#include <имя>`; аргумент с ведущим `"`/`<` — директива как есть. Заголовок
эмитится в сгенерированный C++ только вместе с этим объявлением:

```trust
@include("cstdlib")
abort(x:Int32):Void := %abort...;   # заголовок нужен для внешнего символа
```

## Предварительное объявление {#native}

Любое объявление (`:=`) создаёт trust-сущность; нативная реализация задаётся **справа** целью
`%cpp` (`name(...):T := %cpp ...;`) либо атрибутом `@[export("name")]` для экспорта trust-реализации.
Чистое `name(...):T := ...;` — предварительное объявление trust-функции (не нативная привязка):
определение обязано быть в этом же файле.

Правило линковки нативной цели: имя **без** `::` (`%sqrt`, `%open`, `%abs`) — **C-символ**
(`extern "C"`); имя **с** `::` (`%std::sqrt`) — **C++-символ**.

```trust
open(path:StrChar, flags:Int32):Int32 := %open...;
close(fd:Int32):Int32 := %close...;
read(fd:Int32, buf:StrChar, cnt:SizeT):SizeT := %read...;

fd:Int32 := 0;
fd = open("foo.txt", 0);   # вызов trust-имени; реализация — внешний символ
```

## Нативные шаблоны-типы

Любой нативный C++-шаблон-тип можно объявить в коде TrustLang (регистрация при анализе AST);
заголовок C++ подключается on-use при использовании типа. Объявление — префикс типовых параметров
+ нативное C++-имя:

```trust
@include("vector")
<T> vector ::= %std::vector { };    # trust-тип vector<T> ↔ C++ std::vector

v: vector<Int32> := [1, 2, 3,];
# → #include <vector>  +  std::vector<int32_t> c_v = std::vector<int32_t>{1, 2, 3};
```

Типовой аргумент — голое имя `Int32` (мягкое предупреждение о сигиле `:`) или явный тип
`:Int32`/`:MyClass`/`:MyClass<:Int8>`. Если C++-имя совпадает со встроенным контейнером
(`std::vector`/`std::array` от `:Array`), выдаётся мягкая диагностика, а инстанциация резолвится
через встроенный тип. Подробнее — [Generics](/ru/docs/types/generics/).

## Предварительное объявление нативных классов {#native-class}

Нативный C++-класс (не шаблон) можно использовать в коде TrustLang через **предварительное
объявление** по аналогии с forward-объявлением функций: trust-имя класса связывается с нативным
C++-именем, а члены-интерфейс (методы, поля, конструкторы, статические члены) описываются в теле
`{ ... }`. Тело класса **не** содержит реализации — каждый член — это forward-объявление (`:= ...`):
класс определён в C++-заголовке, который подключается on-use через атрибут `@[include]`.

```trust
@include("string")
String ::= %std::string {          # trust-класс String ↔ C++ std::string
    size(): UInt64 := ...;         # метод объекта → s.size()
    empty(): Bool := ...;          # метод объекта → s.empty()
    c_str(): CString := ...;       # метод объекта → s.c_str()
    data: CString := ...;          # поле объекта → s.data
};
```

Синтаксис:

- **`String ::= %std::string { ... };`** — RHS обязан иметь `%` (C++-имя без `%`). Доверенное имя
  класса — слева от `::=`.
- **Члены** (все — forward, `:= ...`); C++-имя члена = проекция владельца, `%` у члена запрещён:
  - `name(...):Ret := ...;` — метод объекта → `obj.name(...)`;
  - `@::st(...):Ret := ...;` — **статический метод** класса (имя с `::`; `@::` → `ns::Class::`) → `Cls::st(...)`;
  - `field:Type := ...;` — поле объекта → `obj.field`;
  - `@::static_field:Type := ...;` — **статическое поле** → `Cls::static_field`.
- **Классификация:** статический член — имя содержит `::` (задаётся `@::name`); экземплярный — без `::`.
  Правильная регистрация экземплярного члена — ведущая точка (`.name`); без неё — диагностика
  `-Wclass-member-dot` (по умолчанию `ignore`; `-Wclass-member-dot=warning|error`).
- **Доступ к статическому члену:** `Cls::name` (namespace-стиль, без предупреждения) или `Cls.name`
  (как к полю) → `cppName::name`; доступ `Cls.name` выдаёт `-Wstatic-member-as-field` (по умолчанию
  `warning`; `-Wstatic-member-as-field=ignore|error`).
- Атрибут `@[include("заголовок")@]` (или мнемоника `@include("заголовок")`) перед объявлением
  подключает C++-заголовок **только при использовании** данного типа (on-use).

C++-`struct` для нативного класса **не генерируется** — используется существующее C++-имя.

```trust
@include("string")
MyStr ::= %std::string {
    size(): UInt64 := ...;
    data: CString := ...;   # поле объекта → s.data
};

s: MyStr := MyStr("hello");              # конструктор → std::string("hello")
n: UInt64 := s.size();                   # метод → (c_s).size()
d: CString := s.data;                    # поле → (c_s).data
# → #include <string>
```

## Предварительное объявление нативных шаблон-классов {#native-class-template}

Нативный C++-шаблон-класс объявляется так же, но с типовыми параметрами слева и **явной
реализацией** через инстанциацию `%std::pair<T1,T2>` справа (основная форма):

```trust
@include("utility")
<T1,T2> Pair ::= %std::pair<T1,T2> {    # trust-шаблон Pair ↔ std::pair
    first(): T1 := ...;                 # Pair<A,B>.first
    second(): T2 := ...;                # Pair<A,B>.second
};

p: Pair<Int32, StrChar> := ...;
# → std::pair<int32_t, std::string> + #include <utility>
```

Поддерживаются обе формы: явная (`Pair ::= %std::pair<T1,T2> { ... };`) и обобщённая
(`<T1,T2> Pair ::= <T1,T2> %std::pair { ... };`).

## Импорт и экспорт: `@[export("…")]` / `@forward`

```trust
abs(x:Int32):Int32 := %abs ...;        # импорт: реализация — внешний C-символ abs
@[export("ns::fib")@] fib(n:Int32):Int32 := { ... };   # экспорт под C++-именем
@forward later():Int32                  # later():Int32 := ...;
```

- `@[export("name")]` — **экспорт**: trust-реализация публикуется в C++ под заданным именем. Без `::`
  — C-сцепление (`extern "C"`), с `::` — C++-сцепление (namespace). Требует определения
  (тело/инициализатор) и запрещён на членах класса; пустое имя (`@[export("")]`), а также атрибут
  на типе/классе/лямбде — ошибка.
- `@forward` — **предварительное объявление trust-функции/переменной** (`name := ...;`); определение
  обязано быть в этом же файле (см. [Интерфейс файла](../syntax/hierarchy/#file-interface)).
- Импорт задаётся только RHS-целью: `name(...):T := %cpp ...;`; чистое `name(...):T := ...;` —
  предварительное объявление trust-функции.

Различие объявления, алиаса и нативной привязки — в таблице
[Объявление, определение и алиас](../operators/create/#declaration-vs-alias).

## Встраивание C++ кода: блоки `{% ... %}`

```trust
{% for (int i = 0; i < 10; ++i) { printf("%d\n", i); } %}
```

Нативный синтаксис вставляется в выходной C++ код напрямую.

## Атрибуты нативных деклараций

- `@[link("имя")]` — добавить `-l<имя>` к линковке.
- `@[include("header")]` — подключить заголовок C++ для нативной декларации/типа. Голое имя
  (`@[include("vector")@]`) → угловой инклуд `#include <vector>`; аргумент с ведущим `"`/`<` →
  директива как есть (`#include "my/header.h"` / `#include <cstdlib>`). Заголовок эмитится в
  сгенерированный C++ только вместе с объявлением (не глобально). Мнемоника `@include("name")`
  (без `;`, перед объявлением) раскрывается в этот атрибут.
- `@[libstd]` — линковать со стандартной библиотекой.
- `@[format("printf", ...)]` — проверка аргументов против printf-строки формата.

Пример подключения заголовка нативной функции:

```trust
@include("cstdlib")
abort(x:Int32):Void := %abort...;   # → #include <cstdlib>; символ — внешний
```

## Линковка

Линковка нативной цели зависит от наличия `::` в её имени: без `::`
(`%sqrt`) — `extern "C"` (C-символ libc/libm); с `::` (`%std::sqrt`) — C++-линковка
без `extern "C"`. Подробнее о генерации C++ — в [Архитектуре](../architecture/).
