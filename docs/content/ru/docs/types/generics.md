Обобщённое программирование (generic programming) позволяет писать алгоритмы и структуры данных,
работающие с разными типами, независимо от их конкретного вида. Разные языки реализуют эту парадигму
по-своему; сравнительный анализ подходов в других языках опубликован в отдельной
[статье блога](/ru/blog/comparison/generics/).

Это и есть типовое метапрограммирование *TrustLang*. [Макросы](../syntax/macros/) —
синтаксическое расширение: они раскрываются до AST и системы типов, не видят типы данных и не
заменяют обобщённое программирование.

В *TrustLang* обобщения в текущей версии реализуются через **типовые параметры** и их подстановку в
объявлениях нативных шаблонов-типов и методов коллекций/диапазонов. Модель «обобщённой
функции-диспетчера» с рантайм-диспетчеризацией по типам и отдельным синтаксисом шаблонов пока
не реализована (см. раздел «Что не реализовано» ниже). Статические generic-функции (`<T> f(...)`)
при этом **реализованы** — см. раздел «Generic-функции».

## Generic-функции {#generic-functions}

Функция с типовыми параметрами (`<T>`, `<T,U>`) выводит их из типов аргументов при вызове.
В C++ эмитится `template <typename T>`, а вызов инстанцируется явными типовыми аргументами:

```trust
<T> id(x: T): T := { @return x; };

a  : Int32 := 5;
r  : Int32 := id(a);      # T := Int32 → c_id<int32_t>(c_a)
v0 : Any := 5;
v  : Any := id(v0);       # T := Any   → c_id<std::any>(c_v0)  (:Any — конкретный тип)
```

Вывод не из чего построить (например, `T` только в возврате) — явная ошибка
(`cannot deduce template parameter ...`); структурное несовпадение — `no matching overload`.
Type-packs (`<T...>`, `xs:T...`) поддерживаются только как замыкающий параметр функции.
Не поддержаны: именованные/default-аргументы у generic-функций, generic-методы/операторы/лямбды,
явные типовые аргументы в вызове (вывод всегда автоматический). Подробнее о перегрузке —
[Функции](funcs/#overload).

## Нативные шаблоны-типы {#native-template}

Нативный C++-шаблон-тип объявляется с префиксом типовых параметров и нативным C++-именем
(мнемоника `@include` добавляет объявлению атрибут `@[include]`):

```trust
@include("vector")
<T> vector ::= %std::vector { };    # объявляет тип vector<T> с C++-именем std::vector

v: vector<Int32> := [1, 2, 3,];
# → #include <vector>
# → std::vector<int32_t> c_v = std::vector<int32_t>{1, 2, 3};
```

Использование `vector<Int32>` (в аннотациях: объявления, параметры, возвраты) интернирует конкретную
инстанциацию, а C++-заголовок подключается **on-use** — только при реальном использовании типа. Если
C++-имя совпадает со встроенным контейнером (`std::vector`/`std::array` для `:Array`), выводится мягкая
диагностика, и тип резолвится через встроенный `:Array`. Типовой аргумент пишется как `Int32`
(с предупреждением о сигиле `:`) или явным типом `:Int32`/`:MyClass`/`:MyClass<:Int8>` (вложенные
шаблоны).

### Тип-алиас на шаблон

Оператор `::=` принимает ТОЛЬКО тип (тип-имя, типизированный шаблон, `Enum`/`Variant` из словаря), а не
произвольное выражение. Поэтому алиас на шаблон пишется как тип-имя:

```trust
copy ::= :vector<Int32>;
x:copy := [1, 2, 3,];
# → using c_copy = std::vector<int32_t>;
```

## Нативные шаблон-классы (forward-объявление) {#native-template-class}

Нативный C++-шаблон-класс с интерфейсом членов объявляется через `::=` с типовыми параметрами слева
и **явной реализацией** `%std::pair<T1,T2>` справа:

```trust
@include("utility")
<T1,T2> Pair ::= %std::pair<T1,T2> {   # trust-шаблон Pair ↔ std::pair
    first(): T1 := ...;                # Pair<A,B>.first
    second(): T2 := ...;               # Pair<A,B>.second
};

p: Pair<Int32, StrChar> := ...;
# → std::pair<int32_t, std::string> + #include <utility>
```

Поддерживаются явная форма (`Pair ::= %std::pair<T1,T2> { ... };`) и обобщённая
(`<T1,T2> Pair ::= <T1,T2> %std::pair { ... };`). Подробнее — [Нативные типы](../types/native/).

## Пользовательские шаблон-классы {#class-template}

Пользовательский класс можно сделать шаблонным: типовые параметры указываются слева от объявления
(`<T>` или `<T,U>`) и используются в полях/методах как обычные типы. Кодогенератор эмитит C++
`template <typename T> struct`, а использование интернирует конкретную инстанциацию (`c_Box<int32_t>`):

```trust
<T> :Box ::= :Class{
    value: T := _;
    get(): T := { return value; };
    set(v: T): Void := { value = v; };
};

b : Box<Int32> := Box();     # → template <typename T> struct c_Box { T c_value; ... };
b.set(42);                   # → c_Box<int32_t> c_b = c_Box<int32_t>();
```

Шаблон-класс можно наследовать: `<T> :Derived ::= :Base<:T>{ ... }` → `struct Derived : public Base<T>`.
Типовые аргументы обязательны (`:Box` без `<...>` — ошибка). Поддерживаются только типовые параметры;
value-параметры и ограничения — нет.

### Struct-шаблоны (POD)

`:Struct` тоже может быть шаблонным (`<T> :Point ::= :Struct{ x: T := _; y: T := _; }`). Определение
эмитится как `template <typename T> struct Point` **без** `static_assert`: проверка POD над шаблоном
невыразима и зависит от `T`. Проверка эмитится для **конкретной инстанциации**:

```cpp
template <typename T> struct Point { T x; T y; };
Point<int32_t> p = Point<int32_t>(1, 2);
static_assert(std::is_trivial_v<Point<int32_t>> && std::is_standard_layout_v<Point<int32_t>>,
              "trust: Struct 'Point' must be POD");
```

### Конструктор шаблон-класса

Конструктор записывается короткой формой `Box(args)` — C++-имя инстанциации берётся из типа-цели
контекста (аннотация переменной/тип LHS присваивания), поэтому работает и пустой список. Либо явной
формой `:Box<Int32>(args)` (аналогично `:vector<Int32>(...)` для нативных шаблонов):

```trust
b : Box<Int32> := Box();          # → c_Box<int32_t> c_b = c_Box<int32_t>();
b  = Box(7);                      # → c_b = c_Box<int32_t>(7);
c : Box<Int32> := :Box<Int32>(5); # → c_Box<int32_t> c_c = c_Box<int32_t>(5);

v := :vector<Int32>(1, 2, 3);     # → std::vector<int32_t> c_v = std::vector<int32_t>{1, 2, 3};
```

## Ограничения оператора `::=`

Не-тип в RHS `::=` (`func(...) ::= { }`, `name ::= "123"`, `term ::= term2(arg)`) — ошибка: `::=`
создаёт тип, у него нет арифметики/выражений. Форма «класс-с-телом» (`func(arg) ::= Class(){...}`)
в текущей версии не реализована (планируется).

## Наборы допустимых типов {#type-sets}

> ⚠ **В текущей версии не реализовано** (диагностика «type set definitions are not implemented
> yet»). Целевая модель — sugar над явной перегрузкой: `Name ::= :A + :B;` (именованный) или
> `:(:A + :B)` (inline); функция с параметром-набором разворачивается в N определений с общим
> телом. Подробности и ограничения — в [Функциях](funcs/#type-sets).

## Что не реализовано

Типовые value-параметры (`array<Int32, 4>`) и ограничения типовых параметров (`T:Integer`), а также
модель обобщённой «функции-диспетчера» находятся в разработке. Концепция описана в
[статье блога](/ru/blog/comparison/generics/), актуальные границы реализации — в
[Статусе реализации](../status/).
