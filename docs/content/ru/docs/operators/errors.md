Последовательность команд ([блок кода](../syntax/#block)) можно прервать в любом месте
**передачей управления** — единым семейством операторов. Все передачи имеют одну форму
`<маркер> [значение] <маркер>` (значение обрамляется тем же/парным маркером) и различаются
видом, который задаётся записью символа:

| Вид | Запись | Аналог | C++ |
|---|---|---|---|
| возврат | `\|+\|` / `\|+ значение +\|` | `return` | `return` / `co_return` |
| ошибка | `\|-\|` / `\|- значение -\|` | `throw` | `throw` |
| выход из цикла | `\|>\|\|` | `break` (вперёд, за цикл) | `break` |
| к началу цикла | `\|<\|\|` | `continue` (назад, к началу) | `continue` |

- **Синхронные** передачи — рамка `\| \|`: `+`/`-` несут полярность (положительное/отрицательное),
  `<`/`>` — направление для управляющих передач цикла; yield `\|^\| v \|^\|` — тоже в рамке `\| \|`.
- **Корутинные** операции — yield `\|^\| v \|^\|` и await `|*| a |*|` (операция над awaitable/корутиной).
  Корутинность функции определяется её **атрибутом** `@[coroutine]`, поэтому `return` в корутинной
  функции транслируется в `co_return` (отдельного маркера для `co_return` нет).

Прерывание может возвращать значение: `\|+ 'Строка' +|` — вернуть строку, `\|- err -|` — «бросить»
ошибку (аналог `throw err`). Если значение не указано, передача не возвращает ничего
(пустое значение).

## Именованные прерывания: локальный переход и возврат {#named}

Именованные [блоки кода](../syntax/#block) могут выступать локальными метками передачи
потока управления. Если перед оператором передачи указать пространство имён/метку блока, то такое
**именованное** прерывание действует только для указанного блока:

- `block |>|` — **break** по метке `block` (выход из блока);
- `block |<|` — **continue** по метке (переход на первую инструкцию блока).

Один и тот же фрагмент — именованный цикл с выходом по метке и переходом к началу блока — двумя
формами:

<table>
<tr><th>Макросы DSL</th><th>Базовый синтаксис</th></tr>
<tr><td><pre><code>outer {
    @loop {
        @break outer;     # break по метке outer (как outer |>|)
        @continue outer;  # continue по метке outer (как outer |<|)
    };
};</code></pre></td><td><pre><code>outer {
    [1] &lt;-&gt; {
        outer |&gt;|;   # break по метке outer
        outer |&lt;|;   # continue по метке outer
    };
};
</code></pre></td></tr>
</table>

Тело функции — это блок кода, чьё имя совпадает с полным именем функции. Поэтому передача
«возврат» по метке функции возвращает результат из неё (`func_name |+ значение +|`); в DSL этому
соответствует `@return`.


## Перехват прерываний (try/catch) {#catch}

Неименованные прерывания можно «ловить». Для перехвата используются блоки кода со специальной
семантикой, которые оборачивают тело в `try/catch` по классу прерывания:

- `{+ ... +}` — перехватывает положительные прерывания (`IntPlus`);
- `{- ... -}` — перехватывает отрицательные прерывания (`IntMinus`);
- `{* ... *}` — перехватывает оба типа (`IntAny`).

Символы внутри блоков перехвата (`+`/`-`/`*`) — самостоятельные (полярность и wildcard «любой»),
они НЕ связаны с записью оператора передачи.

Статус реализации (важные уточнения):

- **неименованное** `|+ value +|` *всегда* бросает `IntPlus` (положительное/сквозное), а
  `|- err -|` — `IntMinus` (ошибка), независимо от наличия и глубины обработчиков;
- **именованное** `func |+ value +|` — обычный `return` из функции (метка обязана быть текущей
  функцией или глобальной `::`);
- неперехваченный класс пробрасывается насквозь; сквозной `|+|` проходит через вызовы функций до
  ближайшего `{+}`/`{*}`;
- перехват значения (например, через `match`) пока не реализован — перехваченное прерывание
  поглощается.

## Обработка ошибок

«Отрицательное» прерывание используется для возврата ошибки лишь условно — оба вида прерываний
равнозначны. Совместная обработка перехваченного значения в классическом стиле try/catch —
через блоки перехвата (`{*}`, `{-}`, `{+}`) и оператор [оценки выражения](flow/) — **пока не
реализована**: перехваченное прерывание поглощается (см. [Статус](../status/)).
