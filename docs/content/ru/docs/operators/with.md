Одиночный оператор захвата ссылки и синхронизации доступа к объекту (`*ref`, `*ref(...)`)
выполняется для одного действия. Захват ссылки/объекта синхронизации — относительно медленная
операция, поэтому выполнять её для каждого действия нерационально. **Менеджер контекста**
(`with`) однократно захватывает сразу несколько ссылок/объектов и выполняет группу действий под
общим локом, а также служит для **автоматического освобождения ресурсов (RAII)** при выходе из блока.

Синтаксис на базовом синтаксисе — оператор `**( ... )`, в DSL ему соответствует макрос `@with`
(см. [Keyword syntax (DSL)](../syntax/dsl/)).

Сравнение форм записи на примере захвата-блокировки ссылки:

<table>
<tr><th>Макросы DSL</th><th>Базовый синтаксис</th></tr>
<tr><td><pre><code>@with(lock = *ref) {
    ...   # критическая секция
};</code></pre></td><td><pre><code>**( lock = *ref ) {
    ...   # критическая секция
};
</code></pre></td></tr>
</table>


## Захват и блокировка ссылок {#lock}

Ссылочные переменные объявляются атрибутами `@[reftype("shared")@]`/`@[reftype("weak")@]` и
транслируются в `trust::Shared`/`trust::Weak`; оператор take `*ref`/`*^ref` захватывает ссылку
(`lock`/`lock_const`) и возвращает охраняемый доступ `trust::Locker<T>`. Подробнее о ссылочных типах —
в [Управлении памятью](../syntax/memory/).

`with` хранит список пар `(замок, привязка)` и связывает захваченные ссылки с именами внутри тела:

```python
@with(lock = *ref) {     # захват-блокировка ссылки ref
    ...                  # критическая секция
} @else { ... };         # ошибка захвата (ref == nullptr) → else
```

- `with(lock = *ref)` — создаёт временный замок `auto __cap = ref.lock();`, привязка `lock`
  автоматически разыменовывается в значение; вызов `lock()` бросает `IntMinus` при сбое → ветка `else`.
- `with(_ = *ref)` — захват ссылки на всё тело без привязки значения.
- `with(*ref)` — временный лок: снимается сразу, тело выполняется без лока.
- Привязка ссылочной переменной без `*`/`*^` (`with(v = ref)`) — предупреждение компилятора.

## Автоматическое освобождение ресурсов (RAII) {#raii}

Кроме захвата ссылок, менеджер контекста позволяет выделять и освобождать ресурсы: при выходе из
блока вызывается [деструктор объекта](../types/class/) (для объектов по значению). Освобождение
происходит до попадания в ветку `else`, если она есть:

```python
@with(name = expr, ...) {  # RAII-захват значений
    ...
} @else { ... };           # при исключении в инициализаторе expr
```

Это гарантирует закрытие файлов, освобождение захваченных ресурсов и т.п. независимо от того, как
завершился вложенный код (штатно, по прерыванию или по ошибке).

## Статус реализации

Формы `&`/`&?`/`&&`, параметр `__timeout__`, межпотоковая синхронизация и типы `:Class`/`:Thread`
в текущей версии **не реализованы** (см. [Статус](../status/)). Работают: ссылочные переменные
`@[reftype(...)]`, захват ссылок `with(...)` с веткой `else` и RAII-захват значений `with(name=expr)`.
