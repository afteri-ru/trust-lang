### Последовательность этапов обработки исходного текста программы

1. Входной поток исходного текста разбивается лексером на отдельные универсальные элементы
   (токены), каждый из которых несёт информацию о своём местоположении в исходном тексте.
2. Макропроцессор сравнивает последовательности токенов и при совпадении с заданной шаблонной
   последовательностью заменяет определение макроса на его тело.
3. Последовательность токенов анализируется парсером, который строит AST. Отдельное конкретное
   синтаксическое дерево (Concrete Syntax Tree, CST, или дерево разбора) не строится, а для целей
   форматирования текста программы используется информация о положении между соседними элементами AST.
4. Универсальные элементы (токены) конвертируются в конкретные узлы AST, с которыми работают все
   остальные компоненты приложения (анализаторы, вывод типов и т.д.). Информация о местоположении узла
   в исходном тексте также сохраняется.
5. Обработанный AST попадает в генератор кода, который транслирует его в буфер исходного кода C++.
   Одновременно создаётся специальная карта отображения исходного текста программы на сгенерированный
   C++-код (SourceMapper), с помощью которой можно отслеживать трансляцию каждого фрагмента в итоговый
   C++-исходник.
6. Буфер исходного кода сохраняется в сборочный каталог. Рядом с транслированным `.cppt` помещаются
   настроенные файлы сборки `Makefile` и `build.conf`, с помощью которых можно собрать исполняемый файл
   внешним C++-компилятором без ручной настройки. Туда же записывается сжатая информация SourceMapper,
   которая может быть включена в бинарный файл для последующей отладки или подключена LSP-сервером для
   навигации по коду.
7. Если в сгенерированном C++ используются рантайм-заголовки TrustLang, они тоже сохраняются в каталоге
   сборки, чтобы C++-компилятор мог использовать их при сборке проекта.
8. Формальная верификация (AoRTE) реализована как отдельный транспилятор контрактов в формат SMT-LIB 2
   для внешнего SMT-решателя.
9. Возможно создание бэкенда и в любой другой язык программирования или сразу в LLVM. В этом случае
   пропадёт возможность вставок C++-кода (но можно будет вставлять фрагменты кода другого языка),
   однако появится большая универсальность за счёт использования разных бэкендов.
