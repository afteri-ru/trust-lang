## Что такое песочница

**Песочница (playground)** - интерактивная веб-страница, где можно писать код на
TrustLang прямо в браузере, сразу видеть сгенерированный C++ и результат
транспиляции. Это «живой» пример языка: встроен редактор с подсветкой (Monaco),
комбобокс примеров, кросс-навигация между кодом и C++ и кнопка скачивания
build-архива.

Страница сама по себе ничего не вычисляет - она отправляет код на **балансировщик**
(playground), который распределяет задачу на свободный **исполнительный узел
(worker)**, а тот выполняет транспиляцию Trust → C++ и возвращает результат.

## Архитектура

Песочница работает по трёхуровневой схеме:

```
браузер (статическая страница)
        │  POST /run, GET /health, POST /download
        ▼
балансировщик (playground)      ←  https://playground.trust-lang.net (публичный)
        │  реестр воркеров, очередь, rate-limit, статистика
        ▼
исполнительные VPS (worker)     ←  подключаются сами (исходящее соединение),
        │                             reverse long-poll за задачами
        ▼
   trust-lsp --json             (транспиляция Trust → C++)
```

Ключевые особенности:

- **Балансировщик** не выполняет вычислений - только принимает запросы, ведёт реестр
  воркеров и диспетчеризует задачи. Слушает локально (`127.0.0.1`), наружу его
  отдаёт nginx по HTTPS.
- **Воркеры** сами подключаются к балансировщику (исходящее соединение - двойной NAT
  не мешает), регистрируются по токену и выполняют транспиляцию в изолированном
  субпроцессе с лимитами памяти, времени и размера вывода.
- Если свободных воркеров нет, балансировщик отвечает «нет воркеров» со ссылкой на
  эту инструкцию.

## Статус-строка песочницы

Внизу страницы отображается постоянный индикатор связи с балансировщиком:

- 🟢 **балансировщик онлайн · воркеров: N** - связь есть, воркеры активны;
- 🟠 **балансировщик онлайн · нет воркеров** - связь есть, но свободных воркеров нет;
- 🔴 **нет связи с балансировщиком** - балансировщик недоступен (сетевой сбой или  балансировщик остановлен).

## Как запустить свой воркер

Вы можете помочь проекту и запустить свой узел-исполнитель за несколько минут. Для этого нужно:

- Linux-сервер (VPS) с `systemd` и возможностью исходящего TCP-соединения к балансировщику (обычный интернет).
- Дистрибутив `trust-lang-*.tar.gz` (содержит `trust-playground` и `trust-lsp`).
- Токен воркера (64 hex-символа) и URL балансировщика - выдаются администратором.

### Шаги

1. **Получите токен доступа** у администратора проекта (<admin@trust-lang.net>). Воркер  аутентифицируется этим токеном.

2. **Скопируйте или соберите дистрибутив**:
   ```sh
   cmake -B _build && cmake --build _build --target trust-playground trust-lsp
   cmake --build _build --target package
   ```

3. **Запустите воркер напрямую** (без root и без скрипта установки). Он читает
   настройки из `trust-playground.conf` рядом с бинарником или через опции в командной строке:
   ```sh
   ./trust-playground --token <ТОКЕН> --lsp /path/to/trust-lsp
   ```
   По умолчанию воркер подключается к `https://playground.trust-lang.net`
   (`worker.playground_url`), а в консоли появится сообщение
   `settings saved to ./trust-playground.conf as defaults` и запустится воркер со статистикой работы в реальном времени. В следующий раз для запуска будет достаточно просто:
   ```sh
   ./trust-playground
   ```
   Или для работы **в фоне**:
   ```sh
   nohup ./trust-playground >> trust-playground-worker.log 2>&1 &
   ```
   Остановка в фоне: `pkill -x trust-playground`.


### Безопасность

- Воркер подключается к балансировщику по HTTPS (`worker.playground_url`); для этого
  на хосте должен быть установлен `curl` (используется системный TLS-стек).
- Токен аутентифицирует воркера и без токена балансировщик отклоняет запросы.
- Транспиляция выполняется в изолированном субпроцессе с ограничениями памяти,
  времени и размера вывода.
- При запуске воркер проверяет свои настройки (`validateWorkerSettings`): исполняемый
  файл `trust-lsp` (`worker.lsp_bin`) должен существовать и быть исполняемым, рабочий
  каталог `worker.project_dir` (если задан) - существовать и быть каталогом, опции
  `worker.lsp_opts` - корректными. Если проверка не прошла, воркер не подключается к
  балансировщику и сообщает причину.
- Токен воркера маскируется (`<redacted>`) в любом результате, возвращаемом публичной
  песочнице, даже если он ошибочно попал в вывод `trust-lsp`, - чтобы конфиденциальный
  токен не отображался посетителям сайта.

### Защита балансировщика и страницы песочницы

Балансировщик принимает публичные запросы `/run` и `/download` только с конкретной
песочницы и ограничивает автоматический флуд:

- **Доменная привязка** (`playground.allowed_origins`, `playground.allowed_hosts`): публичные
  эндпоинты принимаются только с разрешённого Origin/Host; CORS-ответ отдаётся конкретным
  origin, а не `*`. Посторонние сайты/хотлинк получают `403`. По умолчанию (пустой
  `allowed_origins`) CORS fail-closed: разрешены только loopback-origin (локальная
  разработка).
- **Rate-limit по реальному IP** (`playground.rate_limit_per_ip`): за nginx используется
  первый hop `X-Forwarded-For` (доверяется только с loopback), поэтому лимит считается на
  посетителя, а не на весь балансировщик.
- **Proof-of-work (PoW, `playground.pow_min_difficulty`, по умолчанию выключен):** серверная
  часть реализована — при включении балансировщик выдаёт челлендж (`GET /challenge`) и требует
  заголовок `X-PoW: nonce:solution` с решением `sha256(nonce+solution)` требуемой сложности;
  сложность адаптивная (растёт под нагрузкой). Клиентский (браузерный) солвер на странице
  пока НЕ реализован — это отдельная задача (`docs/pow-full-implementation.md`), поэтому
  слой остаётся выключенным до её завершения. Защита от автоматического распределённого флуда.
- **Кеш примеров:** `/run` для неизменённого примера кешируется по имени файла примера
  (`X-Example-Name`); при изменении текста имя очищается и запрос идёт на воркер. Это
  снижает нагрузку на воркеры для дефолтных примеров.
- **Админ-статистика `/stats`** доступна только по токену: по заголовку `X-Stats-Token`
  (скрипты) или через форму входа `/stats/login` с cookie-сессией (браузер). Токен больше
  не передаётся в URL (`?token=` удалён). На странице статистики есть кнопка «Выйти»
  (`/stats/logout`).

Дополнительно: заголовок `Content-Disposition` санитизируется (нет header-injection),
страница `/stats` экранирует HTML (нет stored-XSS), временные файлы воркера чистятся при
старте и периодически (защита от переполнения диска), у субпроцесса `trust-lsp` стоят
лимиты `RLIMIT_NOFILE` и `RLIMIT_CORE=0`.
