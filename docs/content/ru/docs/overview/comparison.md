TrustLang занимает нишу между системными языками с ручным управлением памятью
(такими как C/C++) и языками с автоматическим управлением памятью и сборщиком
мусора. Ниже - ключевые отличия по основным осям сравнения.

## Транспиляция в C++ вместо собственного бэкенда

| Язык | Модель компиляции |
|---|---|
| **TrustLang** | транспилятор (source-to-source) в C++, сборка внешним C++ компилятором |
| Rust, Go | собственные компиляторы в машинный код / LLVM |
| TypeScript, Haxe | транспиляция (в JS / в целевые языки) |

В отличие от Rust/Go, TrustLang сохраняет прямую, низкоуровневую совместимость с
C++: вставки C++-кода, прямые вызовы C/C++ функций и обратные вызовы TrustLang из
C++ без дополнительных обвязок (FFI).

## Безопасность памяти без сборщика мусора

Как Rust, TrustLang обеспечивает безопасность памяти без сборщика мусора. Но в
отличие от Rust:

- **модель владения через сильные/слабые ссылки** (RAII, `shared_ptr`/`weak_ptr`),
  а не borrow-checker с временами жизни; циклические сильные ссылки запрещены на
  уровне определения типов и контролируются статическим анализатором;
- **автоматическая межпотоковая синхронизация** доступа к разделяемым данным
  решается на уровне переменных, а не вручную в коде.

## Динамическая типизация поверх статической

В отличие от строго статически типизированных Rust/Go и полностью динамических
Python/JavaScript, TrustLang поддерживает **и** статическую, **и** динамическую
типизацию. Это приближает его к таким языкам как Julia и Nim, но с сохранением
возможности явного указания типов и проверки на этапе компиляции.

## Синтаксис без ключевых слов + DSL

TrustLang основан на грамматических правилах, а не на ключевых словах. Это даёт:

- простой и быстрый лексер/парсер;
- возможность создавать собственные диалекты синтаксиса через [DSL-макросы](../syntax/dsl/),
  включая привычный синтаксис с ключевыми словами (`@if`, `@while` и т.п.).

Такой подход отличает TrustLang от большинства мейнстрим-языков, где синтаксис
жёстко зафиксирован.

## Встроенные числовые типы «из коробки»

- **Тензоры** на базе libtorch и **рациональные числа неограниченной точности** на
  базе GMP доступны как базовые типы данных и поддерживаются синтаксисом
  (удобная запись литералов), без подключения дополнительных библиотек.
- Многомерные тензоры зарезервированы для LibTorch-бэкенда.

## Формальная верификация (AoRTE)

TrustLang реализует статическую проверку динамических выражений AoRTE
(«Absence of Run-Time Errors») через trust-контракты (пред-/пост-условия и
утверждения) и SMT-решатель (Z3), по аналогии с gnatprove в Ada. Формальный анализ
не пытается доказать корректность программы целиком - он проверяет пользовательские
утверждения. Подробнее - в [Доказательстве корректности](../syntax/proof/) и
[Диагностике](../diagnostics/).

## Сравнительная таблица

| Характеристика | TrustLang | C++ | Rust | Python |
|---|---|---|---|---|
| Управление памятью | авто (без GC), анализ на этапе компиляции | ручное | авто (без GC, borrow) | сборщик мусора |
| Безопасность памяти | высокая | низкая | высокая | высокая (но медленно) |
| Типизация | статическая + динамическая | статическая | статическая | динамическая |
| Встроенные рациональные числа | да | нет | нет (крейты) | да (`fractions`) |
| Тензоры | да (libtorch) | нет | нет | да (NumPy) |
| Совместимость с C++ | прямая | нативная | через FFI | через ctypes/библиотеки |
| Синтаксис | грамматические правила + DSL | ключевые слова | ключевые слова | ключевые слова |
| Верификация (SMT) | AoRTE / Z3 | нет | нет | нет |
| Сборка | транспиляция в C++ | компиляция | компиляция | интерпретация |
