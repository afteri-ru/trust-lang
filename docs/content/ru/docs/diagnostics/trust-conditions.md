Trust-условия (пред-/пост-условия и утверждения) декларируются мнемониками DSL-макросов
`trust_pre(...)` / `trust_post(...)` / `trust_assert(...)` (или их «сырыми» маркерными
эквивалентами). Полное описание синтаксиса и семантики trust-конструкций - в разделе
[Доказательство корректности](../syntax/proof/).

## Опции `-Wsolver` и `--solver-mode`

Поведение компилятора при обработке trust-конструкций задаётся **двумя ортогональными** опциями
(конвенция GCC/Clang: severity-диагностика и поведенческий флаг не смешиваются):

- `-Wsolver=ignore|warning|error` — severity-диагностика «присутствуют trust-условия»
  (предупреждение/ошибка о самом факте наличия таких условий; по умолчанию `warning`).
  Глушится через `-Wsolver=ignore`. **Не** выдаётся, когда активен `--solver-mode`
  (явная верификация не требует подсказки);
- `--solver-mode=assert|export|calculate` — поведенческий флаг (не диагностика):
  - `assert` — вставляются рантайм-проверки на заданные условия (предусловие - в начале
    тела функции, постусловие - перед выходом, утверждение - в месте определения,
    утверждение переменной - после объявления). И `@assert`/`@verify`, и trust-условия
    сводятся к единому интринсику `trust::intrinsic_assert`, который раскрывается в
    `if (!(cond)) trust::trust__abort__(...)` - единый источник истины для рантайм-проверок;
  - `export` — генерация SMT-LIB 2 файла для z3-решателя (`.smt2` + `.smt2.map` source map);
  - `calculate` — генерация файла и автоматическое выполнение через Z3 (при
    `WITH_SOLVER=ON`); при нарушении (SAT) сообщается контрпример (значения параметров из модели).
    Без Z3 генерация работает, `calculate` сообщает «недоступно».

## Верификация циклов

Циклы верифицируются явным инвариантом (`@{ invariant: I @};` перед циклом →
индукция). Цикл без инварианта выдаёт диагностику `-Wsolver-loop`
(`ignore|warning|error`, по умолчанию `warning`: цикл не верифицируется). Ограниченное
разворачивание включается глобально поведенческим флагом `-fsolver-loop-unroll` /
`-fno-solver-loop-unroll` (как `-funroll-loops`) или пер-циклово термином
`z3_unroll(N)` внутри контракта инварианта.

Кванторные связанные переменные (`z3_forall(i, ...)` / `z3_exists(i, ...)`) должны быть
объявлены **ранее**; квантор пробегает по типу этой переменной. Необъявленная или
автовыведенная связанная переменная - ошибка. `@__OPTION__("<flag>", "on"|"off"|<value>)`
устанавливает флаги из исходного кода (значения валидируются).

## Ограничения реализации

Формальный анализ AoRTE («Absence of Run-Time Errors») не даёт ложных срабатываний,
хотя возможны ложные отрицательные результаты. Реализована генерация SMT-LIB 2 и
авто-выполнение для **контрактов функций** (пред-/пост-условия и утверждения; целые
→ BitVec; тело кодируется как SSA). Пока не реализованы ветвления/циклы в теле,
автономные/тип/переменные утверждения, вызовы в условиях, массивы (фаза 2).
