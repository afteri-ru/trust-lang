## Реализовано в текущей версии (0.6.0)

- [x] Разработана [концепция синтаксиса](/ru/docs/syntax/concept/)
- [x] Определён [синтаксис макросов](/ru/docs/syntax/macros/)
- [x] Парсер и литералы для [базовых типов данных](/ru/docs/types/)
- [x] Сформулирована концепция [гарантий языка](/ru/docs/safety/)
- [x] Разработана [песочница](/ru/docs/sandbox/) для тестирования примеров
- [x] Generic-функции и шаблонные native-import (`<T>`, вывод типов); type-packs (`<T...>`, `xs: T...`) для функций и пользовательских native class templates
- [x] Второе имя существующего типа (`:A ::- T;`): семантический синоним (один `TypeId`), в отличие от `::=` (новый номинальный тип)

## Модули, группы и пакеты

- [x] Файлы, группы и пакеты: импорт файла (`\path(...)`) и группы (`\\group()`, `\\group\dir()`),
  импорт first-level групп пакета (`\\\pkg()`), маски импорта (glob-фильтр видимости)
- [x] Заголовок файла (`\path;`), проверка совпадения с логическим путём, поиск корней проекта и пакетов
- [x] Квалифицированные ссылки `\path::name` (вызов/значение/тип): модуль обязан быть уже
  загружен импортом (ссылка не загружает), видимость — по маскам сайта и экспорт-набору файла;
  модуль входит в идентичность имени (`\a::f` и `\b::f` сосуществуют, голое имя при двух
  импортах — `ambiguous name`)
- [x] Пакеты `.trust`: манифест `trust.toml`, раскладка `[[layout.layers]]`, артефакты `[[artifact]]`,
  линковка по требованию `[[link.headers]]`, целостность `[files]` (MD5)
- [ ] Декларация зависимостей пакетов (`dependencies`), разрешение версий и подпись пакетов — не реализованы
- [ ] Предкомпилированные (бинарные) файлы — не реализованы: интерфейс файла — только исходный текст
- [x] Заголовок модуля (`.hpp`): экспорт-набор файла в автоматическом `namespace <enc>`,
  самодостаточный TU; генерируется и для declaration-only файлов (`.cppt` у них нет); правило в
  `--emit-module-deps`; клиентский TU включает заголовок (`#include "<enc>.hpp"`)
- [x] Тела exported **generic**-функций и `@[constexpr]` free-функций публикуются в заголовке:
  клиент инстанцирует/использует их из другого модуля, `.cppt` их не повторяет; ссылка на `__::`
  в таком теле — Trust-диагностика

- [x] Экспорт-набор определяет видимый тип: forward в интерфейсе → клиент видит неполный тип;
  полное определение в интерфейсе → клиент использует тип по значению
- [x] Определение типа из тела за forward'ом интерфейса — реализация владельца: клиенту не
  публикуется, эмитится в TU владельца (файл получает собственный `.cppt`)
- [x] Видимость областей: `__::` — private (только файл), `_::` — protected (файлы той же группы/пакета); public — экспорт файла.
- [x] Интерфейс файла (`\path { ... };`): объявления вне блока **файл-приватны** (module-qualified
  ключ регистрации, C++ anonymous namespace)
- [x] Реэкспорт набора (`\lib(a, b);` внутри блока интерфейса): имена входят в экспорт-набор
  фасада без изменения исходных объявлений; заголовок фасада — umbrella (`#include` заголовков
  владельцев), клиент видит имена по короткому и по квалифицированному имени фасада; реэкспорт
  транзитивен (цепочка фасадов)
- [x] Модульная изоляция C++-имён: все сущности импортируемого юнита живут в автоматическом
  `namespace <кодированное имя>` (entry и `{% %}` — вне); headerless root-программа не изолируется
  (одноимённые экспорты разных модулей линкуются вместе)
- [x] Алиасы имён (`f :- \path::name;`, курирование фасада): функции и значения/константы; имя-алиас
  входит в экспорт-набор файла, связывается с набором перегрузок/местом хранения цели, C++-сущность
  не эмитится (вызов/чтение — C++-имя и суффикс цели); заголовок файла включает заголовок владельца
- [x] Алиасы типов (`:A ::- T;` / `:A ::- \lib::T;`): второе имя того же `TypeId`; C++-имя типа —
  имя цели
- [x] Namespace-алиасы (`ns:: :- \lib::ns::;`): префикс привязывается к области и разворачивается
  через экспорт-набор владельца; в exported namespace-блоке поднимается в корень с квалифицированным
  префиксом; в блоке интерфейса экспортируется, включая вложенный (`\facade::outer::ns::f`)
- [x] Алиасы модулей (`\m :- \pkg\deep\mod;`): spelling уже загруженного модуля; действует только в
  модуле объявления (не экспортируется), одинаковый spelling в разных модулях допустим; `\m::name`
  нормализуется на цель, новой идентичности нет
- [ ] Namespace-алиас собственного namespace (`a:: :- b::`) не поддерживается: цель обязана быть
  квалифицирована модулем (для поиска коротких имён — `... = ns`)
- [ ] Цепочки алиасов и экспорт модуль-алиаса не поддерживаются: namespace-алиас на другой алиас —
  ошибка, модуль-алиас действует только в модуле объявления (см. [Границы алиасов и импорта](syntax/hierarchy/#alias-limits))
- [ ] Отрицающие маски импорта (`!name`) не поддерживаются: маска только выбирает видимые имена
- [x] Расширенный поиск имён (`... = ns, ns::sub;` / `... = \lib::ns;`): привязан к области
  видимости, наборы перегрузок сливаются, отдельной отмены нет (`... = _;` — ошибка)
- [ ] Полноценное ООП (классы/методы) — не реализовано; см. [Классы](types/class/)
