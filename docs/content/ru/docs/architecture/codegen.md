Генерация C++ кода выполняется компонентом **`transpiler`** (класс `CppTranspiler`)
после успешного семантического анализа. Он преобразует проверенный AST в исходный
код C++ (файлы `.cppt`) с сохранением и установкой атрибутов.

## Манглинг имён

Все trust-идентификаторы, попадающие в C++-вывод, конвертируются в корректные
C++-идентификаторы через единый конвертер `utils::name_to_cpp`:

- простые ASCII-имена получают префикс `c_` (`x → c_x`, `MyInt → c_MyInt`);
- юникод-имена транслитерируются / HEX-кодируются (`привет → ru_privet`);
- `::`-квалификация кодируется как `cpp_std$$vector`;
- нативные имена с ведущим `%` (`%add`) - это уже C++-символы рантайма, `%` срезается.

Подробнее - в [Внутреннем имени и манглинге](mangling/).

## Нативные функции

Различаются две формы:

- **Предварительное объявление (forward-declaration)** - `%name(...):T := ...;`.
  Нативное имя и есть C-стиль идентификатор; реализацию линковщик ищет по имени.
- **Импорт** - `name(...):T := %native...;`. Это алиас: C++-функция `name` не
  эмитится, а вызовы `name(...)` переписываются в прямой вызов `native(...)`.

Линковка нативной декларации зависит от наличия `::` в нативном имени: без `::`
(`%sqrt`) forward-декларация эмитится с `extern "C"`; с `::` (`%std::sqrt`) -
C++-линковка без `extern "C"`. Атрибут `@[link("имя")]` добавляет `-l<имя>` к линковке.

## Вставки C++ (EmbedExpr)

Блок `{% ... %}` вставляется в выходной C++ код как есть; маркеры `$`/`@` внутри
связываются с локальными/статическими объектами программы.

## Интринсики

Некоторые конструкции транслируются в единые интринсики рантайма, например:
- `@assert`/`@verify` и trust-условия → `trust::intrinsic_assert`, который
  раскрывается в `if (!(cond)) trust::trust__abort__(...)`.
